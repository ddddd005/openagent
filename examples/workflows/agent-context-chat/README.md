# Agent 上下文与前端对话示例

本例来自用户在工作台创建的 11 节点工作流，保留其节点、布局、连线、两个提示词条目和上下文精简策略，并补齐 Agent 上下文的读取与写回绑定。

[workflow.json](workflow.json) 仅包含工作流配置，不包含会话、聊天历史、运行结果、检查点、供应商配置或凭据。示例使用独立的工作流身份、初始修订 `1`，不是原工作流的可覆盖备份。

## 能做什么

这是一张可接入模型的多轮对话基础图：

```text
可编辑输入 --------------------> 上下文装配 ----> Agent ----> 前端节点
读取 Agent 上下文 ------------> 上下文装配
两个提示词条目 -> 提示词汇总 ---> 上下文装配
模型来源、上下文精简策略 ----------------------> Agent
读取 Agent 上下文、Agent 执行凭据 -------------> 写回 Agent 上下文
```

前端节点绑定同一张图里的可编辑输入，输入模式已设为可调。Agent 负责本轮计算，写回节点接纳上下文更新，下一轮再通过读取节点取得会话内的上下文。前端聊天数据和 Agent 计算上下文是两个不同的数据项。

本例没有额外的 Agent 工具加载节点；需要工具时，按[工作流包说明](../../../docs/WORKFLOW_PACKAGES.md)显式装载，不要把普通连线节点当成已授予 Agent 的工具。

## 已完成的绑定

| 节点 | 使用的数据项 | 权限 |
| --- | --- | --- |
| Agent execution | 自身登记的 `workflow.effective-context@4` | 提供准确上下文登记，不自行定位或持有会话当前值 |
| Native context output | 同一个 Agent 上下文项 | 读 |
| Merge accepted Agent context | 同一个 Agent 上下文项 | 读、写 |
| 前端节点 | 自身登记的 `workflow.chat-context@1` | 保留原有读写权限 |

**这些绑定已经包含在示例中，不需要用户手工编辑 UUID 或权限 JSON。** 由 harness 导入或调整工作流时，应核对引用关系并代为处理绑定，只向用户说明结果。

## 使用方式

推荐让能读取仓库并调用本地工具的 harness 读取本例，然后按[Vibe Coding 手册](../../../docs/VIBE-CODING.md)协助创建工作流、选择模型和检查配置。

当前没有工作台文件导入按钮。本例是现行 schema 3 配置文档，不是新插件或预设入口。通过现有公开配置接口导入时，助手应：

1. 使用一份副本，为 `workflow_definition_id` 分配新的 UUID4，保持 `revision=1`，不携带旧 `edit_sequence`。保留文档内节点身份、数据项及引用的一致性，不覆盖已有工作流。
2. 经 `definition.update` 创建，使用 `expected_edit_sequence=0` 和新的幂等键；按既有流程保存原请求证据、核对回执并独立重读正式配置。不要直接写数据库。
3. 在“模型来源”选择当前项目中已保存、可用的模型配置。JSON 中的模型引用是内置默认占位身份，不携带作者的模型设置，也不保证目标环境有这条资源。
4. 按实际任务填写两个提示词条目。原图的提示词正文和可编辑输入均为空，本例未替用户编写任务规则。
5. 核对上下文绑定和前端输入绑定，等待配置正式保存。首次发送可创建会话；仅在用户明确要求运行模型后，从“前端节点”打开页面并发送。

用户也可以按[使用手册](../../../docs/USER-GUIDE.md)在画布手工搭建。上下文技术绑定仍应优先由助手完成，不作为留给用户的准备工作。

## 验证与边界

- 通过当前准确包集合完成结构、节点配置、对象登记和图编译校验，11 个节点全部进入执行计划。
- 在独立隔离 SQLite 中通过公开应用入口导入，核对原请求回执，并在关闭、重开后读回同一正式配置，确认没有会话。
- 来源工作流的绑定通过公开配置入口保存，并经独立回执和正式配置读取核对；未改变其提示词、模型选择或连线，未创建会话。
- 本次没有发起真实模型请求，也不据此宣称已完成真实多轮对话、精简或浏览器端到端验收。
- 首次初始化、固定配置派生、会话隔离、检查点白名单和未知请求只读核实，继续遵守现行工作流规则。不要重放旧请求或将源会话历史导入示例。
