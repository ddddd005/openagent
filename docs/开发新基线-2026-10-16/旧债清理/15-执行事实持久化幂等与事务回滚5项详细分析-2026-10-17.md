## 1. 结论先行

这五项不是“当前没有持久化、幂等或回滚机制”。当前源码已有不可变事实存储、同身份同内容重入、相邻序号检查和 Host 事务回滚；也存在三个当前仓储测试，历史基线均通过。

未闭合的是：五个旧身份都先卡在 `seed()` 的 `save_bundle`，尚未通过当前入口重新验证原有有效断言。现有覆盖尤其不能直接替代：

- 读取副本和原始入参被修改后，已经保存的事实仍不变。
- 两个独立数据库连接之间的重入、冲突及序号一致性。
- 写入后/提交前抛错时，由真实 Host 自动回滚，而不是测试自己执行 `ROLLBACK`。
- 失败后重开库仍保留原前缀，没有多出失败事实，也未误改业务记录。

建议保留五项有效意图，补齐当前已有责任边界的等价测试；没有理由仅为这些旧测试恢复旧 API、新建仓储或增加自动重试。

## 3. 当前实现的实际保护路径

当前真实写入入口是 `GraphRuntimeHost._accept_runtime_fact`，简化顺序为：

```text
打开当前 SqliteStore，取得 GraphRecordStore / RuntimeFactStore
→ BEGIN IMMEDIATE
→ 核对 session / chain / node 仍属于这次运行且处于可接纳状态
→ RuntimeFactStore.accept
    → 校验事务、JSON、事实 identity / sequence
    → 按 node_run_id + stream_id + fact_id 查已有事实
    → 已存在：坐标、规范化完整 payload 相同才返回原身份回执
    → 不存在：核对下一序号，INSERT
    → after_runtime_fact_write
→ before_runtime_fact_commit
→ COMMIT
→ 返回事实身份回执

异常：事务仍在时 ROLLBACK，再向上抛出
```

这里可以确认四点：

1. **事实接纳不等于业务状态提交。** 该入口读取运行归属、写入事实，不负责把整个 Agent 轮次或业务对象一起提交。
2. **底层仓储不是事务所有者。** `RuntimeFactStore.accept` 要求调用者已有事务，但不自行提交或回滚；真实 Host 才拥有此调用路径的事务边界。
3. **重复判断不是“文字内容一样就去重”。** 身份范围是 node invocation + stream + fact_id；同一身份还要坐标和规范化完整事实一致。不同调用/流的同名事实可以是不同事实，不能全局去重。
4. **不是只有进程内锁。** Host 源码还有数据库事务及 `(node_run_id, stream_id, sequence)` 唯一约束。不能因为不同 Host 不共用一把 Python 锁，就直接断言必然出现重复写；实际跨连接行为仍须测试。

源码依据：`backend/src/phase1_agent/graph_runtime_host.py:86`、`backend/src/phase1_agent/runtime_fact_store.py:11`、`:25`、`backend/src/phase1_agent/storage.py:47`。

## 4. 逐项分析：原因、影响和取舍

### 4.1 B089：完整持久化、读取隔离和业务分离

**当前已经有什么。** 当前事实写入 `workflow_runtime_facts`；写入前将事实编码成规范化 JSON，读取 `list()` 时重新解析并复制，返回值不是数据库中的可变 Python 对象。已有 `test_fact_commit_duplicate_and_reopen_share_one_immutable_row` 验证一次提交、同值重复、事实只有一行、没有另写管理幂等回执、重开后读到相同事实。

**还缺什么。** 该当前测试只有一个简单事实，没有验证多条有序事实的完整读取，也没有主动修改读取结果或原始入参后再读。它也没有比较实际业务图记录的前后值，不能独自承接旧 B089 的全部断言。

**一个容易测空的地方。** 当前 `SqliteStore.read_bundle()` 默认 `include_graph=False`，会过滤当前图记录。照搬旧测试的 `before = read_bundle()`、前后相等，可能根本没有覆盖实际业务记录。迁移时应核对明确的当前记录/对象范围，例如包含图记录的快照或相关表行，不用一个可能为空的默认 bundle 证明“业务没被改”。

**影响与取舍。** 有效风险是调试读取或调用方修改对象反向污染历史、事实漏存、事实写入误改业务状态；目前未发现这些故障。保留这些检查，去掉旧表名/版本号等绑定。当前接纳只返回 `{"fact_id": ...}`，无需为了沿用旧“修改追加返回的完整事实”断言而恢复完整事实回包，可改为检查当前回执和读取对象不影响事实原值。

依据：`backend/tests/test_runtime_fact_store.py:23`、`backend/src/phase1_agent/runtime_fact_store.py:33`、`:60`、`backend/src/phase1_agent/storage.py:155`。

### 4.2 B090：精确幂等、两个连接和序号竞争

**当前已经有什么。** 当前源码先检查完整事实是否已经存在：同身份且规范化内容相同返回同一 fact_id，内容不同明确冲突；新事实还需相邻序号，并受序号唯一约束。已有仓储测试验证同连接重复、改 payload 拒绝、跳号拒绝及不同 invocation 可保存同名事实。

**还缺什么。** 这些测试没有使用两个独立 `SqliteStore` 连接，未覆盖“连接 A 已提交，连接 B 重入”“连接 B 携带陈旧序号写入”“冲突后读取前缀不变，再按正确序号继续”等跨连接场景。旧 B090 正是需要保留这部分差别。

**必须订正一个强度误读。** 旧 B090 虽然同时打开两个 store，但调用是先后执行，不是真正同时争抢锁的并发压力测试。迁移后重现其双连接顺序对照，可以承接旧意图；不能据旧测试或该迁移就宣布多进程同时写、锁等待和崩溃竞争均已验收。

**不需要恢复旧 CAS 参数。** 当前没有 `expected_sequence`，但事实内 sequence、事务内 MAX(sequence) 检查及唯一约束已是当前可核对的防陈旧写路径。应验证行为，不要求为了满足旧函数签名重装一套 CAS API。通用流允许从 0 或 1 开始，某个测试流使用 1 不等于所有能力流都必须改成从 1 开始。

**影响与取舍。** 有效风险是同一事实重复落盘、同身份内容被覆盖、两个连接产生相同位置的不同事实。目前是跨连接验证欠账，不是已证实的并发 bug。保留独立的双连接检查，不用进程内 RuntimeHost 的去重缓存测试替代数据库测试；真正同时写的扩展验收如需增加，应另明确范围，不默认设计锁重试或调度策略。

依据：`backend/tests/test_execution_facts.py:209`、`backend/tests/test_runtime_fact_store.py:23`、`:39`、`backend/tests/test_runtime_hosting.py:207`、`backend/src/phase1_agent/runtime_fact_store.py:17`、`:36`。

### 4.3 B091：写入前故障

**当前已经有什么。** Host 会先检查运行归属，仓储还会先检查事务及输入，再执行 INSERT；异常向上传播，Host 的事务处理代码会在事务仍有效时回滚。

**还缺什么。** 当前没有旧 `fact.before_write` 注入点。测试如果继续传旧字符串，故障根本不会触发；如果仅用非法 owner 或非法 JSON 让请求被拒，也没有等价证明存储调用抛错时的处理。

**建议怎样承接。** 可在测试侧围绕当前仓储接纳调用，在执行真正写入前抛出确定异常，走真实 Host 已开启事务及归属检查后的路径；确认注入确实命中、没有执行写入、错误未被吞掉、原前缀/业务记录未变。撤掉测试注入后，重新提交同一事实应只新增一次。这里的“重新提交”仅是测试对同一事实的验证，不是重跑模型或工具。

**影响与取舍。** 保护的是“接纳失败不能伪称成功、不能污染状态”。保留意图即可，不必为测试新增生产故障钩子，更不应增加静默重试或成功兜底。

### 4.4 B092：写入后故障

**当前已经有什么。** `after_runtime_fact_write` 位于真实 INSERT 之后。已有 `test_fact_storage_fault_rolls_back_without_authorizing_dispatch` 在这里抛错，随后检查事实表为空。

**现有覆盖的关键限制。** 这个测试是自己执行 `BEGIN IMMEDIATE`，捕获异常后自己执行 `ROLLBACK`。它证明了底层写入能参与调用方事务、写后异常可回滚；**没有证明真实 Host 一定替调用方回滚**。而且名字含 “without_authorizing_dispatch” 并不意味着它实际运行了模型/工具调度；函数没有外部 dispatch 计数断言。

**建议怎样承接。** 将同一个现有故障点放到真实 Host 的事实接纳路径，不由测试代替 Host 回滚；从另一个连接或重开库检查本次事实没有留下、旧事实前缀和业务记录未变。随后去掉故障，用同一事实接纳一次，并核对实际只新增一行。当前直接仓储测试仍有价值，不必为了迁移旧身份把它删除。

**影响与取舍。** 这是“写进去但未提交时出错”的关键保护。重点是补 Host 事务所有权的验收，不是重写存储实现；直接仓储回滚和 Host 自动回滚可以共用准备逻辑，但不能强并成只剩一个层级的断言。

依据：`backend/tests/test_runtime_fact_store.py:58`、`backend/src/phase1_agent/runtime_fact_store.py:53`、`backend/src/phase1_agent/graph_runtime_host.py:90`。

### 4.5 B093：提交前故障

**当前已经有什么。** `before_runtime_fact_commit` 已存在，位于仓储接纳返回后、COMMIT 之前。异常处理在同一个 Host 方法中，可直接用于核对真实回滚路径。

**还缺什么。** 本次在 `backend/tests/` 检索，没有发现直接使用该钩子名称的测试。不能拿 B092 的直接仓储手动回滚测试或“提交成功后回执丢失”的测试冒充此边界。

**建议怎样承接。** 在真实 Host 路径于该现有钩子抛错，验证调用确实失败、事务由 Host 结束、重开后失败事实不存在、先前提交的事实和业务记录不变；撤掉故障后同一事实可接纳且只有一行。

**影响与取舍。** 保护的是未成功提交时不留下本次写入。保留独立参数，不与写后故障因“最后都是零行”而合并掉。该钩子只证明“调用 COMMIT 前出错”的回滚，不等于实际 COMMIT 指令 I/O 故障、断电或磁盘损坏验收；本批不据此新增崩溃恢复设施。

依据：`backend/src/phase1_agent/graph_runtime_host.py:104`。

## 5. 三个必须划清的边界

### 5.1 原子单位是一次事实接纳，不是整轮业务全部清空

当前 Host 每次接纳一条事实并提交。若 request/attempt 事实已经真实提交，而 outcome 接纳失败，正确性检查应围绕“原有前缀保留，本次失败事实不多落一条”，不能要求把此前真实发生的事实全部删除。

因此，迁移故障测试除了空流，还应对照已有合法前缀。检查“无半笔记录”不等于要求整轮所有事实与最终业务对象在一个事务里；扩大原子边界会成为产品/架构变更，本批不做。

### 5.2 提交前失败，与提交成功后回执丢失不同

现有 `test_agent_completed_result_retry_does_not_repeat_model_or_tools[terminal_fact_committed]` 会先调用真实接纳、成功提交，再人为抛出回执不可用错误。最终联合证据中该参数通过，最终 terminal fact 只有一个，模型和工具没有因接纳重入再执行。

这是当前已有的“已知结果接纳重入”防重复证据，不是 B093 的提交前回滚证据。已经提交的事实不应因调用方未收到确认就假定可以回滚；也不能借此替 B013、B371/B372 等其他未裁定失败语义作决定。

### 5.3 事实不可变，不等于数据库文件字节永不变化

事实 API 没有覆盖既有事实内容的写法，且比较规范化原值；这不等于阻止外部直接编辑 SQLite 文件，持久数据伪造属于 14 号 G 类的独立消费校验。

另外，`RuntimeFactStore` 构造时会初始化事实表，当前 Host 在事实接纳事务开始前创建仓储。测试临时库可能因此出现合法的空表初始化；不能用整个文件字节完全相同，替代“事实前缀和相关业务内容不变”的准确断言。

## 7. 取舍和建议接续

**保留什么：** B089 的完整性/隔离/重开，B090 的精确重入和双连接，B091–B093 的三个故障阶段；这些并非纯退役语义。

**不恢复什么：** 旧方法签名、完整事实回包、旧表名、storage 13、旧故障钩子字符串和旧错误文案。它们可在迁移说明中记录替换，不是恢复旧生产设施的理由。

**如何合理复用：** 可以复用当前最小存储夹具，以及真实 Host 的合法运行归属准备；不搭整套模型/浏览器链路来证明一条事实的事务行为。测试侧复用准备不等于把仓储层和 Host 层的独有断言删并掉。

**推荐先后：** 先 B089/B090 补准确存储行为和双连接对照，再用合法 Host 写入上下文分别覆盖 B091/B092/B093。故障测试必须确认命中，观察不同连接/重开后的结果，并保留原前缀和业务记录的对照；不靠额外兼容 API、自动恢复或改期望变绿。

本轮只落分析文档及入口链接，B089–B093 仍为旧夹具前置失败，48/510/403/87 等既有身份统计不变。测试迁移的实际写入、执行和最终验收须另记，不能把本分析当作实施回执。
