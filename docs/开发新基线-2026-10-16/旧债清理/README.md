- 当前有效决定、阶段目标和历史交付事实分开，不将旧方案重新表述为当前安装要求。

- 全目录分类、归档导航和 157 份获准物理归档已完成，不等于每篇正文都做了最终语义审阅。原始字节/哈希与历史事实仍可回溯，不从归档推定其他文件可删或可继续搬移。

## 4. 测试整理原则

每次合并、迁移或移除，都要记录准确用例及原验证意图：

| 处置 | 判断依据 | 必须保留的结果 |
| --- | --- | --- |
| 保留 | 当前行为仍需独立验证，或与其他用例的边界不同 | 原有独立检查 |
| 迁移 | 意图有效，但夹具、入口或数据形状已过期 | 当前契约下的等价断言 |
| 合并 | 验证目标实际重复，契约边界和测试层级适合合并 | 原用例到新位置的映射及独有检查 |
| 移除 | 纯退役语义、无效资产消费者、确已重复或经用户确认收益不足的旧检查 | 准确删除范围、理由、保留检查及有意不再承接的覆盖 |
| 待确认 | 当前语义冲突、等价覆盖未核实或涉及新责任边界 | 问题和证据，不假装已完成 |

不能只凭文件名、失败签名、测试红绿或代码入口已消失作移除依据。权限、并发、事务、历史只读、原请求保管、回执核验及退役拒绝检查仍须按各自意图保留或迁移。不能用 `skip`、`xfail` 或改写期望来掩盖尚未解决的问题。
