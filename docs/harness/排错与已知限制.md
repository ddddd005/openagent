# Harness 排错与已知限制

先看 [入口](README.md)、[工作流搭建](工作流搭建.md) 和 [CLI 手册](../../tools/workflow_cli/README.md)。本文是当前源码和测试的定位指南，不是新一轮服务或浏览器验收报告；本次没有新复现并确认产品 bug。示例命令在仓库根目录执行，`$base`、ID 和文件名均需换成本次真实值；不要把示例端口当成正在运行的服务。

已授权的调试范围内直接诊断，不必对每个操作重复询问。用户已明确启用包含真实模型调用的调试范围时，可在该范围内复用授权；打开项目、阅读手册或本次补文档本身不构成模型调用授权。新产品行为、现有服务启停、业务数据清理等仍须明确授权。不要自动重放未知请求、自动解除业务锁或自动关闭运行。

## 先确定失败发生在哪一层

按定位需要记录已知的源码 SHA、服务地址和启动元数据、数据库身份、工作流 ID、revision、edit sequence、session/chain/node run ID、时间、原始请求身份、HTTP 状态及脱敏后的 `reason_code`、`diagnostics`。HTTP 成功本身不能证明源码或数据库身份；拿不到的字段标为未核对，不为了填表直接打开业务库。查看 `phase`、`path`、`expected`、`actual` 和相关节点/端口，而不是只看错误标题。敏感正文、凭据和供应商私有材料保留在本地，不要贴入报告。

`workflow edit` 的 `prepared` 表示请求已准备且预演请求完成；带 `--apply` 还要看嵌套 `apply.status` 和退出码。预演通过不等于保存成功；保存成功不等于编译成功；`run.start` 返回 202/prepared 不等于执行完成或结果已接纳；离线测试也不等于真实模型或浏览器验证。

| 症状 | 检查命令或字段 | 处理和需要汇报的内容 |
| --- | --- | --- |
| 无法连接、403 或访问了错误实例 | `python --version`；核对用户提供的 `$base`，再运行 `python tools/workflow_cli/oa.py --base-url $base describe` 和 `catalog`。检查启动 metadata、服务进程及浏览器 Network 中的实际地址和 `Origin`。 | CLI 使用现有 Python 标准库，`--base-url` 是不含凭据、路径、查询或片段的 HTTP(S) origin，POST 的 `Origin` 与之相同。手写 HTTP 时也须使用与服务匹配的 Origin。健康响应不能证明源码是当前 HEAD；报告地址、实际身份和错误，未经授权不启停服务或安装依赖。 |
| JSON 或批次被拒 | CLI `error.code`、`details`；核对 [批次契约](../../tools/workflow_cli/README.md#批次契约) 和实际文件。 | 使用不含 BOM 的 UTF-8 JSON，不接受重复键和非有限数；注意部分 Windows 输出可能生成 UTF-16 或带 BOM。字段必须符合规定，已有图的 operations 非空，指定 ID 须为规范小写 UUID4。`--request-out` 只能新建文件；保留已有原请求，另选新文件名。报告准确字段和错误，不贴敏感内容。 |
| 配置改完丢失嵌套值，或 `unknown_alias` | `workflow read ID --full`、批次 `changes`/`replace`、输出 `aliases` 和当前 catalog。 | `node.add.config` 与 `node.configure.changes` 仅顶层浅覆盖，嵌套对象需提交完整期望值；`replace` 替换整个 config。别名不含 `@` 且唯一，引用 `@别名` 只能指向本批次更早添加的节点，仅在支持的节点引用位置解析。按正式基线重新准备；不要把任意字符串或边 ID 当别名。 |
| `remaining_dependencies` 或引用不合法 | 错误的 `dependencies`，预演 `declared_references.diagnostics`，节点目录的 `config_node_references`、控制边、事件目标、对象绑定和 preload。 | 删除节点只自动移除普通关联边；其他依赖必须明确处理。删除 binding 后仍引用它的 preload 也需处理。报告依赖及受影响对象，涉及删除或迁移超出授权范围时先交用户决定。 |
| `stale_baseline` | CLI 的 `expected`/`actual`；`workflow read ID --full` 中的 `revision`、`edit_sequence`。 | 这是批次准备时的本地基线比较；重新读取、结合当前内容重新构造批次和请求，不用旧图覆盖。 |
| `stale_edit_sequence` 或 `stale_revision` | 服务错误及 `definition.read`；确认本次请求的 `expected_edit_sequence`、文档 `revision`，会话操作还须检查该会话的 `expected_revision`。 | 这是服务端提交时的并发检查，和 CLI 的 `stale_baseline` 不是同一阶段。预演不会预留提交权；重新读取后审查冲突并重做，不直接改数字强行提交。 |
| `workflow_modification_busy` | HTTP 状态和 `reason_code`；确认同一工作流是否有另一个修改进行中。 | 修改资格忙时立即拒绝，不排队、不自动重试。等待对方操作明确结束后，重新读取基线并按授权决定下一步；不要直接清理锁或数据库。 |
| `configuration_run_locked` | 错误或预演 `baseline.run_locked`、`occupying_sessions`；对每个会话查询 `session.actions`、`session.read` 和对应 `run.read`。 | G21 由仍有 `active_chain_run_id` 的会话占用，失败或暂停也可能占用。`close` 是显式业务控制动作，先检查 `available_actions`、运行现场和影响，再由用户按当前授权决定；不要自动 close、归档或改库。关闭不撤销已经发生的外部效果。 |
| `confirmation_required` | `preview.changes`、`baseline.has_effective_session` 和服务 `result.outcome`。 | 存在有效会话且 fixed 内容改变时，未确认的结果零写入。派生会产生新工作流 ID，不是原地保存；把影响交用户决定，得到明确选择后才准备 `confirm_derivation: true` 的请求，并记录新身份。 |

## 预演与图诊断

`workflow edit --batch batch.json --request-out request.json` 先创建原始请求文件再调用预演。`preview_failed` 表示预演请求失败，文件已创建；保留文件和错误，不把它当成保存结果。`prepared` 也可能包含业务诊断，逐层检查：

- `structure.ok` / `diagnostics`：文档结构及端点问题；结构失败时后续编译可能标记 `skipped`。
- `declared_references.ok` / `diagnostics`：声明引用、对象绑定及访问一致性。对象 `owner_node_id`、`registrar_node_id`、`readers`、`writers` 必须与实际声明及权限匹配；registrar 并不自动授予读写权限。`binding.put` 是完整替换，检查 scope、owner 和全部权限；不要靠猜测增加权限。
- `compilation.ok` / `skipped` / `diagnostics`：检查节点、端口、类型及配置。保存的结构约束和编译不是同一关，图可能能保存却不能编译。
- `baseline`：检查 edit sequence、revision、归档状态及 G21；`changes` 是预测结果，提交仍重新检查。
- `run_conditions.package_lock_available`、`checked` / `not_checked`：当前包锁检查不证明全局或会话资源、工具、凭据、真实模型调用和后台执行已通过。

用 `catalog --component COMPONENT --version VERSION` 查看当前节点完整描述；不要根据显示标题猜端口。现有集成测试中的 Agent 到 merge 是 `receipts` 到 `receipts`，而 Agent 到前端内容是 `result` 到 `content`，这只是该测试对应的节点契约，实际连线仍以服务当前 catalog 为准。

编译或准备失败时检查模型资源引用、包锁及实际可用包；查询 `platform` 和 `definition.inputs`，后者的 `required_for_run` 在编译失败时可能是 `null`。修好编译后再核对必需输入。`run.start` 的准备阶段拒绝可能没有 run 记录，保留原始错误响应；实际派发后的故障再查 `session.read` / `run.read` 和节点诊断。不要用更换模型、密钥、放宽校验或自动重试掩盖错误。

## 写入结果不明

`unknown` 可能来自写请求的传输失败、5xx 或无法判定的响应；保留原始完整命令信封及 key，用 `python tools/workflow_cli/oa.py --base-url $base receipt --request request.json` 只读核实。原请求的所有字段和内容必须一致，包括完整 `document`；JSON 键序与空白不影响规范化身份。不要泄露原文件。

`matched` 返回正式 result 与 receipt；`unresolved` 只说明本次核实未成功，不证明未执行、已执行或已取消。检查 `reason_code` 和原请求完整性，报告结果未决。同 key 重提属于继续执行，可能首次执行，并非取消；不要自动重放。若用户明确要求终止，`request.abandon` 需要原请求的证据行并有独立仲裁语义；没有证据时保持未决。

`saved_read_failed` 不同于 `unknown`：服务已经接受 `saved`、`unchanged` 或 `derived`，只是后续正式读取失败。保留返回响应，按其中身份重新只读并核对，不重写。通用 `command` 的成功响应也不经过 `workflow apply` 的保存判定和正式重读。

## 浏览器记录与历史问题

浏览器提示保存记录无法读取或版本不兼容时，先核对 origin，保留原 raw 和 key；当前读取失败会保留原记录，不应以空白内容覆盖，也不要先清 localStorage。浏览器工作台与 CLI/API 的结果应各自取证。

历史上的 Esc、错误端口、悬挂保存等记录不能单凭旧报告认定为当前未修复 bug。若当前遇到类似现象，提供本次版本、精确步骤、实际请求和脱敏诊断，再判断是否重现。更多现场取证与安全分享见 [调试说明](../DEBUGGING.md)。

## 当前已知限制

| 限制 | 对操作的影响 |
| --- | --- |
| CLI 批次当前只有七种动作 | 改名、移动、替换、控制边、事件、配置策略和预加载等需显式构造原生完整文档更新；这些不是“后端没有能力”。具体路径见 [CLI 手册](../../tools/workflow_cli/README.md)。替换节点不能猜端口映射。 |
| 当前没有修订列表或差异查询 | `definition.read` 可按已知修订读取；不要把当前图当作历史图，也不要靠改计数覆盖旧版本。原始回执和请求留在原处。 |
| CLI 不自动执行完整前端 outbox 证据流程 | 本地完整请求文件可用于只读核实，但不等于已有服务端 request-evidence 行；没有相应证据不能直接使用 `request.abandon` 解除未知状态。 |
| 本地可信接入没有远程认证 | 服务返回的 management 能力是调用接口，不是跨项目或不受限的任务授权；依照用户当前范围、对象权限及准确包规则操作。 |
| 自定义工具适配器直传输入仍只校验主类型 | `PureToolBindingAdapter` 向 `tools.prompt-to-text@2` 直接传备选类型 `PROMPT@2` 会被拒绝；普通工作流连线不受影响，当前没有已注册适配器使用该组合。见 [汇总、输入装配与世界书](../CONTENT-SUMMARY.md)。 |
| 配置往返不验证模型、浏览器或运行期隔离 | 双 Agent 的分支/权限/端口可在预演和正式回读中检查；真实多轮、实际数据写回和页面行为需在获准范围内另行实际验证。 |

现行依据包括 [外部接入说明](../Agent接入工作流-2026-11-04/外部Agent接入使用说明-2026-11-04.md)、`tools/workflow_cli/tests/test_batch.py`、`test_cli.py`、`test_integration.py`、`backend/tests/test_workflow_preview_diagnostics.py` 和 `test_external_agent_loop.py`。这些测试的存在及历史结果不等于本次已运行测试，也不证明当前服务、浏览器或真实模型状态。
