# Harness 操作入口

面向用户启用的本地代码助手，例如 Codex、dsh。这里是使用预置命令配置、检查和调试 OpenAgent 的当前入口；工作流内部 Agent 的工具装载另见[工作流搭建](工作流搭建.md)。本目录维护操作方法，不是历史执行规划，也不证明当前服务或模型已验证可用。

## 第一次接手

1. 阅读根 [AGENTS.md](../../AGENTS.md)，继承本次对话中用户已经给出的目标、范围和授权，不要求用户重复确认已决定的事。
2. 已有项目正在运行时，取得用户提供的服务地址，使用 [CLI 操作手册](../../tools/workflow_cli/README.md)的免安装入口执行 `describe`。服务地址可能是工作台代理地址，也可能是后端地址；示例端口不代表真实服务身份。已有 Python 3.10 以上即可运行 CLI，不需安装项目依赖。
3. 按任务读取目录和目标工作流：`catalog`、`definition.summaries`、`workflow read ID --full`；新建图也先了解实际节点契约。不要先通读历史规划、凭据库或数据库。
4. 按下表选手册；只有缺少业务取舍、连接地址或本次操作授权时才询问用户。节点 UUID、精确端口、绑定 JSON 和请求文件由 harness 处理。

| 要完成的事 | 直接阅读 |
| --- | --- |
| 执行命令、创建图、增删改节点、连线、对象绑定、保存、查回执 | [CLI 操作手册](../../tools/workflow_cli/README.md) |
| 了解现有功能、搭建基础图、单 Agent 多轮、双 Agent 独立上下文 | [工作流搭建](工作流搭建.md) |
| 定位报错、结果未知、锁定、错误接线和当前限制 | [排错与已知限制](排错与已知限制.md) |
| 查完整原生 API 参数、文档 schema、诊断与能力边界 | [外部 Agent 接入说明](../Agent接入工作流-2026-11-04/外部Agent接入使用说明-2026-11-04.md)及服务 `describe` / `document.contract` |
| 用户希望手工使用画布、供应商、内容或聊天页面 | [使用手册](../USER-GUIDE.md) |
| 当前工具无法满足，需要改源码或制作节点、工作流包、图内 Agent 工具 | [Vibe Coding 手册](../VIBE-CODING.md)、[工作流包](../WORKFLOW_PACKAGES.md) |
| 没有可用服务、缺环境或依赖 | [快速启动](../QUICKSTART.md)；准备环境、启停现有服务仍按当前授权处理 |

CLI 是外部 harness 的客户端，借助现有 HTTP 管理接口工作。它不导入后端内部模块，不是工作流内部 Agent 可自动获得的工具，也没有额外的 MCP 服务或驻留进程。通用 `query` / `command` 保留正式接口能力；没有专用 CLI 快捷操作不等于后端不支持。

## 用户提供什么，Harness 负责什么

用户可以只描述需求和输入示例，不需要预先理解节点系统。已有信息足够时先推进；有多项可用资源但选择会影响费用、输出或数据归属时，再说明差异并请求决定。

| 事项 | 用户需要提供或决定 | Harness 负责完成 |
| --- | --- | --- |
| 目标和内容 | 希望得到的结果、要改哪个现有工作流或新建图；必要的业务规则。可授权助手代拟提示词 | 翻译为节点与连线，起草提示词，发现需求矛盾时说明影响 |
| 连接项目 | 当前服务地址；无法从已给上下文明确目标时，确认目标项目 | 用正式只读接口发现能力和目标身份，保留其他工作流 |
| 模型与供应商 | 选择允许使用的已保存模型；没有配置时，提供准确供应商、型号和真实容量，按凭据入口配置 Key | 查询并引用已有可用预设，核对启用状态与必要配置；不猜造模型身份、容量或凭据，不要求把 Key 写进普通对话或工作流 |
| 上下文与数据归属 | 哪些 Agent 应独立，哪些材料允许共享，是否需要历史。归属已经明确时不用再问 | 处理 UUID、对象键、registrar、readers/writers、前端输入引用；核对实际声明和精确端口 |
| 日常配置修改 | 当前任务内要实现的效果 | 在已授权范围内构造单动作或批次，预演、保存原请求、提交、核对正式结果；不逐节点要求批准 |
| 运行与费用 | 是否包含真实模型调用的调试范围；模型或外部工具调用可产生费用或实际效果 | 已明确授权时在该范围内继续，不逐次问询；“检查配置”“不实际调用”或仅打开项目不等于模型调用授权 |
| 派生、运行关闭、归档、删除 | 已有授权未覆盖时，决定是否派生新图、关闭活动链或删除指定业务对象及历史 | 先说明会影响的图、会话、历史及替代路径；不为了让编辑通过而自动 close、归档或删除 |
| 环境及源码工作 | 需要时确认服务启停、安装、迁移、新架构、Git 操作等超出当前任务的事项 | 先用现有工具诊断；发现工具或产品缺陷时区分配置问题与需要改代码的问题，报告最小证据和影响 |

本表沿用当前协作要求，不新增逐操作把关。用户对一个明确调试范围的授权可在该范围内持续使用；已明确选择派生或允许模型调试，不必因下一条命令重复询问。文档本身不授予新权限；本次会话的明确要求优先。

## 操作时向用户汇报什么

开始前用一两句话说明目标、会修改的工作流及验证范围，特别区分“只检查/编辑”和“执行真实模型”。正常读取目录、生成 UUID、匹配字段和常规连线不逐步汇报 JSON；耗时工作提供简短进展。

| 时点 | 应报告的内容 |
| --- | --- |
| 找到缺失前提或业务歧义 | 缺什么、影响什么、用户需要作出的具体决定；能独立完成的检查继续做 |
| 保存被拒绝或遇到冲突 | 目标工作流和原因，如过期基线、忙、活动链锁定、悬挂引用；本次是否已写入，下一步需检查或决定什么 |
| 需要派生新图 | 原图和会话如何保留、新图不继承哪些运行数据；已明确同意后才执行对应派生请求 |
| 写入结果未知 | 明确说“尚不能确认是否保存”，保留原请求文件和幂等键，用只读 receipt 核实；`unresolved` 不等于未执行 |
| 已保存但回读失败 | 明确说“后端已确认保存，正式重读失败”，保留成功回执；不误报未保存，也不重新提交同一修改 |
| 任务完成 | 哪个工作流已改变、正式身份/修订、主要变更；做过哪些验证、还有什么没验证，是否仍需用户配置模型等前提 |
| 判断为产品或工具缺陷 | 复现条件、实际/预期、错误码及定位字段、影响；未复现的怀疑标为待核实，不写成已确认 bug |

完成说明应先讲用户看得懂的结果，再附必要身份或本地文件位置。不要输出 Key、完整个人正文、原始模型私有协议或庞大的原请求；精确请求文件留在本地供核实。

## 按证据描述完成程度

| 已取得的证据 | 能说明什么 |
| --- | --- |
| 生成批次或请求文件 | 修改提案已构造，尚未保存 |
| `definition.preview` | 返回其列出的结构、引用、编译和基线检查；不预留保存资格，不验证模型连通性 |
| 正式写回执与 `definition.read` | 对应请求已接纳，读到正式配置；`derived` 要使用返回的新工作流身份 |
| 编译、`definition.inputs` 与资源检查 | 在对应检查范围内具备运行前提；可保存与可运行是不同判断 |
| `run.start` 返回 prepared / 接受启动 | 已接纳启动，不代表整轮完成；按返回的会话和链继续读取 |
| 会话/链终态、节点输出和上下文写回 | 只说明本次实际运行涉及的行为；模型正文可见不等于整轮或写回已成功 |
| 浏览器实际交互、真实模型多轮测试 | 仅在实际执行并核对后报告；离线测试或结构分支隔离不能替代 |

当前目录中的操作示例以当前源码和正式契约核对。节点准确版本、端口、配置默认值、包锁、可运行动作仍以目标服务返回为准；旧示例版本存在不等于应自动迁移。历史执行回执用于追溯，不作为新任务清单或当前运行状态证明。
