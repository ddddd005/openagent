# 工作流搭建

本文面向协助用户的外部 harness。沿用用户已经说明的目标、内容和模型选择，缺少影响结果的业务取舍时才询问。节点身份、连线、对象键和权限由助手处理，不要求用户手工填写 UUID 或绑定 JSON；已有授权范围可持续使用，未涵盖的真实服务、数据或模型操作再确认。操作和错误处理入口见 [主入口](README.md)、[排错与已知限制](排错与已知限制.md) 和 [CLI 手册](../../tools/workflow_cli/README.md)。

## 先认识现有能力

| 能力 | 作用与边界 |
| --- | --- |
| 文本、可编辑输入、输出 | 提供文本或展示结果；可编辑输入可由前端节点绑定。正则、文本/JSON/提示词转换是显式节点，不是自动类型转换。 |
| 提示词条目及引用 | 条目提供带角色、位置、顺序和生命周期的材料；全局资源需用对应引用/解析节点接入，保存资源本身不会自动注入图。 |
| 汇总、输入装配 | 汇总保留材料、上下文和本轮输入的结构及来源；输入装配为 Agent 做最终消息排布，必须取得上下文和本轮输入。 |
| 世界书 | 只读匹配输入，只输出自身命中的提示词材料；原输入需另接后续节点。详见下文。 |
| Agent、模型、工具 | 模型来源引用已保存的模型配置；Agent 接收装配输入和模型。工具需显式加载和授权，普通数据连线不会授予 Agent 工具权限。上下文精简策略可接 Agent。 |
| 前端、上下文 | 前端绑定本图可编辑输入并显示结果；聊天数据与 Agent 计算上下文是不同会话对象。读取和写回节点须获得对象权限。 |
| 变量、会话预加载 | 变量可注册、赋值和显式替换；普通新会话可按预加载声明初始化一次，已有会话不会随初值修改重置。检查点分叉恢复已保存状态，不重新应用预加载。 |

新图先查询当前 catalog 中准确的 `component_id`、版本、端口、默认配置、配置中的节点引用声明与可用包锁；不要把示例中的版本表当作永远最新。新节点按声明的默认配置和 schema 构造，按声明处理节点引用；包锁使用目标环境的准确执行包集合。已有图保留其版本，包启用不会自动迁移旧图。CLI 的 catalog 和批量编辑命令见 [CLI 手册](../../tools/workflow_cli/README.md)。

## 最小无模型图

用 `tools.text@1`（默认 `{"text": ""}`，填写所需文本）的 `output` 接 `tools.output@1`（默认 `{"mode": "text"}`）的 `input`。这张图用于检查文本连线和输出，不需要模型或 Agent。通过 CLI 的 `workflow edit` 预览、保存请求，再 `workflow apply`，读取正式配置并核对回执；命令和 batch 格式以 CLI 手册为准。保存配置不等于执行：仅在得到运行授权且环境具备所需条件后运行。此示例不涉及真实模型。

## 单 Agent 多轮：可照做的路径

1. 按用户目标使用其文案或代拟提示词，确认允许引用的已保存模型配置。模型容量和运行参数应使用真实规格；示例的模型引用是占位身份，不能假定目标环境存在。
2. 使用 [Agent 上下文与前端示例](../../examples/workflows/agent-context-chat/README.md) 及其 [schema 3 配置](../../examples/workflows/agent-context-chat/workflow.json) 作为副本。助手为工作流生成新 UUID4，保持 `revision=1`，去掉旧 `edit_sequence`，保持节点及引用一致；核对示例包锁与当前 catalog 的准确执行包集合。示例是完整图文档，不能直接传给 `workflow edit --batch`：构造 `operation=definition.update` 的原生命令文件，参数包含新身份、完整 `document`、`expected_edit_sequence=0` 和新 `idempotency_key`；另将身份、文档及预期序号传给 `query definition.preview --params FILE`，检查后用 `workflow apply --request FILE` 提交和正式重读。不要覆盖原图、直接写数据库或导入历史会话。也可依据当前 catalog 从头用批次搭建。
3. 填写提示词并选择模型；核对前端绑定本图可编辑输入，输入配置模式为可调。示例已有上下文绑定：Agent 登记其 `workflow.effective-context@4`，读取节点有读权限，写回节点有读写权限。助手核对并处理这些技术绑定。
4. 核对以下数据线。示例使用 `prompts.summary@2` 和 `context.assembly@5`，其现有端口如下；从头采用新版时按下一节的新版端口连接，不混用假定的版本契约。

| 来源端口 | 目标端口 |
| --- | --- |
| 可编辑输入 `output` | 上下文装配 `current_input` |
| 各提示词条目 `output` | 提示词汇总 `input` |
| 提示词汇总 `output` | 上下文装配 `materials` |
| 读取上下文 `output` | 上下文装配 `view` 和写回上下文 `view` |
| 上下文装配 `output` | Agent `prompt` |
| 模型来源 `output` | Agent `model` |
| 精简策略 `output` | Agent `compaction_policy` |
| Agent `receipts` | 写回上下文 `receipts` |
| Agent `result` | 前端 `content` |

5. 保存并独立重读正式配置，核对对象绑定、端口和回执。保留原请求证据；若结果不明，先只读核实，不自动重放。已有会话可能涉及修订或派生确认，按实际返回处理。
6. 仅在用户明确授权真实模型运行后打开前端、核对工作流和会话身份，再发送短文本。打开页面本身不创建会话或调用模型；发送才保存输入并启动本轮。检查运行状态及上下文写回，不能仅凭页面显示回答认定整轮成功。上述搭建步骤本身不证明真实模型、多轮或浏览器端到端已通过。

## 新版汇总和世界书

当前新增声明中，`prompts.summary@3` 的 `summary`、`view`、`current_input` 可选，`input` 接多路提示词材料；输出 `output` 为结构化汇总。`context.assembly@7` 接 `summary`、`view`、`current_input`、多路 `materials` 和可选的单一 `tool_prompt`，输出供 Agent 使用的冻结输入。上下文和本轮输入可直接接入，也可来自汇总；最终缺少任一项会报 `input_assembly_incomplete`。重汇总不能静默合并不同上下文或不同本轮输入。

新版世界书 `lorebook.item@2`、`lorebook.group@2` 和 `lorebook.global-activate@2` 的 `structured` 可接汇总、上下文视图或提示词材料，`text` 接文本，至少连接一个；两口都支持多路，全局触发另需 `resource`。结构化上下文历史和本轮输入按扫描深度匹配，普通提示词按正文整体匹配，元数据不参与正文匹配；上游世界书材料按递归规则参与。文本口整体匹配，不按历史深度裁剪。普通提示词要走文本口，先使用 `tools.prompt-to-text@2` 显式转换。已冻结的 Agent 输入不能作为新版世界书扫描输入。准确组件和端口以目标服务当前 catalog 为准。

典型接法：汇总 `output` 分别接世界书 `structured` 和输入装配 `summary`；世界书 `output` 接输入装配 `materials`。世界书不会转发原汇总，漏掉后者会丢失原内容。也可将世界书输出送入后续汇总的 `input`，原汇总另接其 `summary`。完整类型与限制见 [汇总、输入装配与世界书](../CONTENT-SUMMARY.md)。

## 双 Agent 与状态

各 Agent 要保留独立上下文时，各自使用不同 `object_key`，各自的 Agent 是该项 registrar，各自读取节点和写回节点列为 readers，只有各自写回节点列为 writers；每支的读取 `output` 分别接本支装配和写回的 `view`，本支 Agent 的 `receipts` 接本支写回的 `receipts`，`result` 接需要展示该结果的前端 `content`。前端聊天项也按实际会话设计分别绑定。普通边传递数据，不授予会话对象访问权；`shared` 不代表所有节点均可读写。跨 Agent 共享与业务归属需由用户决定，不能自行推断。

变量的 `{{变量名}}` 不会自动全局替换，要连接变量替换节点并授权。预加载与注册节点不要同时初始化同一对象键；预加载也不会自动授予读写权限。类型、初值、检查点准入及分叉规则见 [会话预加载数据](../SESSION_PRELOADS.md)。
