## 0. 结论摘要

1. 带“采集+恢复”语义的数据载体只有一个：`session` 作用域会话对象，且**普通类型只有声明进 `session_preloads` 才会进入检查点 `preloaded_items`**（checkpoint_collection.py:185-192、293-298）；`checkpoint_admission=True` 只决定“该类型可被预加载准入”，本身不触发采集（session_preloads.py:113、checkpoint_collection.py:173-192）。
2. 工具目标代码（纯工具/变量工具目标）没有通用数据层写入口：纯工具上下文为空且禁止对象写（graph_tool_host.py:147-158），变量工具只有单对象读写（graph_tool_host.py:171-202）。工作区工具若要“自行保存”，需要 P1 新增适配面或由 Agent 执行器侧写对象（agents.execute 目前无 `objects:*` 能力，agent_package.py:63-79）。
3. 采集只发生在**成功 round 结束事务**：commit 后追加 success checkpoint（graph_service.py:1503-1544，尤其 1533-1537）；failed/paused/closed/event 完成后不追加（test_success_checkpoints.py:157）。
4. 恢复到独立目标会话的现有构造是 `graph.checkpoint.fork` → `WorkflowChatService._fork_checkpoint_state`（graph_service.py:684-701、workflow_chat_service.py:293-350），原会话不被覆盖；该路径**要求目标定义的全部 preload 值在所选检查点中精确保存在**（workflow_chat_service.py:302-317），因此“给既有历史后加 preload”的旧检查点不可 fork。
5. 程序合成 `result` 只能落在节点输出层：`agent_result.final` 必须等于模型 final_answer 结算（execution_facts_v2.py:367-369），context.merge 只用 receipts/facts 重建消息（context_v4_nodes.py:279-291、context_v4.py:358-373），合成文本当前不会进入下一轮上下文；如需进入须改消息/操作契约。
6. 测试基座完整可复用：离线 transport、隔离 sqlite、examples 包复制到临时 `packages/workflow` 均有现成写法；V10 两回合差异+恢复已有近乎同构的验收（test_preloaded_checkpoint_items.py:275-301）。P4 数据面主要缺口不在平台，而在“地图工具数据尚未进入会话对象层”与“真实工具无长驻进程协议”。

## 1. 工具“经所属领域数据层”的现有写入口

### 1.1 会话对象：唯一带检查点恢复语义的载体

- 存储与权限：`SessionObjectStore` 读 `read`（session_objects.py:106-118）、写 `apply`（:476-532），必须有调用方事务（:64-66），按 `ObjectBinding.readers/writers` 与节点 id 授权（:75-81）；写集 ≤256（:479）、每对象一次（:481-482）、CAS `expected_revision`（:503-504）、幂等 receipt（:495-502）。
- 绑定声明：`ObjectBinding` 字段 `object_key/type_id/schema_version/scope/readers/writers/owner_node_id`，可带 `default_value` 或 `registrar_node_id`（host_sdk.py:546-601；scope 只能 shared/private，:564-566）。
- 节点写入口：`NodeExecutionContext.object_read/object_write/object_delete`（graph_execution.py:129-160）产出 `WriteIntent`，只在节点 **succeeded** 事件携带（:571-573），由 `graph_service._save_effects` 在节点结算事务内 `apply_objects`（graph_service.py:1044-1048）；节点被拒时状态回滚、写不发布（graph_execution.py:535-539）。
- 执行数据读数口：`ExecutionState.objects/read_object/apply_objects/checkpoint_value`（execution_data.py:223-244）。
- 具名注册：节点类型可声明 `provided_session_item_types`（graph_contracts.py:374、419-440），但该声明只被三类“专用类型选择器”消费（见 2.1），普通新类型不因此被采集。

### 1.2 程序共享数据、私有状态、资源/宿主服务（都不是检查点分区）

- 共享会话数据：`read_shared/write_shared` 写的是 program state 的 `data` 分区（graph_execution.py:225-254），定义结构见 resource_contracts.py:84-148；持久化经 `write_variables`（graph_service.py:1037-1041），不在检查点 item 分区中（runtime_checkpoints.py:24-25）。
- 私有状态：`private_read/private_write`（graph_execution.py:162-171）写 `node_session`，仅进 state snapshot 的 `node_states`，检查点 `state_storage` 不包含它（runtime_checkpoints.py:18-25，checkpoint_loading.py:166-249 只初始化对象值）。
- 宿主服务：节点经 `host_call(capability, operation, payload)`（graph_execution.py:74-78）调用包注册服务；授予规则要求能力声明+精确 service/operation（host_sdk.py:246-271）；包注册面 `register_service` 等见 capability_packages.py:140-252。
- 全局资源：`ResourceIdentity`（host_sdk.py:633-654）只标识外部资源，不是会话数据。

### 1.3 工具目标代码实际能拿到什么（现状限制）

- 纯工具目标：`NodeExecutionContext` 传 `state={}, private_states={}, external_inputs={}, object_states={}`、无 host（graph_tool_host.py:147-153），执行后要求无 effects/object_writes（:156-157、tool_bindings.py:110-118）。
- 变量工具目标：`state` 为当前程序变量**快照**、`object_states` 只有声明的单对象、`object_accesses` read/read_write（graph_tool_host.py:171-179）；write 访问必须恰好产生 1 个对象写（:187-201），由 `_accept_tool_write` 在**独立事务**（`graph.tool.object-write`，幂等键 `tool:<tool_execution_id>`）提交并回读校验（:228-264）。
- 工具目标声明限制：必须 `execution_class="working"`、不得声明 `service_requirements`、resources/external/private 能力、`settlement_builder`、`provided_session_item_types` 等（tool_bindings.py:81-120）。即：**现有工具目标不能用 host service，也不能多对象写入**。
- Agent 执行器上下文不受这些限制（execute_graph.py 直接构造完整 context，graph_execution.py:411-424），但 `agents.execute@10` 无对象能力/绑定（agent_package.py:63-79）。执行器侧写数据需要改节点声明/版本（P2 责任，需用户确认边界）。

### 1.4 地图类数据的候选载体与所需声明

现状下唯一可被采集+恢复的组合是：

1. 包注册 session 作用域类型：`DataTypeDefinition(type_id, version, schema, scope="session", checkpoint_admission=True)`（host_sdk.py:289-328；包注册面 capability_packages.py:182-198；admission 要求 session 作用域 host_sdk.py:349-357）。
2. 工作流文档 `object_bindings`：为每个数据键声明 binding，readers/writers 至少含承载工具调用的 Agent 节点 id（调用归属校验按节点 id，session_objects.py:75-81；工具调用上下文 node_binding_id = Agent 节点，graph_tool_host.py:148-149、171-172）。
3. 工作流文档 `session_preloads`：每键 `{object_key, value}`，文档 schema 3，单文件 ≤1024 项（session_preloads.py:16、64-127）；该 binding 不得再有 `default_value`/`registrar_node_id`（:98-100）；类型不得有 validator/references 等特殊回调（:115-121，variable 除外）；初值按类型 schema 校验（:129-156）。
4. 新会话创建时 `initialize_preloads` 一次性建立初值（session_objects.py:179-208、graph_service.py:664-667）；之后工具每回合用对象写更新当前 head，成功回合结束时被采集（见 2）。

候选拆分（**细分待确认**）：`map/meta`（地图、地点目录、地点详情/邻接）、`map/characters`（角色/NPC 位置与状态）、`map/events`（正式操作/行为链及其游标）三个对象，或按地图拆分多对象。约束：单对象值上限默认 1MB（host_sdk.py:22、300；类型可配到 4MB，host_sdk.py:356）；单节点写集 ≤256（session_objects.py:479）；preload 总数 ≤1024（session_preloads.py:16）。地图工具当前把状态放在自己的 sqlite（见 5.5），**该文件不在数据层，也不受检查点保护**（规划 5.2 第 3 条同义）。

## 2. 检查点收集与恢复准确规则

### 2.1 采集（collect）

- 入口只在成功 round：`graph_service._run_settle_stage` 在 `status=="succeeded"` 且 `execution_kind=="round"` 时 commit 后追加 checkpoint（graph_service.py:1503-1544、1533-1537）；追加逻辑 `_append_success_checkpoint`（:1255-1286）。
- 采集内容固定为 4+1 分区：`agent_contexts`、`variables`、`chat_contexts` 必选，`preloaded_items` 可选（runtime_checkpoints.py:23-25，validate_checkpoint_state :117-128；checkpoint_collection.py:328-381）。
- 各分区选择器（全部是“精确类型白名单”）：
  - `agent_contexts` → `workflow.effective-context@4`（checkpoint_collection.py:173-176），要求 binding 类型 `checkpoint_admission`（:130-131）且 registrar 节点的 `provided_session_item_types` 含该精确类型（:151-158）；
  - `variables` → `workflow.variable@1`（:179-182）；
  - `chat_contexts` → chat-context 精确类型（:209-212）；
  - `preloaded_items` → `session_preloads` 中除 variable 外的普通类型（:185-192），逐键读当前 head，缺失或删除即 409（:195-206）。
- 采集读取走内部信任边界 `_checkpoint_current_value`（session_objects.py:220-250），不经节点权限；调用必须处于调用方事务（checkpoint_collection.py:26-28）。
- state manifest 中虽然记录了本会话全部对象 head（session_objects.py:641-657），但 manifest 不是 checkpoint `state_storage`，fork 恢复不使用它（workflow_chat_service.py:318-344 只复制 checkpoint prefix/state）。

### 2.2 “checkpoint_admission=True 不等于自动采集”的代码证据

1. `checkpoint_admission` 的消费点只有两处：session preload 准入（session_preloads.py:113）和专用类型选择器跳过判断（checkpoint_collection.py:130-131）；没有任何代码遍历 `object_bindings` 自动收集 admission 类型。
2. 普通类型的采集入口只有 `checkpoint_preloaded_bindings` → `session_preload_bindings`（checkpoint_collection.py:185-192、293-298）：未写入 `session_preloads` 的 binding 不会出现在 `preloaded_items`。
3. `provided_session_item_types` 只参与三类专用选择器的 registrar 校验（checkpoint_collection.py:151-158），普通新类型声明它也不会被采集；且 node registry 只校验类型已注册（graph_contracts.py:435-437）。
4. 恢复端同样精确匹配：`load_checkpoint_state_in_transaction` 要求 `set(preloaded_items) == preload_bindings.keys()`（checkpoint_loading.py:219-228），fork 要求每个 preload 值精密存在（workflow_chat_service.py:302-317）。未声明 preload 的普通对象在 fork 新会话中按默认值初始化（session_objects.py:144-147、160-162 需要类型/绑定默认值），不会带历史值。

### 2.3 恢复（load/restore）

- 加载函数：`load_checkpoint_state_in_transaction`（checkpoint_loading.py:166-249）：目标必须是**全新初始化会话**——revision==1、source new、无 snapshot/commit/ref/chain/node_run/output、无对象 receipt/manifest、无 program variable 状态、对象全在初始 revision（:29-98）；状态与目标固定定义/绑定精确一致（:184-241）；写入由 `_initialize_checkpoint_values` 直接安装并 CAS（session_objects.py:252-379）。
- 独立目标会话入口：`GraphWorkflowService.fork_checkpoint`（graph_service.py:684-701）→ `WorkflowChatService._fork_checkpoint_state`（workflow_chat_service.py:293-350）：复制 checkpoint prefix、重映射 checkpoint id、`_initialize_session(preloaded_values=历史值)`（:302-317）、加载对象值（:337-343）、提交 `session_seed`（:345）。原会话只被读取。
- chat 楼层分叉走同一入口：`chat_fork_floor`（workflow_chat_service.py:352-371）。
- 失败/警告：early checkpoint 缺 `preloaded_items` 且目标定义已有 preload 时会 `checkpoint_target_preload_binding_mismatch`（checkpoint_loading.py:219-228）；`make_diff` 要求已建立的分区不得省略（runtime_checkpoints.py:205-232）。

### 2.4 两成功回合差异验证所需现存构造

1. 隔离服务+自定义包（注册 session 类型、节点 object_accesses）：test_preloaded_checkpoint_items.py:52-103（`preload_package`、`GraphWorkflowService(..., capability_packages=..., enabled_packages=...)`）。

3. 两回合执行与检查点历史：`submit(service, view, "one"/"two")`（test_workflow_chat_service.py:94-113）+ `checkpoint_history`（test_success_checkpoints.py:25-57，返回 path/state/collected）。
4. 恢复到较早检查点：`_fork`（test_checkpoint_fork_stage2_acceptance.py:36-44）或 `WorkflowChatOperations.fork_floor`（test_preloaded_checkpoint_items.py:321-323）。
5. 断言：目标会话对象值等于回合 1、原会话值仍等于回合 2、关闭重开（新进程/新服务）后仍一致；现有同构验收见 test_preloaded_checkpoint_items.py:275-301（断言 `history["state"] == history["collected"]`、target `(3,17)`、reopen 后一致）与 :304-327（断言原会话 `second` 不变，:327）。

### 5.4 进程与命令协议（关键缺口）

- **没有长驻进程**：只有“每次调用一个短进程/一个库对象”的模式。`Sandbox.__init__` 打开 sqlite（sandbox_v3.py:26-60），`close/__enter__/__exit__` 仅关连接（:62-70）；CLI `main` 一次解析子命令、读一次 stdin JSON、打印一次 stdout JSON 后退出（:571-636）；测试用 `subprocess.run` 逐条调用（test_v3.py:323-345）。
- 无 socket/tcp/http/json-rpc/常驻循环：全目录 `.py` 检索仅命中 sqlite connect 与 stdin 读取（sandbox_v3.py:35、576、603）。
- 正常结束/停止/退出确认：无“stop/quit/exit”命令与退出确认协议；正常结束=进程自然退出或 `Sandbox.close()`。跨进程连续操作依靠 sqlite 中持久化的 ticket（README_V3.md:168-176、test_v3.py:323-345），不是同一运行实例。
- 同调用多命令共享运行态：在单进程内可用同一个 `Sandbox` 对象（RLock，sandbox_v3.py:12、33、144-151）顺序执行；跨进程则共享的是 sqlite 文件而非实例。

### 5.5 数据持久化方式

- 初始世界 JSON 只读：`overview.json`、`maps/**`、`characters/*.json`、settings `.json/.md`；V2 `_load_json`（sandbox_v2.py:663-671）。
- V3 动态状态全部写 `world/.sandbox_v3.sqlite3`（sandbox_v3.py:34-59）：`world_state`（revision/clock/scene_marker）、`characters`（整份角色 JSON payload）、`tickets`、`events`；写角色 `_save_character`（:136-142）、写事件（:240-264）、world state（:109-113）。V3 **不回写**角色/地点 JSON（README_V3.md:159-166；test_v3.py:308-314 断言所有 JSON 字节不变）。
- 无数据层接口：只有 action 级 JSON query/execute；没有“读取/提交/保存整份世界”的导出/导入 API，也没有版本化数据契约。备份=关闭后连同 world JSON 复制 sqlite（README_V3.md:164）。

### 5.7 与本期契约的距离

P3 若接入，最小适配面（均待确认）：

1. 可信包包装：地图工具不是 openagent 本地包（无 `openagent-package.json`/manifest/entrypoint），需新增包（或 examples 包）承载 adapter、工具名/参数与返回值（对齐 tool_binding_contract.py 与 tool_bindings.py 约束）。
2. 实例取得：可选“包内进程内嵌 `Sandbox` 对象（长驻本次调用）”或“每条命令起子进程 + sqlite 持久化”；前者不满足“工具可运行在另一个进程”的规划语句，后者不满足“同一运行实例”语义——**需用户确认**。当前工具没有进程协议可供工作区 open/invoke/close 使用。
3. 数据写入数据层：需工具在正常收尾时导出可检查点快照（地点/角色/NPC/行为链），由新增工作区适配或 Agent 执行器写成会话对象；只把数据留在 `world/.sandbox_v3.sqlite3` 不能宣称受检查点保护。
4. 导出/合成：`generate_action_context()["prompt_text"]` 可作为“工具导出文本”候选（sandbox_v3.py:535-539、494-533），但格式/合成规则需 P2 契约确认；模型内容与导出内容合并到 TEXT@2。
5. 数据量：当前示例 2 地图/6 地点/7-8 角色可放入单对象，但完整世界（工具文档称 50+ 地点目标，ROADMAP_V2.md:572-578）需要拆分与上限设计。
6. 必须等工具完成/补齐的部分：长驻进程或稳定命令协议、正常结束/停止/退出确认、世界级导出/导入或数据层钩子、数据契约版本。工具未完成前只能做离线样例验证，不能报告地图产品已接入（规划 5.2、P3 结束条件一致）。

## 6. P4 缺口清单

1. **接入层**：地图状态在工具自身 sqlite，不在会话对象层；无“工具保存→数据层对象”的保存与重载路径（需 P1/P2 提供写入口）。
2. **声明层**：缺少地图数据类型（register_data_type）与 `object_bindings`/`session_preloads` 声明；没有这些，采集/恢复两端都不会覆盖（2.2 证据）。
3. **历史兼容**：给已有定义新增 preload 会产生新固定修订；旧检查点缺该分区时 fork 直接 409（checkpoint_loading.py:219-228；workflow_chat_service.py:302-317）。修复历史回合是否属于 P4 范围需确认。
4. **行为链**：当前是工具内追加日志，不是对象值；若要被检查点覆盖必须纳入某个地图对象（大小/游标语义要定）；否则只能声明“行为链不在检查点保护范围”。
5. **数据量/事务**：单对象默认 1MB（可配 4MB）、单节点写集 ≤256、每对象一次写入/node、preload ≤1024；完整世界需对象拆分与写入合并策略。
6. **Agent 节点能力**：agents.execute@10 无对象读写能力/绑定（agent_package.py:63-79）；若由执行器写地图对象需节点声明与版本变更（P2 决定）。
7. **进程协议**：真实工具无长驻进程/退出确认，工作区正常收尾只能 close 库对象或杀子进程；需用户确认接入形态，或等工具补齐。
