### 2.1 声明（加载节点配置 + 适配器可选能力）

```

```

### 2.2 读取（open 传值）

- `open` binding 扩展：`"data": {"<object_key>": {"value": <JSON>, "revision": int, "revision_id": str, "type_id": str, "schema_version": int}}`（仅声明对象、仅数据能力开启时）。
- 宿主实现位置：`_open_bound_workspace`（`graph_tool_host.py:220-247`）在 `_require_workspace_owner` 同款读事务内取值：`with self._lock, self._data_management.read_execution(registry=basis.registry) as data:`（:112-114；`configuration_data.py:370-383`）后 `data.state.read_object(context.workflow_session_id, key, node_id=context.node_binding_id)`（`execution_data.py:227-232`；`session_objects.py:106-118`）。

### 2.3 保存（finish 返回 saves，宿主独立事务）

- `finish` 返回形状扩展（向后兼容旧适配器）：
  `None | {"text": str} | {"text": str, "saves": [{"object_key": str, "value": <JSON>, "expected_revision": int}]}`
  宿主 `_checked_workspace_export`（`graph_tool_host.py:116-127`）扩展为同时校验 `text` 与 `saves`：saves 为数组、每项严格三字段、object_key ∈ 冻结声明且在该 Agent writers、单对象一次、`expected_revision` 必须等于 open 时宿主记录值（`_WorkspaceInstance` 增存 data basis，:22-30,243-246）、value 仅 JSON；非法→`workspace_export_invalid`（或新 `workspace_save_invalid`）。
- 宿主独立事务（对照变量工具 `_accept_tool_write`，HEAD:228-264 / 当前:498-534）：
  1. `_change("graph.tool.object-write", "workspace:"+<node_run_id>+":finish", request, change)`（`graph_service.py:454-457`；`graph_store.py:131-153` 用 `BEGIN IMMEDIATE` + 幂等 receipt + 异常回滚）；
  2. change 内 `self._require_tool_owner(data, context)` 后 `data.state.apply_objects(sid, node_id=context.node_binding_id, writes=[...], write_evidence={key:{...}})`（`execution_data.py:234-239`；`session_objects.py:476-532`）；
  3. `write_evidence` 每对象建议 `{tool_binding_id, agent_node_id, chain_run_id, node_run_id, stage:"workspace-finish"}`（对照 :513-515），进入幂等请求摘要与 `write_validator` 上下文（`session_objects.py:491-515`；`host_sdk.py:413-439`）；
  4. 提交后开独立读事务重读并比对 revision/revision_id/value canonical bytes（对照 :525-533），不一致→建议 `workspace_save_mismatch`(500)，如实报告不一致、不回滚、不重试。
- 幂等/一次写/CAS：`operation_key = "workspace:"+node_run_id+":object:"+sha256(object_key)`；重复 key 同摘要返回原 receipt（`session_objects.py:495-502,527-530`）；执行器状态机保证 finish 恰好一次（`agent_executor.py:290-291`），接纳再入不重放（:389-391；04 V8）。CAS=`expected_revision`==open revision（`session_objects.py:503-504`，`stale_object_revision` 409）。
- 多对象顺序与部分失败：所有 saves 在同一事务一次 `apply_objects`，任一失败整事务回滚→本次 finish 无任何保存生效；不存在"部分对象已写"。前序回合已提交对象按事实保留（02:103-113；会话对象值按 revision 不可变，不提供回滚）。
- 向上：宿主保存成功后只把 `{"text"}` 返回执行器→`agent_executor._workspace_export_value`（:321-334）与合成（:302-319）零改动；saves 不进入节点输出、事实、回执或模型上下文（02:119；04:34）。

### 2.4 失败语义（阶段、事实保留、不重试）

| 情形 | 阶段/码 | 已保存事实 | 收尾/重试 |
| --- | --- | --- | --- |
| open 读取失败 | `workspace_open_failed`（可含对象键），节点失败且不进模型循环（`agent_executor.py:284-286`） | 无本次保存 | 无 open 重试；dispose 释放局部资源 |
| finish 适配器异常/导出非法 | `workspace_finalize_failed` / `workspace_export_invalid`（:267-272,:116-127） | 本次事务未开始，无本次保存 | 执行器标 finalize 阶段后 dispose→abort；不自动/人工重试（Q6） |
| saves 形状/未知对象/非 writer/重复/超大小 | 建议 `workspace_save_invalid`(400/500) | 事务回滚，无本次保存 | 同上，不重试 |
| CAS 冲突（对象被改） | `stale_object_revision`(409) 或包装为 save 失败 | 无本次保存；前序已提交保留 | 不重试、不覆盖 |
| 提交后重读不一致 | 建议 `workspace_save_mismatch`(500) | 已提交按实际事实保留 | 不重试、不报告回滚 |
| 保存成功、compose/close 失败 | 现状 `workspace_compose_failed`/`workspace_close_failed`（:302-319） | 保留（V9 已证，04:67） | 不再保存；dispose abort/close |
| 模型错误/用户终止/pause | 不调用 finish，abort 只释放（:336-352） | 无保存；已提交事实保留（04 V6） | 不重试、不重跑模型 |

3. 文档 `session_preloads`（schema 3）：每键 `{object_key,value}`；该 binding 不得再有 `default_value`/`registrar_node_id`；类型不得有 validator/references/migrator/write_validator 等特殊回调；schema 仅本地 fragment；初值按类型 schema 校验（`session_preloads.py:64-127,129-156`；保存时校验 `workflow_configuration.py:316-318`）。
4. 新会话 `initialize_preloads` 建初值（`session_objects.py:179-208`；`graph_service.py:655-674`）；之后 finish 保存更新 head；成功 round 的 settle 事务在 commit 后追加检查点（`graph_service.py:1507-1548`，尤其 1537-1541）采集 `preloaded_items`（`checkpoint_collection.py:185-192,195-206,293-298,376-381`）。
5. 恢复：`fork_checkpoint`→`_fork_checkpoint_state` 用源固定文档的 preload 值初始化独立目标会话并安装对象值（`graph_service.py:688-705`；`workflow_chat_service.py:293-350`；`checkpoint_loading.py:166-249`；`session_objects.py:220-250,252-379`）；原会话只读。

**是否可完全不改 checkpoint_collection/loading**：可以（前提：不新增分区、不改 schema 4、不迁旧检查点）。证据：`preloaded_items` 是可选第 4 分区并已有完整校验/差分/物化（`runtime_checkpoints.py:23-25,96-106,117-128`）；采集选择器只按 `session_preloads` 选普通类型（`checkpoint_collection.py:185-192`）；加载端只做键集/类型/CAS 精确匹配并安装（`checkpoint_loading.py:219-249`）；fork 端逐键取历史值（`workflow_chat_service.py:302-317`）。`checkpoint_admission=True` 本身不触发采集（`session_preloads.py:113`、`checkpoint_collection.py:173-192`；03 勘察 2.2 同结论）。

限制：①只有进 `session_preloads` 的对象被采集；②新增 preload 会产生新固定修订，旧会话仍用旧修订；fork 端要求所选检查点中每个目标 preload 值精确存在（`workflow_chat_service.py:302-317`），旧检查点缺分区时 `checkpoint_loading.py:219-228` 直接 409（`docs/SESSION_PRELOADS.md:92-94`）；③失败回合不采集（只 succeeded round，`graph_service.py:1537`）；④单对象默认 1MB（类型可配 4MB）、preload ≤1024（`session_preloads.py:16`）、单事务写集 ≤256（`session_objects.py:479`）；⑤行为链/票据须并入某对象值或明示不在检查点保护（03:113-115）；⑥旧适配器不声明数据则完全不受影响。

## 3. 备选方案评估与推荐

- **A（上述窄接口：读+保存+预加载+检查点）**：唯一能满足 03 的 A7/A8/A11。代价=契约三文件改动 + 沙盘包 + 工作流文档声明 + 新测试；风险=适配器/桥契约新增字段需用户确认；工作流必须声明 `object_bindings`/`session_preloads`（前端目前只有"高级 JSON"文本域可录数组/对象，`frontend/src/components/GraphSchemaFields.vue:65-69`；对象键无下拉与 ACL 提示，除非新增编辑入口，`GraphNodeConfiguration.vue:38-68` 的现成选择器只服务 `object_accesses` 且按 loader 节点 id 校验，不能复用）；新增失败码；旧检查点兼容限制；文档需明示"数据面/检查点已可用"（当前 `docs/WORKFLOW_PACKAGES.md:329-330` 明确写"不新增通用数据写端口/不受检查点保护"，S4 后必须改写）。
- **B（只做 S1-S3，S4 延后）**：最小可交付、风险最低；工具状态留在 worker/sqlite 隔离存储，finish 只导出文本；不能完成 A7/A8/A11，也不得宣称正式数据层/检查点（03:161,174）。若用户暂不批数据接口，选 B。
- **C 更小可行方案**：
  - C1 只做读取（open 传 data，保存仍留工具自身存储）：可验证"工具读正式对象"链路，但不解决 A7（第二次调用还原正式数据）与 A11。
  - C2 做保存但不入检查点（finish saves + object_bindings，**不**声明 session_preloads）：数据层保存/重载可用，但检查点不覆盖（S4 部分）；代价最小且不动固定修订/兼容性；可作为 A 的第一落地点，文档须明示不保护历史回合。
  - C3 走既有变量工具/单对象协议承载地图数据：破坏既有单对象写、ACL 与版本约束，且无法表达完整世界，不建议。
  - C4 新增独立桥操作 `workspace-read-object`/`workspace-save`：接口更显式，但多一层桥契约、与 finish 一次收尾语义重叠；首版不建议。
  - C5 由执行器/Agent 节点侧写对象：需改 `agents.execute` capability/版本与事实契约，且违背"工具自行保存"的已确认方向（02:176；`agent_package.py:63-81`），不建议。
- **推荐**：若用户批准数据面→A（可先 C2 再补 preloads）；否则 B。无论选哪个，均需在 02 契约补记失败码与桥/返回形状，并同步 `docs/WORKFLOW_PACKAGES.md`、`docs/SESSION_PRELOADS.md` 的可用性声明。
- **审批边界**：新增数据接口属 03/S0 待确认项（03:167,199-207），未确认前不得实施；真实沙盘数据迁移、正式数据写入、服务启停、真实模型与浏览器不在本轮授权（03:197；04:53,77）。
