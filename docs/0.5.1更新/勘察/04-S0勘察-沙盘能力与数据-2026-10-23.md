### 2.4 拒绝/异常方式

- 业务拒绝=返回值不抛：`ActionRejected(message,**details)` 携带 `.result`（`sandbox_v3.py:20-23`），`execute` 捕获后回滚并返回（`:212-215`）；批次子错误包装 `ActionRejected("Scene transition rejected: ...",failed_change_index=i,rolled_back=True)`（`:447-451`）。
- 参数/存储异常 `(KeyError,TypeError,ValueError,OverflowError,OSError,sqlite3.Error)` 捕获→回滚→`{ok:false|success:false,error}`（`:181-184,216-219`），不向上抛；无结构化错误码（仅 `STALE_TICKET:` 前缀）。V2 四层错误（`error`/`ok:false`+verdict/`success:false`/`warnings`，`HANDOVER_V2.md:509-533`）保留。
### 2.5 事务与回滚

- `sqlite3.connect(timeout=10, isolation_level=None, check_same_thread=False)`（`:35-37`）＝自动提交 + 显式事务；`query` 对 `pre_move` 用 `BEGIN IMMEDIATE`、其余 `BEGIN`（`:150`）；`execute` 一律 `BEGIN IMMEDIATE`（`:191`）；成功 `commit`（`:179,209`），异常 `rollback` 后 `_sync_state()` 回读 DB（`:181-184,212-219`）。进程内 RLock 串行；跨进程 SQLite 写锁（busy 10s）+ 票据 revision CAS 仅一个提交（`:271-277`；`test_v3.py:290-306` 实测 1 成功、1 STALE_TICKET）。
- 批次：`_apply_scene` 整批一个事务，任一子操作失败回滚状态/事件/场景/票据消耗（`test_v3.py:177-193` 断言 character、world_state、events、ticket 全部复原）。
### 2.6 票据（ticket）

- 生成：`pre_move` 成功生成 `mv_<uuid4hex[:12]>`，字段 `id/character_id/from/to/world_revision/world_clock/created_at/expires_at/intent`，TTL **5 分钟**（`sandbox_v2.py:256-269`；`HANDOVER_V2.md:259-271`）。V3 在 `query` 事务内先清过期行、成功后 INSERT（`sandbox_v3.py:166-178`），启动 `_sync_state` 全量载入（`:104-107`）→ CLI 可跨进程 pre_move→move（`README_V3.md:168-176`；`test_v3.py:323-345`）。
- 清理仅发生在 `pre_move`，无后台任务；`get_world_state().active_tickets` 只计未过期（`:555-557`）。校验顺序（`_apply_move`:266-285）：存在→未过期→`world_revision` 相等→角色仍在 `from`→目标地点仍存在；任一失败拒绝且不落状态。成功后 DELETE+内存删除（`:340-341`）；失败不消耗可在有效期内重试（`test_v3.py:111-122`）。
- 时间语义：`datetime.now()` 本机 naive 时间（`sandbox_v2.py:265-266`、`sandbox_v3.py:169,252`），TTL 独立于世界时钟；恢复不得续期/自动执行（`03规划:115`）。
### 2.7 场景批次约束

- 必须显式非空 `scene_marker`（`:197-198,415`）；`changes` 必须 list（`:417-419`）；子操作仅 `move`/`update_character`（`:432-445`）。整批一个 scene + **一次** revision 提交（`:193,455`；`test_v3.py:163` 断言 `world_revision=1`）；时钟取最大到达时间（`:424-452`），update 子操作以该角色到达时间为基准（`:438-443`），scene-only 切换不推进时钟。
- 父事件先写入、子事件带 `parent_event_id`、父 `data.child_event_ids` 回填（`:420-454`）；event_id 表示记录顺序，精确时间看 `world_time_start/end`（`README_V3.md:117-123`）；子操作若带 `scene_marker` 必须等于批次值（`:430-431`）；同角色连续多段移动应分别预检提交（`README_V3.md:121`）。

## 3. 持久状态与快照

### 3.2 状态与不可变资源的分界

- 来自只读 JSON：`overview.json`（world_name/description/maps）、`maps/*/_meta.json`（name/summary/locations/adjacency.connected_to/atmosphere）、`locations/*.json`（name/description/sub_locations/adjacency/settings_refs/metadata.access_level 等）、`characters/*.json` 初始档（name/title/current_location/fine_grained_state/attributes/movement_history 种子）、settings JSON/MD（按 `settings_refs` 热加载，`sandbox_v2.py:107-118`）。
- 仅动态状态入库：`world_state` 三元组、**被修改过的**角色整份 payload、票据、事件。有效角色 = DB 有行则整份用 DB，否则读资源 JSON（`sandbox_v3.py:115-122`）；**没有独立 NPC 表**，NPC 与主角同为 `characters` 记录（7 文件/7 条）。
- 地点 `current_characters`：V3 由角色 `current_location` 派生（`:124-134`），资源该字段不生效且 V3 不写回（V2 的 `_update_location_characters` 仅 V1/V2 路径，`sandbox_v2.py:587-606`）。路径/裁决/检查点/估算耗时均为「资源+当前位置」派生，**不持久化**（`sandbox_v2.py:295-404`）。
### 3.3 资源身份建议

- 现状无版本字段：`world/overview.json:1-14` 只有 world_name/description/maps，`_meta.json` 与角色 JSON 均无版本。建议包内固定 `world_name`（实测 `幻想大陆`）+ `world_resource_id`/`world_resource_version`（包内常量或资源 manifest）+ 逐文件 sha256 清单；聚合值用 §1.2 实测 `3e58090717f5b395f3108a4aabae5ebb50802bdbf07de488fcbd5ad499ab7a9a`。
- 理由：BFS 路线、门禁（`metadata.access_level`）、跨图连通（`_meta.adjacency.connected_to`）、角色初始档案与设定文本都来自这些文件；资源变化会使同一快照被不同解释，恢复时 hash 不一致必须显式拒绝、不得静默混用。
### 3.4 完整快照 JSON 结构建议

```json
{
  "schema": "openagent.sandbox.snapshot/1",
  "world": {"world_name": "幻想大陆", "resource_id": "<pkg id>", "resource_version": "1.0.0", "aggregate_sha256": "3e5809...",
            "files": {"overview.json": "<sha256>", "...": "..."}},
  "state": {"revision": 0, "clock": "2024-01-01T08:00:00", "scene_marker": null, "last_event_rowid": 0,
    "characters": [{"id": "protagonist", "name": "艾伦", "title": "流浪剑士", "current_location": {"map": "capital_city", "location": "market_district"},
                    "fine_grained_state": {}, "attributes": {}, "movement_history": []}],
    "events": [{"event_id": "ev_00000001", "action": "move", "status": "committed", "scene_marker": "scene_01", "parent_event_id": null,
                "world_revision": 1, "world_time_start": "2024-01-01T08:00:00", "world_time_end": "2024-01-01T08:15:00",
                "recorded_at": "2026-10-23T14:30:00+08:00", "annotation": "...", "data": {}}]},
  "tickets": {"policy": "dropped", "items": []}
}
```

说明：`created_at` 仅诊断；`events` 按 id 升序；导出**全部有效角色**（含未修改者）；若将来 `policy=kept`，`expires_at` 原样保存且不得续期。
### 3.5 恢复等价要求

1. `revision/clock/scene_marker` 逐字段一致；clock 为 naive ISO 字符串原样保存，不做时区/格式转换（`scene_marker` 可为 null）。
2. 有效角色集合与 payload 深度相等（含 `movement_history` 顺序与 V2 种子条目）；必须导出全部有效角色，只导出 DB 已改行会在资源变化后不等价。
3. 事件条数、rowid/event_id、payload（`recorded_at/annotation/data/world_revision/world_time_*`、`parent_event_id`）完全一致且不重编号；`last_event_rowid` 一致；恢复显式插入原 id 并校正 `sqlite_sequence`，下一事件 id=max+1。
4. 票据按 policy：`dropped` 时恢复后 active tickets=0，与来源运行态允许不同（**唯一明确的非等价项**，必须写入诊断）；不得把旧票据恢复成可用。
5. 恢复单事务完成（失败不留半份状态），之后 `_sync_state()` 并校验；资源身份不匹配→拒绝并明确报错。
6. 快照不含 DB 文件本身、只含逻辑状态；目标是新建同 DDL 的运行 DB 后导入（便于跨版本/隔离）。
### 3.6 票据是否跨回合保存：建议**否**（policy=dropped）

理由：a) TTL 为真实时间 5 分钟（`sandbox_v2.py:266`），下一回合几乎必然过期；b) 票据是一次性预检凭据，恢复旧票据等于跳过 pre_move 的路由/门禁确认，绕过模型可见裁决；c) world_state 已持久化，重新 pre_move 可无损重算；d) `03规划:115` 要求恢复时不得续期/自动执行。同回合内进程续跑本有 DB 持久化支持（现行为），不属快照契约。
### 3.7 无法恢复/不纳入快照

- 派生预览（path/verdict/checkpoints/consequences/est_duration）不存；票据墙钟过期语义不可重演；`recorded_at/created_at` 只能原样保留。资源文件内容不在快照内（靠 hash 固定）；SQLite `sqlite_sequence`/journal 不属契约；V2 内存 `change_log` 不持久（V3 以 events 取代，`sandbox_v3.py:547-552`）。
- `get_world_state()` 只是摘要（`:554-565`），没有角色/事件内容，**不是完整存档接口**（`P0-03:174-178`、`03规划:115` 同结论）。

## 5. 持续进程入口设计（只设计，不实现）
### 5.1 现有 CLI 方式

`sandbox_v3.py:571-640`：每进程处理一个子命令；`query/execute` 从位置参数或 stdin 读一份 JSON（`:576-577,603-605`）；`with Sandbox(args.world)` 开→用→关（`:601`）；stdout 打印一个 JSON（indent=2，`:632`），业务失败 exit 1（`:633`），构造/IO 异常写 stderr JSON 并 exit 1（`:634-636`）。无 stop/quit/长驻循环/心跳；跨进程连续操作靠 DB 持久化票据（`README_V3.md:168-176`；`test_v3.py:323-345`），不是同一实例。
### 5.2 worker 最小设计

- 新文件 `sandbox_tool/worker.py`：启动参数＝只读资源根、本次运行 DB 路径（绝对路径，由包按 invocation/会话隔离目录生成，`03规划:104-111`）；启动即建一个 `Sandbox(world_path=...,database_path=...)`，保持到进程结束（同调用内多命令共享实例）。
- 通道：stdin 每行一个 JSON 对象；stdout 每行一个 JSON 对象（固定 `ensure_ascii`、`allow_nan=False`、逐行 flush）；**stdout 只放协议返回**，诊断/异常栈只写 stderr；非法 JSON/非对象/未知 op 返回 `{ok:false,error}` 继续循环，不退出、不重试。

| op | 请求 | 返回/行为 |
| --- | --- | --- |
| `state` | `{}` | `Sandbox.get_world_state()`；`open` 握手用 |
| `query` | `{request:{...}}` | `Sandbox.query(request)` 原样返回（业务拒绝不转异常） |
| `execute` | `{request:{...}}` | `Sandbox.execute(request)` 原样返回 |
| `facts` | `{after_event_id?,scene_marker?,limit?}` | `generate_action_context` 分页结果（limit 1..1000） |
| `finish` | `{after_event_id?}` | 快照原子写（临时文件+`os.replace`）＋从游标分页导出本次事实→`{ok:true,text,snapshot_path}`；任一失败→`{ok:false,error}`，不半写、不重复保存 |
| `quit` | `{}` | 关 DB，回 `{ok:true}` 后 `exit 0`（正常收尾，适配器 close 用） |
| `abort` | `{}` | 不写快照/不导出，关 DB，回 `{ok:true}` 后 `exit 0`；适配器也可直接 terminate（未提交事务自动回滚） |

- 启动/退出确认：`open` 发 `state` 握手；`close` 发 `quit` 并要求 `returncode==0`，超时显式报错（参照样例 `examples/workflow-packages/workspace-demo-1.0.0/workspace_demo/package.py:165-180`）；`abort` 只释放（样例 `:183-188`）。
- 子进程：`subprocess.Popen([sys.executable,"-X","utf8",str(WORKER),resource_root,runtime_db], stdin=PIPE, stdout=PIPE, stderr=PIPE 或独立日志, text=True, encoding="utf-8", bufsize=1, cwd=运行目录)`。**不要照搬样例 `stderr=subprocess.STDOUT`**（样例 `:123`），否则诊断混入协议输出。可参照样例 `worker.py:91-133`（op 分派/逐行循环/finish 原子写/quit 退出）与 `package.py:115-188`（六阶段边界）；沙盘差异：finish 需同时写快照与导出事实、open 需两个路径。
- 不做：不新增宿主 manifest/host_sdk/桥操作（`02契约:54-62`、`04回执:31-35` 已冻结）；不实现自动重试/重连/超时重发（`03规划:122-123,205`）。
### 5.3 包侧适配最小改动

`normalize` 声明工具（可 `query`/`execute` 透传或按业务拆分，复杂 `updates/changes` 编码按 `03规划:139` 另行确认）；`open` 起 worker 并握手；`invoke` 转发 request 并返回严格 JSON；`finish` 返回 `{"text": str}`；`close` 要求退出确认；`abort` 只释放。与 `02契约:26-33/73-83` 六阶段一致，不改宿主。

## 6. 风险与未知
### 6.1 版本/依赖/时间

- 包必须同时携带 V2（`sandbox_v3.py:14-17` 继承依赖）；V1 不被引用（`sandbox.py`/`demo.py`/`test_v2.py` 仅留档）。`test_v3.py:16` 是平铺 `from sandbox_v3 import Sandbox`，引擎若放 `engine/` 子目录，测试副本需改 import 或加 `sys.path`（引擎内部已 `if __package__:` 兼容相对导入，`sandbox_v3.py:14-17`、`demo_v3.py:8-11`）。
- 版本口径冲突（README 3.10+/HANDOVER 3.7+/实测 3.12.8），S1 需固定解释器（建议仓库 `.venv` 3.12.8）。naive 本机时间（`sandbox_v2.py:265-266`、`sandbox_v3.py:169,252`）使 TTL 受时区/DST/改机影响，世界时钟也是 naive ISO；快照恢复不得续期（§3.6）；测试/worker 若需可控时间需注入时钟（现状无注入点，`03规划` 未定）。
### 6.2 规模上限（未知，需契约固定）

events 无上限、无删除/裁剪 API；分页查询上限 1000（`sandbox_v3.py:461-492`）；`get_change_log` 全量读（`:547-552`）；`get_world_state` 只给 last id。仓库侧单对象默认 1MB、可配 4MB、`session_preloads` ≤1024（`P0-03:206`）→ **全量事件快照可能超限**：快照契约须定义事件上限或「快照+事件分卷/游标」策略；`finish` 导出必须从本次调用开始游标分页，不能默认 100 条截断（`03规划:145`）。当前角色 7、地点 6，规模无压力。
### 6.3 资源漂移与 Windows/进程/存储

资源无版本字段；资源变更后旧快照的解释会变（§3.3）→ 必须 hash 拒绝。`movement_history` 的 V2 种子条目不自动追认 V3 事实（`README_V3.md:166`），快照原样保留但不混入 facts。UTF-8 强制（§1.3）；子进程 stdout/stderr 分离（§5.2）；SQLite 单写者+10s busy timeout，不应让多进程共享同一运行 DB（按调用隔离）；强杀时未提交事务自动回滚、已提交事实保留；快照写必须临时文件+replace 原子；快照/导出须来自同一份已停止接收修改的状态（`03规划:149`）。
### 6.4 测试断言暴露的业务规则（S2 必须保持，均 `test_v3.py`）

- 事实边界：查询/预检/intent/失败/门禁失败不进正式事实（`:68-82,111-122`）；move 记录世界时间、位置、movement_history（`:84-109`）；update 只记实际叶差异（`:124-148`）；重命名不改写历史文本（`:246-252`）。
- 批次：单 revision、时钟取最大（`:150-175`）；失败整批回滚含票据消耗（`:177-193`）；scene 继承/切换（`:195-221`）；重启恢复 facts/clock/scene/revision/票据（`:205-221`）。
- 其它：分页非破坏、越界游标报错（`:223-244`）；存储失败整体回滚（`:254-263`）；非法 duration/零跳零时长（`:265-280`）；预检后目标地点被删→拒绝（`:282-288`）；并发 CAS（`:290-306`）；运行期 JSON 字节不变（`:308-314`）；多行 annotation 原样引用（`:316-321`）；CLI 跨进程票据+非 0 退出（`:323-345`）。
### 6.5 待确认项（S0 需用户定）

1. 快照事件规模上限与形式（单 JSON / 快照+事件分卷），是否允许越过 1MB/4MB 对象限制。
2. 票据 policy=dropped 是否定稿（§3.6 推荐）。
3. 资源身份版本号命名与归属（包 manifest 字段 vs 包内资源 manifest 文件）。
4. worker `abort` 用协议消息还是 terminate 兜底；`finish` 返回是否必须含快照保存证据（A8 验收用）。
