## 0. 结论摘要

1. 现有纯计算/变量工具链在**运行准备事务**里生成一份整体冻结的 `PreparedToolFrame`；准备期只解析声明、校验来源/目标/参数/权限，不调用适配器业务阶段、目标 executor 或业务数据（`backend/src/phase1_agent/tool_bindings.py:215-284`、`graph_service.py:1000-1024`）。
2. 工具适配器不是 manifest 导出种类：它作为 `NodeRegistry.register(tool_binding=...)` 的实现钩子挂在显式注册的加载节点上，manifest 只导出节点身份（`capability_packages.py:200-205`、`graph_contracts.py:457,480-492,520-522`）。因此工作区路径**不需要**新 manifest schema/导出种类/包版本规则变化。
3. 最小核心新增面为：共享模块新增 `WorkspaceToolBindingAdapter`/Prepared 类型与联合类型；准备分派新增工作区分支；`GraphToolHost` 新增工作区桥操作与实例表；`NodeExecutionContext` 新增生命周期转发方法；`PublicAgentExecutor` 在 advance 中 open/close、在 dispose 中 abort 并参与结果合成。
4. 实例取得必须放在**调用生命周期**（规划:78），不能在准备期：现有 public service 的“包工厂实例”恰在准备期创建（`graph_runtime_host.py:181-188,248`），不能照搬。候选位置是 Agent 执行器进入内核循环前在 `advance` 内 open，宿主只在内存表中持有不透明句柄。
5. 进程协议归属可信包/工具侧：包代码在 open/invoke/close/abort 内部自行启动、持有、通信；宿主只搬运 JSON 与身份，不出现具体工具命令分支。`host_sdk` 目前没有通用“受控实例/不透明句柄”入口，也无需新增（见 §4）。
6. 原始 final 已由 `agent_result` 事实保留（`agent_executor.py:247-252`、`execution_facts_v2.py:42,368`）；程序合成只改 `outputs["result"]` 文本，合成格式与是否进入下一轮上下文仍待确认（规划:92,180）。
7. A4“六个文件哈希未变”是 0.5.0 A5 范围内新增第二个示例无需改核心的证据（`docs/中期检查2/152-本地包与通用Agent工具第一阶段实施回执-2026-10-22.md:66`、包说明:260-262），不是永久冻结；规划:128-131 已把其中多数文件列为预期改动范围，但改后必须重建证据，不能再声称哈希未变。

## 2. 准备与调用的边界

- **准备期**（0100 事务）：同一时刻捕获 registry/manifests/definitions 作为唯一依据；扫描文档中的显式加载节点，解析声明，校验来源/目标/参数/ACL/引用，生成 `binding_id`，组装准备帧。禁止取得业务数据或进程资源（规划:78）。
- **调用期**（Agent 节点实际运行，执行器创建到 final 收尾）：只能使用准备期冻结的声明与来源；按 `binding_id` 路由；模型参数在调用时重新按冻结 schema 校验。业务数据加载与进程取得放这里（规划:4.1 第 65-76 行、:78）。
- 因此工作区实例的创建点不能是 `prepare_tool_frame`，也不能复用“准备期创建实例”的 public service 时间点（`graph_runtime_host.py:181-188,248`）；这一点与既有纯工具/变量路径一致，不需要删除任何旧限制。

## 3. 工作区能力候选局部契约（字段级，均待用户确认）

### 3.1 适配器类型（候选，放 `tool_binding_contract.py`）

```text
WorkspaceToolBindingAdapter(
    normalize(config) -> list[dict],
    open(spec, invocation) -> handle,        # 包可信代码启动/取得进程与业务数据
    invoke(spec, arguments, handle) -> dict, # 模型逐次结果
    close(handle) -> dict | None,            # 正常结束：工具自行经数据层保存 + 导出
    abort(handle) -> None,                   # 仅释放，不保存、不导出
    prompt_output: tuple[str, str, int] | None = None,
    agent_config_field: str = "agent_node_id",
)
```

构造校验沿用现有两类适配器（可调用阶段必须 callable、`prompt_output` 精确三元组、`agent_config_field` 非空），且不因工作区放宽首版同步边界（`tool_binding_contract.py:33-44,62-73`；包说明:242）。

独立新类型而不是扩展现有两类的理由：① 变量适配器有准备期 `bind` 阶段，会读取会话对象生成声明（`tool_binding_contract.py:27`、变量分支 `tool_bindings.py:151-212`），而工作区明确禁止准备期读业务数据（规划:78）；② 现有准备分派用 `isinstance(entry.tool_binding, PureToolBindingAdapter)` 二分（`tool_bindings.py:248-259`），新增第三分支需显式类型，避免被误分派到变量路径；③ 现有适配器形状/行为保持不变，纯工具与变量工具回归面最小。

### 3.2 `normalize` 声明字段

- 候选 A（推荐，最小）：每项**恰好** `{name, description, parameters, config}`。“目标实现身份”不写在声明里，而由准备期从锚点登记记录导出：调用期从冻结依据取 `anchor_entry.tool_binding` 作为适配器实现（`graph_tool_host.py:118-121`），实现身份 = 锚点 `(component_id, component_version)`，来源 = 锚点 source（`tool_bindings.py:61-78,234`）。即“准确目标实现”由锚点身份+包来源固定，不引入伪节点或新导出种类。
- 候选 B（需确认）：每项含 `target:{component_id, component_version}`，指向同包注册的声明节点或新 manifest 导出种类；若选 B 需新增节点种类/导出与契约比较，不是最小面（见 §5.3）。
- 两种候选共享首版约束：`name` 非空且非 `final_answer`、`description` 字符串、`parameters` 满足严格标量对象规则（`tool_bindings.py:33-46`；`tools.py:154-171`）、`config` 严格 JSON 对象（44-46）、声明数 1..64、同 Agent 工具名唯一、总预算≤120。

### 3.3 Prepared 类型（候选）

- `PreparedWorkspaceToolSpec`：`name, description, parameters, config, binding_id, agent_node_id, source`；`operation` 恒为 `"invoke"`；`public()` 形状与纯工具一致（`binding_id/name/operation/description/parameters`）；`adapter_spec()` 提供 `binding_id/agent_node_id/config`。
- `PreparedWorkspaceToolBinding`：`binding_id, anchor_node_id, anchor_component_id, anchor_component_version, agent_node_id, tools, anchor_source`。
- `PreparedBinding` 联合类型扩展第三类（`tool_binding_contract.py:176`）；`PreparedToolFrame` 结构不变，工作区绑定与纯/变量绑定同帧（理由见 §5.2）。

### 3.4 生命周期操作边界与返回形状

| 操作 | 谁/何时调用 | 入参与返回 | 边界与失败 |
| --- | --- | --- | --- |
| `open` | Agent 执行器，首次 `advance` 进入内核循环前；每次 Agent 调用一次 | 入参：声明投影 + 调用身份 `{workflow_session_id, chain_run_id, node_binding_id, node_run_id, binding_id}`；返回：**不透明 handle**（任意 Python 对象；宿主不检查、不序列化、不持久化，仅内存） | 进程启动、数据加载都在包的可信代码内；失败阶段 `workspace_open_failed`，不进入模型循环；同一次调用内重复 open 必须幂等返回已有实例（pause/resume） |
| `invoke` | 每次模型工具调用；宿主先按冻结 schema 校验参数 | 返回严格 JSON 对象（`validate_json_value`+dict，受内容传输预算约束，`content_contracts.py:20-21`） | 逐次返回只进模型工具消息，不自动并入最终 `result`；无实例时显式 `workspace_not_open`，不自动创建 |
| `close` | 有效 final 之后、组装节点结果之前，执行器调用**恰好一次** | 返回导出内容：严格 JSON 对象或 `None`（建议≤1MB；最终 TEXT@2 合计受 4MB 传输预算） | 工具按自身逻辑经数据层保存并导出；close 成功后不得再次 close；abort 后不接受 close |
| `abort` | 模型报错、用户终止、执行器 `dispose`、释放阶段兜底 | 返回 `None` | 仅释放进程/句柄，不保存、不导出；幂等；失败作为清理错误报告，不覆盖原始业务失败 |
| `export` | 不作为独立操作 | 唯一来源是 `close` 返回值 | 首版拒绝单独 export 调用，避免二次副作用；abort 后无导出 |

不透明句柄语义：宿主只保存 `(链, 绑定)`→handle 的映射并在 close/abort 时原样回传；句柄不得出现在模型可见 JSON、准备帧、事实或持久记录中。调用期不经宿主向工具传递 repo/连接/任意 SQL；工具数据保存走其所属领域数据层（规划:24,52），确切入口由 P0-data 与 P3 确认。

实例创建方：**包的可信代码**在 `open` 内创建/启动实例并返回句柄，宿主不实例化进程、不解释句柄、不提供工厂注册入口；宿主只提供调用身份、冻结声明与生命周期时序。失败阶段候选码：`workspace_open_failed`、`workspace_invoke_failed`、`workspace_close_failed`、`workspace_abort_failed`（abort 失败只作清理报告）。`invoke` 的适配器异常仍走内核既有 `tool_contract_error` 分类与 `outcome_unknown` 语义（`runtime.py:942-951`），不新增吞错/自动重试。

## 4. 实例取得与进程协议归属

### 4.1 `host_sdk` 现状：只有 public service 是“包工厂 + 宿主持有实例”的先例

- 包可见注册面只有 `HostRegistration`：数据类型/节点/执行器/pause/服务/前端扩展/信息源（`capability_packages.py:140-252`）；没有“受控实例/不透明句柄/工作区”入口。
- public service（manifest schema≥3）机制：`register_service(definition, factory)`（`host_sdk.py:233-240`）→ `HostServiceRun.prepare` 在**准备期**调 factory 并以受控环境实例化（`host_services.py:36-57`）→ 节点需声明 capability+grant 才可 `host_call`（`host_services.py:76-87`；`graph_execution.py:74-78`）→ `release_run/dispose` 释放（`host_services.py:103-121`）；应用接线在准备期（`graph_runtime_host.py:181-188,248`）。
- 结论：service 的“准备期创建 + 按节点 capability 授权”不满足本次“按 Agent 调用取得、同调用共享、正常结束保存”的语义（规划:78）；且采用它需要 manifest schema 3、Agent 节点新增 capability 与版本变化。首版**不新增 host_sdk 导出种类**：进程协议完全归可信包/工具侧，宿主只定义生命周期边界与 JSON；这也能避免在核心出现具体工具命令分支（包说明:247-249；规划:41）。

### 4.3 同调用实例唯一、不同调用隔离的实现位置

## 5. 与 Agent 装配及版本影响

### 5.1 工具与 Agent 的绑定关系进入工作流配置

- 加载节点仍是显式注册的普通声明/执行节点；配置字段 `agent_node_id`，`NodeDefinition.config_node_references` 必须声明该字段且 `multiple=False`、`target_types=[agents.execute@10]`（注册约束 `graph_contracts.py:537-542`；示例 `examples/workflow-packages/text-metrics-1.0.0/text_metrics/package.py:94-97`）。
- 准备时 `validate_config_node_references` 校验 UUID、节点存在、精确类型、不重复（`graph_contracts.py:774-795`；调用 `tool_bindings.py:237`）；Agent 必须在本计划内（`tool_bindings.py:238-240`）。
- 描述材料权限：物料节点必须配置同一 Agent 才获得 `descriptors`（`tool_bindings.py:262-281`），加载节点用 `context.bound_tool_prompt` 取得自己的声明并生成成对说明/参数材料（`graph_execution.py:86-90`；`graph_tool_host.py:71-91`）。
- **工作区工具必须进入同一 `PreparedToolFrame`**：否则 Agent 的 `_bound_tools` 看不到声明，提示材料无权读取，单 Agent 工具名冲突/120 预算也无法统一执行。候选实现是在 `agent_bindings` 同表追加第三类绑定，不做第二帧。

### 5.2 一个 Agent 多工具、多工作区工具与上限

- 一个 Agent 可有多份绑定并混合纯/变量/工作区（准备帧按 Agent 聚合元组，`tool_bindings.py:261,282-284`）；模型工具名冲突在准备期拒绝（130-131,188-189,244-247）并在执行器再次兜底（`agent_executor.py:41-44`）。
- 单 loader 最多 64 项声明（`tool_bindings.py:242-243`）；同一 Agent 的工具+唯一 `final_answer` 合计≤120（`agent_executor.py:38-40`）。
- 工作区候选：一个 loader 的多个工作区声明视为**同一绑定/同一实例**的多个工具；每 Agent 首版至多一个工作区绑定（多绑定/多实例拒绝，需用户确认）。`final_answer` 保留名不可占用（`tools.py:157-158`）。

## 8. 兼容与回归风险

- 现有纯工具/变量路径必须字节级不变：新增分支不得改变 `prepare_tool_frame` 对既有适配器的分派顺序、`public()/adapter_spec()` 形状、120/64/名称冲突与变量 ACL 行为；纯工具目标准备期限制不得删除（规划:41）。
- 执行器向后兼容：`PublicAgentExecutor` 在缺少工作区桥方法/`bound_tool_specs` 的测试上下文（如 `backend/tests/test_agent_executor_v2.py:48-97` 的 SimpleNamespace）必须沿用旧行为（`getattr` 守卫，参考 `agent_executor.py:50-51` 的既有写法），`dispose` 不得因 abort 抛错中断。
- 重复收尾：pause/resume、结果接纳再入（`runtime_hosting.py:331-376`）、节点结果接纳失败重入（`graph_execution.py:425-445`）都不能重复 open/close/save；close 产物需在执行器内保留并复用（V8）。
- 释放与 dispose 不得双操作同一资源：正常 close 已移除实例；`dispose` 与释放阶段只对残留实例 abort，且 abort 幂等（规划:80,106）。
- 工具调用异常仍走内核既有 `tool_contract_error` 路径（`runtime.py:942-951`）与 `outcome_unknown` 语义，不新增吞错/重试。
- 事实与上下文：原始 final 保留在 `agent_result`（`execution_facts_v2.py:42,368`），合成文本只影响节点 `result`；`execution_facts_v2/context_update_v2` 消费者与“合成结果是否入上下文”必须与 P0 执行器勘察结论对齐。
- 结果大小：`result`/导出合并受 4MB 内容传输预算（`content_contracts.py:20-21`），须在 close/合成处显式拒绝超限。
- 版本与证据：若触发事实/能力/执行器变化，必须新 exact_version + 新节点版本 + 包版本；不得静默改旧身份（规划:132）。相邻回归候选：`test_generic_tool_bindings.py`、`test_variable_tool_bindings.py`、`test_tool_frame_preparation_guard.py`、`test_tool_binding_control_acceptance.py`、`test_independent_local_tools.py`、`test_agent_tool_budget.py`、`test_agent_executor_v2.py`、`test_runtime_hosting.py`（历史结果不能记作本期通过）。
