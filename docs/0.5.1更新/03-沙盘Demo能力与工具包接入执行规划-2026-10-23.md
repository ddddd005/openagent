## 4. 第二部分：四项改造与工作区接入

### 4.1 改造一：资源、运行副本与持久状态分离

目前 [Sandbox 初始化](</G:/AI/shapan/sandbox_demo/sandbox_v3.py:27>) 把数据库固定放在世界目录，[execute](</G:/AI/shapan/sandbox_demo/sandbox_v3.py:186>) 每次正式操作都会提交。需要允许将只读世界资源位置与本次运行数据库位置分别指定。

建议保留沙盘内部单次操作的 SQLite 事务和批次回滚，事务只修改本次工作副本：

```text
open：工具读取本会话已保存状态，载入本次运行数据库
invoke：查询、预检、移动和状态更新只作用于运行副本
finish：工具经已确认的数据层接口保存完整状态并导出本次事实
close：释放数据库、退出进程、清理本次运行资源
abort：停止并释放本次运行资源，不执行正常保存
```

不同会话和调用不能共享同一个默认可写世界目录。正式保存成功后的下游失败不撤销已提交事实，也不通过再次运行模型补偿。

完整状态导入导出至少覆盖：世界版本和时钟、当前场景、有效角色状态及移动历史、正式事件内容及其原始编号。未修改角色仍依赖初始 JSON，地图与设定也从资源读取，因此必须固定对应世界资源身份；只复制动态数据库不能保证在资源变更后恢复原世界。

快照结构、准确数据类型及对象绑定在 S0 确认。票据是否跨回合保存也在此固定；V3 当前票据按真实时间过期，不能在恢复时擅自续期或自动执行。现有 `get_world_state()` 仅是摘要，不作为完整存档接口。

### 4.2 改造二：增加持续接收命令的独立进程

现有 [CLI](</G:/AI/shapan/sandbox_demo/sandbox_v3.py:571>) 处理单次请求后退出。新增包内 worker，持有一个 `Sandbox`，在同次调用内持续接收并执行命令。

优先复用现有受控进程样例的接入方式，以串行请求和结构化返回建立闭环。协议准确字段在 S0 固定；至少覆盖初始化、业务调用、正常收尾、停止退出和退出确认。标准输出只承载协议返回，诊断使用独立错误通道。

每次业务调用保留宿主提供的工具调用身份，不能由模型选择会话、进程、数据库或资源路径。进程退出、通信中断、无效返回和超时应明确报错，不自动重发命令。停止及退出处理沿用确认后的进程生命周期规则，不新增恢复或重试平台。

### 4.3 改造三：制作能力包与模型命令适配

通过现有本地能力包机制注册工具加载节点，挂载 `WorkspaceToolBindingAdapter`，将工具说明和参数投影接入上下文装配。一个加载节点下的多个沙盘工具共享同一个实例。

候选模型命令覆盖以下业务，准确命名和参数在 S0 确认：

| 命令类别 | 对应沙盘能力 | 适配要求 |
| --- | --- | --- |
| 地图、地点和人物查询 | `list_maps/enter_map/enter_location/list_characters/get_character/spatial_check` | 明确标识参数，保持查询结果及设定内容来源 |
| 预检移动 | `pre_move` | 将目标地图、地点等标量参数组装为原请求，返回真实票据和路线判断 |
| 正式移动 | `move` | 将描述、耗时、注释和门禁确认组装为原请求；保留票据和版本检查 |
| 人物更新 | `update_character` | 保留更新白名单；复杂更新结构的传参形式单独固定 |
| 场景批次 | `scene_transition` | 保留原有批次事务和同一场景约束；复杂 changes 的编码单独固定 |

当前模型工具参数仍为严格必填标量对象。简单动作扁平化；复杂 `updates/changes` 若采用 JSON 文本参数，必须在包内解析并校验完整业务结构，不能以字符串包装为理由忽略校验。是否采用该形式属于 S0 命令契约，不静默扩大宿主 schema。

业务拒绝与运行故障需分别识别：路线受阻、票据过期等返回可理解的业务结果；进程或数据层故障使用明确错误通道。适配器不自动重新预检、不替模型确认门禁、不把缺少能力或未知返回解释为成功。

### 4.4 改造四：收尾事实导出与检查点状态

复用 [generate_action_context()](</G:/AI/shapan/sandbox_demo/sandbox_v3.py:535>) 及既有固定模板。开始时记录当前事件位置，finish 导出本次新增正式事实；存在分页时读取完整范围，避免默认 100 条截断本次行动。

沙盘自行组织正式事实文本，适配器 finish 只返回已确认形状 `{"text": str}` 或 `None`。程序按现有规则组合模型 final 与导出，之后 close。沙盘不接管模型 final，完整状态也不自动进入最终文本。

保存快照与事实导出应来自同一份已停止接收业务修改的运行状态。导出无效、保存失败或关闭失败时报告实际阶段和已知提交事实，不声称整个调用已成功，也不重复保存。

检查点接入必须证明以下完整链路：

```text
准确会话数据类型与绑定
  -> 工具正常结束时保存
  -> 成功回合采集该工具状态及世界资源依据
  -> 选择历史检查点并恢复到独立目标会话
  -> 新沙盘进程加载并还原所选回合
```

优先核对现有普通预加载对象路径是否适用；仅注册 `checkpoint_admission=True` 不足以保证采集。新数据接口、类型和兼容范围确认前，可用隔离存储替身验证进程链路，但不能报告正式数据层或检查点接入完成。
