## 0. 结论摘要

1. **承载者**：工作区实例持有一份在 `PublicAgentExecutor`（一次 Agent 调用一个实例）；pause/resume 与结果接纳再入由 `RuntimeHost` 保留同一 handle，不得重开或重复收尾（勘察01 §1-2）。
2. **声明与准备**：新增 `WorkspaceToolBindingAdapter` 与此前两类适配器并列；工具加载节点仍是可信包显式注册的节点，适配器经 `NodeRegistry.register(tool_binding=...)` 实现钩子挂载，**不需要新 manifest 导出种类、包 schema 或节点版本**（勘察02 §0/§5.3）。
3. **实例取得**：准备期只冻结声明与来源（`PreparedToolFrame`），**不读业务数据、不启动进程**；执行器首次 `advance` 进入内核循环前 open，宿主只在内存表持有不透明句柄（勘察02 §2/§3.4）。
4. **调用路由**：模型逐次工具调用复用现有 `invoke` 桥，按冻结 `binding_id` 命中工作区实例；参数 schema、只有绑定 Agent 可调用、owner/运行态检查全部保留；结果必须是严格 JSON 对象（勘察02 §1.3）。
5. **收尾一次**：有效 final 后、组装节点结果前：`finish`（通知正常结束；工具保存并导出）→ 程序合成 → `close`（释放/停止进程）。`dispose` 只作幂等兜底（未 finish 则 abort、已 finish 未 close 则 close），不承载成功保存（勘察01 §2）。
6. **统一结果**：只替换节点 `result`（TEXT@2）文本；原始 final 保留在 `agent_result` 事实与消息流，不改 `execution_facts_v2`/`AGENT_RECEIPTS@2`/context 投影（勘察01 §3、勘察03 §3）。
7. **数据与检查点**：现有唯一可采集恢复载体是声明进 `session_preloads` 的 session 作用域对象；真实地图工具无长驻进程、状态在自身 sqlite、未提供数据层接口，**P3/P4 本轮不能宣称接入或历史回合恢复**（勘察03 §2/§5/§6）。
8. **首版范围**：围绕一个工作区能力闭环；每 Agent 至多一个工作区绑定/实例；纯工具、变量工具路径行为不变（勘察02 §3.5）。

## 1. 工作区能力声明契约（候选）

### 1.1 适配器类型（`tool_binding_contract.py`）

```text
WorkspaceToolBindingAdapter(
    normalize(config) -> list[dict],            # 每项恰好 {name, description, parameters, config}
    open(binding, invocation) -> handle,        # 包可信代码取得/启动实例，返回不透明句柄
    invoke(handle, tool, arguments, invocation) -> dict,   # 逐次模型工具调用
    finish(handle, invocation) -> {"text": str} | None,    # 正常结束：工具保存并导出
    close(handle) -> None,                      # 释放/停止进程（合成之后）
    abort(handle) -> None,                      # 仅释放，不保存不导出
    prompt_output: tuple[str, str, int] | None = None,
    agent_config_field: str = "agent_node_id",
)
```

- 构造校验沿用现有两类适配器（阶段 callable、`prompt_output` 精确三元组、`agent_config_field` 非空）；首版仍要求同步、非 async/生成器。
- **不透明句柄**：任意 Python 对象，宿主不检查、不序列化、不持久化；不得出现在模型可见 JSON、事实或持久记录。
- `invocation` 为宿主生成的调用身份：open 提供 `{workflow_session_id, chain_run_id, node_binding_id, node_run_id, binding_id}`；invoke 另含 `{tool_call_id, tool_execution_id}`。
- 失败阶段码：`workspace_open_failed`、`workspace_invoke_failed`、`workspace_finalize_failed`、`workspace_export_invalid`、`workspace_compose_failed`、`workspace_close_failed`、`workspace_abort_failed`（abort 失败只作清理报告）。invoke 内的业务异常仍沿用内核现有 `tool_contract_error`/`outcome_unknown` 语义，不吞错、不自动重试。

### 1.2 准备对象（`tool_binding_contract.py`）

- `PreparedWorkspaceToolSpec`：`name, description, parameters, config, binding_id, agent_node_id, source`；`operation` 恒为 `"invoke"`；`public()` 与纯工具同形（`binding_id/name/operation/description/parameters`）；`adapter_spec()` 提供 `{name, description, parameters, config, binding_id, agent_node_id}`。
- `PreparedWorkspaceToolBinding`：`binding_id, anchor_node_id, anchor_component_id, anchor_component_version, agent_node_id, anchor_config, tools, anchor_source`。`anchor_config` 是准备期冻结的加载节点配置深拷贝，供 open 使用（normalize 已消费同一配置）；不在调用期重读文档。
- open 入参：`{"binding_id", "agent_node_id", "config": anchor_config, "tools": [{"name", "config"}, ...]}`；invoke 的 tool 入参：`{"name", "config", "binding_id", "agent_node_id"}`。
- `PreparedBinding` 联合类型扩展第三类；工作区绑定进入**同一个** `PreparedToolFrame`（名称冲突、120 预算、物料权限统一执行）。

### 1.3 准备规则（`tool_bindings.py`）

- 锚点=带 `tool_binding` 的显式加载节点；来源必须命中本运行 `package_lock`；配置经 `validate_config_node_references` 指向本计划内的 Agent（同现有锚点）。
- `normalize` 结果 1..64 项；每项严格 `{name, description, parameters, config}`；`name` 非空、非 `final_answer`；严格标量对象参数（沿用 `_model_tool_schema`）；`config` 严格 JSON 对象；同 Agent 工具名唯一、合计 ≤120。
- **每 Agent 至多一个工作区绑定**；第二个工作区锚点指向同一 Agent 时以 `workspace_binding_conflict` 明确拒绝（不静默合并）。
- 纯/变量/工作区绑定可混装于同一 Agent；既有纯工具准备期限制、变量 ACL 与单写协议**不删除、不修改**。

### 1.4 包与版本影响

| 对象 | 是否变化 | 说明 |
| --- | --- | --- |
| `PackageManifest.schema_version` / 导出种类 | 不变 | 适配器是节点实现钩子，不是 manifest 导出；新包只导出自身节点身份 |

## 2. 生命周期与桥操作契约（候选）

### 2.1 桥操作（`graph_tool_host.py` `_tool_bridge` 分派）

| 操作 | 入参 | 返回/边界 |
| --- | --- | --- |
| `workspace-specs` | `{agent_node_id}` | 该 Agent 的工作区绑定声明（供执行器判断是否需要 open）；无则 `[]` |
| `workspace-open` | `{agent_node_id}` | 按准备帧打开该 Agent 的工作区实例；复用/重复 open 幂等返回已有；仅该 Agent 可打开自己的实例 |
| `workspace-finish` | `{agent_node_id}` | 调用适配器 `finish`，返回 `{"text": str} | null`；无实例显式 `workspace_not_open`（409），不自动创建 |
| `workspace-close` | `{agent_node_id}` | 调用 `close`，释放并移除实例；成功后再次 close 显式报错（由执行器状态机保证恰好一次） |
| `workspace-abort` | `{agent_node_id}` | 调用 `abort` 仅释放；清理阶段允许按链+绑定直接释放，不要求 DB 仍 running；幂等 |
| `invoke`（复用） | 现有字段 + **可选 `tool_name`** | 参数/归属校验全部保留；按 `PreparedWorkspaceToolSpec` 分派到工作区实例；结果严格 JSON 且受大小预算。同一工作区绑定内多个工具靠 `tool_name` 精确选中：执行器从内核 `ToolInvocation.tool_name` 传入；不含 `tool_name` 的旧 payload 保持原样通过（纯工具/变量工具行为不变） |

**接口补全记录（2026-10-23）**：上表 `invoke` 原“复用现有字段”无法区分同一 binding 内的多个工具（W1 联调实证）。按已确认的“同一实例多工具”方向补一个**可选** `tool_name` 字段，属最小实现补全，不改变 Q1-Q6 结论和既有纯/变量工具路径语义；`graph_execution.invoke_bound_tool` 增加同名可选参数，缺省时不追加字段。

- 返回形状：`workspace-specs` → `[{binding_id, tools: [public()...]}]`；`workspace-open` → `{"opened": [binding_id...]}`；`workspace-finish` → `{"text": str} | null`；`workspace-close` / `workspace-abort` → `{}`。
- 实例表：`_tool_workspaces: dict[chain_run_id, dict[binding_id, instance]]`，与 `_tool_frames` 同生命周期；close/abort 后移除；链释放时 `_release_tool_bindings(chain_id)` 对残留实例 abort 兜底（不保存、不重试）。
- 适配器实现从本次冻结依据的锚点登记记录取得（与纯工具调用同法），不从当前 registry 兜底；调用身份由宿主生成，模型参数不得取得身份、权限或进程控制。
- 无新 `NodeDefinition` capability；`NodeExecutionContext` 新增转发方法（`bound_workspace_specs` / `open_bound_workspace` / `finish_bound_workspace` / `close_bound_workspace` / `abort_bound_workspace`），与 `bound_tool_specs` 同层，不经 `_allow`。

### 2.2 执行器状态机（`agent_executor.py`）

```text
NEW --open--> OPEN --finish(保存+导出)--> FINISHED --compose--> COMPOSED --close--> CLOSED
dispose：OPEN→abort（不保存）；FINISHED/COMPOSED→close（只释放，不再保存）；CLOSED/ABORTED→no-op
finish 抛错时状态仍为 OPEN，dispose 走 abort；close 抛错保留 COMPOSED，报告失败且不重试
```

- `__init__`：只读取得工作区声明（`getattr` 守卫，无桥/无声明时完全保持旧行为）；不加载业务数据、不启动进程。
- `advance`：`continuation is None` 且尚未 opened 时 open（open 失败明确阶段、释放已取得局部资源，不进入模型循环）；pause/resume 与接纳再入不重开。
- 有效 final 后（`kernel.run` 返回、`_completed_result`/`agent_result` 之前）：finish → 合成 → close → 保留 `_workspace_export`/`_composed_result_text`/`_workspace_state`；之后才置 pending acceptance、生成 `agent_result`、进入 `recover_acceptance`。
- `recover_acceptance`：用保留的合成文本生成 `result`，不再次 finish/close/保存、不重跑模型。
- `dispose`：仅幂等兜底释放（见状态机），不承载成功保存；abort/close 异常不给原始业务失败改名，按清理错误记录（沿用宿主 `disposal_error` 呈现，节点诊断保留阶段）。
- 合成结果文本：`result = 模型 final 文本`（无导出）或 `模型 final 文本 + 分隔 + 导出文本`（导出存在）；具体格式见待确认 Q1。

### 2.3 失败边界

| 情形 | 契约 |
| --- | --- |
| open 失败 | 明确 `workspace_open_failed`；释放已取得资源；节点失败；不进入模型循环 |
| 模型报错 / 用户终止 / 服务关闭 | 不调用 finish、不保存、不导出；dispose→abort 释放；已提交数据按实际事实保留（是否已提交由工具/数据层事实说明） |
| finish 失败 | `workspace_finalize_failed`；不合成、不 close 成功声明；节点失败；dispose 走 abort/close 释放；不自动重跑模型或工具 |
| 导出无效（非 `{"text":str}`/null、超预算、非 JSON 安全） | `workspace_export_invalid`；节点失败；不把非法导出拼入 result |
| close 失败（已完成保存与合成） | `workspace_close_failed`；节点失败；已保存事实保留，不报告回滚；dispose 不重复保存 |
| 合成/图层接纳失败（已保存） | 失败可见；已提交事实可核实；不报告虚假回滚；drive 成功后的图层接纳失败当前无可重试保留（勘察01 §4），如实报告 |
| 结果接纳再入 | 复用已完成收尾产物；finish/close/模型调用次数不增加；不重复发布已接受事实 |
| pause | 工作区保持打开，不 abort/close；同进程 resume 继续原实例 |
| 释放失败 | 沿用宿主 disposal_error 只读呈现；不自动重试、不假装已释放 |

## 3. 统一结果契约（候选）

- 输出端口不变：`result` = TEXT@2；`receipts` = AGENT_RECEIPTS@2。不新增对外输出端口。
- 合成只改 `outputs["result"]` 的文本；`agent_result.final`、`message_accepted`、`model_*`、工具 settlement、receipts 全部保持原样。
- 合成文本不得伪装成模型消息；不进入下一轮模型上下文（context.merge 仅用 receipts/facts 重建原始 final；如需进入须另立上下文契约）。
- 合成证据：节点输出 `workflow_output` 即结果层证据；工具保存事实由工具所属数据层/其领域记录；本期不新增执行事实或回执字段（待确认 Q4）。
- 大小：合成文本受现有内容传输预算（4MB）限制，close/合成处显式拒绝超限，不截断。

## 4. 数据层与检查点（本轮范围与缺口）

- 现有唯一带“采集+恢复”语义的载体：声明进 `session_preloads` 的 session 作用域对象（`preloaded_items` 分区）；`checkpoint_admission=True` 本身不触发采集；成功 round 结束才追加检查点；恢复到独立目标会话经 `graph.checkpoint.fork`（勘察03 §2）。
- 工作区工具“自行保存仍应通过所属领域的数据层接口”：本轮不新增通用数据写端口（会触及 Agent 节点能力/版本与新事务契约）。样例包只在受控存储内演示“finish 保存 / abort 不保存 / 第二次调用重载”，**不以样例文件冒充产品数据层**。
- 真实地图工具（`G:\AI\shapan\sandbox_demo`，仓库外、未完成）：无长驻进程/stop/退出确认协议；状态在自身 `world/.sandbox_v3.sqlite3`；无世界级导出/导入或数据层接口（勘察03 §5）。因此：
  - **P3 真实接入本轮不做**，只记录工具现状与最小适配面；不得报告地图产品已接入。
  - **P4 历史回合恢复本轮不做**；地图状态未入会话对象层、无数据类型/绑定/预加载声明时，检查点不会覆盖；补声明还会产生新固定修订、旧检查点不可 fork 的兼容限制（勘察03 §6）。
- P4 候选路径（待真实工具完成后另立契约）：包注册 session 类型（`checkpoint_admission=True`）→ 工作流 `object_bindings`（readers/writers 含 Agent 节点）→ `session_preloads` 初值 → 工具在 finish 时更新对象 → 成功 round 采集 → fork 恢复。行为链需确定是入对象还是仅工具导出事实。
