### 3.2 worker 协议（包内 `sandbox_tool/worker.py`）

- 启动参数：只读资源根、本次运行 DB 路径（绝对路径，由适配器按调用隔离目录生成）；启动即建 `Sandbox(world_path, database_path)` 并保持到进程结束。
- 通道：stdin 每行一个 JSON 对象；stdout 每行一个 JSON 对象（`ensure_ascii`、`allow_nan=False`、逐行 flush）；stdout 只放协议返回，诊断/异常栈只写 stderr；非法 JSON/未知 op 返回 `{ok:false,error}` 并继续，不退出不重试。
- op：`init {snapshot?}` → `{ok:true,state}`（可选恢复快照）；`query {request}` → `Sandbox.query` 原样；`execute {request}` → `Sandbox.execute` 原样；`snapshot {}` → `{ok:true,snapshot}`；`finish {after_event_id?}` → 从游标分页调用 `generate_action_context`（limit 1000、循环 `has_more`）→ `{ok:true, text: <str|null>, snapshot}`；`quit {}` → 关 DB 后 `{ok:true}` 并 exit 0；`abort {}` → 不保存不导出，关 DB 后 exit 0。
- 退出确认：适配器 `close` 发 `quit` 并限时等待 `returncode==0`（超时 kill 并报错，不宣称已关闭）；`abort` 只释放（终止进程/关闭连接），不写快照与导出。

### 3.3 包适配器六阶段（复用 P1/P2 契约）

- `normalize` → §6 的 10 个工具声明（严格 `{name, description, parameters, config}`）。
- `open` → 校验资源 bundle hash；按 `binding["data"]`（S4）或运行文件（S2）恢复快照；启动 worker `init`；返回不透明句柄（进程/通道/运行目录/初始 world revision/事件游标/资源身份）。
- `invoke(handle, tool, arguments, invocation)` → 按工具映射 `application/action`，透传 worker `query`/`execute`；JSON 文本参数在包内解析校验，非法值返回 `{success:false,error}` 业务结果（不抛进程错误）；业务拒绝原样作为工具结果返回。
- `finish` → 取本次调用开始时的 `last_event_id` 游标，worker `finish` 分页导出本次正式事实；快照与导出必须来自同一份已停止接收业务修改的状态；返回 `None`（零事件且无保存）或 `{"text": str}`（零事件但有保存时可为 `{"saves": [...]}`）或 `{"text": str, "saves": [...]}`。
- `close` → `quit` + 退出码确认；`abort` → 释放不保存。

## 4. 快照契约（候选）

```json
{
  "schema": "openagent.sandbox.snapshot/1",
  "world": {"world_name": "幻想大陆", "resource_id": "example.sandbox-demo",
            "resource_version": "1.0.0", "bundle_sha256": "<64hex>",
            "files": {"overview.json": "<sha256>", "...": "<sha256>"}},
  "state": {"revision": 0, "clock": "2024-01-01T08:00:00", "scene_marker": null,
            "last_event_rowid": 0,
            "characters": [{"id": "protagonist", "payload": { ... 完整角色 JSON ... }}],
            "events": [{"event_id": "ev_00000001", "payload": { ... 完整事件 ... }}]},
  "tickets": {"policy": "dropped", "items": []}
}
```

- 恢复等价：revision/clock/scene 逐字段；有效角色集合与 payload 深度相等（含 movement_history）；事件条数/event_id/parent/payload 完全一致且不重编号；`last_event_rowid` 一致；单事务安装。
- 唯一非等价项：`active_tickets`（票据按 policy 丢弃），必须写入诊断/回执。
- 大小：单对象默认上限 1MB、可配至 4MB；`finish`/保存前测量快照字节数，超过所选上限 → 明确失败（本版不分卷，见 §9 Q4）。

## 5. S4 数据对象接口契约（候选 A，待确认）

### 5.1 声明与准备

- 适配器新增可选 `data_config_field: str | None = None`（默认 None = 旧行为不变）。
- 加载节点配置在该字段声明 `data_objects: [{"object_key": "<key>"}]`；**类型、scope、readers/writers 的唯一来源是工作流文档 `object_bindings`**，不在工具配置重复声明。
- 准备期（`prepare_tool_frame` 已持有文档 object_bindings）校验：key 命中文档 binding；`agent_node_id ∈ readers`（否则 403）；冻结 `writable = agent_node_id ∈ writers`；`registry.data_types.get(type_id, schema_version, scope="session")` 存在；**只读元数据、不读值**。
- `PreparedWorkspaceToolBinding` 增冻结字段 `data_objects` / `writable`；每绑定声明对象 ≤8。

### 5.2 读取（open）

- 宿主在 `_require_workspace_owner` 同款读事务内 `data.state.read_object(session, key, node_id=Agent)`，并通过 `binding["data"] = {key: {value, revision, revision_id, type_id, schema_version}}` 交给适配器；失败 → `workspace_open_failed`（诊断含对象键），不进入模型循环。
- 暂停/恢复、结果接纳再入不重开；open 快照 + finish CAS 足以发现漂移。

### 5.3 保存（finish）

- `finish` 返回扩展：`None | {"text": str} | {"saves": [{"object_key", "value", "expected_revision"}]} | {"text": str, "saves": [...]}`；非数据能力的旧适配器行为不变。
- 宿主校验：saves 数组、每项严格三字段、object_key ∈ 冻结声明且可写、单对象一次、`expected_revision` 等于 open 时记录值、value JSON 且受类型 `max_bytes`；非法 → 建议 `workspace_save_invalid`。
- 独立事务（对照变量工具 `_accept_tool_write`）：`_change("graph.tool.object-write", "workspace:<node_run_id>:finish", ...)` → `_require_tool_owner` → `apply_objects(session, node_id=Agent, writes, write_evidence)` → 提交后独立读事务重读并比对 revision/revision_id/value canonical bytes；不一致 → 建议 `workspace_save_mismatch`（已提交按事实保留、不重试、不报回滚）。
- 幂等：`operation_key = "workspace:" + node_run_id + ":object:" + sha256(object_key)`；执行器保证 finish 恰好一次，接纳再入不重放。
- 同一事务全有或全无；`saves` 不进入节点输出/事实/回执/模型上下文；向上仍只把 `text` 交给执行器合成。

### 5.4 检查点（复用现有机制，不改核心）

- 包注册 session 类型：`register_data_type(DataTypeDefinition("example.sandbox.world", 1, schema, scope="session", checkpoint_admission=True, max_bytes=4_000_000))`。
- 工作流文档：`object_bindings`（readers/writers 含 Agent 节点）+ `session_preloads`（schema 3，初值=初始世界快照；该 binding 无 default_value/registrar，类型无特殊回调）。
- 成功回合 settle 后自动采集到 `preloaded_items`；`fork_checkpoint` 恢复到独立目标会话；原会话只读。
- 限制：仅 preload 对象被采集；新增 preload 产生新固定修订；旧检查点缺分区时 fork 409（不承诺旧聊天历史可恢复）；失败回合不采集；单对象 ≤4MB、preload ≤1024、单事务写集 ≤256。

### 5.5 版本与失败码影响

- 改：`tool_binding_contract.py`、`tool_bindings.py`、`graph_tool_host.py`（仅数据面三文件）；包/文档/测试。

## 7. 事实导出（S3）

- 每次调用在 open 时记录当前 `last_event_id` 游标；finish 从该游标分页读取 `generate_action_context`（limit 1000，循环 `has_more`），只导出本次新增正式事实，零事件返回无导出。
- 导出文本由沙盘固定模板生成，适配器只返回已确认形状 `{"text": str}`；程序按 `模型 final 文本 + "\n\n" + 导出文本` 合成 `result`（TEXT@2，无新端口）。
- 历史事件/`movement_history` 种子/`recorded_at` 墙钟不进本次导出；事实与快照来自同一份停止接收修改的状态；导出/保存失败报告阶段与已知提交事实，不重复保存、不重试。
