## 已确认机制

- 两种条目模式：常驻、关键词触发；每条独立启用或禁用，禁用始终不输出。
- 概率相当于本次是否开启条目。常驻不检查关键词；常驻加概率只在概率通过时输出。关键词模式加概率要求两者同时通过。
- 匹配关键词时插入该条目的正文，不把关键词、名称或配置 JSON 当成提示词正文。
- 主关键词、副关键词分别配置；每组内部任一关键词命中，空组视为未命中。首版组间规则为主 OR 副、主 AND 副、主 AND NOT 副。
- 默认忽略大小写，按字面子串匹配，中文正常匹配，不强制词边界，不把触发词当作正则表达式。
- 每个 lorebook 节点只扫描自己收到的上游提示词与上下文，不主动查看其他节点，不另读完整历史、不补回精简前原文。
- 非递归只匹配输入中的真实用户和模型会话正文，不因提示词采用 user / assistant role 就把它当成真实会话。
- 递归额外匹配本节点输入中已有的 lorebook 正文，以及本节点本次计算新激活的 lorebook 正文。首次匹配不计递归，之后最多追加三轮；不通过工作流循环实现。
- 节点独立计算递归次数，不追踪上游进行了多少轮，不共享全图递归计数，不回头重跑上游。
- 关键词扫描深度默认 20，使用逻辑楼层坐标，不是完整历史回合数，也不是工具协议消息条数。
- 插入位置、插入深度、role 和排序沿用提示词条目机制。扫描深度与插入深度是两个独立配置。
- 变量关键词先读取并求值，再匹配；不赋值、不修改变量对象。缺失、未赋值或空变量不使节点报错，无有效匹配值的关键词按未命中处理；其他有效关键词照常匹配。空字符串本身不能算作命中。
- lorebook 输出仅包含已激活的结构化提示词材料，可进入提示词汇总或装配；不复制扫描输入上下文。
- lorebook 材料为 per_request / never，不写入持久上下文，每次节点计算重新决定激活条目。
- 单条目和条目组共用条目结构及激活引擎。每条在一次计算中最多激活一次；概率结果不因追加递归轮次重复抽取。

## 条目配置

字段遵循现有 schema 风格，单条目配置为 `entry` 和 `object_keys`，条目组配置为 `entries` 和 `object_keys`；启用开关复用 `presentation.enabled`。不建立第二套 role / placement / depth / order 规则。

| 配置 | 首版语义 / 默认 |
| --- | --- |
| 稳定条目 ID、名称、正文 | ID 用于来源与去重；名称只作管理标签，正文才是输出和递归扫描材料 |
| 启用 | 每条独立开关，默认开启；禁用不匹配、不输出、不提供递归触发正文 |
| 模式 | 常驻 / 关键词触发；新条目默认关键词触发 |
| 主关键词、副关键词 | 两个字符串列表，各自任一关键词命中；空组为 false |
| 组间规则 | 主 OR 副 / 主 AND 副 / 主 AND NOT 副；默认主 OR 副，允许仅填写主关键词 |
| 大小写 | 默认忽略大小写；中文使用同一字面匹配路径，不依赖英文分词或词边界 |
| 递归 | 每条独立开关，默认关闭；开启后才允许 lorebook 正文参与它的匹配 |
| 扫描深度 | 默认 20 个逻辑楼层，和插入深度分开 |
| 概率开关、概率值 | 默认不开启；概率值默认 100%，范围 0% 到 100% |
| role、位置、插入深度、排序 | 复用现有呈现结构；role 为 system / user / assistant，不允许伪造 tool 协议 |
| 变量读取绑定 | 只读、显式授权的当前变量对象；不使用旧变量快照机制，不隐式枚举会话或全局变量 |

输出生命周期固定为 per_request / never，不提供把 lorebook 本文留在持久上下文的配置。组内条目稳定 ID 不得重复；组和单条目共享同一结构、校验和计算逻辑。

## 触发与关键词

条目禁用优先于全部条件。启用后：

| 模式 | 输出条件 |
| --- | --- |
| 常驻 | 始终输出，不检查关键词 |
| 常驻加概率 | 概率通过 |
| 关键词触发 | 关键词规则通过 |
| 关键词触发加概率 | 关键词规则与概率都通过 |

设主组匹配结果为 P、副组为 S：

| 组间规则 | 判定 |
| --- | --- |
| 主 OR 副 | P 或 S |
| 主 AND 副 | P 且 S |
| 主 AND NOT 副 | P 且非 S |

每个关键词只匹配允许扫描的正文，不搜索名称、变量名、JSON 字段、来源、role 标签或工具参数。不将相邻消息拼接后形成跨消息的虚假关键词；不同关键词可以分别在同一允许扫描范围的不同正文中命中。

只对触发词中明确的变量引用求值，不更改关键词配置、输入提示词、正文或变量值，不执行赋值宏和脚本。替换结果作为字面文本，不递归解释其内部宏。缺失 / 空值对应关键词不能通过空串匹配误触发全部条目，也不阻止其他关键词的正常判断。变量权限或绑定类型不合法仍是配置 / 权限错误，不能借“未命中”绕过授权校验。

概率相当于本次开启门槛，0% 不通过、100% 通过；其他概率每条每次计算最多抽取一次。未通过的正文不能触发后续条目。已有接受结果的接纳重试复用原产物，不重新抽取或重新调用节点。

## 扫描与节点递归

本节点只使用它的显式输入：

1. 依据楼层、来源及文本块选择输入中的真实用户 / 模型会话正文；仅 role 相同不意味着是真实会话。
2. 先按扫描深度裁剪真实会话楼层，不额外查询档案或恢复精简前原文。输入中的 checkpoint、预设、角色卡和普通提示词材料不冒充真实会话。
3. 对开启递归的条目，额外允许扫描输入中已有的 lorebook 正文；这是已经收到的材料，不追踪上游节点或其递归次数。
4. 完成首次判定：常驻条目按概率门槛处理，触发条目按关键词规则与概率门槛处理。
5. 若产生新激活条目，将其正文加入本节点的递归匹配材料，再追加最多三轮。每轮先确定本轮新激活集合，下一轮才使用这些新增正文，不能按条目遍历顺序偷偷扩展轮数。
6. 已激活条目不重复输出；没有新增条目时提前结束。非递归条目不因其他条目的正文而新增触发。
7. 只返回本节点激活的结构化条目，不复制输入，也不把节点内部追加扫描当成持久会话写入。

每个节点都是“首次匹配加最多三轮”，没有跨节点共享状态。例如 A 节点输出被显式汇入 B 的输入时，B 按自己的扫描和递归配置处理；A 此前递归了几轮不占用 B 的轮数。B 也不会自动把自己的输出重新送回 A。

首版扫描窗口约定：深度 D 扫描从最新 user 下方 depth 0 向上跨 D 个真实会话逻辑楼层的正文；不足 D 层时扫描已有的全部允许正文。D 为非负整数，0 表示不扫描真实会话正文，不影响常驻或递归额外正文的独立条件。

扫描窗口和插入位置分别负责触发与最终排列。首版递归额外正文不增加真实会话楼层，也不因其输出 role 或插入 depth 变成真实会话；插入位置由最终装配处理，不通过重复装配重排递归材料来获得额外轮数。资源总量仍受既有内容大小与引擎扫描预算限制，三轮上限不等于无限扫描容量。

## 深度修正

以旧 `prompt_assembly.py` 的逻辑楼层规则为准：

```text
更早 user
--- depth 2 ---
最近 assistant 的完整生成增量
--- depth 1 ---
最新 user 输入
--- depth 0 ---
```

一个历史 user 根和它的完整模型增量分别算一个逻辑楼层。增量可能包含多条 assistant 文本、工具调用及工具结果，整体是一层，不在工具协议中间插入提示词。

- depth 0 在最新 user 输入之后。
- 向上每跨一个逻辑楼层，depth 增加 1。
- 超过可用楼层时夹紧到最前面的中区边界，与旧装配一致。
- before、middle、after 在同一边缘仍保持区域顺序；同一实际边界按 order 排序。
- 精简 checkpoint 和一次性提示词不是新增的真实会话楼层；保留其正文与来源，不补回已替换内容。
- 新装配产物显式记录 `placement_profile=logical-floors-v1`。没有该字段的旧冻结产物仍按原投影校验，不能重写原执行请求或借新规则改变历史证据。
- 本次修正覆盖普通提示词装配的 depth 0，以及上下文 PROMPT@3/4/5/6 的逻辑楼层插入。无显式上下文的普通装配仍拒绝 depth 大于 0，不擅自猜测历史。
- 原有精简策略 keep_depth 仍是保留完整回合数，与提示词插入深度无关，不随此次修正改变。

原 `PLAN-CONTEXT-COMPACTION.md` 中按历史回合锚点检查的文字保留为当时实现记录；本次深度修正以本文为准，不改写固定基线或此前验收结果。

现有提示词汇总只合并材料，不能直接汇总上下文。首版规划复用上下文装配形成 PROMPT@6 作为一个扫描输入，内含上游材料、上下文、最新 user 输入、楼层和来源；不为扫描先转换成丢失来源的纯文本。

```text
上游提示词材料 + 上下文 + 当前输入
                 |
        扫描准备：现有上下文装配
                 | PROMPT@6
        lorebook 单条目 / 条目组
                 | PROMPT_MATERIALS@1
        提示词汇总 + 原有材料
                 |
        最终装配 + 同一上下文 / 当前输入
                 |
                Agent
```

扫描准备是纯装配，不调用模型、不持久写入、不消费一次性条目。lorebook 只有一个结构化输出端口；未激活任何条目时输出合法空材料集合。输出保留稳定条目身份、来源、role、placement、depth 和 order，沿用 PROMPT_MATERIALS@1 汇总与最终装配路径。

原有材料单独连到最终汇总；不让 lorebook 把整份输入再输出一次，防止重复上下文、重复当前输入和普通材料被误记成 lorebook 内容。多个 lorebook 串接时，每个节点需要的提示词与上下文都由显式上游接线准备。

本期不扩展提示词汇总的旧输出契约，也不新增独立上下文汇总节点。未来若确需“汇总、lorebook、单次最终装配”的更简接线，再单独设计保留来源与楼层的新版扫描输入契约，不把该扩展当作首版前置条件。
