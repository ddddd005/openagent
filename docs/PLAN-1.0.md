### 阶段 B：统一入口与退出旧实现

按依赖推进 REPLACE-03、REPLACE-04、REPLACE-05：

- 先退出旧运行与加载依赖，再统一客户端及数据入口，最后退役确认无必要调用者的旧专用实现和测试。
- 必要基础节点先迁出；共用 Agent 内核、存储设施和算法按依赖保留，不与旧专用宿主一起删除。
- 统一业务权威，不用长期双写维护两套路径；已保存定义、会话及数据的去向必须明确，不以清理代码为由删除用户数据。
- 先分开历史精确包选择与当前执行配置，使冻结旧 active/facts 不阻塞同库新图；纯档案及 receipt-only、浏览器冻结 passthrough 到位后再关闭旧入口。旧请求无法核实时保持 unresolved，不重 POST、不伪造结算。
- VERIFY-05 随实际改动执行，迁入必要回归和共用夹具；不自动重跑全量。

阶段 B 不能仅以“新路径可用”或“旧路径已隔离”结束。完成时必须关闭旧专用写入/运行路由，将正式旧 UI/store 换成必要只读入口并删除，退役旧宿主/私有执行器、适配及无必要调用者的专属测试；共用设施和历史纯数据读取按裁决保留，不保留旧执行 fallback 或长期双写。后续切片按能否解除对应旧调用链的删除前置来收口，准备片本身不算架构移除。

### 阶段 C：独立架构与基础使用验收

REPLACE-06 核实架构独立性，之后集中完成 VERIFY-01–04 和必要修复；VERIFY-06 的底线检查及 VERIFY-07 的证据整理随收口完成。

- 核实独立安装、节点目录、类型/构建、常驻启动和受支持入口均不再依赖旧路径。
- 在目标代码上验收浏览器配置、编辑保存、串行与多轮、历史/复制/分叉后续聊、暂停及已有失败处理。
- 对重复点击、冲突、断网和原请求核实补对应证据；真实模型请求仍需当次场景、授权和费用范围。
- REPLACE-06 与 VERIFY 的同版本、同范围重叠证据可以复用，不重复组织同一轮验收；旧版本或不同场景的结果不能代替新证据。

1. 所有受支持的运行、客户端和数据入口只走新架构，不再靠旧路径兜底；旧能力处置有完整记录。

4. 受影响回归、类型检查、构建、浏览器使用和必要安全检查有对应版本证据；本阶段发现的阻断问题已处理。
