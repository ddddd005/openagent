## 2. 运行与数据职责

一次正常回合遵循以下顺序：

```text
保存工作流定义及修订
→ 创建或选择会话，提交本轮输入
→ 校验身份、配置、依赖、对象权限及实际运行依据
→ 冻结运行依据，编译激活计划
→ Runtime 调用节点，解析依赖并提供上游已接纳产物
→ 节点返回，平台校验并接纳产物及声明的对象更新
→ 全部激活节点成功接纳
→ 公共结算保存完成回合检查点
→ 消费者读取显式公开的展示结果
```

Agent 是 Runtime 托管的一种执行器。Agent 内核负责内部模型调用、工具顺序及活动消息；公共 Runtime 负责调用、暂停协调、接纳和整图状态，不维护另一份可独立修改的 Agent 消息队列。

| 数据 | 当前权威及更新职责 |
| --- | --- |
| 节点配置、自有文字、连接、执行根和包锁 | 工作流定义及修订 |
| 变量、各 Agent 有效上下文、前端持久业务状态 | 登记式会话对象，由获授权的节点提交更新 |
| 全局提示词、供应商等当前资源 | 全局当前资源层；会话分叉不回滚全局当前头 |
| 本次冻结输入、节点产物、调用和接纳事实 | 公共运行记录及产物存储 |
| Agent 活动消息、工具顺序及继续现场 | Agent 内核现场；已记录事实另按持久协议保存 |
| 完成回合的定义和对象清单 | 公共完成结算生成的检查点 |
| 草稿、展示缓存、设备偏好、原请求恢复记录 | 客户端工作数据，不替代后端权威 |

上下文节点组织是绑定 Agent 的 `context.output@2`，同一视图进入 `context.assembly@3` 和 `context.merge@2`；`agents.execute@3` 输出本轮上下文，merge 负责合成并请求写回。

前端业务通过读取、追加和展示节点接入工作流。前端节点完成一次调用不等于整图完成，检查点继续由公共运行与结算流程负责。只在正常 assistant 回合完成后形成检查点；轮间编辑、待输入和局部事件不新增编辑检查点。历史定义不可用时明确报错，不自动换用当前定义。

对象效果逐节点接纳。前面已接纳的效果不会因后续节点失败自动撤销；当前实现不提供整图回滚或外部工具效果回滚。

串行 Demo 的第一波补充 **1/2/5** 已完成本期范围：

- 模型供应商当前资源管理和模型源字段编辑。
- 显式创建 18 个普通节点的 A→B 示例，A/B 分别维护上下文。
- 原输入进入两套装配，A 的本轮结果转换为 B 的附加材料。
- B 成功后按控制依赖写回上下文，再读取/追加前端状态并公开展示。
- 保存、消费入口、完成回合历史、复制/分叉和完成库重开读取。

确定失败续跑仅覆盖已声明的安全首片：例如事实确认未派发或模型 429/503、没有工具派发、原同进程现场和冻结依据仍可用。新尝试保留同一 chain 和已完成前缀，旧失败事实不覆盖。超时、断连、未知效果、现场丢失等不自动取得重发许可。

新公共 Agent 以合法 `final_answer` 结束，不恢复历史模型调用次数额度机制。

- 默认只运行真正受影响范围的必要验证，不再自动启动全量，也不把旧通过结果当作新修改的验证。
