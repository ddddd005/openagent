# 画布端口坐标刷新

日期：2026-11-04。

## 现象与定位

点击 Agent 执行节点的 `receipts` 输出口时，临时连线从 `result` 所在行引出。本次依据用户截图排查，未操作用户正在编辑的页面，也未读取或改写其工作流。

隔离浏览器复现确认：目录尚未加载时，已有连线使画布先显示第一行的 `receipts`；目录加载后，完整声明变为第一行 `result`、第二行 `receipts`。输入列仍比输出列高，节点外框尺寸保持不变，Vue Flow 未重新测量原有 `receipts` 的坐标。

在 1 倍缩放的复现中，节点外框始终为 242 × 198；`receipts` 的可见纵坐标由 229.5 移至 256.5，缓存仍为 229.5，恰好与 `result` 重合。实际点击元素、拖线起点事件和最终连线的 `sourceHandle` 均为 `receipts`。该复现属于显示坐标错位，不能据此认定用户当前工作流中的边字段已经被修改。

后端声明保持明确：`result` 为 `TEXT@2`，`receipts` 为 `AGENT_RECEIPTS@2`，写回上下文的 `receipts` 输入接受后者。后端不会将这两个口互相替换，类型不兼容的边会在编译时报告错误。

## 修复与验证

`GraphCanvasNode.vue` 在端口顺序、身份、显示标签或影响布局的节点内容变化后，于 DOM 更新完成时调用 `updateNodeInternals`，重新测量当前节点。监听比较稳定的布局签名，普通连线高亮变化不会触发全图刷新。原有端口 ID、连线存储与后端执行契约保持原样。

新增 `test_graph_port_geometry_browser.py` 与 `graph_port_geometry_browser.mjs`，通过实际画布组件和隔离 Vite 测试页面验证：

- 目录延迟加载且节点外框尺寸不变时，各端口的缓存坐标与 DOM 一致。
- 输入、输出端口重排且节点外框尺寸不变时，两侧坐标均刷新。
- 在 1 倍和 1.75 倍缩放下，临时线从点击的 `receipts` 行引出，最终源口与目标口均为 `receipts`。
- 测试拒绝产品 API 和外部网络请求，不使用产品状态或真实模型。

修复前新增浏览器回归实际失败，报告保留在 `.local/test-runs/agent-port-geometry-20261104.xml`。修复后浏览器回归 1 项通过，内部覆盖上述 4 个场景，报告为 `.local/test-runs/agent-port-geometry-final-20261104.xml`，对应临时测试目录内保留坐标记录及截图。

本次前端全量测试 128 个文件、1,574 项通过，报告为 `.local/test-runs/agent-port-frontend-20261104.xml`；`npm run build` 的类型检查与构建通过，构建仍提示产物超过 500 kB。未启动或重启既有产品服务，未执行真实模型请求，未安装依赖或提交代码。
