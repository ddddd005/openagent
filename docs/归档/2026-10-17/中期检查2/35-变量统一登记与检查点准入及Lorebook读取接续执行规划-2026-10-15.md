## 1. 已确认机制

| 对象 | 职责 |
| --- | --- |
| 变量数据类型 | 首版数据层使用已登记的一个会话变量类型；不同变量是该类型下的独立项，不为每个变量重新注册一种类型 |
| 定义模块 | 提供变量类型定义及明确的检查点准入声明，供配置、读取/更新及检查点消费；不维护变量当前值 |
| 工作流配置 | 保存提供节点、独立项登记、消费者选择和明确授权；节点新增或更新时同步登记 |
| 会话数据层 | 维护各项已接纳当前值，以会话和具体项共同定位；同一工作流的不同会话互不影响 |
| 注册及初值交互 | 用户通过按钮等交互节点主动调用数据层能力，沿已有非工作分类，不进入普通自动执行计划 |
| 流内读取与更新 | 工作节点向数据层读取或提交目标项；读取输出是当时的一份值，处理后的变化须明确写入 |
| 检查点 | 在既有成功时点保存准入变量的逻辑状态，分叉时在新会话中装载所选点的值 |
| Lorebook | 在执行时内置调用变量读取，取得所选本会话项的值，再进行既有关键词替换和匹配；不注册或修改变量 |

统一定义来源沿已有`NodeRegistry / TypeRegistry`，不另建同名模块或登记系统。变量类型只登记一次；新增变量及按钮操作登记的是该类型下的具体项或变量状态，不重复注册类型。现有类型默认值为未注册空壳，配置建立项身份与实际会话注册不同；名称、标量类型及可选初值由主动注册操作接纳，重复注册不重置已赋值或分叉装载的内容。

非工作分类仍是既有`execution_class = non_working`：节点可以存在于配置图中，由用户主动操作触发；普通runtime筛选不自动调度它。分类由准确节点类型声明，不按实例是否显示按钮临时改变；分类本身不生成按钮或事件绑定，后者仍需明确接线。流内普通赋值/更新继续按数据边、控制边及已有创建序调度，不能因按钮存在把所有赋值节点改成非工作，也不按共享变量自动补先序。

类型、项、名称和当前值分别处理：类型决定值契约，项键决定具体变量，名称用于已授权集合中的替换，当前值按会话隔离。同类型多项不能只按类型名取第一项，也不能以变量名称绕过具体项选择及权限。

用户进一步确认首版变量按会话绑定，但绑定关系不能成为永久业务假设。会话归属集中在数据层访问/存储边界和调用上下文：变量值契约不内嵌必需的会话身份，项键不拼接会话身份，读取、更新及Lorebook调用数据层入口，由数据层按本次上下文定位当前值。首版准确声明仍为session范围；不让各消费者自行管理会话定位，也不提前实现全局变量或跨会话共享。

无会话时仍只保存配置及项登记，不提前创建会话或业务值。有有效会话时，固定配置/节点新增、复制、删除沿既有确认派生无会话新工作流；源会话和检查点保持原值。这个配置派生与从检查点初始化新会话不同。

### 交互能力与连线

**2026-10-15前端接续订正：** 用户明确前端仅与其绑定的后端节点通信，由该后端节点调用输入修改、控制、分叉等独立功能；上下文展示副本只接纳后端数据。见[40号简述](40-阶段E输入修改能力与前端后端节点职责简述-2026-10-15.md)。下文前端直接复用调用入口的建议按此收口为后端节点复用，具体操作契约仍后续讨论；不增加能力连线及暂停不等待普通图执行的边界保持。

用户提出前端节点后续需调用启动、暂停、重roll、分叉等能力，并明确若连线会显著复杂现有工作流机制则不增加。当前接续规划不引入能力连线：数据边及控制边继续表达既有执行依赖，不混入前端可调用能力的绑定关系。

前端节点复用负责这些操作的统一调用入口，按钮负责交互、目标和结果展示，不在前端节点仿写runtime控制或检查点分叉。能力复用不要求将它们布置为图中相连的执行节点；暂停等控制仍通过实际控制入口操作运行中的runtime，不等待普通图执行到某个节点。既有局部事件用于其准确目标操作，不能把当前运行期间禁止提交的局部事件直接说成暂停通道。

当前[workflowManagement.ts](../../../../frontend/src/application/workflowManagement.ts)已有启动及控制调用，[graph_application_contracts.py](../../../../backend/src/phase1_agent/graph_application_contracts.py)已有检查点分叉操作；[WorkflowFrontendSdk](../../../../frontend/src/plugins/workflowFrontendSdk.ts)尚未向节点前端暴露这些控制能力。具体前端节点施工时再接必要的窄调用、目标绑定及实际状态校验，不新增通用能力图或在本批安装E。重roll的具体行为须与失败重试区分，不以现有retry接口自动替代其业务定义。

## 3. 执行顺序

1. **统一变量定义与准入来源。** 沿已有类型注册入口整理变量定义、值校验和转换的单一来源，登记到统一定义模块；明确首版变量属于session范围并进入检查点白名单，会话定位集中于数据层边界。先核对实际消费者所需的最小声明和保存值形状，不新增声明表单、另一份变量值表或全量类型自动准入。
2. **接实例登记与准确项绑定。** 提供节点登记同类型独立项；注册操作、读取及更新指向准确项并使用明确ACL。沿现有新增/替换/复制/删除及固定编辑确认，不继承源会话当前值。退出变量默认旧键及专用绑定特判。
3. **接主动交互和普通读写。** 注册/初值按钮沿非工作分类和既有主动调用机制，操作目标绑定原节点、工作流、会话及项；普通运行不隐式注册、重置初值或触发按钮。读取取得当时值，更新显式提交，按用户编排再次读取。普通上游赋值保持工作节点职责。
4. **补检查点闭环。** 成功收集从定义白名单定位实际登记项；配套逻辑值校验、full/diff、物化、前缀复制和新目标装载。只在分叉新会话初始化已保存状态，建立目标自己的当前状态；不覆盖源、不依赖节点执行、不制造普通写回回执。初值操作不得覆盖已装载的变量值。
5. **接续Lorebook变量读取。** 内嵌单条、条目组及全局激活使用同一变量读取契约和精确项选择，执行时取本会话已接纳值；将值快照交给既有引擎。全局引用节点自身不读取变量，无需扩改。全局资源保存、匹配规则、递归、概率及输出格式不因变量迁移重做；变量仍只替换关键词，正文不新增替换。缺失、未赋值及空字符串使该关键词不参与匹配，`0/false`仍为有效文本。
6. **成组验证并记录实际退役。** 验证正式配置保存/回读、主动操作、普通图执行、成功保存及分叉再运行；分别列出新契约证据、准确历史排除和未完成内容，不累计已有验收数量。

符合以上已定职责的最小落实方案沿主代理审核委托推进。必要的具体声明、节点、按钮请求及保存格式在对应施工批次列清，不把未接接口写成现成能力；实际发现额外架构或行为矛盾再报告用户。

## 4. 聚焦验收要求

- 同类型至少两项、同工作流至少两会话：注册、初值、读取、写入与Lorebook消费均只影响目标会话/项。
- 提供声明与独立项登记一致；登记不自动赋予消费者权限；复制创建独立键并只映射明确消费者，确认派生后的新流无源运行数据。
- 非工作交互节点不进入普通计划；主动操作按实际目标调用；连通上游的普通更新节点仍按依赖执行，不自动注册或重置变量。
- 加载值在数据层更新后保持原值；再次读取才见新值。`set/add/subtract`、四种标量、类型错误、未赋值和已授权集合内的同名冲突行为准确。
- 检查点保存当时完整变量逻辑状态，区分未注册、已注册未赋值、已赋值；`0`、`false`和空字符串不得按空项丢弃。后续写入不追改旧点。
- 所选点及父链复制后，新会话恢复所选变量值，源当前值不变；目标继续更新/存点/再次分叉保持独立，失败按已有单事务回滚。
- Lorebook内嵌及全局激活读取同一会话范围，前后明确更新产生对应匹配结果；匹配过程不修改变量，不冻结全局资源中的会话变量值。
- 迟到回执归原对象，取消无数据写入；原请求核实、unknown保护及执行期间手动写入限制沿既有规则。

## 5. 退役与范围

本批替代的是变量旧登记/默认键及特殊绑定入口、普通运行隐式注册/初值路径，以及Lorebook对工具包私有变量契约的依赖。底层会话存储、明确权限、类型校验、原请求回执、正常流内更新和世界书匹配职责继续复用。

变量类型准入由本次用户决定明确扩展；聊天`frontend-state@1`、通用messages、private-state和其余已注册类型没有随之入点。仅接续Lorebook的变量读取，不据此退役整个Tavern、迁移世界书资源存储或安装E输入/展示节点；34号对应范围仍独立。

35号编写时只更新规划和当前决定索引，未修改产品代码或运行产品测试。随后获准的源码施工与限定验收见[36号](36-变量统一登记与检查点及Lorebook接续实施回执-2026-10-15.md)：注册@2非工作提供节点、准确项与事件、默认拒绝的类型准入、严格schema3检查点及Lorebook统一读取已接入。未升级产品数据库、启停产品服务、调用真实模型或再次提交，不从本稿推断D整体完成。
