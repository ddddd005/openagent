## 1. 最新决定与范围

- 变量本轮保持现状；待 Agent 上下文与聊天上下文两个核心贯通并验证后，再另择时机沿同一登记机制迁移，不预建变量迁移或兼容。

## 4. 完整登记仍需收口的最小内容

当前可复用 [TypeRegistry](../../../../backend/src/phase1_agent/host_sdk.py)、宿主 `register_data_type` 及图的 `object_bindings`。但 `ObjectBinding` 只含项键、类型、读写者和 private owner，没有“由哪个实例登记”的关系；private owner 只允许 owner 自己读写，不能拿来代替 Agent 登记、独立加载/写入节点消费的关系。

| 待收口内容 | 当前事实与实际影响 |
| --- | --- |
| 测试期输出的具体接线 | 输出职责已定为普通节点按内部逻辑输出内容，不是永久统一出口或完成指令。`tools.output@1` 可作为现有测试实现候选；具体目标及最小登记接线仍须列明。业务状态读取、展示及模型调用不因旧名字或 `is_output` 声明而自动成为同一数据归属 |
| 登记和当前值粒度 | 当前值由 `SessionObjectStore(session_id, object_key)` 存储，无会话只有图配置绑定。每会话分别持值还是跨会话共用节点的一份值、无会话何时初始化，尚不能从现存表推定 |
| 复制与删除 | 新实例独立身份已经确定；复制初值、部分图复制的外部项引用及删除后的保留/清理尚需明确，不能先共享源项或自动清理 |
| 必要公开契约 | 消费者配置及 CONTEXT_VIEW 的旧 Agent owner、更新包、真实执行校验和检查点 `{agent_node_id,value}` 消费须成组改接 item 身份；精确字段/版本先列最小影响，保留 producer、精确输入、权限、CAS、回执和原请求保护 |

建议复用现有图绑定与类型入口，将实例登记关系与权限 owner 分开，而不建设第二套类型注册或把当前值放进节点定义。此处是供审建议，不是本批已安装的新字段或存储模型。
