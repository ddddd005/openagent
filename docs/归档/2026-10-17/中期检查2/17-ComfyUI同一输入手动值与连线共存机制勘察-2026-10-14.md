日期：2026-10-14，Asia/Shanghai。

## 2. 输入声明与前端建模

后端节点只声明一个命名输入。例如 `CLIPTextEncode.INPUT_TYPES()` 中的 `text` 是 `STRING`，配置为多行输入；执行函数也只接收一个 `text` 参数。见 [nodes.py](../../../../../step1/ComfyUI/nodes.py#L57)。

前端 `addNodeInput()` 同时处理 socket 和 widget；普通可编辑类型会创建手动控件，并在同一个输入槽上挂载同名 widget 元数据，使该槽也能建立连线。见 [litegraphService.ts](../../../../../step1/ComfyUI_frontend/src/services/litegraphService.ts#L276) 和 [litegraphService.ts](../../../../../step1/ComfyUI_frontend/src/services/litegraphService.ts#L339)。

- `forceInput: true`：只创建连线输入，不创建 widget。
- `socketless`：有 widget 时不创建 socket。
- `defaultInput`：前端 v1.16 起已弃用；不是当前双模式输入的开关。字段说明见 [node_typing.py](../../../../../step1/ComfyUI/comfy/comfy_types/node_typing.py#L104)。

## 3. 连接时的界面行为

当前前端在 widget 行左侧显示输入插口，控件仍保留在原位；未连接时插口通常在悬停时显现，已连接时常显。见 [WidgetGrid.vue](../../../../../step1/ComfyUI_frontend/src/renderer/extensions/vueNodes/components/WidgetGrid.vue#L11)。

检测到该槽已连接时，前端将对应 widget 标记为 disabled，而不是隐藏或删除；断开连接后不再命中 linked 状态，手动控件恢复可编辑。见 [processedWidgetRenderModel.ts](../../../../../step1/ComfyUI_frontend/src/renderer/extensions/vueNodes/composables/processedWidgetRenderModel.ts#L371)。

## 4. 执行时的取值

前端先把 widget 值写入节点的 `inputs`，随后遍历输入槽：已连接的槽写入 `[上游节点ID, 输出序号]`，覆盖同名手动值；未连接的槽保留手动值。两种来源最终只占 API prompt 中的同一个输入键。见 [executionUtil.ts](../../../../../step1/ComfyUI_frontend/src/utils/executionUtil.ts#L127)。

后端以二元 link 形式识别连线。普通输入收到 link 时解析上游输出，否则把字面值作为节点参数。连接值与 widget 值不合并；连接后也不会在上游值缺失时回退到手动值。见 [graph_utils.py](../../../../../step1/ComfyUI/comfy_execution/graph_utils.py#L1) 和 [execution.py](../../../../../step1/ComfyUI/execution.py#L163)。

**要点：**一个输入名 / 一个输入槽 / 一个运行参数；手动 widget 是无连线时的值来源，link 是有连线时的值来源。当前实现保留并禁用已连接 widget，不采用旧式“把 widget 转换成 socket”的流程。
