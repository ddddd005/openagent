## 1. 功能与节点解耦

[workflow_operations.py](../../../../backend/src/phase1_agent/workflow_operations.py)新增`WorkflowOperations(service)`，不导入前端节点，不要求图内存在前端节点：

| 功能 | 实际职责 |
| --- | --- |
| `start` | 无会话时协调正式create与start；有会话时启动一轮。两个阶段分别保留真实结果；通用接口支持显式外部`inputs`并冻结其值 |
| `control` | 复用正式pause/resume/close；`close`表示结束当前运行，不是归档或删除会话 |
| `list_checkpoints / read_checkpoint` | 调用既有准确会话检查点元数据接口，不开放任意数据读取 |
| `fork_checkpoint` | 按原三个revision条件调用正式分叉，只初始化新会话，不覆盖源或自动运行 |
| 原回执观察 | 对原请求、操作和key核对已保存plan与native receipt；部分完成/unknown重放只读核实，不再次派发 |

独立模块可使用默认操作命名；可信适配层可传入自身命名、原请求、稳定子key和准确归属核对函数。核对在首次plan接纳时执行，派发释放服务锁后调用正式原语；同原请求再次调用只观察原plan及回执。没有另建调度器、会话值表或检查点存储。

[frontend_node_operations.py](../../../../backend/src/phase1_agent/frontend_node_operations.py)移出原create/start与pause业务编排，只保留准确W/R/N/S、注册项及目标许可核对，然后调用独立模块。旧start/pause的namespace、原请求、child key和四字段plan保持；旧回执无需转换。未知派发诊断按新归属命名为`workflow_operation_dispatch_unknown`，不改变unknown不重派的行为。

## 2. 实际入口与页面

[frontend_node_channel.py](../../../../backend/src/phase1_agent/frontend_node_channel.py)、[frontend_node_evidence.py](../../../../backend/src/phase1_agent/frontend_node_evidence.py)和[frontend_node_http.py](../../../../backend/src/phase1_agent/frontend_node_http.py)补齐：

- `resume / close`及其原请求、回执核实和接纳。
- `checkpoints / checkpoint`准确绑定只读入口，不接受会话、对象或节点替换选择器。
- `fork_checkpoint`窄命令，保留读取时的会话、data、head三个条件，冲突不自动重基。
- 分叉结果单独核对四个目标身份；返回同W/R/N、不同S的`next_owner`。原owner及原请求不改写，冷回执观察不依赖目标当前值。
- 状态按正式服务结果提供`can_resume / can_close / can_fork`；接纳暂停与实际安全暂停仍区分。

现有私有客户端、host及节点页面补齐继续、结束本轮、检查点选择/详情和分叉按钮。页面仍只调用准确节点channel，不获得通用工作流管理权。分叉后展示准确新绑定，用户接续后才绑定目标，不自动启动。未保存输入或待核实操作阻止页面发送分叉，已发unknown只能核实原请求。

没有新建能力连线、额外数字端口、全局保存定时器或浏览器业务存储。当前节点的200ms输入行为范围保持。

## 4. 最新语义与实际剩余

用户本轮进一步明确：

1. 重跑/重roll是同一用户消息所在回合重来。
2. 这一楼全部生成回复都是候选，例如五次生成的五条都要写入数据层并进入检查点。
3. 用户任选其中一条向下聊，其他候选仍保留；后续计算要消费所选候选对应状态。

[51号](51-重roll与候选独立功能勘察及待裁决-2026-10-15.md)已据此订正，文件名保留初次调查名称，原业务疑问不再待用户重复裁定。仍需形成准确实现合同的是回合起点、首轮前基线、完整候选集/选中值与所选计算上下文如何共同保存。

[52号](52-聊天数据检查点准入与分叉引用边界勘察-2026-10-15.md)调查证实旧`frontend-state@1`保存产物引用，直接装入无源历史的新目标会被`session_object_reference_denied`拒绝，并且没有候选业务表达。结合最新语义，建议独立逻辑聊天新类型保存用户消息、全部候选正文与选中身份，再成组接登记、写入/读取、展示、检查点及分叉。该类型合同尚未安装，也未先增加跨会话授权平台或schema半成品。

当前分叉入口沿现有白名单保存配置、Agent上下文和变量；**聊天与全部候选尚不能随点分叉**。操作入口交付不表示重roll/候选已交付，不恢复旧candidate.select或旧snapshot分叉。

没有操作产品数据库、启停产品服务、调用真实模型、提交、合并或推送。产品常用端口8765/8766/5178/5179复查无监听；临时HTTP、浏览器和测试进程均已结束。
