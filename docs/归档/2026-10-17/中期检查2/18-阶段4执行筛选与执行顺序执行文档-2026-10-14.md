## 3. 目标规则

1. 工作/非工作类别由可信节点注册声明承担。普通执行集中忽略非工作节点；显式交互仍按自己的准确入口、授权及目标调用，不因无普通图连线而被禁止。
2. 孤立排除与非工作筛选是两条规则。无上下游的普通工作节点不进入普通执行；有上游的无输出写入节点可进入，不在executor重复判断连接或激活。
3. 普通范围不能继续只用输出反向闭包代表全部工作节点激活。图内真实连接和依赖参与计划；输出存在仍是普通运行的必要结构要求，保存不以可运行为前置。
4. 实际数据依赖和用户显式控制依赖优先。每次从当前就绪节点中按创建次序串行选取，不按UUID、画布坐标、显示名称或端口输入排序选取。
5. 多输入端口的`edge.order`只控制输入值次序，不能成为无依赖节点的执行优先级。依赖双方的创建顺序倒置时，仍先执行依赖。
6. 不因共享变量或对象键自动激活节点、补依赖或报普遍无序错误。世界书等读取节点读取实际执行时的值；需要特定先后的业务图使用真实连线。
7. 不硬编码Agent A/B、上下文写回与聊天收尾的固定先序。权限、类型、CAS、实际写入冲突、结果接纳和原请求事实保持。

## 4. 最小实施次序

### 4.1 核清声明与范围

- 先列出实际参与的注册声明、普通compile与compile_event差别、生产计划消费者。类别是执行声明，不复用UI分类、不散落component ID黑名单。
- 给出最小声明形式及哪些生产节点需要改变。对已有声明的同版本不可变约束必须保留；不得静默改写历史descriptor、自动升级节点或迁移工作流。
- 节点具体分类、端口和主动交互入口尚未确定的部分明确留待后续节点审阅。可用隔离测试节点验证筛选核心，但不能据此声称生产变量注册交互已安装。
- 被过滤的非工作节点若成为工作节点输入来源，不自动穿透、造值或执行它；准确报告现有真实依赖缺口。若需要新增跨类别连接契约，先交用户决定。
- 事件执行保留准确目标、payload、scope及原回执；普通筛选与显式调用分开，不扩大事件目标，也不将普通输出替代事件目标。

### 4.2 形成稳定顺序

- 首选核实并复用`nodes`数组的持久相对创建次序，删除不改变剩余节点相对次序，复制排在原节点之后，移动不改序。这个选择只在全部真实写入/读取路径能保序时成立。
- 若现有路径不能保证上述语义，先报告实际缺口和最小表示方案；不要自行加创建时间、全局计数表或升版迁移平台。
- 在实际依赖图上生成稳定的串行就绪顺序；复用`GraphPlan`和`execute_graph`。不新增工作流层Agent引擎、并行调度或持久恢复。
- 核对编译诊断的受影响目标、executor祖先关系、`node_run_ids`、暂停继续的完成前缀与真实接纳都消费同一计划。

### 4.3 退出冲突门禁并联验

- 退出仅因共享对象读写而强制手工先序的门禁；保留对象绑定、类型、读写授权、CAS和接纳结果检查。
- 控制边格式仍有效。仅删除旧普遍业务门禁，不删除用户确实声明的先序，也不重写上下文/聊天/世界书示例。
- 明确列出实际改动、未接入的具体节点和残余关口。发现额外架构或未定契约时，报告原因、影响范围和效果，由用户裁定；不预建处理。

## 5. 聚焦离线验收

| 验收场景 | 必须证明 |
| --- | --- |
| 普通工作/非工作混合图 | 普通运行不执行非工作节点；类别来自可信登记，不是executor自判 |
| 孤立节点与终端写入 | 孤立工作节点排除；有上游、无输出写入节点确实进入真实运行 |
| UUID逆序、坐标变动 | 同时就绪按创建次序；依赖优先不受创建次序影响 |
| 新增、复制、保存重读 | 相对创建次序稳定；复制新身份，新节点排在已有节点后 |
| 同对象读写无先序边 | 不仅因对象共享被拒；实际顺序决定读取时值，权限/CAS冲突仍真实报告 |
| 显式控制边 | 保留实际先序约束，循环和真实缺失上游仍报告 |
| 多输入端口 | 输入`edge.order`保持，和调度次序相互独立 |
| 正式服务入口 | 新计划实际进入`ordered_nodes/node_run`及串行执行，不只是helper测试 |
| 显式事件与正常暂停 | 准确事件目标和payload仍有效；同进程暂停继续保持已完成前缀，不重放未知请求 |
| 管理/配置与安全回归 | 不完整图仍可保存；普通读取不构造执行；原回执、unknown和正常结果接纳不退化 |
