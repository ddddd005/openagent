## 1. 控件及实际效果

这些控件直接写在 `App.vue`，没有独立的工作流工具栏组件。

| 控件 | 实际动作 | 后端作用 |
| --- | --- | --- |

## 2. 新增及示例创建链路

```text
App 点击事件
  -> leaveEditor()
  -> persistence.flushAll() 保存所有表单及工作台
  -> createWorkflow() / createSerialAgentExample()
  -> newGraph() / 前端模板构造器
  -> registerWorkflowDraft()
  -> 写 graph.entries、登记 workspace.workflows、直接打开
  -> persistence() 与工作台保存观察器安排落盘
```

创建时：

- 工作流 UUID 在前端生成。
- 文档 `revision=1` 是首次保存的预备值，不代表后端已保存定义。
- 条目为 `saved_revision=0`、`session_id=null`、目录状态 `draft`。
- 新草稿直接打开，节点与连线选择清空，撤销历史初始化。
- 原工作流不会被替换、删除或自动重绑。

`registerWorkflowDraft()` 调用持久化但不等待返回值；工作台观察器也会在变化后安排保存。目录条目先可见，不等于该次创建已经确认落盘。失败通过工作台保存状态提示，创建方法自身只返回工作流 ID。

源码依据：[workflowGraph.ts:144](../../../../frontend/src/stores/workflowGraph.ts#L144)、[workflowGraph.ts:154](../../../../frontend/src/stores/workflowGraph.ts#L154)、[workflowGraph.ts:162](../../../../frontend/src/stores/workflowGraph.ts#L162)、[workflowGraph.ts:415](../../../../frontend/src/domain/workflowGraph.ts#L415)、[workbenchPersistence.ts:239](../../../../frontend/src/stores/workbenchPersistence.ts#L239)。

模板配方位于 [serialAgentDemo.ts](../../../../frontend/src/domain/serialAgentDemo.ts) 和 [tavernDemo.ts](../../../../frontend/src/plugins/tavern/tavernDemo.ts)，以确切节点及包版本构图。当前没有独立后端模板目录或模板创建服务。

## 3. 草稿保存与定义保存不是同一件事

| 时点 | 后端操作 | 效果 |
| --- | --- | --- |
| 新增及自动保存 | `draft.save` | 将目录、全部编辑图、当前选择和会话引用打包为工作台草稿 |
| 点击保存工作流 | `definition.save` | 写入工作流定义修订、节点绑定及节点声明记录 |
| 后续新建会话 | `session.create` | 为已保存定义创建持续会话状态 |
| 后续启动 | `run.start` | 根据会话绑定定义准备执行 |

工作台草稿地址为 `scope=management`、`kind=workbench`、`key=workbench:v1`，工作流和会话地址字段均为 `null`；不是每个工作流一个独立目录记录。

```text
draft.save
  -> /api/graph/commands
  -> GraphApplication
  -> GraphWorkflowService 继承的 GraphEditingHost
  -> LocalDraftStore
  -> SQLite local_editor_drafts
```

显式保存定义则由 `GraphWorkflowService._save_definition()` 校验修订并写图记录。空图或模型尚未配置的示例可以成为编辑草稿；创建成功不能等同于已经具备可运行的模型配置。

源码依据：[localDraftsApi.ts:29](../../../../frontend/src/adapters/localDraftsApi.ts#L29)、[graph_editing_host.py:62](../../../../backend/src/phase1_agent/graph_editing_host.py#L62)、[graph_drafts.py:246](../../../../backend/src/phase1_agent/graph_drafts.py#L246)、[workflowManagement.ts:59](../../../../frontend/src/application/workflowManagement.ts#L59)、[graph_service.py:234](../../../../backend/src/phase1_agent/graph_service.py#L234)。

## 4. 酒馆创建的额外路径

工作流区域的同名按钮只执行 `openSidebarSection('content')`。真正创建位于 `TavernChatPanel`：

1. 面板读取共享供应商和模型配置。
2. 按启用状态、协议及凭据引用筛选可选配置。
3. 创建时若选了已有配置，查询 `credential.status` 确认保存状态，不读取或填写 Key 正文。
4. 将全局模型配置引用写入前端模板，登记为草稿并打开，选中酒馆展示节点。

可以选择创建待配置流程。模板创建不会更改全局供应商或模型配置，也不会自动产生会话、执行节点或发送模型请求。

源码依据：[App.vue:220](../../../../frontend/src/App.vue#L220)、[TavernChatPanel.vue:17](../../../../frontend/src/plugins/tavern/TavernChatPanel.vue#L17)、[TavernChatPanel.vue:37](../../../../frontend/src/plugins/tavern/TavernChatPanel.vue#L37)。

## 5. 归档实际链路

顶部“显示已归档工作流”只是显示开关。条目右侧的归档及恢复才调用下列流程：

```text
App.archiveWorkflow(id)
  -> archiveState() 检查缓存会话和图锁
  -> 归档时确认保留数据
  -> persistence.flushAll()
  -> 再核对前端状态依据
  -> managementLabels.update({ kind: workflow, id }, { archived })
  -> formDrafts.stage() + flush()
  -> draft.save
  -> LocalDraftStore
```

准确语义是“本机目录隐藏标记”：

- 不删除、搬移或打包工作流定义、会话、运行历史、草稿及共享资源。
- 条目仍留在 `workspace.workflows` 和工作台快照中。
- 当前打开项不因归档而关闭或切换。
- 恢复只是把 `archived` 改回 `false`。

标记与显示名称一起保存为 `{ label, archived }`，外包通用表单的 `basis` 与 `raw`。`basis` 只有 `managementTarget`，因此草稿地址的工作流和会话字段为 `null`，关联身份放在 JSON 中由前端解释。

后端校验草稿范围、JSON、保存序号及幂等，不理解“工作流归档”业务，也没有在一个归档事务中核实会话状态。

源码依据（历史位置）：[App.vue:52](../../../../frontend/src/App.vue#L52)、[App.vue:68](../../../../frontend/src/App.vue#L68)、[managementLabels.ts:34](../../../../frontend/src/stores/managementLabels.ts#L34)、`formDrafts.ts:26`。旧表单壳后续已删除，当前状态见[38号回执](../中期检查2/38-阶段D后旧架构代码整理实施回执-2026-10-15.md)，本页不是当前入口要求。

这里的目录归档，与旧浏览器记录的原文归档、开发数据库离线归档不是同一种操作，不能用同一个“归档”词推导相同的数据效果。

## 6. 限制及跨功能影响

### 归档限制

`archiveState()` 使用前端已缓存的目标会话列表及所选会话。以下情况会阻止归档或恢复：

- 目标条目不存在、目标原请求待核实，或所选会话尚未读取。
- 已知会话 `can_submit` 为假，或状态为 `prepared/running/pausing/paused`。
- `graph.locked` 为真。

`graph.locked` 包含当前打开工作流的未决、复制及会话选择状态，还有全局提交忙状态。因此操作非当前条目也可能受当前工作流影响。状态核对来自前端缓存，不是后端归档业务事务。

### 新增限制

空图按钮及 `createWorkflow()` 不检查 `graph.locked`；串行按钮检查目录加载及空目录，方法额外检查目录错误；酒馆入口及 `createWorkflowDraft()` 则检查锁。

这是已确认的准入规则差异。是否允许某个会话运行或请求未决时创建另一份独立草稿尚待产品规则裁定，不能直接将规则差异登记为越权或执行故障。

### 全局保存依赖

新增和真实归档都经过 `persistence.flushAll()`，先保存所有表单，再保存工作台。不相关表单失败也可能阻止新建空图或隐藏目录条目。

源码依据：[App.vue:58](../../../../frontend/src/App.vue#L58)、[App.vue:86](../../../../frontend/src/App.vue#L86)、[workflowGraph.ts:49](../../../../frontend/src/stores/workflowGraph.ts#L49)、[workbenchPersistence.ts:129](../../../../frontend/src/stores/workbenchPersistence.ts#L129)。

## 8. 规范方向

这些操作属于应用层的工作流管理：目录负责创建、归档和恢复，模板提供初始图，草稿负责编辑持久化，运行服务负责执行。

本页记录当前特点和待讨论事项，不授权修改归档含义、直接删除数据、改动会话或引入第二套执行架构。后续按产品规则和明确模块边界逐项实施。
