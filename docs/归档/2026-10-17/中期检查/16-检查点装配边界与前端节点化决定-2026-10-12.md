## 1. 表单与配置收敛

沿用已确认方向：表单是节点配置的编辑界面，只保留当前输入所需的内存状态；取消独立草稿、应用到节点后再保存工作流等多阶段生效路径。固定/可调策略由工作流内节点持有，不是表单状态；初期按钮只做单条提示词条目，包含允许的 `context_once` 业务编辑，不扩展到提示词组或所有节点参数。恢复保留当前可调配置，并恢复节点注册允许保存的内容。

没有有效会话时原地保存；有未归档会话时，固定修改由后端判定需要派生，前端弹窗询问，同意后才创建不带原会话和历史的新工作流，拒绝则不写入此次修改。可调提示词原地保存。节点身份、类型、版本、连接及资源绑定保持固定。全局模型、供应商和内容仍由各自模块管理。

2026-10-12 用户补充第一步：通过节点内部按钮切换固定/可调，使用节点注册与现有扩展/宿主机制。按钮和字段编辑走同一正式配置提交入口，成功结果仍归原节点；不由应用壳硬编码另一个管理入口。初期只开放单条提示词，按钮切换本身是否触发派生确认仍待明确，不能沿旧建议自动裁定。

上一轮接口建议是文本失焦提交、选择和开关操作完成后提交、复合节点配置完整提交；后端根据实际变化判断保存或派生，返回正式结果后界面跟随目标工作流。完整提交不能把未变化的固定字段误判成固定配置修改，也不能将一次混合修改分别写入两个工作流。这些具体触发、粒度和接口表达仍是建议，尚未逐项确认或实施；与已确定的“自动提交、不做草稿”规则分开记录，详见 15 第 4 节。

## 2. 成功回合检查点

### 用户已确定

- 检查点形成于一回合成功结束、助手消息闭合且工作流结束本次运行的时点。助手文字已输出但后续工作流仍在运行，不满足这个条件。
- 该助手消息及其后面一条用户消息，都归属于该回合检查点。不能自行改成“用户消息及它后面的助手消息”分组。
- 用户随后明确：用户消息本身只提供输入，不独立形成计算后的运行状态或新检查点；回到历史助手消息或紧随它的用户消息，恢复同一个检查点。新的成功回合状态在后续助手消息闭合且工作流成功结束后形成。
- 回合执行途中、失败或中止不形成新的成功回合检查点；必要运行进度、输入和请求事实仍按现有归属保存，不冒充成功检查点，也不建设编辑草稿。
- 统一状态基线和 diff 的存储方向保持；初始状态基线不冒充已经完成的助手回合。
- 检查点类似存档，只保存成功回合规定的结果并提供固定恢复起点；形成后不随未发送输入、交互、工作流未启动时的修改或运行中变化更新。当前数据和未完成进度由节点、数据层及 runtime 维护，不归成功检查点管理。
- 检查点是唯一历史回溯权威，仅保存节点明确注册且允许保存的内容，以及数据层的上下文、变量和其他合规注册内容。输入和控制数据不作无差别扫描；具体声明、默认处理及初始检查点时点仍待收敛。
- 回溯建立独立会话时拷贝整份历史检查点，不以源 current/Head、原产物来源链、跨会话 history membership 或逐层事实证明作为恢复条件。检查点之外的不规范历史数据不补救。

### 时序与已确认恢复规则

以下编号以助手消息及其后续用户消息为一组，与用户最新说明一致；不是已确定的数据字段：

```text
初始状态 + 首条用户输入 -> 运行 1 -> 助手消息 A1 闭合且运行成功结束 -> C1
C1 的消息归属：A1，以及紧随 A1 的用户消息 U1
回到历史 A1 或 U1：都恢复 C1
C1 的完成状态 + U1 -> 运行 2 -> 助手消息 A2 闭合且运行成功结束 -> C2
C2 的消息归属：A2，以及紧随 A2 的用户消息 U2
回到历史 A2 或 U2：都恢复 C2
```

回到 A1 与回到 U1 不存在两份不同的运行状态快照。U1 是 C1 之后下一次执行的输入，保存或显示这条输入不生成另一个状态检查点。再次处理 U1 时复用该输入，不在聊天记录中重复插入一条 U1；生成新的 A2 候选并成功结束后，才形成对应的新成功检查点。

接口需要区分成功结束时的状态快照与随后提交的用户消息关联。U1 归属 C1，C1 的完成状态仍表示 A1 结束时的事实，不声称快照提前包含尚未发生的输入，也不为等 U1 而延迟生成 C1。首条用户输入之前尚无助手检查点，其起点使用初始状态基线。状态恢复归属已由用户确认，具体关联字段及事务一并在状态接口方案中给出。

按已确认边界整理的历史操作如下，具体命令和接线仍需核对：

| 操作 | 状态与执行起点 |
| --- | --- |
| 回到历史 A1 或紧随它的 U1 | 两者都恢复 C1，不为用户消息单独保存或恢复另一份运行状态 |
| 继续未完成运行 | 沿原运行已确认进度继续；不能因为没有新成功检查点就默认整回合重放 |
| 明确重来产生 A2 的回合，或为 A2 生成新候选 | 以 C1 的完成状态及其后属用户输入 U1 为起点；不以已经包含 A2 的 C2 为生成 A2 的起点 |
| 选择已有 A2 候选 | 采用所选候选对应的成功检查点；后续运行从该历史位置及其所属后续输入继续，选择本身不调用模型 |
| 从历史建立新会话 | 拷贝整份历史检查点，建立同工作流下自己的检查点和当前状态，之后独立；节点身份相同，不做节点映射或跨流改绑 |

用户消息的检查点归属不等于已经写入模型上下文。实际消息写入、上下文更新、成功收尾与检查点提交的先后，需要在节点数据流方案中给出。原已发送请求、已确认结果及其他历史分支不因重来或候选选择被追溯改写；未知结果请求不自动重放。

## 3. 可调提示词的装配边界

用户已确定：可调提示词只对其对接节点后续尚未装配的内容实时生效；在装配时求值，进入装配结果后，这份内容不再由提示词节点控制。

因此以装配是否发生为边界，不以“必须等下一回合”或“整个运行固定一份提示词”作为边界。同一未完成回合中，后续尚未装配的提示词可以采用当前已保存值；已经装配的材料、模型请求及历史上下文保持各自的实际内容。装配后修改提示词不自动重跑装配，也不追改其结果。

实现时须核对现有“先产生静态材料、后装配”的链路：不能让过早固化的节点输出继续成为后续装配的唯一旧值来源，也不能通过改写已接纳输出来伪装实时。求值接口和相应节点/端口调整在具体方案中说明。

`context_once` 按 39 改为装配依据当前上下文实时检测，不另建检查点 once 台账或消费账本。检查点维护规定上下文，恢复保留当前可调配置，不追证旧请求。必要上下文来源信息、压缩后检测方式及具体字段仍须收敛，旧消费 ID/pending 机制不能直接作为新安装方案。

## 4. 模型配置与压缩触发

### 用户已确定

- 尽量在模型配置模块集中管理模型相关设置，工作流不再维护一套模型参数副本。
- 可调参数界面收敛为思考强度、上下文长度、压缩阈值、输出上限。温度及其他旧参数不继续作为本轮要求保留的可调项。
- 上下文长度限制用于触发，可以默认采用模型配置容量，也可以调低于模型配置容量；降低触发基准不等于降低模型真实容量。
- 用户补充确认：压缩阈值表示达到多少上下文占用时开始压缩，不表示压缩后的目标长度。
- 同一模型配置引用下允许切换协议或能力；后续新请求采用当前配置，已有请求保持原事实。

这里的“引用”指模型节点指向一份已保存命名模型配置的资源标识，不是工具调用。身份不变可以更改该配置的模型、协议或能力；改为引用另一份配置，仍属于节点资源绑定变更，按固定定义规则处理。

四项是运行参数界面的精简范围。模型选择、配置名称及供应商地址、Key 等分别承担身份或连接职责，不能因为四项清单就删除必要连接信息；也不把它们复制到每个工作流。此划分与已有供应商管理归属一致。

### 需要给出的具体接口方案

建议模型节点只传达配置引用及必要授权，单次新请求取得一致的当前设置，预算、压缩判断和通信使用这一份依据。普通请求和压缩请求各自在自己的新请求边界读取；“一致”指单次请求内部一致，不要求整个 Agent 运行始终沿用首个请求的值。

本页早期关于“阈值采用比例还是绝对数量”的讨论已被后续确认的三项默认值覆盖：上下文长度 `300000 tokens`、压缩阈值 `0.85 = 85%`、输出上限 `32000 tokens`，不重新作为方向待选。必要请求计算和消费者适配按 40 收敛，不擅自增加压缩目标等更多用户参数。模型真实容量和输出约束仍按实际请求检查，不能把压缩触发器当作上游容量保证，也不能静默裁剪、换模型或猜测补全。

协议和能力切换需要现行消费者、请求投影和通信入口共同适配；不能仍由旧的固定协议节点或旧能力快照悄悄限制该方向。遇到真实不支持直接报错，不自动降级或改变旧请求事实。公开绑定字段、版本和受影响消费者需要形成可审阅清单，不将方向确认写成改造已经完成。

## 5. 前端能力节点化与序号

用户已确定：大部分现有节点保留，将部分端口表达的能力提升为节点；前端所需的运行接口尽可能作为工作流内部节点注册，不由一个长期存在、跨工作流复用业务状态的前端实例持有。

按既有管理边界落实：每个节点绑定自己的前端实例，输入、输出、展示上下文及运行交互归对应工作流和节点，会话数据归对应会话；复制节点的新实例绑定复制后的节点，不继续向原节点发操作。组件代码、类型声明和渲染宿主可以复用，实例和业务状态不共享。切换目标后的迟到结果仍归原对象，不覆盖当前另一实例。全局资源和应用壳继续独立。

29 进一步明确前端注册、端口/页面激活、用户输入、运行开关、重 roll、分叉和功能映射的节点化能力范围。后端节点维护以数据层为基底、每回合更新的展示上下文；页面无独立正式数据。未发送输入经 200ms 自动通信并被后端接纳后已是节点数据，未进入后端的临时部分刷新或崩溃丢失不建设恢复副本，也不恢复独立草稿机制。

上下文及变量显式引用、读取或导入数据层内容，成为运行时值后消费或编辑，结果明确写回。Agent 执行器与内核归节点内部，不单列工作流层；工作/非工作节点统一注册，runtime 过滤普通执行中的非工作节点但保留显式交互调用。

具体端口转为哪些节点、哪些现有节点复用，以及消息/上下文更新和成功收尾的连接，必须通过现有节点盘点形成具体方案。本轮没有批准一份尚未列出的节点增删名单，也不将所有数据端口机械改成节点。

节点序号从工作流中的节点创建开始分发，只负责排序，不是唯一身份；UUID 继续承担节点身份。依赖优先，同批就绪节点按序号串行的规则保持。用户本轮未指定手动改号或排序编辑界面，不擅自增加这类交互。
