## 2. 严格声明语言

以下是直接约束后续 JSON Schema 的精确记法，不是“实施时自由增字段”：

- `Obj{...}`：Draft 2020-12 object，所列全部字段 required，`additionalProperties:false`。`List(T,n)` 是最多 n 项数组；标注 unique 的列表不得重复。
- `U`：规范 UUID4 小写字符串；`N0/N1`：严格整数，分别从 0/1 至 `2^53-1`，不接受 bool。`Name`：复用 host `bounded_name`。`Key`：1-128 字符且非全空白的原 idempotency key。
- `Digest`：`json-v1:sha256:<64个小写hex>`；输入正文摘要唯一算法为既有 `content_digest({"text":text})`，不另造 UTF-16、trim、换行替换或裸字符串摘要。
- `Text`：字符串，最多 1000000 个字符，并继续通过既有 canonical JSON/对象字节上限；不因输入自动保存新增无限正文。
- `JSchema`：合法、完整的 Draft 2020-12 JSON Schema；本页操作使用下表精确 `Obj` 展开，不能用 `{}` 或开放 object 代替。业务 schema 不允许外网 `$ref`。
- `ArtifactRef=Obj{scope:"artifact",output_id:U}`；`InputRef=Obj{scope:"submitted-input",workflow_definition_id:U,workflow_session_id:U,input_id:U}`。后者原 session 是出处，不是目标读许可。
- `Owner=Obj{workflow_definition_id:U,fixed_definition_revision:N1,workflow_session_id:U,node_binding_id:U}`；`Basis=Obj{session_revision:N1,head_revision:N1,checkpoint_id:U}`。
- `ObjectReceipt=Obj{object_key:Name,revision:N1,revision_id:U,deleted:boolean}`，保持现有真实对象 receipt shape。

所有声明和请求都按 exact keys 检查；上述上限沿用当前宿主规模，不建立新的容错/重试框架。

## 3. 历史 Runtime Traits 1 提案

现不批准原全面保存/reset表达、独立once台账、历史核验证据或额外必存分区。只按两类允许保存内容重新收敛注册声明；本节原exact字段保留参考，不直接实现。

### 3.1 唯一形状

```text
Obj{
  schema_version: 1,
  kind: "workflow.runtime-traits",
  component_id: Name,
  component_version: Name,
  execution_class: "work" | "non-work",
  interaction_operations: List(InteractionOperation, 32),
  runtime_checkpoint: Obj{
    include: boolean,
    restore: "saved" | "reset-default",
    object_fields: List(Name, 32) unique
  }
}

InteractionOperation = Obj{
  operation_id: Name,
  operation_schema_version: 1,
  mode: "query" | "command",
  audiences: List("management" | "consumer", 2) unique,
  basis_fields: List("session_revision" | "head_revision", 2) unique,
  service_requirement: Obj{
    service_id: Name,
    exact_version: Name,
    capability: Name,
    operation: Name
  },
  payload_schema: JSchema,
  result_schema: JSchema
}
```

旧提案当时约束如下：

1. identity 是 `(component_id,component_version,schema_version=1)`；一 node export 必须恰有一个同包的 traits export。声明缺失、重复、未知 exact component、同 identity 改正文直接拒绝，不给默认 work/non-work。
2. 本批 work 节点 `interaction_operations=[]`；non-work 的所有 port mode 均无普通输入/输出，`is_output=false`，无 graph executor/executor_ref。non-work 有准确交互 handler，不能用 catalog `executable=false` 推定它无法交互。
3. 每个 operation ID 在一个 component 内唯一，audiences 非空且排序固定为 management、consumer；query 的 basis_fields 为空，command 精确为上述两项。payload/result schema 与 service 声明的 request/response schema canonical 相等。
4. operation 的 capability 必须在该新 `NodeDefinition.capabilities`，准确 service requirement 必须在它的 `service_requirements`，并通过现 grants 核对；query 不包含写 capability，不能因包装名含 query 就执行写 handler。
5. `include` 仅表示该节点业务 private payload 是否进入 checkpoint 的 `node_states`；`true` 必须配 `restore:"saved"`，`false` 必须配 `restore:"reset-default"`。它不控制整个对象库、program/history 或 unfinished frame。
6. `object_fields` 仅取本节点已有 `object_accesses.config_field` 的完整显式键；必须与该 access 类型/schema/multiple、固定 object binding 一致。不存在任意 JSON path、通配符或从 payload 猜 UUID。多节点声明同一个 object_key 去重，类型/版本不一致拒绝。
7. 成功投影只从当前固定 revision 的全部 traits 所声明的对象键取 typed 正文，包括 non-work 注册能力所负责的变量对象；不从本次计划的 work 子集推断。31 的完整 `program_state.values/data` 和精确 history 是统一结果分区，不复制为每节点声明。

本批全部节点原 private 默认为空且无已声明成功后私有业务存档；因此表中的 `include=false/restore=reset-default` 是**本次具体提案**。上下文/generation/once 保存在明确 effective-context 对象与其不可变产物，不把执行现场纳入 private checkpoint。若未来节点新增成功后的私有业务状态，必须新 component/traits version 后审阅，不能给已发布版本偷偷改 include。

### 3.2 Reset 不回退 CAS

输入节点新 private schema 1 精确为 `Obj{text:Text,input_sequence:N0,submitted_input_id:U|null}`，默认 `{"text":"","input_sequence":0,"submitted_input_id":null}`。instance private schema 1 为 `Obj{registered:boolean}`，默认 false。其他本批节点保持各自原声明的空 private default。

新会话当前节点默认值必须按该固定定义的全部准确node/traits初始化，包括non-work input/instance；不能只从普通work计划的definitions取得默认值而漏掉它们。初始化与31的C0同事务，只做注册schema/default与真实owner核验，不执行交互handler、变量注册、模型或工具，也不以ordinary图可运行为会话初始数据写入条件。C0仍按明确成功投影排除输入/控制，当前默认数据另在原node_session3中存在。首次入口何时申请这个所属会话仍留E用户流程审阅。

`input_sequence` 是该输入对象乐观并发依据，不是待恢复业务值。恢复输入的 `reset-default` 明确写 `text=""`、`submitted_input_id=null`，但从当前值将 `input_sequence` **加一**，不得写回初始 0；同时按 31 前移实际 session/Head CAS。回执列 `reset_node_ids` 及实际新输入 sequence。正常 `input.save` 每次首次接受也增加一次 input sequence；`input.submit` 不改 text/sequence，只记录该正式版本所提交的 input ID。

这不新增第二个 current-state 表，不恢复 `data_version`，也不回退对象/变量 revision。`reset-default` 针对业务默认值，不意味着重置数据层的真实并发包络。instance 的 registered 控制数据不存入成功点，恢复设 false；后端按当前固定映射重新 query/register，不保存浏览器连接或 TCP port。

### 4.2 结果与权限

各操作 result 共用：

```text
Obj{
  schema_version: 1,
  kind: "workflow.node-interaction-result",
  operation_id: Name,
  operation_schema_version: 1,
  owner: Owner,
  basis: Basis,
  value: <第5节该操作的exact对象>
}
```

application 外层继续既有 `workflow.application-command@1/application-receipt@1`，receipt 的 accepted 是上面完整薄结果，不是整份 session/private state/facts。相同原 request/key 回原结果，绝不再次创建 input/会话、reset、派发或写对象；同 key 异 body 拒绝。unknown 只查这一准确原身份，缺回执不能证明没接受，也不能自动重发。

后端核对 workflow/session/current fixed revision、component/traits、scope/audience、实际实例与固定 mapping、归档状态、当前 session/Head CAS，再 dispatch 精确 handler。错误 node ID、source UUID、页面 can_submit、知道 operation 名称都不授能力。management 可以按正式 node declaration 调用；consumer 只能调用 `frontend.instance` 自身的 bootstrap/query，或已 registered 实例的准确 function mapping，其 target schema/audience 与 traits 必须一致。

人工 runtime mutation（input.save/input.submit/variable.register/register 的控制写）均拒绝任何 unfinished active chain，包括 prepared/running、暂停请求未确认、paused、budget_exhausted、archive_failed；没有“下一轮输入队列”例外。run.control 是明确管理 active progress 的例外，按本操作 action 检查；history restore/select/fork/restart 要求无 active chain，必须先显式 close/确认。可调配置及资源/Key 表单不是这些操作，不能由本门禁锁死。

非工作操作不造 node_run/chain_run/workflow_output，不出 graph port。run.start/restart 转交现 runtime 准备路径时才创建真实工作 chain；后续 pause/progress 是它自己的实际执行记录，不是交互用的虚构 producer。

### 7.3 创建顺序和配置响应

creation_sequence仅服务器排序metadata。新增节点从 `next_node_sequence` 分发，批次依本次已提交完整document中新UUID出现顺序；同流旧UUID不变，复制分新UUID、新序号，删除空位不复用。禁止重引入本工作流历史revision中已退役UUID；检查原正式bindings，不建设额外tombstone/order表。

固定修改派生新workflow保留相同UUID的相对序号和源next counter，新节点从该counter开始；只继承固定定义元数据，零session/history/fact membership。初建模板从1按显式模板顺序分发；不从rowid、UUID、时间、页面当前数组或旧产品补算。

现 [workflow.configuration-result@1](../../../../frontend/src/domain/workflowConfiguration.ts#L66) 是strict字段集合；SDK2 的 [submit/accept signature](../../../../frontend/src/plugins/workflowFrontendSdk2.ts#L25) 和host2消费该准确结果。为不扩大配置保存协议，本提案**保留result1和已有SDK2/host2准确语义**，不加序号字段、不增host3，也不把排序放入current adjustable配置。32“回执返回序号”仅是先前待审建议，收敛为下述独立只读正式元数据查询。

新增只读 `definition.order.read`，exact参数 `Obj{workflow_definition_id:U,fixed_definition_revision:N1}`，result `Obj{schema_version:1,kind:"workflow.definition-order",workflow_definition_id:U,fixed_definition_revision:N1,node_creation_sequences:<UUID->N1>,next_node_sequence:N1}`。只返回当前正式definition/bindings服务器记录，并核对sameowner和唯一序号；无写号命令，不能用页面自报mapping编译执行。

页面接纳原result1后，按其实际workflow_definition_id/definition_revision读取该准确fixed revision的排序元数据；query结果的workflow/revision必须和被接纳文档一致，迟到元数据只归捕获的原owner。读失败直接报告“排序元数据读取失败”，不能撤销已真实成功的配置保存、自动重交保存或把旧数组推测成序号。ordinary runtime直接从服务端binding3编译，不等页面查询成功。这个查询既可用于已存在正式定义的编辑页面，也可用于原保存receipt完成后的显示，不成为保存/派生的新增提交阶段。

## 9. 历史 Runtime 具体调用提案

28的真实依赖、集中筛选和成功时点行为保持；本节exact traits/记录/closure/集中映射字段尚未最终收敛。恢复只用完整检查点，不需要为旧产物和历史模型事实逐层追证。

普通run的scope确定为：先取得同fixed revision的可信节点/traits/sequence，排除non-work；普通数据或control edge的任一端为non-work直接契约错误，显式interaction/config mapping不算普通连接。排除无任何work数据/control上下游连接的孤立work，再纳入剩余connected work的全部实际节点，包括仅有上游、无输出的writers及各真实connected component。`execution_roots/is_output`不能让孤立节点越权进入，也不能漏掉side-effect sink。

按现runtime准备/节点接受事务保存真实inputs/outputs/reads/effects；工作节点不能从non-work旧产物冒充同chain accepted producer。变量register不自动执行，assign不重复激活判断，Lorebook执行时读已授权当前值；不以共享object key补硬控制边。无真实依赖的同对象写者仍串行，各自read/basis/CAS不一致直接报冲突；不得为“帮它成功”重新读取后改原冻结input。
