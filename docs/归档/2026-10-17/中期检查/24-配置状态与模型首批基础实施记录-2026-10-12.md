## 2. 配置正式读写

实现主要在 [workflow_configuration.py](../../../../backend/src/phase1_agent/workflow_configuration.py)、[graph_service.py](../../../../backend/src/phase1_agent/graph_service.py)、[graph_contracts.py](../../../../backend/src/phase1_agent/graph_contracts.py)、[graph_store.py](../../../../backend/src/phase1_agent/graph_store.py) 和 [storage.py](../../../../backend/src/phase1_agent/storage.py)。

统一请求为：

```text
definition.update {
  workflow_definition_id,
  document,
  expected_edit_sequence,
  idempotency_key
}
```

可通过既有 `/api/graph/commands`，或新增 `/api/graph/definitions/update` 提交。只允许管理 scope；不接受客户端自报变更类别或可调能力。提交 schema 3 必须有节点 `configuration_policy`。

- 初建固定修订/编辑序号为 `1/1`，请求编辑序号为 `0`。当前正式文档附带只读 `edit_sequence`；提交时若携带该字段，必须与请求编辑依据一致。
- `unchanged` 不增长；可调及显示修改仅增长编辑序号；没有有效会话的固定修改同时增长固定修订和编辑序号。
- 写事务内查询源工作流全部未归档会话，包括未执行会话。有任一有效会话时，固定或混合修改整体派生。源定义、current、会话和运行数据不变，新目标没有会话或运行数据。
- 派生目标从 `1/1` 起；返回 `source_has_effective_session`、实际目标文档和全部目标节点的 identity mapping。节点 UUID 沿用，身份仍须带工作流。
- `changed_categories` 按 `display / adjustable / fixed` 顺序返回。节点数组顺序属于固定正文，不在保存时重新排序。
- `definition.read` 未指定 revision 和 `definition.list` 合成 current 配置；指定 revision 读取完整不可变历史 seed。当前可调值的唯一权威为 `workflow_current_configuration`。
- 首批能力仅允许精确 `prompts.item/group@3` 可信声明。包缺失时可使用此前服务器保存的可信 descriptor；没有可信声明只能 fixed。保存不 compile，也不要求执行器、模型或执行输入可用。已提供的提示词字段保留格式校验，缺少执行必需字段可以保存。
- schema 3 新会话只允许绑定当前固定修订。旧 save/copy/rebind 不能绕过 current 配置权威。删除工作流时，在其删除事务内按精确 ID 删除 current 行；删除会话不删除共享配置。

前端尚未切换，原有 schema 1/2 路线维持其原入口，没有添加迁移、自动升级或旧格式转写。新 schema 3 只经 `definition.update` 创建和修改，不能用旧入口制造缺少 current 的定义。原路线在前端及整体替代时退出；本批不称旧图架构已退役，不安装两套新节点或执行服务。

正式回执接入 [graph_application_contracts.py](../../../../backend/src/phase1_agent/graph_application_contracts.py)、[graph_application_identity.py](../../../../backend/src/phase1_agent/graph_application_identity.py)、[graph_http.py](../../../../backend/src/phase1_agent/graph_http.py) 和 [graph_receipts.py](../../../../backend/src/phase1_agent/graph_receipts.py)。核实结果使用原请求及已保存的 native/application 证据，验证实际目标、文档、类别、序号和节点映射，不依赖今天的 current 值，也不重放请求。

## 3. 运行消费事实

[graph_records.py](../../../../backend/src/phase1_agent/graph_records.py) 保留 binding 与不可变定义完整 seed 的一致性。固定模式的 run 仍核对完整 config；可调模式以原定义策略和准确持久化 descriptor 核对固定投影，并验证历史实际消费配置。不会拿今天的 current 可调值判断昨天的 run。repository bundle 同时提供精确可信 node_definition。

[graph_execution.py](../../../../backend/src/phase1_agent/graph_execution.py) 的 retained result 使用 `pending.basis.config`，继续核对固定投影及完整 inputs、input_refs、state、private、objects 原依据。接纳重试保留原消费配置和原结果，不重复 executor 或通信；`node_run.config` 仍不可覆写。

这只是事实校验及准确接纳重试基础；尚未改变生产调度读取 current 的时点，尤其没有实现“旧静态材料生成后、尚未装配时求新值”。该行为仍依赖 D 的惰性引用及消费者接线。

## 4. 状态与模型纯基础

[runtime_checkpoints.py](../../../../backend/src/phase1_agent/runtime_checkpoints.py) 新增：

```text
validate_runtime_state(state)
validate_state_storage(storage)
validate_checkpoint(checkpoint)
make_diff(parent_state, state)
materialize(checkpoint_id, load_checkpoint)
```

`make_diff` 返回 `upsert/delete`；调用者提供 full baseline ID 并封装 diff。节点 envelope、program values/data、typed objects 和 history 完整保留；业务 null、typed tombstone 和删除分开。物化只沿目标 parent 链，验证同 workflow/session/固定修订、initial full 根、diff base、缺失父点和环。CAS revision 不进入逻辑恢复正文；业务计数和正文 generation 保留。注册类型正文、artifact 闭包、权限和当前事务写入仍属于后续生产恢复边界。

[model_request_contracts.py](../../../../backend/src/phase1_agent/model_request_contracts.py) 与 [model_request_budget.py](../../../../backend/src/phase1_agent/model_request_budget.py) 交付 M1。默认四参数中的三项数值为上下文 `300000`、比例 `8500` 万分比即 `0.85`、输出 `32000`；context 为 null 时取实际窗口，摘要输出 `S=min(O,1024)`。触发按 `I+O >= ceil(B*q/10000)`，硬容量按 `I<=K && I+R<=C`，两者分别校验。

可信 transport fixture 明确型号、协议、输出上限、声明版本和来源；缺声明或准确匹配失败即拒绝，人工 capacity 不能替代可信输出能力。测量使用传入的实际 prepared wire，并标注 estimator；同设置压缩证明核对 projector 版本、estimator、tools、普通输出预留及容量。四操作为 prepare/dispatch/discard/measure-context，仅声明而未安装。M2 仍负责把测量绑定到准确授权 preparation、投影器及其生命周期。

现行模型 reader、UI、服务、节点和旧 8192 限制没有切换。真实供应商上限尚未登记；后续安装前按官方资料核验，不以合成容量作为真实模型能力。
