## 3. 状态基础与完整切换的分界

首批接口为 `validate_runtime_state`、`make_diff(parent_state,state)` 和 `materialize(checkpoint_id,load_checkpoint)`。使用 18 第 6 节的 node_states、program values/data、objects、history；节点 owner/schema envelope 完整保留，四个映射分区按键整项替换，history 变化时整项 upsert。明确区分业务 null、对象 tombstone 和 delete；验证 full 基线、parent 链、owner、固定修订及分支一致性。事务/CAS revision 不混入可恢复业务正文。

首批只交付这些契约和纯函数及必要验证，不接生产 checkpoint/Head，不把现有 snapshot/manifest 指针称为完整状态。完整切换必须成组包含：

- 正文及不可变 artifact 闭包物化，复用 [注册引用遍历](../../../../backend/src/phase1_agent/graph_runtime_host.py#L234)，核对每个必要 artifact 的 workflow/membership；不存在的正文或越权引用直接失败。
- 工作流拥有不可变 runs/outputs/model facts；会话拥有当前状态、关联、checkpoint parent 链与 membership。同步修改 [bundle 活源会话假设](../../../../backend/src/phase1_agent/graph_records.py#L251) 和源会话删除范围，不能只改 fork 响应。
- 沿用 `expected_session_revision + expected_head_revision`，变量/对象保留自己的 CAS，不新增 state_sequence。历史业务值恢复后取得新的当前写入序号。
- D 的输入节点消费稳定 input_id/entry_id，收尾提供准确助手 `entry_id/source_ref/run_id/receipt`。成功检查点、助手关联、Head 与 chain succeeded 在同一事务接纳；close/失败只写 progress boundary。
- restore/restart/select/from-history 共用同流状态恢复入口，保留当前可调配置、真实历史出处和未知请求证据。准确 retained result/retry_archive 不重新运行节点或模型。

当前 append 按 node_run 生成消息身份，且 finish/close 都会写 commit，见 [聊天身份](../../../../backend/src/phase1_agent/tavern/chat_contracts.py#L180)、[完成事务](../../../../backend/src/phase1_agent/graph_service.py#L1013)、[close](../../../../backend/src/phase1_agent/graph_service.py#L1147)。D 具体节点/端口及成功证据仍需整体审阅，不能先删 close commit 而缺失进度依据。

| 缺口 | 推荐具体决定 |

| transport 输出能力 | 在受信任 transport capability 中登记准确型号匹配和输出上限来源/声明版本。缺少声明直接拒绝准备，人工 model.capacity 不能代替安装能力。M1 用合成声明验证；真实数值在安装前按供应商官方资料单独核验，本文不猜测或授权查询 Key。 |
| live/history 事实授权 | live merge 从精确已接纳 context 输入授权；历史从已获授权的 view/object artifact 闭包沿 update_ref 追溯准确 Agent、binding、receipts 和模型 facts。两入口共用纯验证器及只读宿主 callback，不接受任意 UUID，不实例化旧服务帧或可派发 lease。 |

拟确认的新增参数语义为：runtime 四字段、比例存储 `8500` 万分比、context 为 null 时沿用真实窗口、摘要规则 `S=min(O,1024)`。三项默认值不再待选。触发 `I+O >= ceil(B*q/10000)` 与硬门禁 `I<=K && I+R<=C` 分开；估算来自实际 wire，标明 estimator，不声称上游精确 tokenizer。

source 7、chat 5、execute 9、context 三节点 5，models 服务 2.0.0、context 服务 4.0.0 及 19 的 facts/update/receipts 版本方向保持。最终端口、grants、exports、包依赖与 D 一次对齐后安装，不能先发布临时 context@5 再覆盖声明。
