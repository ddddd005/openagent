## 2. 配置前端契约与回执

[workflowGraph.ts](../../../../frontend/src/domain/workflowGraph.ts) 增加 schema 3 和节点 `configuration_policy`、`edit_sequence` 类型及严格存储校验。不可变历史 seed 可以没有编辑序号；正式 current 必须有正编辑序号。保存校验只负责存储格式，不要求缺失包可用，也不把运行时循环或资源检查前置为保存门禁。

校验与后端统一 Unicode 码点计长，拒绝孤立 UTF-16 代理码和非 JSON 值，包括 NaN/Infinity、undefined、getter、自定义对象或 `toJSON` 转写。旧 schema 1/2 解析保留，`newGraph` 仍创建 schema 2，没有自动升级或将 schema 3 降级的入口。完整事件 JSON Schema 和 canonical 4 MB 上限仍由后端最终裁定；前端不仿造 Python 数字序列化摘要。

新 [workflowConfiguration.ts](../../../../frontend/src/domain/workflowConfiguration.ts) 定义正式 document/request/result。请求严格只有：

```text
{workflow_definition_id, expected_edit_sequence, document, idempotency_key}
```

完整结果必须与捕获的原请求核对实际目标正文、全部节点 identity map、固定修订/编辑序号、原地/派生关系、类别及 `session_id:null`。类别仍由后端事务权威判定，前端不自行推测可调修改或有无有效会话。

[workflowApplicationApi.ts](../../../../frontend/src/adapters/workflowApplicationApi.ts) 接入 `definition.update` 和对应 accepted-result 字段。新 [workflowConfigurationApi.ts](../../../../frontend/src/adapters/workflowConfigurationApi.ts) 通过正式 commands 提交；`readGraphConfigurationReceipt` 只读原请求回执，既不重放提交，也不读取今天的 current 来解释原结果。捕获的原请求及返回值都复制隔离。

## 4. 模型 M2 当前资源授权读取

新 [model_request_resources.py](../../../../backend/src/phase1_agent/model_request_resources.py) 的 `ModelRequestResourceReader` 由 trusted host 注入冻结 TypeRegistry、准确 model source 组件和 authority loader。authority loader 必须使用同一个 connection 读取真实 session、chain、consumer/producer run、accepted output 及冻结节点声明，不能由客户端提供授权事实。

三项接口为 `authorize_binding`、`read_resource_bundle` 和 `check_resource_bundle`：

- SQLite 使用 URI `mode=ro` 和 `query_only`，当前 profile/provider 从一致只读事务取得。
- 核对运行 owner、active chain/next node、精确 model input output、producer、source root，以及 consumer 的准确 service/version/capability/operation grant。
- 只沿可信 profile 2 的当前 provider reference 读取 provider 3，核对既有 TypeContractStore 已接纳声明；profile 改绑新 provider 后，下一请求可以沿新依赖读取，不扩大初始全局资源白名单。
- 捕获后仅检查实际已读取 bundle 的两项 revision heads。helper 不取得 Key 或 lease，不保留资源正文，也不跨网络持有事务。

该模块未注册到生产服务或节点。51 项 reader 测试及联合验证都使用独立临时数据库。

## 5. 模型 M2 请求生命周期

新 [model_request_service.py](../../../../backend/src/phase1_agent/model_request_service.py) 的 `ModelRequestService` 使用 M1 四操作契约，并由 trusted host 注入 binding 授权、资源读取/核对、broker、transport resolver 和 fact acceptance。`ModelRequestTransport` 留存准确可信能力、projector 版本及 callable、当次 factory 和可选精确 counter。

同一逻辑键先核对原 intent 和授权，再判断已有准备/结果；旧键不读取最新 profile、不重新投影或派发。只有新键读取当前 bundle，捕获私有 lease 后核对一次资源修订，发生换代即拒绝，不循环读取。公开 settings、binding、结果和 facts 不含 Key、lease 或私有 address。

派发使用原 settings/wire，factory 前及紧邻通信前核对原 lease。transport 关闭，`max_retries=0`，一个准备只通信一次。request/attempt/outcome 事实使用固定预分配 IDs 和序号 1/2/3；prepare/discard 不产生已接纳模型事实。未知、上游错误、非法回应及未派发分类不能自动换键重发。

原 outcome 接纳失败或已提交但回执丢失时，只重交原事实，保持原 fact IDs、settings 和回应，不再通信。释放运行先阻止新 prepare/dispatch；已持久 unknown facts 不随私有准备释放而删除。清理失败报告受控错误码并保留待释放私有引用，不能丢原结果/事实，也不能通过释放重试模型请求。

摘要后的普通上下文 measure 使用原 settings、projector、counter 和普通输出预留 O，不读取新资源、不捕获 lease、不通信、不新增 facts。tools 的压缩前后相等由 M1 reduction 证明核对；普通测量 tools 不必等于可使用 `tools=[]` 的摘要请求 tools。

用户指定 `300000 / 0.85 / 32000` 在新契约及合成请求中验证。现有生产模型 reader、UI、服务注册、节点和旧 `8192` 限制尚未切换；不把合成能力视为真实供应商上限。
