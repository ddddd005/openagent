# 调试说明

先确认实际源码与运行，再分类失败，最后按当前许可处理。刷新页面、读取历史、重发请求和恢复原执行不是同一种操作。

## 启动身份与证据

根 `start.bat` 选干净 `main`，默认后端/工作台 `8765/5178`；`start-dev.bat` 选当前 `develop`，默认 `8766/5179`，两者数据库和浏览器 origin 独立。推送代码不更新已启动进程，端口能响应也不能证明正在运行当前 HEAD。

记录触发步骤、完整 Git SHA、启动源码/数据库路径、端口、定义 ID/修订、会话 ID、`chain_run_id`、`node_binding_id`、实际 `node_run_id`、时间和错误码。API 中部分参数使用 `session_id/chain_id/node_id` 短名，归属坐标使用完整字段；不可混用不同会话/尝试的证据。

| 入口 | 用途 |
| --- | --- |
| 后端/前端可见控制台 | 服务错误、Vite 代理、启动和依赖问题；默认 BAT 不产生新的 resident 日志 |
| `.local/service-starts/<launch>/services.json` | 选中源码、数据库、端口及有创建时间/命令行的进程身份，位于实际服务工作区 |
| 浏览器 Console / Network | 实际请求 origin、HTTP 状态与页面异常，导出前脱敏 |
| 工作台运行、节点诊断 | 激活计划、输入、冻结依据、产物与当前许可 |
| 信息读取与运行事实 | 精确 owner 下的请求、响应、工具、接纳及错误事实 |
| 会话对象、公开结果及检查点 | 确认实际写回和正式交付，而非只看模型正文 |

旧 `.local/resident/run/` 只作先前安装/部署证据，不是当前 BAT 默认来源。日志不是完整账本，目录里有某声明也不证明本次执行绑定了它。若能力包提供失败新尝试，查看 `node_run_attempts`，区分旧失败与当前尝试；当前原生 Agent 不提供旧失败节点重试策略。

## 最小定位顺序

1. 检查 `GET /api/health` 和 `GET /api/graph/node-types/v2`；核对启动 metadata、默认 44 声明/41 家族及实际包锁。健康响应 `status: "ok"` 只表示服务正常，不保证工作流不会联网。
2. 核对定义修订、会话和 chain，确认保存完成，没有原请求待核实；草稿不能代表运行冻结内容。
3. 查看首个失败节点及 diagnostic，分清编译/资源预检拒绝与实际模型/工具派发。
4. 查看实际输入、模型资源/参数及请求事实；串行示例核对 A/B 本轮材料，不凭节点标题推断正文。
5. 检查结果是否接纳、上下文 merge/聊天对象是否写回、presentation 和完成检查点是否成立。
6. 读取 `available_actions` 再操作；后端会复核修订、owner 和原现场，曾亮起的按钮不等于永久授权。

| HTTP 入口 | 用途 |
| --- | --- |
| `GET /api/graph/sessions/{session_id}/runs/{chain_id}` | 读取确切运行历史 |
| `GET /api/graph/sessions/{session_id}/actions` | 读取当前管理侧动作 |
| `GET /api/graph/sessions/{session_id}/consumer/actions` | 读取消费者侧许可 |
| `POST /api/graph/receipts/read` | 按完整原 operation/parameters 核实管理侧回执 |
| `POST /api/graph/consumer/receipts/read` | 在原 consumer 作用域核实回执 |

更细事实通过工作台或统一应用查询读取，不临时绕过 scope/owner。回执读取在服务构造前使用 raw SQLite 只读路径；缺原身份、证据不匹配或 unresolved 不代表原 mutation 未发生。

## 故障与动作

| 情况 | 处理 |
| --- | --- |
| 配置、资源、协议或凭据无效 | 修正可编辑定义/资源，按明确用户动作发起新运行；不改原冻结事实 |
| HTTP 429/503、`model_provider_error` 或 `model_not_dispatched` | 保留事实；错误码本身不授予安全重试，当前原生 Agent 没有 `retry_failed_node` 策略 |
| 超时、断连、`model_dispatch_unknown` 或工具效果未知 | 核实原事实，不自动换 key、重发模型或重放工具 |
| 响应/schema/元数据非法 | 保留诊断，检查精确协议和原数据，不放宽校验或猜测缺失内容 |
| 成功结果仅接纳失败 | 原进程保留结果且提供 `retry_acceptance` 时复用结果，不重复模型或工具 |
| 图收尾归档失败 | 仅按实际 `retry_archive` 等许可处理，不等同于重执行失败节点 |
| 暂停尚未确认 | 仍为 `pausing`，不能按已暂停执行 `resume` |
| 已暂停且原现场保留 | 仅在 `resume` 可用时继续原执行；待接纳响应或工具队列不重复派发 |
| 页面丢回执、保存结果未知 | 保留原 body/key，在原作用域核实；后续 403/冲突不证明原保存没有发生 |
| 进程重启丢活动现场 | 可读持久历史，不授予活动恢复或接纳重试；按可用关闭许可处理 |

公共失败续跑只适用于能力包明确注册的策略，并要求原同进程服务、冻结依据和失败证据仍有效。当前 `agents.execute@4/@8` 没有注册该策略，不能依据历史测试中的“只重试 B”步骤操作。已接纳前缀和外部工具效果不会因关闭、选择候选或开启新运行自动回滚。

## Gemini 与思考

回答正文、可见 `thinking_summary` 与私有 `provider_metadata` 分开核对。摘要可以展示，原始协议封套及 `thoughtSignature` 不能当作回答或公开日志。摘要不是完整内部思维链，缺摘要不等于签名丢失。

`gemini_thought_signature_missing` 的诊断应核对精确模型、响应/历史来源和 part 位置；Gemini 必需签名缺失不能填合成值、使用 validator 绕过字符串或把文本拼接回请求。多个同名工具按调用 ID 与原 part 顺序关联，不按工具名配对；`gemini_tool_pairing_invalid` 要检查每次原调用与结果的对应关系。

对带签名历史，不改模型身份、不重排或正则改写原 part、不精简覆盖签名记录。检查响应 -> 已接纳消息 -> 事实/上下文 -> SQLite 重读 -> 下一次请求是否保留相同协议内容。底层 `model_response_invalid` 可能包裹具体协议诊断，应读其事实而不导出整个私有 payload。

供应商支持与思考模式由当前代码白名单校验，派发前拒绝不是自动降级理由。离线测试只证明协议保真与本地校验，不能证明合成 fixture 签名在真实供应商端有效；在线复现需另有真实调用/费用授权。

## 存档和版本

“保存记录无法读取或版本不兼容，原始记录未覆盖”表示浏览器工作台 JSON 解析、schema、结构或容量校验未通过；不是模型错误，也不直接代表 SQLite 历史损坏。当前读取失败会保留原 raw，不用空白页面覆盖它。不要第一步就清 localStorage；先确认正确 origin，保留原始记录和当前 key，仅在明确弃用时重建。

与读取失败不同，明确退役的旧节点/包、旧提示词资源及关联测试图按已授权规则删除：SQLite v15 在升级事务内整组清理，浏览器重读按精确旧身份清理。不会静默换成新节点版本，也不会重发旧 pending。未知插件/未知版本不按“目录缺失”猜测删除，应检查包选择、错误与数据身份。

应用 `0.2.0`、存储 v15、节点版本和各内容 schema 是不同编号；不能只靠软件版本号判断单条保存记录兼容性。新主干不会自动混合 `.local/dev` 稳定库与 `.local/develop` 开发库。

## 隔离复现

优先使用 [测试说明](TESTING.md) 的受控 transport 和临时库。人工调试使用独立库/端口，不默认打开、删除或替换现有演示库，也不为调试启动隐藏后台服务。

停止前确认无 active/in-flight 或结果未知业务，按本次启动打印出的 `stop-services.ps1 -MetadataPath ...` 命令停止已证明归属的进程。正式服务 metadata 在 `main` 工作区时，用该工作区的停止脚本；脚本会检查 metadata 根及进程身份，不从开发区强行停止另一个工作区，也不按端口批量杀进程。

调查原数据库前保留一致备份及 SQLite 伴随文件；停止相关写入或使用 SQLite backup API 获取一致快照，不将活动库的随手单文件复制视为完整备份，不直接改表“修复”状态。原证据不覆盖，分析与复测另存。

系统 Temp `WinError 5`、浏览器/包装脚本失败与产品业务失败分别记录。已有后端全量 50 项基线失败不能因定向通过关闭；旧日志包装退出 1 也不能因业务完成倒改退出码或重发模型。

## 安全分享

脱敏密钥、Authorization/cookie、环境变量值、个人正文、私有供应商协议材料和本机绝对路径。公开报告可一致匿名化标识，同时保留 owner 关系、错误码、尝试顺序和结果未知状态。

不要上传整个 `.local`、运行数据库、浏览器存档或模型原始请求。先提供最小复现、脱敏诊断和必要事实摘要；本地原始证据不是远端文档附件。当前声明与验收边界见 [开发说明](DEVELOPMENT.md)、[节点目录](NODE-DIRECTORY-2026-10-09.md) 和 [主干晋升](MAIN-PROMOTION-2026-10-09.md)。
