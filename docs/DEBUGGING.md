# 调试说明

先定位执行，再分类失败，最后按当前许可采取动作。不要把刷新页面、重新提交和恢复原运行当成同一种操作。

## 先收集什么

记录触发步骤、源码版本、工作流定义 ID 与修订、会话 ID、`chain_run_id`、节点 `node_binding_id`、实际 `node_run_id`、时间和错误码。界面及部分查询参数使用 `session_id`、`chain_id`、`node_id` 短名，归属坐标使用完整字段。

失败重试后，同一链及节点可能有多个尝试。查询 `node_run_attempts`，区分当前尝试与旧失败尝试，不把旧 HTTP 失败当作当前节点最终状态。

| 入口 | 用途 |
| --- | --- |
| 后端终端 stdout/stderr | 服务启动、HTTP 访问及进程错误；快速启动不额外配置日志文件 |
| 前端终端 | Vite 启动、代理和构建问题 |
| 浏览器 Console / Network | 请求地址、状态、代理与界面异常；导出前脱敏 |
| 工作台运行/节点诊断 | 编译、配置、状态及当前操作许可 |
| “统一登记与信息读取” | 按会话、运行和节点筛选调用信息源，读取精确 owner 的事实/诊断 |
| 会话对象、历史与公开结果 | 核对接纳效果、完成检查点、实际展示引用 |

日志不是完整账本；模型调用和节点执行应优先核对持久事实。目录中出现声明也不证明该来源已绑定到本次节点调用。

## 最小定位顺序

1. 检查 `/api/health` 和新版节点目录，确认正在连接正确后端。`offline` 字段不证明没有网络请求。
2. 确认图及修订、当前会话和 chain；检查保存是否真的完成，以及是否仍有原请求待核实。
3. 查看激活计划、首个失败节点及 diagnostic，区分编译/准备阶段拒绝和实际执行失败。
4. 查看失败节点的实际输入、冻结配置、模型依据、请求事实与输出。核对 A/B 的当前输入和 A -> B 本轮材料，不以画布标题推断内容。
5. 检查节点结果是否接纳、对象是否更新、后续节点是否完成。模型成功后仍可能在 merge、聊天追加或展示阶段失败。
6. 读取 `available_actions`，按当前动作许可处理。控制提交前后端还会再次校验；按钮曾可用不保证状态未变化。

后端只读运行路由为 `GET /api/graph/sessions/{session_id}/runs/{chain_id}`，动作路由为 `GET /api/graph/sessions/{session_id}/actions`。更细的信息读取使用工作台或统一应用查询，避免临时手写绕过 scope/owner 检查的接口。

## 故障与动作

| 情况 | 处理 |
| --- | --- |
| 配置无效、资源缺失、凭据不可用 | 修正可编辑定义/资源后发起新的有效运行；不要改原冻结事实 |
| HTTP 429/503 或事实确认未派发 | 只有暴露 `retry_failed_node` 时才人工重新调用失败节点 |
| 模型超时、断连或结果未知 | 保留请求事实并核实；不据此换 key 或重新调用 |
| HTTP 400、响应非法、工具已派发或证据不足 | 首片失败续跑不予许可；保留诊断、查询与实际可用关闭动作 |
| 节点产物成功，仅本地接纳失败 | 使用 `retry_acceptance` 复用原成功结果，不重新执行模型 |
| 暂停请求尚未被确认 | 仍是 `pausing`；不能将其当作 `paused` 并调用 `resume` |
| 已确认暂停且原现场仍在 | 仅在许可提供时 `resume`，不换成新运行 |
| 页面丢回执、资源保存结果未知 | 用已保存的原 body/key 核实；后续 403 或幂等冲突不证明原保存没发生 |
| 进程重启、活动现场丢失 | 读取持久事实并按剩余许可处理；不宣称活动内核已恢复 |

`retry_failed_node` 保留同一 chain、冻结输入及已接纳前缀，为失败节点生成新的尝试和请求身份；不是覆盖旧 run，也不是整图重跑。前面已接纳的对象效果可能继续保留。

## 隔离复现

优先使用 [测试说明](TESTING.md) 的受控 transport 和临时库复现。手工操作可停止自己的测试服务，再以新的 `.local/debug.sqlite` 启动；不要默认打开、删除或替换已有演示库。

对原数据库做只读调查时，先停止相关写入服务，保留原文件及 SQLite 伴随文件，再使用一致副本分析。不要把活动数据库的单个文件随手复制后视为完整快照，也不要直接改表“修复”状态。

单独区分产品错误与验收工具错误。例如已有六回合验收中的 Windows `WinError 5` 发生在报告原子替换：原包装退出 1，但只读核验确认业务完成。应保留包装失败和原证据，不能因此重发模型，也不能倒改退出码。

## 安全分享

删除密钥、Authorization 请求头、cookie、环境变量值、个人文本、供应商响应中的私有内容和本机绝对路径。工作流/会话标识可在公开报告中一致匿名化，同时保留相互关系、错误码和状态顺序。

不要把整个 `.local`、运行数据库、浏览器存储或原始模型请求包直接上传。先提供最小复现、脱敏诊断和必要事实摘要；保持原始证据不可变，新的分析报告另存。
