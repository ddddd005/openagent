## 1. 本轮决定与范围

本规划接续本次对话中的明确决定：

1. 普通节点可以选择统一映射；复杂节点允许定制。统一生成、局部字段定制和整体界面定制共用节点身份、端口、配置与执行契约。
2. 打组用于查看和管理复杂画布。进入组相当于聚焦视图，仍在同一个工作流内观察、编辑实际节点。
3. 组内提供输入节点和输出节点，把内部真实端口映射到组外接口。它们是编辑器接口节点，不增加业务计算、独立执行器或运行回合。
4. 真实节点的身份、执行逻辑、数据边、控制依赖及排序规则不因单纯建组、解组或切换视图改变。内部节点不必连续执行，组不成为整体调度单元。
5. 普通节点的统一映射与分组视图分别交付；本轮规划不介入其他执行方正在进行的施工。

历史 [BACKLOG 的 PAUSE-01](../BACKLOG.md) 记录了建组、解组、嵌套等能力的暂停。本次最新请求已明确恢复上述限定方向的论证与规划，不再以旧暂停要求用户重复确认本轮方向；它没有自动恢复历史共享组树、跨工作流组资产等全部设想，也不是产品代码施工授权。

## 3. 节点统一映射与定制

### 3.1 已确认的能力层次

| 层次 | 预期行为 | 共用约束 |
| --- | --- | --- |
| 统一映射 | 按节点声明生成端口、基础参数表单和标准卡片；使用已有类型及控件的普通节点无需逐个修改画布核心 | 继续使用准确的 `component_id@version`、统一目录和原执行器 |
| 局部定制 | 专用编辑器接管明确字段或展示区域，其余内容仍统一生成 | 同一配置字段不能由通用编辑器和专用编辑器各维护一份状态；变更走现有配置入口 |
| 整体定制 | 复杂节点可提供自己的卡片/编辑界面，仍与通用选择、接线、诊断和运行状态协调 | 自定义呈现不另设端口类型、配置事实源或执行入口 |

这里的“统一映射”以显式声明为依据，不包括凭任意函数签名自动推断模型调用、持久写入、权限或恢复语义。复杂节点原有执行逻辑保持由其可信实现提供。

### 3.2 实施工作

1. 列清现有声明、前端 policy 与专用编辑器的实际职责，优先处理名称/分类/说明、字段展示和端口呈现。首选版本涉及目录选择规则，不作为普通文案直接迁移。
2. 明确统一/定制方式由谁选择、声明如何绑定，以及卡片通用部分与定制部分的边界。精确契约不在本规划中预造，见 D-M。
3. 复用现有 `node-fields` 和字段接管机制，选一个普通节点和一个已有复杂字段节点验证同一条配置保存链；不按历史节点清单全量重写。
4. 在明确整体定制契约后补画布接入，选择一个现存复杂节点验证。既有 `session-object` renderer 的用途保持准确，不把它扩写成万能插槽。
5. 对缺失实现、重复绑定、类型或声明不符提供可定位诊断；没有声明定制时走统一生成是正常路径，已声明定制却缺失实现不应被静默当作普通节点成功接入。

展示元数据的具体归属、插槽名称、宿主协议版本及升级策略须在 D-M 落定后记录；本规划不指定版本号，也不要求全部属性都移到节点卡片内。

## 4. 分组聚焦视图与接口映射

### 4.1 展示与真实连接的关系

```text
组外视图：上游 ──> [组 G：输入口 / 输出口] ──> 下游
组内视图：组输入 ──> B ──> C ──> 组输出
真实依赖：上游 ─────────> B ──> C ─────────> 下游
```

- 组输入节点在组内提供输出端口，映射到外层组的输入接口。
- 组输出节点在组内提供输入端口，映射到外层组的输出接口。
- 外层接口、组内接口节点和真实业务端口必须能明确对应；接口名称和排列不是连接身份。
- 组内输入、输出节点没有业务执行器，不生成自己的业务运行记录；组输出不冒充 `is_output` 工作流执行终点。
- 编辑器负责把接口操作解释为真实节点端口的操作。执行仍消费准确的真实节点依赖，不按折叠画布重新调度。

数据表示尚待 D-G 确定。无论组资料和业务图是否同处一个文档，都不能形成两份可独立编辑、相互猜测同步的真实连接依据。具体存储和映射更新方式是后续局部契约，本规划只固定上述语义。

### 4.2 建组、进入、编辑与解组

| 操作 | 预期结果 | 执行含义 |
| --- | --- | --- |
| 建组 | 选中的真实节点归入一个展示组，建立跨边界端口对应关系，组外显示组卡片 | 保留节点 ID、节点顺序、配置、真实边及边顺序；不通过复制节点实现 |
| 进入/退出 | 聚焦组内或返回外层；组内能看到输入、输出节点及成员 | 不切换工作流身份、会话或运行目标，不触发执行命令 |
| 接口改名/排序、折叠与布局调整 | 调整可读性与组织方式 | 只要真实映射目标和业务连线不变，执行计划应保持一致 |
| 通过组接口接线或修改组内接线 | 通过映射定位实际源/目标端口，再走正常图编辑与校验 | 实际连接变化时，正常改变依赖；仍遵守业务图的保存、锁定与固定配置派生规则 |
| 解组 | 移除展示分组和接口视图，恢复成员直接可见 | 不删除业务节点，不改变实际连接和业务引用 |
| 撤销/重做 | 恢复同次操作涉及的分组资料、映射及实际图修改 | 不出现已撤销画面但保存内容仍为另一状态的部分结果 |

“删除整个组及成员”与“解组”不是同一操作；前者不是本次自动附带的需求。普通节点增删仍沿用既有业务行为，组视图必须正确反映成员或端口的实际变化。

### 4.3 必须保持的运行与引用语义

1. 组不是整体执行单元。`B（组内）→ X（组外）→ C（组内）` 应继续按 `B → X → C` 执行；折叠后看似 `G → X → G`，不能据此误报循环。只有真实依赖图的循环才按原规则诊断。
2. 建组不重排 `document.nodes`，不改变真实边的 `order`；同时就绪节点继续使用原来的稳定排序依据。现有数据边与控制边共同参与排序的规则保持。
3. 对象读写权限、事件目标、公开输出、会话预加载、配置中的节点引用和历史运行定位继续指向真实节点。仅分组不重分配这些业务身份。
4. 外层接口的类型依据映射到的真实端口及版本核对，不按显示名、同名类型或首个内部端口猜测。修改类型或删除端口产生的失效要可见、可定位，不静默换绑到相似端口。
5. 跨边界控制依赖必须完整保留。控制关系如何在外层及聚焦视图表达属于 D-I，不能为简化画面删除、合并或伪装成普通数据连接。
6. 状态与错误继续来自真实节点。外层可提供内部状态提示和定位入口；不创建组级独立暂停、重试或成功判定。

### 4.4 资料与生命周期要求

组资料至少要表达：组及其成员的稳定引用、名称与布局、外层接口身份、接口到真实节点端口的映射，以及组内接口节点所需的展示信息。这里列的是信息需求，不是已经冻结的字段或数据库表。

资料需要正式保存、重读，并与编辑版本及撤销一致；不能只保存在浏览器临时状态。用户通过接口改变真实接线与仅修改展示资料，要按实际效果区分。现有组外节点复制、工作流复制/派生、导入导出和历史查看若会遇到新资料，应在 D-G 明确保留、重映射或显式不支持的范围，不能默默丢组。

进入/退出聚焦视图是观察行为。运行中的视图切换与运行中的结构修改需区分；本规划不因允许观察而放宽现有编辑锁，也不要求重建保存/回执系统。

优先做能证明行为边界的小型当前检查，不恢复旧清债测试矩阵，不以历史通过数抵扣本次验证。使用隔离数据和确定性执行器验证执行语义，不需要真实模型调用；浏览器交互使用已具备环境，缺环境时报告未验范围，不自行安装或启动现有服务。

| 检查 | 需要证明的行为 |
| --- | --- |
| M-A 统一生成 | 一个只提供普通声明、复用现有控件的节点，目录、端口、配置编辑、保存重开和执行均正确，不需要为该节点改画布核心 |
| M-B 局部定制 | 接管字段只出现一个有效编辑入口，其余字段继续自动生成；两者写回同一配置；校验和业务运行不因呈现变化而分叉 |
| M-C 整体定制 | 自定义卡片仍可选中、拖动、接线、定位错误并显示真实状态；缺失/冲突实现诊断可见，不伪装为已成功接入 |
| G-A 仅分组等价 | 对同一业务图建组、改组名/排列、进入退出及解组，真实节点 ID 和顺序、配置、数据/控制边及 `order`、对象/事件引用均保持；比较编译计划顺序与输入绑定，并用确定性执行记录核实一致 |
| G-B 跨组交错 | `B（内）→ X（外）→ C（内）` 合法且顺序保持；真循环仍被原规则检出；多个无依赖节点的并列顺序不因分组或画布投影改变 |
| G-C 接口接线 | 从外层组端口编辑与直接编辑目标真实端口得到相同业务结果；类型、版本、必填、多源基数及边顺序按真实端口校验；多目标只测获批范围 |
| G-D 保存与撤销 | 建组/解组/改映射的保存重开、撤销重做及正式拒绝保持一致；继续服从原编辑版本、锁、派生和请求结果确认语义；不只验证内存画面 |
| G-E 变更与定位 | 成员删除、端口变化、失效映射和内部错误有准确定位，不猜测重绑；仅进出视图不调用启动/暂停/恢复；组输出不成为额外执行终点 |
| G-F 关联生命周期 | 按 D-G 的确认范围检查工作流复制/派生、节点复制、历史查看与导入导出；显示资料不能改变原业务身份或消失而无提示 |
