# 本机存档恢复与供应商空状态

本记录承接用户验收时出现的“保存记录无法读取或版本不兼容，原始记录未覆盖”和“暂无供应商当前资源”。独立登记，不改写 P5 与此前启动器验收的历史结论。

## 当前处理方式

2026-10-09 现行代码已进入 `main` 并正常推送，本文修补不再只是本机未提交内容。正式 `start.bat` 使用入口工作区 `.local/dev/workflow.sqlite`、端口 `8765/5178`；开发 `start-dev.bat` 使用 `.local/develop/workflow.sqlite`、端口 `8766/5179`。两套库与浏览器 origin 隔离，不自动合并。新机器不会取得原开发机的数据库、浏览器记录或 `.local/` 验收文件。

“保存记录无法读取或版本不兼容，原始记录未覆盖”来自浏览器工作台存档的安全读取，不是模型响应错误，也不证明后端库丢失：

1. 用“导出原记录”保存捕获的完整原文，不清空 localStorage、不先解析重写。
2. 要继续编辑时明确选择“另建本机工作区”，新存储位置与原记录分开；它不修复旧图、不复制会话、不重放原请求。
3. 如需恢复原内容，单独检查真实导出记录及原请求边界。独立记录损坏时仍拒绝写入，不自动新增第三个存储位置。

“暂无供应商当前资源”表示当前连接后端读取成功但列表为空；读取错误显示单独诊断。先核对启动器打印的端口、库和源码身份，再显式创建供应商。不能凭当时空库检查断言当前库仍为空，也不能自动读取其他库或迁移密钥。

现行存储 v15 和浏览器读取器另按精确名单删除退役节点/包的旧测试图及关联记录，不保留兼容执行或静默改版本。此类已明确授权的旧图清理与损坏/未知记录保全不同；未知插件、未知版本不会仅因目录缺失被猜测删除。范围见 [节点目录](../NODE-DIRECTORY-2026-10-09.md)，操作见 [使用手册](../USER-GUIDE.md#保存与故障)。

## 当时问题边界

这两条提示来自不同数据层：

- 工作台存档保存在浏览器 localStorage，原键为 `workflow-workbench:fixed-base:v1`。读取器已有明确的旧格式处理；无法识别的格式、损坏 JSON 或不能安全恢复的原请求仍应阻止覆盖，不能直接取消校验。
- 供应商当前资源保存在后端 SQLite。当时开发启动使用 `openagent/.local/dev/workflow.sqlite`，只读 SQL 核对 `global_resource_current WHERE deleted=0` 为零条，所有资源类型均为空。旧数据库没有被自动迁移到该库。这是当时观察，不是现行正式库的实时状态。

本次未能读取用户实际浏览器的原始存档，因此不能断言是哪项字段损坏，也没有恢复其旧工作流。新增的是安全导出和继续工作的入口，不是静默兼容未知记录。

## 已实现修补

工作台错误栏新增“导出原记录”和“另建本机工作区”：

- 导出保留捕获的原始文本，不先解析再序列化；独立工作区已启用后仍可导出先前原记录。如果独立工作区自身损坏，导出的是当前被拒绝的独立记录，两个保存键均不改写。
- 另建是用户明确点击后的操作，使用独立键 `workflow-workbench:isolated-graph:v7`。原键保持原样，不清空浏览器存储，不迁移数据库，不重放原请求。
- 新工作区为当前 workbench schema 7、空图 schema 2。错误出现后用户新建的安全未保存草稿及撤销历史可继续保留；会话、待核实请求或被锁定的草稿不能借此绕过保护。
- 已有独立记录优先恢复；再次刷新继续写入独立键。独立记录损坏时继续阻止写入，不创建第三个隐藏保存位置。
- 原键和独立键都检查写入前的预期原文；其他页面更新、存储容量错误或恢复键已占用均拒绝。跨页 storage 事件按当前活动保存键保护。

供应商面板区分读取中、确实为空和读取错误；错误出现时不再同时宣称“暂无供应商当前资源”。已有新增入口保留，没有自动创建供应商或读取、迁移凭据。
