## 1. 设计与范围

全局提示词预设就是可复用的提示词组，已有后端契约足够，无须新增预设引擎、数据类型、节点、API 或能力包版本。

继续使用：

| 身份 | 用途 |
| --- | --- |
| `workflow.prompts@1.0.0` | 既有提示词能力包 |
| `workflow.prompt-resource@2` | 显式包含生命周期的全局提示词组 |
| `prompts.global-reference@2` | 声明完整全局资源引用，参与启动预检 |
| `prompts.global-resolve@2` | 从本轮冻结资源读取并生成 `PROMPT_MATERIALS@1` |

接线仍为：

```text
全局提示词引用.output -> 全局提示词解析.input
全局提示词解析.output -> 提示词汇总或 context.assembly@4.materials
```

资源、引用管理保留在原工作台提示词组件中。这是原提示词包的通用组操作，不含 ST 复制代码；后续 ST 代码及酒馆聊天适配仍必须放入酒馆包，不借本批扩大通用聊天的范围。

本批不更改后端产品实现、提示词生命周期、精简规则或 Agent 有效上下文实现，也没有增加聊天正文编辑、删除、重排或上下文操作。

## 2. 管理操作

- 面板明确显示“提示词组 · 全局资源”，继续提供新建、编辑、资源/条目启停、增删草稿成员和完整呈现/生命周期配置。
- 每个资源增加“复制为新提示词组”的图标操作。复制只打开独立草稿，不立即请求保存，也不自动修改工作流节点引用。
- 复制保留 scope、schema 版本、正文、启停、metadata、role、placement、depth、order、lifecycle 和 compaction；资源 UUID 与所有成员 UUID 均重新生成，首次提交采用 `expected_sequence: 0`。
- 编辑和移动原组成员保留其 UUID。成员身份只读显示，不能通过改正文隐式产生新身份。
- 增加成员上移/下移。明确移动时同步数值顺序；原列表的 rank 严格递增时交换对应 rank，否则将移动后的列表重编号，避免相同 rank 的 UUID 决胜或乱序 rank 抵消用户动作。
- 移动不会改变 placement/depth。实际装配仍优先考虑 before/middle/after 和逻辑深度，同一装配区域内再按 order 排序；上下移不能代替改变装配位置。
- 新增成员以现有最大 rank 加一，不仅因追加条目就重编号旧成员；超出安全整数上限时不增加条目，明确报错。
- 保存未知结果时沿用原 pending body/key 和资源修改锁。成功核实原回执后关闭旧表单，避免继续用旧 CAS 序号提交；核实不重发保存。

schema 2 正文仍严格为 `enabled / members`，没有组级 `name`。列表沿用首个非空成员正文的首行作为标签，没有擅自增加名称字段。旧 schema 1 仍可编辑/复制，不自动升级；版本 2 引用选择器和后端预检不接受旧 schema 1 资源。

实现入口：[组领域操作](../../frontend/src/domain/workflowPromptResources.ts)、[工作台面板](../../frontend/src/components/CurrentPromptPanel.vue)。API、pending 控制器和节点引用选择器继续复用既有实现。

## 3. 身份与一次消费

材料稳定身份由解析节点 UUID 和成员 UUID 共同生成，即既有 `stable_item_id(node_id, member_id)`，不是资源序号、资源 UUID、标签或正文。

- 修改原条目正文、rank、启停或其他配置不会改变其身份。已经消费的 `context_once` 条目不会因这些编辑重新注入；先前正常写回的背景仍按已有上下文机制保留。
- 复制是显式创建另一组身份。为所有成员分配新 UUID，因此副本的 once 条目有独立消费身份；在用户保存并显式改绑后，可在同一 Agent 上下文中消费一次。
- 仅替换资源 UUID、但保留解析节点和成员 UUID，不足以获得新的消费身份。这也是复制需要同时刷新成员 UUID 的原因。
- `per_request` 材料继续每次装配，且不会作为固定规则正文写入正常有效上下文；禁用条目不会被标为已消费。
- 跨节点的同文材料聚合、来源证据、生命周期和 compaction 仍按原契约处理，没有给预设增加特殊执行路径。

保存资源只影响后续回合。本轮开始后更新全局组不改变当前冻结读取，旧运行历史及接受产物保持不变。
