## 1. 结论

可以实施，现有节点化后端不需要改成 ST 后端。首版采用用户允许的直接复制路线：复制 ST 聊天相关模板/样式/可用函数到独立酒馆包，复制现有前端业务层形成酒馆节点，再用适配层接当前消费者和平台分叉。

不是把完整 ST `index.html` / `script.js` 原样挂上就能运行。所勘察的入口耦合供应商、角色卡、扩展、宏、聊天文件和全局状态，需在包内选取必要片段并裁剪依赖。该裁剪是本期移植工作，不预设全部 Vue 重写，也不宣称零适配。

已确认不修改 Agent 有效上下文。唯一新增历史状态操作为已完成检查点的分叉；当前会话候选选择/回退不在范围内。

### 3.1 复制控制

- 上游原克隆只读；复制文件或片段的来源提交、路径、范围、摘要、许可和后续改动记入包内清单。
- 复制区、修改后的 UI 和适配层都位于独立酒馆子包。通用源码中不保存第二份 ST 模板或样式。
- 仅闭合选取片段的必要依赖，不复制完整 ST 项目、Node 服务、API 路由、角色/聊天目录或设置文件。
- 未实现的控件从模板移除，不能通过隐藏页面入口却保留事件副作用来声称退出。
- 需要头像/图标/字体时选择本地可追溯资产并核对各自许可；不把头像显示扩展为角色卡管理。
- 首次抽取后核对静态 import、资源 URL、运行时请求与全局初始化；本轮尚未执行这个运行验收。

### 4.1 精确边界

- `frontend_contracts.py:227/239` 固定核对原 `frontend.state.append/output@1` 身份。酒馆复制必须替换为自己的完整证明链，不能复用原写权限绕过校验。
- `static/graph-chat-core.js:18` 的消费者查询列表没有候选 list；`graph_application_contracts.py:60/94` 的 fork/list 当前属于 management。
- 现有 `consumer.read` 主要给 session revision，不完整提供 fork 所需的 data/head CAS 依据。不能用 UI 本地推断或管理对象读取补数。
- `graph_receipts.py:271` 的消费结果只列 create/start/control/event，尚未覆盖 fork。管理 fork 已有结果验证，不能直接把它当作消费者回执已闭环。
- `static/graph-chat-core.js:47` 的支持类型列表固定含 `FRONTEND_DISPLAY`；新酒馆展示类型需要明确校验接线，不能放开所有未知类型。
- `static/frontend-package-host.js` 和 `graph_public.py` 的消费扩展目前仅绑定 `public-output`。一个渲染扩展不能自行提供整页会话、输入和分叉壳。
- `capability_packages.py:81` 的 manifest 导出没有静态资产项，现有 SDK 不等于独立插件安装/资产分发系统。
- `server.py:25/141` 采用有限静态文件表及严格 CSP；`backend/pyproject.toml` 只列 `static/*.html/css/js`，酒馆嵌套资产尚未包装。
- 原聊天 CSP 没有酒馆头像/字体所需的 img/font 放行，ST 原 HTML 还含内联脚本与 style。新页面需要单独有限资产策略，不能全站启用任意脚本或内联执行。

以上都是实施缺口，不是本轮已修复内容。

## 5. 分叉裁决

ST `getBranchChatSnapshot` 从消息索引切出数组并保存聊天文件；OpenAgent `fork_graph_candidate` 从完成检查点创建新会话，继承冻结 manifest、会话对象和历史。两者不等价。

本期采用后者：

1. 消息引用映射回其来源运行，再由后端确定该运行对应的完成候选。
2. 一回合有多个展示条目时共同对应整回合边界，不制造消息级内部检查点。
3. UI 仅展示可用的完成回合目标；部分成功、失败、在途和纯草稿条目不可分叉。
4. consumer 仅获得必要候选/分叉依据及子会话结果，不暴露所有对象、manifest 或管理权。
5. 平台创建子会话，父会话不推进、不回退；历史定义、缺包、范围与稳定性校验保持。
6. fork 命令、应用身份、只读回执结果、客户端原请求与页面重开保护共同接线。
7. 新会话中另行发送才调用工作流。完成历史冷重开不等于活动内核跨进程恢复。

“不改上下文”不取消平台分叉的必要继承：子会话从选中检查点获得对应的 Agent 上下文对象。这不是编辑父上下文，也不是从浏览器重建模型历史。
