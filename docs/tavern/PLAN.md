## 3. 全局内容设计

### 3.1 全局 Lorebook

- 全局共享的是条目内容，不是扫描状态、概率结果、递归计数或 Agent 上下文。
- 复用既有触发引擎及条目结构；单条目和条目组沿同一语义计算，不重写主副关键词、概率、逻辑楼层和三轮递归规则。
- 新资源使用独立的酒馆全局类型身份；组内条目 ID 稳定，名称不参与触发。
- 工作流节点显式声明完整资源身份，使用现有全局资源预检和运行冻结读取，不能在执行时直接读不断变化的 current 头。
- 变量对象授权仍属于节点在当前会话中的配置，不把会话对象 key 当成全局资源的跨会话读权限。
- 新全局节点继续接收精确 `PROMPT@6` 扫描产物，输出 `PROMPT_MATERIALS@1`，材料保持 `per_request / never`。
- 原 `lorebook.item/group@1` 内联节点保留。需要转换时，由明确的创建资源/重新绑定操作形成新定义，不静默转换已有图或冻结历史。

P1 已确定 `workflow.tavern.lorebook@1` 资源，正文严格为 `name / enabled / entries`；新增 `lorebook.global-reference/global-activate@1` 和工作台管理组件。复用当前全局资源的 CAS、请求幂等、原请求核实及大小边界；不恢复 ST 的世界书数据库或旧变量 registry。详细接线与证据见 P1 记录。

### 3.2 全局提示词组

- 复用 `workflow.prompt-resource@2`、`prompts.global-reference@2` 和 `prompts.global-resolve@2`。
- 保留成员 ID、正文、role、placement、depth、order、启停、生命周期和精简许可。
- 不新增模型生成参数、动态工作流、上下文或 Lorebook 扫描状态到预设中。
- 先复用已有管理/引用能力，只补本次使用确实缺少的组操作。资源复制要明确成员身份和 `context_once` 的消费语义，不因正文相同或编辑原条目自动重新注入。
- 当前资源严格 schema 没有组级 `name` 字段。首版可以沿用现有标签；确需持久名称时必须显式版本化设计，不能向 schema 2 偷加字段。

这不是新的预设引擎，也不是 ST PromptManager、模型参数 preset 或角色卡系统的整体移植。

P2 已补独立复制草稿、成员上移/下移、追加 rank 边界以及回执核实后关闭旧表单。原组编辑/移动保留成员身份；显式复制刷新资源和成员 UUID，保存后仍需用户显式改绑。未新增后端实现、契约或包版本，验证与消费语义见 P2 记录。

## 5. 分叉的唯一语义

用户最新明确只要分叉，不改写上下文，因此不做 `candidate.select`。

- 分叉目标必须是当前会话可见、可用且整图已完成的执行检查点。
- 一个回合的用户消息和多个 Agent 展示条目可以关联同一个检查点；不是任意消息索引截断。
- 未完成、失败、仅部分节点成功、乐观展示或无检查点的消息不能分叉，不猜测最近检查点。
- UI 展示可用回合目标，并在确认前明确实际分叉边界。
- 复用 `fork_graph_candidate` 的完整对象/历史继承和新会话创建，不在客户端裁剪聊天数组模拟。
- 父会话、父对象和原事实不改变；子会话使用检查点上的工作流定义与对象状态，不混入父会话后来产生的历史。
- 分叉本身不调用模型；用户在新会话中另行发送才开始新一轮。
- 平台对运行中/暂停中/不稳定会话的限制保持。重复点击、CAS 冲突、网络失败和迟到响应不得创建重复子会话。
- 原 fork 请求结果未知时保留原 body/key，核实只读回执；重开或核实失败不自动重 POST。

P4 已一起补齐受限候选投影、命令、实际子会话结果和 pending/纯回执核实，不给按钮接管理 URL。首版消费者只接同一工作流身份内的可用完成目标，包括旧定义版本与祖先继承回合；跨工作流身份的历史目标继续仅由管理端处理，不增加多工作流请求日志迁移。

## 7. 验收要点

- 全局 Lorebook 内容共享、局部扫描、单次概率、三轮独立递归、变量只读和材料不持久化保持既有规则。
- 全局提示词组的保存、引用、冻结、排序及生命周期在实际工作流中生效。
- 酒馆节点写入的是经证明的聊天展示引用，不能制造产物、越会话读取或写 Agent 上下文。
- 普通聊天与酒馆页面可独立打开；卸载/离开酒馆不残留样式、事件监听或 DOM 修改。
- ST 未纳入范围的入口、扩展、API 和网络请求不被初始化；无 `/api/chats`、`/api/characters` 或真实模型旁路请求。
- 新建/切换、发送、多轮、历史冷重开、消息去重和子会话续聊通过隔离离线场景。
- 分叉继承选中检查点而非父最新状态；父会话 revision/对象/历史不变，子排除检查点后历史。
- 重复分叉、stale、断连、回执失败、页面重开、迟到响应保持原请求并且不自动重发。
- 仅接受显式公开的展示引用；Markdown 的脚本/事件属性不执行，原文不被格式化器改写。
- 页面及包内资产在独立安装中可用，必要桌面/窄视口无重叠、空白或缺失资源；不以开发机源目录可读代替安装证据。

每批只跑实际受影响的定向测试，浏览器联合验收集中执行。需要构建时沿实际修改范围统一检查，不自动全量、不重复此前收费测试，不借本专项清理全部 TEST/HIST 债务。
