## 1. 本次收敛决定

1. 工作流存在有效会话时，不原地改变节点结构和固定配置；已有确认派生流程保留。可调内容、全局引用等按既定规则取当前已保存值，不因此为每个会话维护一份可写配置。
2. 定义及数据项登记与当前值分开。登记提供类型、独立项身份及节点登记关系；当前值不进入定义模块，也不增加会话级定义目录或第二份配置权威。
3. 现有会话存储层承担当前值维护和隔离；现有检查点承担规定成功状态的历史保存与新目标分叉。复用已有机制，不另建存储、隔离或上下文历史平台。
4. Agent 上下文与会话/聊天上下文继续按节点实例登记独立数据项。多个 Agent、多个测试输出的项不合并；具体消费者选数据项，不再绑定 Agent 内核 ID。
5. 显式加载、加载时值快照、显式写回及用户编排顺序不变。会话存储不隐式向流程注入值，runtime 不代节点加载或写回。
6. 会话/聊天上下文以后可以通过自身类型登记及明确检查点准入接入保存；首版限定内容是退役期间的极简范围，不是永久排除其他类型。**本批仍不扩大检查点白名单，不迁移变量注册。**
7. 类型名决定数据契约，独立项身份决定具体哪份数据，会话范围决定当前值；不按类型名自动选择第一项。Agent 只消费已装配的计算内容、输出结果和真实执行证据，不直接读写或识别持久项，持久候选投影移到上下文更新侧。
8. 成功点按登记和准入收集已接纳值；分叉由检查点与数据层限定初始化新会话，不运行上下文更新节点，不借用其 reader/writer 身份。

上述“会话上下文”指本轮讨论的随输出实例登记、可显式加载和写回的独立业务数据，不把通用 `messages` 改成每会话必有集合。类型登记、实例登记、当前值持久化和检查点准入仍是不同职责。

## 2. 职责分工

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 定义/登记 | 统一提供节点声明、已有类型契约及所需数据项登记信息，供消费者查询 | 当前上下文值、逐会话复制定义、另建类型表或配置表单 |
| 工作流配置 | 保存节点、实例参数、固定/可调策略、数据项选择及必要绑定；维护配置固化与确认派生 | 已加载值、当前业务值、运行事实 |
| 会话存储/数据层 | 按既有会话和数据项范围读取、显式更新当前值；配合检查点限定初始化新目标；保持类型、权限、版本与事务写入 | 自动替节点读取上下文，因输出或 Agent 成功隐式写回，以初始化职责任意覆盖已有会话 |
| Agent计算 | 消费已装配消息和计算所需属性，维护正常临时状态，输出结果和真实执行证据 | 持久项定位、owner/CAS 处理、持久 next_view 投影或直接数据层调用 |
| 上下文交互节点 | 按精确类型选择具体项，加载快照；更新侧核实原输入与执行事实、构造候选并显式提交 | 仅按类型名取值、以登记者限定实际执行者、未调用时隐式写回 |
| runtime | 使用实际图筛选和调度节点，维护运行输入、已接纳输出及正常暂停现场，判断回合完成 | 增加业务读写固定先序，替输出节点维护上下文 |
| 检查点 | 成功收尾后收集明确准入值，保存不可变历史，完整事务创建并装载新分叉目标 | 持续追踪当前值，保存每次中间写入，覆盖原会话 |

工作流内可复用相同登记和固定配置，当前可变值的隔离直接沿用会话存储，不把所有节点都改造成需要逐会话建值的对象。独立项身份、登记者身份与读写权限分别处理；不能把数据项设为仅 Agent 本人可读写的 private 对象，阻断独立加载/写入节点。

## 6. 检查点范围与后续类型接入

**本批：** 仍只保存已声明配置及白名单 Agent 已接纳逻辑状态。已有极简状态结构和保存范围是当前过渡实现，收集、full/diff 和分叉只做解耦必需调整。

未写回的流内值不进入当前业务值收集；失败回合不创建成功点，已接纳的节点写入仍按既有会话存储职责维护。每次覆盖都有检查点的保证并不存在，不为此另建历史台账。

## 7. 验收与剩余关口

| 必须覆盖的场景 | 预期 |
| --- | --- |
| 无会话新增与重读 | 节点和独立项登记一致保存；没有会话、执行现场或业务值写入 |
| 多 Agent、多输出 | 同类型不同项，写一个不改变另一项的值、版本或后续加载结果 |
| 同工作流不同会话 | 复用同一固定定义及登记，当前值和写入回执按既有会话范围隔离，不维护第二份定义 |
| 显式加载/写回 | 只加载或完成 Agent/输出不写回；写入后旧加载值不刷新，再次加载才读到新值 |
| 实际编排 | 真正数据/控制依赖优先，就绪按创建顺序；不补共享项固定先序 |
| 更新与回执 | 错项、错误会话、伪造 producer/输入、失效 CAS 拒绝；该节点的值、产物和回执原子接纳 |
| Agent职责 | 计算侧不处理持久项定位/basis/next_view；实际执行者可合法消费其他登记者项，更新侧准确核实原输入 |
| 检查点和分叉 | 只收既有白名单已接纳状态；新目标与源隔离，失败完整回滚，目标规定内容不依赖源数据 |
| 初始化与普通交互分开 | 保存/新目标初始化不要求 reader、唯一 writer 或 merge 节点，不执行节点或伪造回执；普通 ACL 不放宽 |
| 范围回归 | 变量、配置固化/可调/派生、筛选排序、正常暂停续跑、原请求保护和测试输出/runtime 分工保持 |

存储复用、显式闭环、独立数据项及变量暂不迁移已经确定，不再重复询问。剩余具体关口为：

- 复制节点使用空初值还是复制一份内容；部分图复制的外部项引用如何处理。
- 删除节点后数据保留或清理的准确范围，不默认联动删除已有会话、检查点或请求证据。
- 必要公开字段、计算证据/更新端口及版本变化的最小实际清单；`PROMPT@6` 外层不改，整份装配和输入核实保持，不能仅沿用28号嵌入 next_view 适配清单。
- 节点实际消费时的具体项及 reader/writer 接线、确需外部输出时的准确目标；登记不自动赋权。frontend-state@1 的测试期复用和保存状态的新会话初始化职责已确定，不再等待这两项裁定。
