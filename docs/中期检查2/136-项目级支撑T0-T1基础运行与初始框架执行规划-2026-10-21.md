## 3. 最小接线与框架完成口径

建议采用以下正常通路，名称可按现有代码风格调整，不强制一项职责对应一个类或文件：

```text
main / create_server 的正常项目入口
→ WorkflowHost：项目基础运行的装配、取得与持有
  → 存储环境 / 项目数据管理最小承载
    → 工作流管理/执行入口的既有 _store 取得缝
      → WorkflowDataManagement → 原领域接口与原事务
  → 项目定义框架：可取得，明确未接入子能力
  → 薄执行组织：按需取得和委托现有工作流入口
→ HTTP dispatch_graph → GraphApplication 原业务分派
```

| 框架部分 | T1 必须真实完成 | 本批仍未接入的部分 |
| --- | --- | --- |
| 环境/数据管理 | 正常 Host 的工作流管理/执行入口经统一环境创建新 store，并走原领域读写；不是只增加一个无消费者对象 | 新项目业务表、跨域数据调度、所有领域全面迁移 |
| 定义管理 | 基础运行持有且可内部取得；能明确表达当前未注册项目子能力，不复制工作流内部目录 | 工作流公开声明、跨域依赖 schema、校验阶段和真实装载归 T2 |
| 薄执行管理 | 现有请求可沿统一取得组织进入原业务入口；管理不额外取执行租约，生命周期复用已有协调者 | 新项目调度器、第二份运行状态/回执、统一任意业务操作协议 |

环境与项目数据管理可以由一个轻量承载实现，避免只做多层转发。定义框架的“可取得但未接入”是本批占位交付，不能写成工作流能力已注册；薄执行以现有真实请求证明接线，不能用模拟成功代替。

## 4. 已确认的三项职责边界

以下根据用户在规划后的逐项讨论订正，固定加载、存储环境和生命周期三项职责。这里的“服务”指承载业务操作并持有必要资源的后端运行对象，不指前端页面或 HTTP 服务器；内部文件名、类名、参数排布和对象数量由工程在既有结构内落实。

| 事项 | 已确认的职责 | 工程落实及保护边界 |
| --- | --- | --- |
| G1 工作流基底与执行按需加载 | 项目基础运行统一取得和持有工作流能力；工作流内部区分管理所需支撑、按需激活的执行资源及每次运行的准备内容。普通配置修改仍做必要校验、运行锁检查和持久化，不因此启动整条执行链或模型调用 | 复用 WorkflowHost 和原 authority 分类，管理/执行内部用一个或多个对象不作为项目契约；普通管理不主动激活执行权威，运行控制及需协调的生命周期操作仍到已有执行协调者。不迁工作流内部构造到项目层 |
| G2 项目环境与工作流领域管理 | 项目统一提供现有 SQLite 主库的存储环境与取得方式；工作流从中取得自己的领域接口，继续由自身模块解释和管理配置、会话、运行等数据，项目不跨域改表 | 不另建项目主库或工作流库；独立连接不等于第二个数据库。正常 Host 传同一环境；保留既有直接构造支持，未传环境时也基于明确路径建立同类环境，不自动造 Host/执行服务；显式路径与环境不符在使用前拒绝。凭据独立库及既有事务保持 |
| G3 生命周期持有与关闭 | 生命周期所有者发起关闭，各能力通过自己的公开关闭入口释放内部资源。正常路径由主程序创建 Host 并在退出时关闭，Host 负责所持工作流服务；HTTP 服务器借用这些能力，关闭自己的网络和传输资源 | 调用方提供的 Host、工作流服务或注入对象不由 HTTP 服务器代关；兼容分支若由服务器适配部分自行创建并持有业务对象，该部分必须负责正常关闭。保留现有直接/兼容/注入支持，不借此退役入口、收窄类型或改变业务权威 |

补充限定：

- “外部创建再传入”是指在 HTTP 服务器创建函数之外装配，通常仍在同一进程中；正常 main → WorkflowHost → create_server 已采用此方式，不是仅测试才有的场景。直接传入工作流服务及假服务目前另有测试用途。
- 不能仅按“哪一行调用构造函数”判断关闭责任，应明确谁持有和管理生命周期；同一对象不得同时登记为两个负责关闭的所有者，也不能无人负责。兼容分支的具体适配布局由工程落实，不要求一定新建独立模块。
- 本批不增加“关闭异常后继续清理、吞错、聚合异常、自动重关”的政策，也不默定关闭后重新取得或新增关闭幂等语义。若实现离不开这些改变，先单列行为、影响和验证再由用户决定。
- 管理与执行的角色按原 authority 分类，生命周期操作仍委托已有执行协调者；不要求管理角色为处理普通查询先创建执行图。
- 启动预检归属、阻断条件、Vite 代理、可选 `--workbench-dist`、包来源/启用/加载/发布保持现状；这些不作为本批额外待选方案。必须改动时才进入 D4/D7，不能以“框架整理”代替批准。
