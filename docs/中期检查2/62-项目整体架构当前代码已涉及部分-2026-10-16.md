## 1. 收录口径

只要当前产品代码已经涉及某项职责，就纳入本文，包括局部实现、由其他模块承载的实现，以及与设想不一致的实现。名称中带 `graph` 或 `workflow`，不妨碍其代码事实上承担项目共享职责。

“已涉及”不等于目标架构完成、功能充分、测试通过或已部署。已有模块尚缺独立外壳、统一管理或清晰边界，属于本文的实现差异，不整体移入 63 号。

当前产品实现以 `backend/src/phase1_agent/`、`frontend/src/` 和 `scripts/` 的实际入口、调用和注册为依据。历史文档、退役页面源码、`vendor/` 归档、测试替身和外部开发工具不能单独证明某项产品能力已安装。

## 2. 总体结论

当前是以工作流为核心的本机应用，已经具备独立内容管理、独立供应商管理及多种共享基础机制。它并非所有功能都必须通过工作流执行才能使用，但还不是完全按项目母层与并列子模块组织的平台。

主要依据：

- [WorkflowHost](../../backend/src/phase1_agent/workflow_host.py)按需提供内容、供应商、原请求证据、图管理和图执行服务。
- [GraphApplication](../../backend/src/phase1_agent/graph_application.py)统一分派命令与查询，部分操作转向独立管理服务。
- [GraphWorkflowService](../../backend/src/phase1_agent/graph_service.py)仍通过多个 mixin 组合配置、数据、历史、生命周期、聊天及执行职责。
- [App.vue](../../frontend/src/App.vue)的主区域仍是工作流画布/历史；[WorkbenchSidebar](../../frontend/src/components/WorkbenchSidebar.vue)提供工作流、供应商、内容三个并列导航入口。

因此，用户提出的“项目不绑定工作流”已有局部实现基础，但当前应用组织仍明显以工作流为中心。

## 4. 多层数据管理涉及情况

当前内容、供应商及工作流服务主要共享所选业务 SQLite；私有凭据使用其旁独立的 `<database>.credentials.sqlite`。稳定和开发入口默认使用不同业务库。

数据管理已经按职责分开，但不是“每一层一个物理数据库”，也没有一个可任意读写全部业务的统一数据服务。

| 数据领域 | 当前权威及代码 | 与设想的关系 |
| --- | --- | --- |
| 全局内容、供应商和模型配置 | [global_resources.py](../../backend/src/phase1_agent/global_resources.py)，由各业务管理服务使用 | 已有项目级资源身份、当前值及修订，不属于某个工作流会话 |
| 工作流目录、定义与正式配置 | [graph_store.py](../../backend/src/phase1_agent/graph_store.py)、[workflow_configuration.py](../../backend/src/phase1_agent/workflow_configuration.py) | 已涉及列表、定义修订和当前配置，固定与可调部分分开处理 |
| 会话及会话下内容 | [session_objects.py](../../backend/src/phase1_agent/session_objects.py)、[program_variable_store.py](../../backend/src/phase1_agent/program_variable_store.py) | 会话隔离、准确项、对象权限和版本更新；不是登记处保存全部当前值 |
| 类型和节点声明 | [graph_contracts.py](../../backend/src/phase1_agent/graph_contracts.py)、[type_contract_store.py](../../backend/src/phase1_agent/type_contract_store.py) | 声明与契约检查已有，不能将其等同于普通业务值仓库 |
| 运行事实与产物 | [runtime_fact_store.py](../../backend/src/phase1_agent/runtime_fact_store.py)、[graph_records.py](../../backend/src/phase1_agent/graph_records.py) | 保存实际运行依据、状态、输出及事实，与当前编辑图区分 |
| 检查点 | [checkpoint_collection.py](../../backend/src/phase1_agent/checkpoint_collection.py)、[checkpoint_repository.py](../../backend/src/phase1_agent/checkpoint_repository.py)、[checkpoint_loading.py](../../backend/src/phase1_agent/checkpoint_loading.py) | 按明确准入收集、保存和新目标装载，不是数据库的任意全量快照 |
| 凭据 | [credential_store.py](../../backend/src/phase1_agent/credential_store.py) | Windows 当前用户及原路径保护，通用业务数据不保存 Key 正文 |
| 操作证据 | [request_evidence.py](../../backend/src/phase1_agent/request_evidence.py)、[graph_application_identity.py](../../backend/src/phase1_agent/graph_application_identity.py) | 保存原身份并核实结果，不以重发替代核实 |

当前存储版本为 `20`，正式编辑图使用 schema `3`，检查点 schema 为 `4`。这些与节点版本、能力包版本和软件版本独立，不能统称某一个“数据库层版本”。

差异归类：统一数据规则、跨域归属和公共装配已经有相关代码；尚未形成目标中的统一项目级数据管理结构，是“已涉及但组织不同”，不属于完全空白。

## 9. 工作流内部的已涉及结构

### 9.1 基础构建与初始化

`GraphWorkflowService._initialize_service` 已处理持久化准备、能力包装载、声明校验和执行宿主所需依赖。`WorkflowHost` 区分按需的图管理与图执行访问；会话有独立初始化路径。

这已经涉及用户的“基础构建”，但不是独立、纯粹的统一初始化模块。相关责任分布在服务装配、包、资源和数据模块中。

### 9.2 定义、数据及检查点

节点和类型声明由 registry 与定义契约管理；图定义和配置通过仓储保存；会话对象通过显式身份、授权及版本更新；运行事实和检查点各有模块。

上下文、变量、逻辑聊天不是同一份数据。Agent 和前端节点可以登记相应类型下的独立项，实际读取、更新与保存职责由对应模块承担。

检查点按准入保存配置、Agent 上下文、变量及逻辑聊天，分叉初始化新会话，不覆盖源会话。可调配置不因分叉恢复成旧点中的任意历史值，须按正式配置规则解释。

### 9.3 工作流配置

[workflow_configuration.py](../../backend/src/phase1_agent/workflow_configuration.py)管理正式配置、编辑依据、固定与可调修改及确认派生；[configuration_mutations.py](../../backend/src/phase1_agent/configuration_mutations.py)提供准确节点的窄配置修改规则。

[workflowGraph.ts](../../frontend/src/stores/workflowGraph.ts)组织前端图与管理动作，[graphConnections.ts](../../frontend/src/domain/graphConnections.ts)处理连线校验。

这里的实例创建和修改，不等于 `CapabilityPackageLoader` 的节点类型注册。相关工作已经存在，但代码仍跨前端 store、应用服务和 graph mixin 分布。

### 9.4 运行和工作流操作

[graph_contracts.py](../../backend/src/phase1_agent/graph_contracts.py)负责图契约和编译；[graph_execution.py](../../backend/src/phase1_agent/graph_execution.py)、[runtime.py](../../backend/src/phase1_agent/runtime.py)、[graph_runtime_host.py](../../backend/src/phase1_agent/graph_runtime_host.py)承担执行和宿主接线。

普通执行按工作分类及实际连接筛选，依赖优先，就绪节点按创建顺序处理。输出节点出现结果不等于整轮完成，Runtime 仍等待计划内工作及接纳完成。

[agent_package.py](../../backend/src/phase1_agent/agent_package.py)注册 `agents.execute@10`；[context_v4_nodes.py](../../backend/src/phase1_agent/context_v4_nodes.py)提供读取、装配、写回。Agent 计算与会话持久上下文管理已有明确分工。

独立的 [workflow_chat_operations.py](../../backend/src/phase1_agent/workflow_chat_operations.py)、[workflow_chat_service.py](../../backend/src/phase1_agent/workflow_chat_service.py)处理逻辑聊天、候选和接续；[frontend_node_operations.py](../../backend/src/phase1_agent/frontend_node_operations.py)核实准确节点归属后调用独立功能。

这些是“运行与功能调用”已有的实际结构，不表示通用并行调度、生成代码执行或活动执行跨进程恢复已经实现。

## 10. 对设想的差异汇总

| 设想方向 | 已涉及但尚不一致的地方 |
| --- | --- |
| 独立项目母层 | 有独立服务，但外壳、装配、部分契约及执行身份仍以工作流组织 |
| 统一数据管理 | 有共享设施与分域仓储，但不是完整项目数据管理平台 |
| 独立模型能力 | 管理可独立，运行请求的授权和事实仍绑定工作流上下文 |
| 内容工作台 | 业务已有，前端仍在工作流中心外壳；旧预设入口不能当现行能力 |
| 项目功能配置 | 配置和协调已涉及，但分散且没有完整独立的项目层 |
| 功能和插件管理 | 有可信本机包机制，不是面向不可信代码的通用插件平台 |
| 工作流四部分 | 相应职责均已有代码，实际模块边界不与设想逐项一一对应 |

这些差异属于现有架构的分析对象，不因未达目标就记为“代码完全没有涉及”。
