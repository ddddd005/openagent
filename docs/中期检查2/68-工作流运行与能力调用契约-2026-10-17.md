# 工作流运行与能力调用契约

日期：2026-10-17，Asia/Shanghai。

性质：本阶段职责契约。本文规定 Runtime、工作流运行图、定义目录和检查点、重roll、分叉等能力模块的调用关系。

2026-10-18 接续：[75 号能力资产与统一调用规划](75-工作流能力资产与节点工具统一调用接续规划-2026-10-18.md)补充节点与 Agent 工具绑定真实能力、共用调用渠道，以及工具所加载的节点与实际节点实例同等加载和准备、纳入工作流启动范围的要求；不只是提前加载实现函数。Agent 不继承其他节点实例配置，也不要求画布上存在对应业务节点；Runtime 不因此接管 Agent 内部思考与工具选择。具体调用机制归属、加载步骤、实例和持久数据接纳仍待确认，不修改本文历史事实或表示产品已完成接入。

## 1. Runtime 职责

Runtime 负责把固定的工作流定义修订和会话上下文转换为一次可执行运行：

- 读取节点和功能定义；
- 构建工作流运行图；
- 根据数据边和控制边规范化执行顺序；
- 规范化节点和功能调用；
- 推进运行状态；
- 保存运行事实、输出和错误；
- 判断节点、阶段、轮次和整批运行是否完成；
- 发出能力模块可以消费的生命周期通知。

Runtime 不负责：

- 维护静态工作流定义；
- 直接操作数据库表；
- 直接实现检查点、重roll和分叉的业务语义；
- 为每种后续能力写死专用分支。

## 2. 工作流运行图

工作流运行图是 Runtime 的运行期结构，来源于：

- 固定的工作流定义修订；
- 节点类型和功能声明；
- 数据边和控制边；
- 会话当前允许使用的配置和资源；
- 当前能力包和精确版本。

运行图可以是内存结构，也可以保存必要的编译事实，但不能反向修改静态工作流定义。

本阶段优先明确数据边和控制边的执行语义。`execution_roots` 已于 2026-10-17 由用户单独决定退役并在本地实施：普通执行只由真实数据边和控制边决定范围，孤立 working 节点不执行，图文档不再接受该字段；历史定义在读取时丢弃该键。实施与验证见 01 号 D2 结论。

## 3. Runtime 与数据管理

Runtime 通过会话数据接口写入：

- 运行状态；
- 节点运行和链运行；
- 运行事实；
- 输出；
- 错误；
- 批次完成信息；
- 能力模块产生的会话引用。

Runtime 不直接写工作流定义域。需要改变静态配置时，必须回到配置管理流程。

## 4. 能力注册和生命周期

能力模块通过定义目录声明：

- 能力身份和版本；
- 可消费的生命周期事件；
- 所需的数据读取和写入范围；
- 是否允许在运行期间调用；
- 失败时的诊断方式；
- 与其他能力的依赖关系。

Runtime 只负责发出规范化事件和提供运行上下文。能力模块通过数据管理接口保存自己的数据，不把能力内部数据混入 Runtime 的通用状态。

最低生命周期事件可以包括：

```text
run_started
round_started
node_completed
round_completed
run_failed
batch_completed
run_finished
```

具体事件名可以调整，但事件的作用域、顺序和失败处理必须明确。

## 5. 检查点、重roll和分叉

三者属于不同能力：

### 5.1 检查点

检查点负责按照准入规则收集、保存和装载会话状态。它是重roll和分叉可以复用的基础能力，但不拥有整个会话数据库。

### 5.2 重roll

重roll负责在同一轮次中基于规定的轮次基线生成并保存多个候选，并记录选中的候选如何继续运行。它不应覆盖原会话的既有候选或历史事实。

### 5.3 分叉

分叉负责从检查点或候选状态创建新的会话分支。分叉不修改源会话，新的会话固定自己的定义修订、数据引用和运行历史。

## 6. 检查点与配置层、数据层的边界

本阶段需要专门论证检查点的准入和读取路径。阶段指导建议如下：

- 检查点的最终保存和装载通过数据管理模块完成。
- 检查点使用明确的准入名单或准入策略决定哪些数据可以保存。
- 配置管理只提供静态配置快照或配置读取视图，不负责检查点写入。
- 会话变量、上下文、逻辑聊天、运行事实和候选由各自会话数据接口提供。
- 检查点不直接绕过数据管理调用配置表或数据库表。

采用这一边界的原因是检查点覆盖的不只是静态配置，还包括会话对象、变量、上下文、聊天、运行事实和候选。配置层无法成为全部检查点数据的归属者，但配置快照可以作为被准入的数据项之一。

最终准入名单、检查点版本和失败处理仍需在实施中依据现有 checkpoint contract 验证，不在本阶段提前扩张为全量快照。

## 7. 能力失败和运行失败

能力模块的失败必须有明确分类：

- 不影响主运行结果的附加能力失败；
- 阻止后续继续或分叉的能力失败；
- 导致当前批次失败的能力失败；
- 数据一致性或版本冲突。

Runtime 不能静默吞掉能力失败，也不能为所有能力预设自动重试或回退。能力注册声明应说明失败是否影响运行状态，基础支持负责向工作台展示诊断。

## 8. 本阶段完成要求

阶段结束时至少应能证明：

1. Runtime 可以从固定工作流定义生成运行图。
2. 执行顺序和功能调用不再依赖页面按钮顺序。
3. Runtime 的运行数据通过会话数据接口保存。
4. 检查点、重roll和分叉有独立能力边界。
5. Runtime 根据注册能力和生命周期事件调用后续功能。
6. 检查点的准入名单、数据层交互和配置快照读取路径有明确结论或明确的待决记录。
