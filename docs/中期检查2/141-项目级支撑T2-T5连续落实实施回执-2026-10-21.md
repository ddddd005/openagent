### 6.2 事务顺序（实际）

```text
应用层校验请求形状与固定身份
→ configuration_service.copy_definition 构造精确五字段请求
→ 复用原配置命令事务 _configuration_change → GraphRecordStore.atomic
   → BEGIN IMMEDIATE
   → 先查同 operation/key 回执并比对原请求摘要
       → 命中：COMMIT 并返回原结果，不再读取源/目标，不重建已删除目标
   → 未命中：事务内配置端口读源 current + 确切 fixed
       → 无 current：有固定记录 → graph_configuration_missing(409)；
         无任何正式记录 → not_found(404)（不读历史固定文档补造 current）
       → 来源修订/编辑序号与请求不符 → stale_revision / stale_edit_sequence(409)
       → 目标任一正式定义/current/管理记录存在 → graph_definition_conflict(409)
       → 深拷贝正式 current 组合，改目标身份/名称、revision=1、去 edit_sequence
       → validate_graph_document + schema3 + validate_session_item_registrations +
         validate_node_configuration
       → save_fixed_revision(document, 0) → _write_configuration(..., 1)
       → 事务内 _configuration_view 回读正式 current
       → 写原生回执 + application identity
   → 同事务提交；异常原样回滚业务与回执
```

不写源、不锁源、不调用源定义配置运行锁、不暂停源运行；不新增资源存在性/安装检查；不复制任何会话、运行、检查点、变量值或前端未保存编辑。
