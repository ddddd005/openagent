### 3.1 G-A：手工目录、声明与启用

建议默认目录为 `<主 SQLite 所在目录>/packages/workflow/`，通过 `--workflow-package-root` 可显式指定其他目录。包文件属于项目提供的来源环境，工作流仍负责加载及解释包；不将此目录变成项目任意子能力动态注册入口。同一父目录的数据库可以共用来源文件，启用选择仍分别保存在各自主库；需要不同来源时显式指定目录。

每个直属子目录放一个包版本，目录名不承担身份权威。例如：

```text
packages/workflow/sample-nodes-1.0.0/
  openagent-package.json
  sample_nodes/
    __init__.py
    package.py
```

建议外层声明只包含自身格式版本、包内入口和原有 manifest，不重新发明包导出格式：

```json
{
  "schema_version": 1,
  "entrypoint": "sample_nodes.package:create_package",
  "manifest": {
    "schema_version": 1,
    "package_id": "sample.nodes",
    "version": "1.0.0",
    "host_protocol_version": 1,
    "dependencies": [],
    "exports": {
      "nodes": [{"component_id": "sample.echo", "component_version": "1.0.0"}]
    }
  }
}
```

建议同时确认以下用户可见行为：

1. 放入目录只使包可发现，不自动启用或升级。启用复用现有 `packages.configure` 准确版本选择，不新增安装器。首版操作方式须在交付使用说明中明确，不用测试直接注入冒充用户入口。
2. 发现阶段仅读声明；选中包及其完整依赖才加载入口。声明 manifest 与入口返回身份/依赖/导出声明必须一致。未选包不执行入口。
3. 目录包之间、目录包与内置包的重复准确身份明确拒绝；不静默覆盖。现有可信直接构造参数的替换语义保持，不随目录接入重构。
4. 目录/声明错误显示具体诊断；所选集合依赖坏项时整集合失败。缺 Python 依赖明确报告，不自动安装；不做运行期目录热扫描。入口须来自该包目录，不能通过全局模块搜索意外取得另一个同名实现。

目录创建方式、私有缓存组织、内部模块命名属于工程细节。导入隔离方案须满足包内相对导入及准确来源，不能只把包目录插入全局 `sys.path` 就宣称多包同名模块已隔离；也不承诺隔离任意 Python 副作用。

### 3.3 G-C：工具首版支持边界

建议首版支持“纯计算 + 既有变量对象读写”，以无变量工具的真实包消费证明通用装配。支持边界固定后，准备结构/适配接口的兼容实现由执行方具体设计并记录，不要求用户逐字段设计代码。

| 类别 | 首版建议 |
| --- | --- |
| 纯计算 | 原生同步目标，仅显式参数、配置及准确内容类型；无对象、会话变量、共享态、资源、服务、私有态和外部业务副作用，返回 JSON 对象 |
| 既有变量对象读写 | 保留注册变量、`read/set/add/subtract`、Agent ACL、单对象逐次接纳与独立重读，不扩为任意对象 CRUD |
| 参数 | 沿用严格对象、必填非空类型标量及零参数；不顺带开放可选/嵌套 schema |
| 资源/网络/文件/宿主服务/私有态 | 当前不开放；不能通过参数或直接传入 Host 绕过 |
| `executor_ref`、特殊结算、多对象写、删除 | 当前不开放，须有各自领域契约后再接入 |

纯计算是可信本地包应遵守的宿主接口约束，不是 Python 沙箱承诺。现有目标检查尚未全面排除旧变量与共享态能力，不能直接把“通过旧检查”认作纯计算准入。

共同准备层只承载准确来源、Agent 归属、名称/数量/schema、目标与配置；变量对象解释和权限核查放在变量适配中。共同调用层校验归属、参数、输入输出和结果；变量调用保留当前接纳链，纯计算调用不提供业务状态、不伪造对象、不借 `read` 操作冒充无状态。包内新增同类工具不得要求通用核心增加工具名或业务类型分支。
