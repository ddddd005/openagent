## 3. 绑定与准备

### 3.1 锚点配置

```json
{
  "agent_node_id": "<真实 Agent 节点实例>",
  "variables": [
    {"alias": "score", "object_key": "variable/score",
     "operations": ["read", "set", "add", "subtract"]}
  ]
}
```

锚点 `non_working`、无端口、无 executor、无 `object_accesses`、无 service/resource 声明，不进入 `plan.ordered_node_ids`，不建边、不建隐藏节点。`agent_node_id` 用 `config_node_references` 指向 `agents.execute@10`；同一 Agent 内 alias 与模型工具名唯一；变量必须已在文档 `object_bindings` 中声明。

### 3.2 逐目标准备对照

| 检查项 | 变量首版实际处理 |
| --- | --- |
| 定义与准确版本 | `registry.get(component_id, component_version)` + `basis.definitions.get("node", ...)`；缺定义/来源显式失败 |
| 包来源与版本 | `PreparedToolSpec.source` 与 `PreparedToolBinding.anchor_source` 保存 definition 查询返回的 `{package_id, package_version}`；不按名称或 latest 猜测 |
| 实现 | 目标必须有原生 `executor`；`executor_ref`、缺失 executor 显式拒绝 |
| 配置与参数边界 | `registry.validate_config` 校验目标配置；调用前按目标输入端口校验内容；结果按输出端口校验 |
| 类型 | `workflow.variable@1` 且已注册；启动检查 value_type 与 operations；add/subtract 只要求数值类型，是否已赋值由每次调用的真实 executor 检查（允许上游普通节点先赋值） |
| ACL | Agent `node_binding_id` 必须在对象 `readers`；写操作还须在 `writers`；读取当前对象与接纳均再次按 Agent 身份校验 |
| 服务/资源 | 变量目标无声明；出现 service/resource/外部输入/私有态/settlement/额外图连线时启动拒绝 |
| 对象访问 | 目标上下文使用目标节点定义的能力和单一对象访问声明；不把变量对象权限并入 Agent 定义 |
| 宿主 | 首版只接受原生 executor；宿主目标显式拒绝并记入留存 |
| 执行 | 准备阶段只读对象当前记录用于类型/操作检查，不调用 executor，不创建 node_run，不改变变量值 |

### 3.3 准备结果

`PreparedToolFrame` 按链路保存在 `_tool_frames[chain_id]`，与 `_execution_registries` 同址，释放点一致；包含：

- 每个 Agent 的 `PreparedToolBinding`（binding_id、锚点、alias、object_key、operations、工具集合、包来源）；
- 每个工具入口的 name/operation/access/description/parameters/target component+version/config/source；
- descriptor 节点到 Agent 的只读映射，供提示词节点读取同名工具材料；
- `target_count`，用于准备证据。

没有画布变量业务实例时仍完成上述准备；测试 `test_start_prepares_tool_targets_without_business_execution` 以拦截 executor submit 证明准备返回时变量 executor 调用 0 次、Agent 模型调用 0 次。

## 4. 共同调用与身份

```text
Agent 内核生成 tool_call_id + tool_execution_id
→ RegisteredTool.execute(..., invocation=ToolInvocation)
→ NodeExecutionContext.invoke_bound_tool(binding_id, operation)
→ GraphToolHost 校验 owner、准备帧、绑定与参数
→ 目标 NodeDefinition + 原生 executor(deepcopy(config), deepcopy(inputs), 有限 context)
→ 变量 executor 形成写意图
→ 逐次接纳事务
→ 事务后独立重读
→ 工具结果返回内核 → tool_settled / message_accepted 事实
```

- 模型工具名、描述、参数 schema 与内核 callable 来自同一 `PreparedToolSpec`；`make_public_agent_snapshot` 的 `tool_definitions` 与 `SnapshotKernel.run` 的 tools 由 `_agent_tools` 同一结果生成，快照和内核仍互相校验。
- `final_answer` 仍是内核控制工具，不伪装成业务节点。
- 普通节点入口和工具入口都调用注册表中同一个 `tools.variable-assign@1` / `tools.variable-to-content@1` executor；测试用包装计数器证明正常节点与工具调用命中同一函数对象。
- `tool_call_id` 是内核生成的身份，不是模型参数；`tool_execution_id` 每下发一次生成且不重复。
- 不新增 Agent 节点 capabilities、不新增 `agents.execute` 版本；调用桥只由执行层注入，非 Agent 节点无法取得已准备绑定进行调用。

## 5. 写入接纳、独立重读与失败保留

### 5.1 单次写事务

1. 桥从数据库读取目标对象当前记录，构造只含该对象的有限 `NodeExecutionContext`；`node_binding_id` 为真实 Agent，`operation_scope="tool:<tool_execution_id>"`。
2. 真实 executor 只形成写意图；不并入 Agent 的 `object_writes`。
3. 要求恰好一个 `put` 意图，目标、期望修订与读取一致，操作键前缀匹配本次执行身份。
4. `_change("graph.tool.object-write", "tool:<tool_execution_id>")` 在事务内重查 session/chain/Agent node_run 仍活动，调用 `ExecutionState.apply_objects`，`node_id` 为 Agent，`write_evidence` 含 tool call/tool execution/binding，revision 与 CAS 由对象存储复核。
5. 事务提交后独立重读对象；`revision`、`revision_id`、值与接纳回执一致才返回成功，否则报 `tool_acceptance_mismatch` 并停止。
6. 接纳回执的结果载荷保存 `object_key`、`binding_id`、`tool_call_id`、`tool_execution_id` 与对象存储回执；操作键与 `session_object_receipts` 关联本次工具执行。
7. 更新 Agent 运行对象视图；Agent 节点成功结算时对象写集为空，后续普通节点从数据库刷新对象视图。

### 5.2 失败与控制

- 第二次工具失败不回滚第一次已接纳写入；测试中第一次 set(10) 已提交，第二次 set(2^53) 类型错误后会话 failed，对象仍为 10。
- 参数 schema 错误在能力执行前失败，不写对象；越权、缺对象、缺目标实现均在 `start` 前失败，后台提交与模型调用为 0。
- 接纳事务内 owner 复核拒绝暂停/关闭竞争；独立重读失败显式停止，不自动重放已计算的 add/subtract。
- `tool_dispatch`/`tool_settled` 仍是独立事实事务；对象接纳回执是独立命令事务；两者不合并，也不把过程事实冒充保存回执。

## 6. 提示词材料

新增 `tool-bindings.tool-prompt@1`：配置引用同一真实 Agent 与精确工具名，运行时从本次准备帧读取该工具的描述和参数 schema，生成 `tool-descriptions` / `tool-schemas` 两个 `PROMPT_MATERIALS@1` 材料端口。它不授予权限、不决定加载、不改变工具集合；展示位置与顺序由 presentation 组织。`prompts.tool@2` 的内置静态目录未改动。

验收测试同时断言：Agent 快照中的 `score_read` 描述与参数 schema 出现在提示词材料中；正常 Agent 工具调用仍可执行。
