## 1. 本步任务与最新决定

1. 工作流保存独立的会话数据预加载列表，声明名称/准确类型/初始值及权限；列表不局限于变量。
2. 普通新会话完成基础初始化后，通过会话域操作一次性注册数据并赋初值，在同一创建事务中完成后才返回成功。
3. 列表本身持久保存；对每个会话只应用一次。后续配置变更只影响新依据下创建的会话，旧会话不被追随修改、重置或补值。
4. 会话域负责所有实际值及后续更新；节点依准确对象键和权限读写。项目、工作流配置不跨域直接改会话值。
5. 普通创建与检查点/floor fork 区分；分叉继承检查点数据，不重新应用预加载初值。
6. Agent 仅操作已有获准值。将来独立的数据草稿工具不在本批；不开放声明/首次注册/类型维护或工作流通用创建删除权限。
7. 类型统一复用 `DataTypeDefinition` / `TypeRegistry` 及准确包来源、版本证据、目录和运行冻结。本批用变量真实链与新增非变量结构证明通用性。
8. 预加载只承载数据初始化，不调用模型、网络、文件业务或调度任务，不增加 T6 运行阶段。

154 中“沿用注册节点作为唯一维护入口”和“建会话后仍需显式注册”的建议已被以上决定取代。新列表以独立来源落地；旧注册节点保留历史行为，不能为兼容同时维护同一键的两份声明。

## 3. 最小数据契约

### 3.1 单一声明来源

schema 3 工作流文档新增可选 `session_preloads`，每项严格为 `{object_key, value}`。`object_key` 引用同文档唯一 `object_bindings`；准确 type_id/schema_version、shared/private、owner、readers/writers 仍由该 binding 唯一承载。`value` 是该类型的完整初始逻辑值，列表是它唯一的配置来源。

规则：有界数组、键唯一、必须存在对应 binding；该 binding 不得另有 `default_value` 或 `registrar_node_id`，避免旧节点与列表同时负责注册。旧文档没有字段时保持原字节形状，不自动加空列表或批量迁移。旧 schema 1/2 不接受新字段，编辑按已有升级流程进入 schema 3；旧程序读取新字段会拒绝，不能声称向旧程序兼容。列表变化属于固定配置，沿原运行锁、CAS、有效会话确认派生、回执与独立重读。

变量沿用 `workflow.variable@1` 完整值格式。前端提供名称、标量类型、是否赋初值与初值控件，生成已注册逻辑值；会话创建后即可被原变量消费者使用。未赋值变量仍可表达，禁止用未注册空壳冒充完成预加载。其他普通结构直接使用同一准确类型的 JSON 值。

### 3.2 类型与首版准入

普通结构由已加载可信包通过既有注册接口提供，进入同一 session 类型目录；不在列表内再定义 schema，不增加第二注册权威。本批不新增交互式类型 CRUD 平台、项目共享声明库或任意用户 Python 执行入口；新增结构通过现已可用的本地包加载链供给，列表消费这些类型。

本次普通结构支持 `scope=session`、准确版本、`checkpoint_admission=true`、声明式 JSON schema 的类型。变量使用已有准确类型校验器；其他类型若需要自定义 validator、引用解析/映射、迁移、写入钩子、artifact/public 引用或内容变换等专用行为，保存时明确拒绝并报告，不把它们当作可直接复制的普通结构。已有 Agent/chat 等特殊类型继续原路径，不自动迁入通用列表。无类型默认值但列表有显式初值应可初始化，不造假默认值。

这些限制使首版从保存到恢复都有完整语义；后续特殊类型接入须落实其领域规则。类型声明版本仍不可原地改写，运行仍取同次冻结依据。

实施交叉核对的具体化：变量、chat、effective-context 的类型 ID 保留专用语义，除准确 `workflow.variable@1` 外，其其他版本也不能假借普通结构进入列表。声明式 schema 的引用限本地 fragment；远程/文件引用在调用类型校验器前拒绝，维持本期“不执行网络、文件业务”边界。

### 3.3 会话初始化与事务

普通创建继续原 `graph.session.create` 幂等事务：基础会话/私有态和旧对象初始化 → 会话域预加载入口创建列表对象 → 完整对象/类型/权限与引用一致性校验 → session_seed commit/manifest → 原回执/返回。预加载对象不先要求不存在的类型默认值，初始记录只创建一次；失败整事务回滚，重放原创建回执不再加载。

实现可让基础初始化暂不创建列表负责的对象，再由专用会话初始化操作写入。该操作只可用于准确、尚未完成种子提交的新会话，要求既有基础对象完整、新键尚无记录，不是给运行期新增任意数据的公开 API。不能靠放宽普通写权限完成。存在跨对象引用的旧基础项须在完整初始集合形成后校验，不能漏校验。

### 3.4 检查点及计算态承接

三路勘察确认当前只有 agent_contexts/variables/chat_contexts 三分区，且变量检查点要求节点 registrar。这不足以保存用户新要求的独立预加载及普通结构。本批以有限扩展支持已批准的“分叉继承历史”：

- 独立预加载变量仍进入原 variables 分区；准确预加载声明可作为注册来源，不伪造隐藏节点。
- schema 4 检查点逻辑态增加可选 `preloaded_items`，只记录列表声明且通过上述准入的非变量普通类型，形状为键到 `{type_id, schema_version, value}`。不扩大成所有会话对象自动采集。
- 贯通 full/diff、物化、原事务收集、RunData 收集、新目标 load、chat 初始计算态、reroll/select/floor fork。旧记录缺省分区不注入空对象，保持原哈希/不可变记录及旧检查点读取。
- fork 的基础准备从准确历史状态取得预加载对象的恢复初始值，不读取列表初值；之后保留原 pristine/CAS、类型及绑定核对并在同一 fork 事务装载。无默认值普通类型也不能用列表默认值假装历史恢复。
- 三个专用分区与通用分区键不重叠；类型失配、缺键、额外键或不支持引用明确失败，不能静默忽略或填默认值。

同一检查点差分链出现 `preloaded_items` 后，后继态若移除整个字段须明确拒绝；清空应显式保留 `{}`。原本没有该字段的旧链保持原形状，不注入空分区。此为实施交叉核对发现的形状收口，不新增差分字段删除协议。

这是通用预加载闭环必需的数据承接，业务分叉范围、候选截断和原事务所有者不变。若实现发现必须修改上述已定业务规则，停止报告，不继续扩大。

## 4. 前端与模块职责

| 模块 | 本批职责 | 明确分开 |
| --- | --- | --- |
| 新预加载契约模块 | 结构/来源/准确类型准入与初值校验，可由配置和创建共用 | 不存数据库、不发模型请求、不持有会话 |
| graph_contracts / 配置保存 | 接受字段并校验，原正式保存/复制/派生保留字段 | 不自动迁旧注册节点、不直接写会话值 |
| SessionObjectStore / Graph 创建入口 | 会话域一次初始化，原事务原子性与创建回执 | 普通创建与历史恢复分路；不增加运行期公开注册权 |
| runtime_checkpoints / collection / loading / chat | 通用值准确保存和恢复，保留旧形状和专用规则 | 不把 preload 初值用于恢复，不扩大未声明对象准入 |
| 工作流 Workspace 新数据视图 | 无会话也可编辑列表；选择已加载准确类型、值、归属和节点 ACL | 工作流配置界面与会话当前值界面分开，不显示运行值为可改默认值 |
| 工作流 Store / 前端 document 类型 | 同一次编辑提交 binding 与 preload，沿原配置应用和证据/回执链 | 不分两次保存造成半配置，不恢复旧 save API |

前端从当前 Workspace 禁用的变量入口接入“会话预加载数据”，采用现有工具栏/工作区风格。列表支持新增、选择、编辑、删除；变量提供明确控件，普通结构用 schema 对应控件或有错误提示的 JSON 编辑。类型来源显示准确 ID/版本；空状态、运行/归档/待核实只读状态、错误及切换工作流都按现有模式处理。

实现核对后，列表的已创建对象键保持稳定，编辑不自动重命名该身份；仍可修改变量名称、初值和权限。不以通用核心猜测包内 opaque 配置的引用位置。类型匹配同时要求 `scope=session`、ID 与版本，避免与同名同版本的 content/global 类型混淆。

原绑定编辑器与节点增删/复制/替换须保留新列表：删除 binding 不可留下 preload 悬挂；复制私有 binding 时相应初值需要准确重映射；旧 provider 节点的自动绑定不能覆盖列表项。同一工作流正式复制保留配置列表、不携带会话；已有注册节点仍是旧键的唯一来源，不自动迁移或修改其 @2 契约。未来节点可在配置阶段通过同一编辑入口提供预加载数据，不需要核心为每个类型增加分支。
