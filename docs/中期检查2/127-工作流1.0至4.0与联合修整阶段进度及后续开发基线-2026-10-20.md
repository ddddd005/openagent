## 2. 已建立的主干及接入边界

当前可以作为后续工作的已有基础：

```text
配置来源 → 配置功能接口/共用规则 → 数据管理/配置域 → 正式配置及独立读取
包来源 → 既有 loader/注册 → 只读定义目录 → 本次 RunBasis
启动 → 准备事务/图计划/类型实现权限核验/工具准备帧 → prepared 与 chain_start
准备提交 → 后台图推进 → 真实节点或宿主调用 → 节点接纳 → 下游
Agent 工具 → 同次准备结果/自身授权/共同 executor → 逐次接纳与独立重读
图结束 → 适用的共同结算 → 提交后通知/窄诊断 → 保留或释放 → 查询消费
```

| 职责 | 已有主干承担什么 | 后续接入继续遵守什么 |
| --- | --- | --- |
| 功能管理与业务 | 变量、上下文、聊天、检查点等领域实现具体业务 | 功能不自行激活、不决定下游；不强制节点内部每步登记结果 |
| 配置管理 | 维护节点实例、参数、引用、连线与规则，统一受理配置修改 | 保存不执行节点；定义级活动链锁在原写事务内检查；工具变量写不等于配置提交 |
| 定义与注册 | 来源维护声明/真实实现，首批只读目录供配置与执行消费 | 不另造可编辑权威；正常运行依据缺失时报错，不以服务当前 registry 掩盖 |
| 项目包支持 | 已有加载、准确包版本及项目选择机制，首批工具校验冻结包来源 | 复用基础；未建设完整发现、安装、热切换、发布平台 |
| 执行 | 流执行组织准备、图调用、控制和结束，图执行按真实数据边/控制边推进 | 工作流、工作流图、图计划分别表达；Agent 在执行层内，不要求耦合图执行模块 |
| 数据管理 | 分发有限领域接口，所属数据模块承接真实存取 | 保留原事务、回执、归属和幂等；不向业务暴露任意 SQL，不互调其他领域仓储 |

这些是职责划分，不要求六类各建一个服务。会话承担数据隔离和归属，不建设包办业务的“会话层”。页面连接、候选操作和图内执行分别受管理，不引入常驻自行激发的前端节点。

4.0 当前准确产品入口为 `workflow.tool-prompts@1.0.0` 中的 `tool-bindings.variable-tools@2`，输出唯一 `TOOL_PROMPT@1`，由 `context.assembly@6` 的可选 `tool_prompt` 输入消费。工具说明/参数成对，各有上下文前、中、后布局；展示不取得执行权限。启动准备只读，不调用业务 executor；缺帧、来源不符、schema 非法显式拒绝。真实合并后的静态工具、绑定工具与唯一 final_answer 总量上限为 120。

图成功、节点接纳、共同结算、通知成功分别表达。后续错误中止当前业务调用链并显式报错，已接纳前缀保留；不安装默认吞错、自动重试、补偿或未知请求重放。必要共同结算不能拆成“先成功、后补写检查点”。详细语义沿用 [90 号](90-执行层三阶段论证与节点自由度确认-2026-10-19.md)、[92 号](92-工作流业务对象与操作职责表及3.0边界整理-2026-10-19.md)、[95 号](95-执行层3.0阶段3.2数据端口与事务绑定局部契约-2026-10-19.md)和 125 第 5-6 节。
