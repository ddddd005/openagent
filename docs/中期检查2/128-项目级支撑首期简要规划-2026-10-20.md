## 1. 本期目标

**将现有项目级支撑组织成清楚、可实际使用的主干，让工作流能够从明确的项目环境取得资源、功能和注册结果。**

首期以已有实现的装配、归属、接口接续和缺口补齐为主。供应商、模型预设、内容资源、包加载和节点注册已有真实实现；缺口主要在项目级组织，并非这些领域业务全部空缺。

相较图内执行修整，首期预计交叉较少。这个判断限于下述范围，不是工期承诺；项目管理、跨库结果和包发布仍需逐项核对。

## 3. 首期边界

1. 当前没有独立生产 project_id/workspace_id 实体的勘察证据。首步确认“项目”和“全局”的作用域；本篇不预设多项目、租户隔离或新的项目库。
2. 项目提供能力来源与资源，工作流保有配置、运行依据和自身数据归属；不把共享实现解释为共享运行状态或权限。
3. 数据管理按领域承接存取，功能模块维护业务规则。公开资源与凭据的存取分别表达；供应商跨库业务不包装成一次原子提交。
4. 注册声明和真实实现继续由来源维护，定义目录提供只读查询；不增加第二套注册权威或第二套加载器。
5. 项目资源保留各自取用时机：提示词/Lorebook 在使用时读取，供应商/模型在每次新请求准备时解析；已准备或发送的请求保留原依据，不因整理而改为整轮冻结。
6. 包切换继续保留活动运行与内存保留态检查，核对加载、类型证据提交和新注册结果发布的先后；不能因装配迁移绕过这些边界。

本期暂不包含：工作流外层顺序注册、创建/归档/删除/复制的整体重构、动态类型注册、更广的 Agent 工具族、插件市场/安装平台/热加载。包选择是否新增前端操作界面，待确认真实消费者后再定，不在本篇预设新页面。

127 号的资产交付限制、接纳分类待决、公开损坏读取、请求证据风险及历史审计损失继续单列；首期不默认包办全部遗留项，遇到实际依赖再报告。

## 4. 预想落实步骤：五步

| 步骤 | 主要内容 | 当步产出与进入下一步的条件 |
| --- | --- | --- |
| P1 范围与职责确认 | 沿本篇入口核对项目作用域、服务/数据清单、真实消费者和原事务，选出首批接入路径 | 简要职责与通路表、局部执行安排；涉及新架构、责任边界或行为的事项先由用户确认 |
| P2 基础装配整理 | 接通项目环境、数据库配置、服务依赖与关闭路径；整理 Graph 服务承担的本批项目装配职责 | 一条真实启动与服务取得路径，资源管理不额外激活执行权威；记录迁移范围和保留路径 |
| P3 数据与资源接入 | 先用提示词/Lorebook 验证项目数据通路，再接供应商、模型预设和凭据协作 | 保存 → 回执 → 独立读取 → 工作流实际消费闭环；跨库部分成功/未知等结果保持可辨 |
| P4 包与注册组织 | 整理来源配置、准确包选择、加载、共享功能注册、定义查询与工作流准备之间的接续 | 代表性真实包被工作流消费；版本/来源错误显式拒绝，切换限制与发布失败边界有证据 |
| P5 联合验证与基线 | 汇合装配、资源和包两条主链，核对工作流既有运行及关闭行为 | 实施与验收回执、剩余项清单和后续开发基线；按实际影响选择回归范围 |

依赖顺序以 `P1 → P2 → P3/P4 → P5` 为主。P3 与 P4 在装配和依赖清楚后可分别推进；共享构造、注册发布等修改先协调。每条路径先接通代表调用，再扩大到本期其余路径，不要求先整体拆完 Graph 服务。

P1 确认范围后，再展开局部契约、涉及文件和验收要求；本篇不提前固定完整 API、类名或新表结构。

## 5. 首期完成判断

- 项目环境、数据库与各服务有明确归属，真实入口按该关系装配和关闭。
- 供应商/模型预设、提示词/Lorebook 经过约定业务与数据入口完成保存、独立读取和实际消费。
- 代表性包沿既有加载与注册机制提供真实能力，工作流消费准确来源；声明、实现与查询结果对应。
- 整理保留运行依据、原事务、权限、回执及资源取用时机；错误显式可见，不增加掩盖异常的回退或自动重试。
- 未接入路径、待决行为与未验证内容分别登记，完成依据来自实际改动和当批验证。
