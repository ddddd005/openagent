## 2. 节点声明的精确缺项

源码事实：

- [NodeDefinition及to_dict](../../backend/src/phase1_agent/graph_contracts.py#L305)没有checkpoint_save；[注册校验](../../backend/src/phase1_agent/graph_contracts.py#L396)没有保存路径检查。to_dict是目录及持久descriptor的统一来源，不另造前端权威。
- [descriptor记录校验](../../backend/src/phase1_agent/graph_records.py#L112)只检查descriptor是对象；[完整描述比较](../../backend/src/phase1_agent/graph_service.py#L306)与[配置读取比较](../../backend/src/phase1_agent/workflow_configuration.py#L252)会拒绝同版本变义。
- [固定revision读取](../../backend/src/phase1_agent/graph_service.py#L225)与[固定配置投影](../../backend/src/phase1_agent/workflow_configuration.py#L192)可供核对；后者的members场景会把数组变成身份键控投影，不能把其结果冒充原config_schema的完整配置或直接写回node.config。

本版声明只有 `checkpoint_save.config_paths`。每条路径只沿config_schema.properties，拒绝通配、表达式、数组下标、重复、祖先/子路径并存和不存在的路径；对象/数组可整体声明。配置排除策略先于保存，不能用宽路径夹带可调值或取最新的全局正文。

同一份接口文本还须明确：

| 环节 | 待定稿的最小内容 |
| --- | --- |
| 字段/规范化 | 空声明唯一wire表示；路径顺序是否规范排序；声明必须是有效非空属性段数组，空声明不等于空路径 |
| 注册/序列化 | 注册、to_dict、持久descriptor及目录使用同一规范表示；新描述不可在同component版本下静默变更 |
| 收集输入 | caller-owned事务、实际session/workflow/fixed revision及该定义绑定的精确descriptor；不接页面未提交值 |
| 收集结果 | 按node_binding_id定位的配置逻辑投影；未声明节点/可选路径缺失与显式null的表示；固定投影改变容器形状时的取值规则 |
| 分叉消费 | 配置只核固定定义身份/一致性，保留当前可调值；没有可写配置副本、overlay或private-state装载 |

这些细节尚未被填成最终签名或新schema，不为支持路径额外扩造通用JSON查询语言、$ref解析平台或配置存储。

## 3. 旧全局descriptor

[storage身份键](../../backend/src/phase1_agent/storage.py#L17)将node_definition按component_id/component_version全局保存；[首存逻辑](../../backend/src/phase1_agent/graph_service.py#L266)只在缺记录时写入，[不可变记录检查](../../backend/src/phase1_agent/graph_records.py#L440)不允许普通覆盖。归档/删除工作流不自动移除它，[可用性检查](../../backend/src/phase1_agent/graph_service.py#L188)仍比较运行描述。

因此，新字段即使为空也可能改变完整descriptor。仅升package版本、归档workflow或切隐藏按钮都不解决该冲突；同版本静默重写、自动升包和旧格式兼容不获许可。

后续03已实测当前开发库records为空，因此上述是旧行实际存在时的约束，不是该目标当前冲突。用户已决定将旧descriptor列入执行中退役，不再要求其先选择新组件版本或回收站保全路线；按实际新注册/序列化/收集消费者成组替代，出实际问题再报告。不虚报删除不存在的旧行，也不因空库声称源码退役已经完成。

不需要重审private-state排除；要裁定的是共享描述的处置，不是节点保存范围。

## 4. Agent上下文的独立逻辑投影

根登记坐标为 `session / workflow.effective-context / 4`。当前[注册项](../../backend/src/phase1_agent/context_v4_nodes.py#L118)具有schema/引用hook，但没有新检查点逻辑投影处理器。[根对象](../../backend/src/phase1_agent/context_contract.py#L38)只有view_ref及accepted_delta_ids，[mapper](../../backend/src/phase1_agent/context_contract.py#L53)保留原引用。

| 当前字段 | 必须收口的投影/写回职责 |
| --- | --- |
| view_ref | 收集时读取实际已接纳内容，不能把源artifact ID冻结成目标依赖；目标内容引用由目标写入处理器建立 |
| owner | Agent/node/object逻辑绑定核实；target workflow_session_id使用新目标，不复制源session身份 |
| basis | 当前对象revision_id/head_revision是CAS依据，不是历史业务值；目标采用自身初始化后的正常CAS |
| messages及layout | 保持必要推理内容、顺序和工具调用/结果关系；哪些message/source/tool身份、provider_metadata及layout分组字段保留或本地化待裁定 |
| accepted_delta_ids/applied_delta_ids | 是更新接纳的消费去重边界，不是once台账；目标保留、重置或本地化的规则待裁定，不静默清空 |
| generation | 与现有压缩/更新规则一起核对，不能为了通过校验随意补数值 |
| derivation | 当前指前序view/update及其prompt/model等源依赖，不作为点内恢复前提；合法source-free目标起点尚无可直接复用的写入规则 |

字段结构见[CONTEXT_VIEW校验](../../backend/src/phase1_agent/context_v4.py#L18)。[读取](../../backend/src/phase1_agent/context_v4.py#L85)核消费边界，[接纳](../../backend/src/phase1_agent/context_v4.py#L275)把accepted/applied合回根值；消息本身还有严格source及协议字段，见[agent_message schema](../../backend/src/phase1_agent/contracts_v2.py#L644)。

这里的messages是Agent逻辑上下文内部必要内容，不等于新增通用messages白名单或聊天集合；工具协议内容、必要provider元数据和已有压缩文本不能仅因名字像消息/摘要而擅自丢弃，也不能据此把聊天展示或运行证据全部入点。

现有[write-validator](../../backend/src/phase1_agent/context_v4.py#L366)仅允许官方context.merge产物，并经[prove_native_context_view](../../backend/src/phase1_agent/context_v4.py#L300)验证旧lineage；非空view不允许无前序内容的新read起点。现有[restore_logical](../../backend/src/phase1_agent/session_objects.py#L422)也依赖HistoryArtifactAuthority。复制外层对象、只换owner或造一次merge不能冒充独立目标。

待裁定的关键是上下文专属处理器如何建立source-free的目标内容/起点及配套校验，不能擅自增加derivation分支、升类型版本、伪造运行事实或取消正常live校验。其读取、逻辑校验、本地化、目标同事务写回及独立读取须成组定稿，不能缺一而仅登记白名单。

[当前once判重](../../backend/src/phase1_agent/context_prompt_v6.py#L68)依赖来源item身份，与已定无来源标识/无台账不符。内容相等的粒度、压缩后原文不存在时的判定仍需明确，属于原1.3契约，不在本轮暗增语义匹配、摘要反查或once账本。
