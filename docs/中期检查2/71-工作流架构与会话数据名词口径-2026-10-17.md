## 1. 总体口径

架构命名统一使用“定义”。“属性”表示对象中的具体字段；“声明”保留在自然语言、旧文档或现有代码的原有表达中，后续正式模块与接口命名采用“定义”。

定义、配置和实际数据分别表达规则、具体设置和具体内容。使用同一名词口径时，继续保留它们各自的维护权与存储归属。

## 2. 核心名词

| 名词 | 含义 | 例子 |
| --- | --- | --- |
| 定义 | 描述对象及其结构、约束和使用规则 | 节点类型定义、变量定义、功能定义、能力定义 |
| 数据类型 | 对某一种或一类数据的概念分类 | 上下文这一类数据 |
| 数据类型定义 | 对该类数据结构和使用规则的具体描述 | 上下文有哪些内容、允许怎样使用 |
| 属性 | 对象中的单项字段 | 名称、类型、默认值、作用范围 |
| 配置 | 具体实例的设置及静态依据 | 节点参数、类型版本选择、绑定、静态内容 |
| 数据对象 | 符合相应定义的一份具体数据 | 某会话中的一份上下文 |
| 数据项 | 从集合角度描述其中的单条数据 | 上下文集合中的一条上下文 |
| 会话数据 | 归属于某个会话的数据 | 变量当前值、上下文、候选、运行记录 |
| 注册 | 将已有定义纳入可查询、可取用范围的操作 | 注册节点类型定义、注册能力定义 |
| 定义视图 | 定义目录向消费者提供的只读解析结果 | Runtime 查询到的节点或功能定义 |

这些词描述不同角度，不要求每一项都有独立类、仓储或数据库表。“数据对象”与“数据项”可以指同一份数据，无需据此建立两套结构。

## 3. 定义与声明的统一

| 先前表达 | 后续正式口径 | 保留的含义 |
| --- | --- | --- |
| 变量声明 | 变量定义 | 名称、类型、默认值、作用范围和允许操作等，独立于会话建立 |
| 功能声明 | 功能定义 | 供消费者识别和调用功能所需的约定 |
| 能力声明 | 能力定义 | 能力身份、版本、生命周期消费及相应规则 |
| 数据类型声明 | 数据类型定义 | 一类数据的结构和使用规则 |
| 配置 schema | 配置定义，可附注 schema | 描述配置结构和约束，与实例配置值分别表达 |
| 注册 / 声明表单 | 定义视图 | 供模块只读消费的定义信息 |

“注册”继续作为操作名词使用，已有“注册表”可以描述内部登记结构。“定义视图”描述消费者取得的结果，不预定注册表是否落库或采用何种结构。

前端用于输入和编辑的界面继续称“配置表单”或“编辑表单”；面向 Runtime、检查点等模块的定义信息统一称“定义视图”。

现有代码标识、序列化字段和历史证据保留原名。本轮不批量重命名 65–69 号或产品代码，旧词按上述映射理解；涉及兼容性的实际改名在对应代码范围内另行确认。

## 4. 定义的来源、维护与消费

“定义层”是本轮对定义目录相关职责的称呼。它读取、解析并向消费者提供统一的只读定义视图，定义的维护权保留在来源模块。

定义来源包括工作流持久数据、配置管理形成的工作流内定义、基础包或插件，以及功能和能力的来源模块。

例如：

- 配置管理维护变量定义，经数据管理保存，定义目录提供消费视图。
- 包提供节点类型定义，配置管理据此建立绑定具体类型版本的节点实例。
- 实例配置值和节点实际内容通过相应数据接口读取。

“节点类型定义、节点实例、节点运行”继续分别使用，名称统一不合并三者职责。

## 5. 会话数据：类型与具体对象

数据类型回答“这是什么数据，具有怎样的结构和规则”；会话归属回答“这份数据属于哪个会话”。两者是独立维度。

以上下文为例：

```text
上下文这一类数据
→ 数据类型定义描述其结构与规则
→ 某会话保存符合定义的具体上下文数据对象
→ 从集合角度，可以称其中一份为上下文数据项
```

代码可以直接使用“上下文”等具体对象名称。无需为所有数据引入统一的 `DataObject` 基类，也无需因使用“数据项”而增加一层包装。

“单条上下文”的具体边界、集合组织方式和存储结构，按实际对象和已有实现核对；本篇仅统一表达，不据此决定新的对象结构或检查点准入范围。

后续会话数据盘点按对象种类展开，例如上下文、变量当前值、聊天、候选、运行记录。每种对象分别写明数据类型定义、单条边界、维护方、会话绑定及存取方式。

## 6. 变量定义与当前值的例子

| 内容 | 口径与归属 |
| --- | --- |
| 名称、类型、默认值、作用范围、允许操作 | 变量定义中的属性，属于工作流定义数据或相应定义来源 |
| 会话 A 当前使用的变量值 | 会话 A 的变量当前值 |
| 会话 B 当前使用的变量值 | 会话 B 的变量当前值，与 A 隔离 |

创建变量定义不要求先创建会话。默认值进入变量定义，当前值按会话保存；当前值如何初始化继续按实施待决项确认。

## 7. 层、数据域与存储模块

| 用语 | 本轮口径 |
| --- | --- |
| 配置层 / 配置管理 | 维护工作流配置和修改规则，经数据管理保存 |
| 数据层 / 数据管理 | 统一承接领域数据交互，内部包含相应数据模块、仓储及数据库适配 |
| 配置数据仓储 | 数据管理内部专门负责配置数据存取的部分 |
| 配置层数据库 | 相应逻辑数据区的讨论用语，本阶段继续使用共享 SQLite |
| 工作流定义域 | 静态工作流及其修订依据的逻辑归属 |
| 会话域 | 会话身份、数据绑定、当前值和运行数据等的逻辑归属 |
| 工作流基础支持 | 只负责工作流运行相关的启动、恢复、抛错、当前状态及会话指向的薄口 |
| 项目能力层 | 承担创建、删除、归档、复制等项目管理能力；不属于当前工作流底层运行施工范围 |

保留会话数据域，不建立承揽这些数据全部业务的功能性会话层。具体功能维护自己的业务，存取通过数据管理；上下文由节点经执行 / Runtime 层读写。

“功能层”用于描述具体业务职责，“能力模块”用于检查点、重roll、分叉等可区分能力；两者的统称不意味着它们具有相同调用时机或数据依赖。

项目能力层与工作流内的能力模块按作用范围区分，不因此为工作流增加第七层。这里只确认职责归属，不要求新增特定类或目录；配置管理的节点实例增删、运行准备的数据初始化及已定分叉语义保持原有边界。
