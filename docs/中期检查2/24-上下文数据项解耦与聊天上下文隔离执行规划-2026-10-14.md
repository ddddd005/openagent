## 1. 已确认的目标与范围

1. 上下文，包括会话上下文，必须经加载节点读入工作流；之后的流内处理消费这份已加载数据。
2. 加载输出表示**加载时读到的一份值**。数据层后续变化不刷新已有输出；流内编辑、装配、Agent 成功或展示也不自动更新数据层。
3. 持久更新必须由对应写入节点明确提交。需要新值时再加载；写入节点可以输出本次结果，但不能反向改写旧加载输出。
4. 读取、计算、写入、再次读取的顺序由用户通过图编排。runtime 保持真实数据/控制依赖优先、同批就绪按节点创建顺序执行，不新增上下文或聊天的固定先序。
5. 节点提供数据类型声明；同一类型下可以登记多份独立数据项。Agent 内核实例加入工作流时提供自己的 Agent 上下文数据项；上下文消费节点选择具体数据项，并按类型校验，不再绑定 Agent 内核 ID。
6. 聊天上下文遵循同一规则：随输出节点实例登记独立数据项。多个输出节点的数据身份、值和后续更新互不干扰；不能因类型相同或使用同一组件而合并。
7. **本轮不改变变量注册。** 变量现有主动注册、初始赋值及消费机制保持；不顺带重做世界书、模型配置、压缩策略、检查点前端或 E 入口。

“同一类型”不表示“同一份值”；“随节点登记”也不表示节点内部可以绕过加载/写入节点直接读写上下文。

变量迁移是两个核心验证后的独立后续事项，不在本批预建迁移或兼容代码。上下文精简产生替换后的流内值，仍须经显式写入节点才能覆盖数据层；精简本身不增加隐式持久写。既有检查点保存成功收尾时的已接纳 Agent 上下文，不保证每次写回或失败回合的中间值均有检查点；聊天上下文也不因本次补充自动进入首版白名单。

## 2. 类型、数据项与节点的职责

| 对象 | 本规划中的职责 |
| --- | --- |
| 数据类型定义 | 描述值结构、校验及已有读写契约。同一类型复用一份定义，不为每个节点生成一个新类型 |
| 数据项 | 一份可独立识别、读取和更新的数据。多个 Agent、多个输出节点分别持有独立项 |
| Agent / 输出节点实例 | 提供相应类型及本实例数据项的登记依据；节点实例身份与数据项身份不能混为一谈 |
| 加载节点 | 选择具体数据项，验证类型和读取权限，输出当时值及必要写入依据 |
| 流内消费者 | 只处理已收到的值；不因收到数据项身份而隐式查询最新上下文 |
| 写入节点 | 对明确目标执行类型、权限、输入依据及实际 CAS 校验，提交后输出真实结果 |
| 定义层 / 配置层 / runtime | 两类节点声明仍归统一定义层；实例选择归配置层；实际执行范围及顺序归 runtime |

复用现有 `TypeRegistry` 和宿主登记入口，不新增第二套类型表或类型管理平台，也不把数据项当前值塞入 `NodeDefinition`。本批新工作是节点实例与独立数据项的登记、选择和消费接线，不是改写23号已安装的声明模块。

用户最新明确“输出节点”为测试期按内部逻辑输出内容的节点，未来可以由自定义的输出能力节点替代。现有 `tools.output` 是可复用的测试实现候选；`frontend.presentation`、`tavern.chat.output` 分别承担展示和读取，不能仅凭名称当作相同职责。登记不要求建设永久统一出口，也不使输出节点承担 runtime 完成判断或上下文隐式写回。

### 登记和初始化分开

工作流尚无会话时，也应能添加节点、建立数据项登记关系和保存配置，不要求提前创建会话。数据项登记不等于已向流程注入值。按27号最新决定，本批复用既有会话存储及初始化入口维护上下文当前值，不再把是否新建存储列为关口，也不为所有节点逐会话复制定义或创建值；类型具体初值和复制/删除规则另按已定边界处理，通用 `messages` 非会话必有的规则不变。

新增或复制 Agent / 输出节点，必须获得独立的数据项身份，不能沿用源实例的可变项。复制时使用空初值还是复制一份当前内容、复制部分节点时如何处理外部项引用、删除后的数据保留/清理规则，本页不代用户决定，见第7节。

## 3. 目标数据流与隔离

```text
Agent A 实例 → 登记 Agent 上下文项 A ┐
Agent B 实例 → 登记 Agent 上下文项 B ┘ 同类型，不同项

输出节点 X 实例 → 登记聊天上下文项 X ┐
输出节点 Y 实例 → 登记聊天上下文项 Y ┘ 同类型，不同项

某个具体数据项
    ↓ 显式加载
加载时的值 → 装配 / Agent / 聊天等流内处理 → 对应写入节点 → 数据层
    └─ 保持原值                                  ↓
                                           后续再次加载才读到新值
```

图示表达职责关系，不是新接口字段或强制节点链。Agent 推理上下文与聊天上下文保持不同业务含义，不因登记方式一致而混成一个必有的消息集合。聊天登记也不意味着 Agent 结果自动追加到聊天。

隔离同时覆盖后台数据及前端实例映射：写 A 不改 B，写 X 不改 Y；打开、关闭、切换或复制展示实例不共享可变业务状态。迟到回执仍归原工作流、数据项及节点，不污染当前打开对象。代码、渲染器与传输可以复用。

去掉的是“数据项必须属于某个 Agent ID”的业务约束，保留的是“这次更新由哪个真实执行产生、使用了哪份输入、写向哪个目标”的事实校验。不能把去耦实现为删除 producer、精确输入、授权、写入依据或原请求保护。跨项误用更新应被拒绝，不建设自动合并或静默重试。
