## 5. 跨阶段检查与必须分开的逻辑

用已有代表链核对阶段间接口，而不新增一套业务：

```text
工作台 / 绑定节点页配置请求
→ 配置业务与数据管理保存 → 独立读取
→ 准确包来源、定义查询与固定修订引用
→ 本次 RunBasis、图计划与工具准备帧
→ 普通节点调用 / Agent 受控工具调用
→ 各自既定接纳与必要结算
→ 新读取上下文中的结果及现有消费者
```

至少核对配置到准备、定义到执行、工具帧到提示与 callable、接纳到独立消费者这四处边界。证据可以由现有不同测试分段支持，但回执必须写明分段，不得声称存在一条未实际运行的浏览器→TS→Python→模型全链。

| 必须分开 | 检查原则 |
| --- | --- |
| 当前配置、固定修订、本次采用配置 | 分别核对身份、序号和作用时点；不因同一个工作流就混用 |
| 定义正文、可信实现、实例配置、一次调用 | 查询和提示不授予执行能力；实现来源不被工作流复制接管 |
| 配置领域、定义证据、运行状态、事实、信息绑定 | 数据入口分发，各领域独立适配；跨领域规则在上层协调 |
| 节点接纳、工具逐次接纳、独立事实、整次结算 | 保持各自原事务，不为统一入口合并成整图事务或提交后异步补写 |
| 管理命令、运行控制、历史观察、前端连接 | 不把合法图外命令当作节点常驻激活，也不以历史读取得新执行许可 |
