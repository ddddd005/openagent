## 3. E1：工作流合规修改与简单输入

第一批交付一个可独立调用的配置修改模块及简单输入节点，不等待新Tavern前端。

1. **集中修改许可。** 在工作流配置层组织统一规则查询、校验和提交入口，首条只允许新输入的`text`。准确component/version、允许字段与格式校验归集中规则条目；调用端不散写输入节点特判。首版可信代码名单即可，保留以后统一登记规则的接口边界，不提前建设插件平台。
2. **区分修改许可与可调声明。** 前者决定节点调用能改哪些内容，后者决定固定/可调保存及检查点投影；不可因为字段是可调便自动授予修改权。输入操作不携带策略修改，切换固定/可调仍走正式编辑与既有固定修改规则。
3. **复用正式保存内核。** 入口核对工作流、准确目标节点、编辑序号、字段及内容；后端形成实际保存内容，调用者不上传任意整图。保存沿现有当前配置、事务、版本及确认派生，不增加输入专用存储。
4. **保证窄请求的原回执。** 建议复用现有事务/回执设施，抽取`update_definition`内部保存逻辑供窄操作调用，在同一事务核对原补丁请求、目标和版本。不能每次重放时读最新图重建不同正文，使同一个幂等键对应不同请求；不自动重基或换键重试。准确操作名和结果形状在这一批开工前列清。
5. **安装输入契约。** 建议使用新的简单节点，配置仅`text`、普通working executor输出`TEXT@2`，执行体参考`_text`。准确名称/版本未定；建议空字符串合法、保存原始文字、不自动清空，格式上限沿已有100万字符量级，发送空值的业务行为另列。
6. **接集中策略信息。** 建议默认可调，创建默认值与固定/可调控件从可信集中声明/规则查询，退出相关提示词专属UI判断，不在各新增/复制分支增加新输入特判。沿用既有`prompt_mode`字段，不顺带改名或迁移策略协议。
7. **检查配置入点。** 建议新输入显式声明`checkpoint_save.config_paths=[["text"]]`：固定时按现有规则保存；可调时文字继续被固定投影排除。此为待审的新节点声明，不是聊天类型准入，也不改变已准备运行。

这一批需要列清新节点身份、默认策略、文字格式、修改操作请求及保存/未变/待确认/派生回执。以上推荐可以作为首批审阅稿，尚未安装。

## 4. E2：对应后端节点的对外能力

先完成后端调用和归属核对，可在没有浏览器前端时验证；之后内部通信只调用这些明确处理函数。

| 对外部分 | 接法与限制 |
| --- | --- |
| 输入修改 | 由后端保存的准确输入目标绑定调用E1；前端不能换任意节点/字段。许可校验不代替固定修改确认 |
| 类型与项登记 | 节点包声明所提供类型，沿现有统一定义安装；实例项沿正式配置登记。自有项与外部读取项分别列出，登记者不自动获得读写权 |
| 数据读取/更新 | 按准确类型、项和调用会话取得值；普通图更新使用实际executor/结算及CAS。展示数据写入由节点业务发起，前端不提供编辑后的上下文覆盖请求 |
| 启动 | 对应后端节点协调现有create/start原语；已有会话直接按准确会话启动，无会话仅首次运行时创建。两个实际结果分别接纳，不冒充单个原子事务 |
| 暂停等控制 | 主动处理入口直接调用既有control，运行期间无需等普通图调度；区分请求已接纳、`pausing`与实际`paused` |
| 检查点 | 后续窄调用现有list/read/fork，版本由真实服务快照取得；分叉返回明确新目标，保持既有新目标事务，不借节点回放恢复 |

类型定义、实例项登记与会话值初始化不是同一次“注册”。无会话新增节点只登记配置身份；创建会话后才由既有存储初始化值；前端打开不承担这两项工作。

新节点的普通graph executor与主动操作处理入口分别声明、实现和验证。`execution_class`只决定普通计划筛选；不能因为有按钮把有流内职责的整体节点一律设为非工作，也不能让按钮触发所有图内写入。主动入口不伪造`node_run`取得权限。

本批最小契约包含：节点提供的操作集合、准确输入目标、提供项及外部读取项、各项ACL、版本与幂等依据、实际结果归属。后端从已经确认的节点绑定与配置取得目标，不接受前端任意管理operation、对象键或冒充另一个节点。

**展示写入单列施工项。** 若选用测试期`frontend-state@1`，须同时审阅它的实际producer、读取basis、输入产物和结算证明如何接入新节点；只读展示可以先复用既有准确读取，新增写入不能靠删除旧验证放行。新节点可以调用已有能力，但不因展示、输入或浏览器操作自动追加聊天记录。写入的内容和触发方式按实际流内节点职责列清。

当前检查点准入保持配置、Agent上下文和变量；聊天当前值持久化不等于已经随点分叉。`fork_checkpoint.expected_data_revision`沿现有服务的data版本含义，不混同独立对象CAS。重roll及候选具体行为另议，失败重试不作为其替代实现。

### 4.1 用户确认的消息追加与展示顺序

用户在E1完成后明确：整体前端节点收到的是**本轮新增消息**。后端先向自己登记的聊天项追加这些消息；写入被数据层接纳并真正提交后，再从数据层读取已保存的值，生成临时展示快照。前端打开时接收该快照，未打开时仍完成后端写入、读取与缓存。前端不能上传修改后的上下文覆盖数据层；之后的数据变化也必须再次由后端读取才反映到展示副本。

主代理依照已确认职责审阅的E2首批安装合同如下，属于实现方案，不扩展运行、存储或检查点的职责：

- 整体节点为`frontend.node@1`，普通working节点，`is_output=True`；runtime继续判断整个执行计划何时完成。`content:TEXT@2`多输入表示本轮新增消息，顺序沿真实输入边绑定；同次调用角色由配置`role`指定，默认`assistant`，不新增通用消息格式。
- 配置包含自有项`object_key`、`role`及可空的准确`input_node_id`。未绑定输入时仍可执行图内消息追加；输入修改必须另行核对绑定为`tools.editable-input@1`。每个节点声明提供独立`workflow.frontend-state@1`项，自身读写仍需要显式ACL和准确登记者核对。
- 旧`FRONTEND_VIEW@1`及显式读取/追加节点的证明保持原义。新节点的内部读取没有真实`view`图输入，不能伪造输入边；采用独立`FRONTEND_NODE_APPEND@1`产物证明本次真实content输入、内部读取的CAS依据和保留前缀。数据层仍校验准确producer、冻结配置、节点/会话/项归属、来源产物和追加结果。
- 结算事务只保存证明、CAS写入及实际写入回执。事务提交后才以准确后端节点身份执行真实数据读取；不能把执行器冻结副本或计算结果称为写后重读。缓存依工作流、节点实例和会话区分，附实际对象修订及本次调用身份，返回深拷贝。
- 本批先接后端普通执行和同进程窄能力。新浏览器路由、推送传输、开窗按钮及默认前端入口仍沿E3/E4接续；不将主动操作塞入现有通用浏览器命令入口。无前端时的写入和缓存可独立验收。

节点的输入修改、主动读取和运行控制继续按第4节分别核验原请求、准确目标与真实结果。未定的传输合同、重roll和候选不借本次追加逻辑安装。

## 5. E3：节点内部通信、输入与展示

实现仍显示为一个前端节点，内部至少有四个可识别部分：

- 通信接收与结果返回：接收已允许的意图，绑定原工作流/节点/可空会话，交给业务处理；不执行任意管理命令。
- 输入交互：仅当前`frontend.node@1`内部采用拟定的200ms输入更新时间，向对应后端节点提交文字，后端调用E1。它复用正式配置，不再维护一份业务输入或浏览器草稿；不把这个时间扩为其他节点/表单的保存规则，不抽取通用核心保存机制。
- 展示处理：后端明确读取/取得内容，提供临时展示副本；前端渲染，不回传修改后的上下文覆盖数据层。数据层变化后，后端再次取得新值才刷新展示。
- 入口与绑定：节点声明自己的前端通信入口与默认归属；宿主承载校验，配置层保存必要实例信息。此部分在内部逻辑及操作契约清楚后接线。

建议输入最小顺序为：200ms提交→等待正式保存结果；点击发送时提交最后一份待保存文字并等待成功→由对应后端节点按需创建会话→启动本轮。接收ACK、配置保存回执、运行接纳回执分别呈现。保存失败、版本冲突、unknown或待固定修改确认不能继续当成成功发送；不预建自动恢复或补救重试。

用户在E2完成后再次明确：200ms仅为这一个节点当时拟定的更新时间，不是核心机制。E3按节点私有输入交互实现；E1的可编辑输入及其他工作台字段不安装定时保存。

保存中继续编辑与迟到回执均按原节点归属处理。已准备的本轮使用`node_run.config`冻结值，下一轮取得新保存值；可调输入仍是工作流当前配置，多个会话共享该配置，上下文当前值仍按会话隔离。

建议先实现后端状态重读及运行结果后的明确刷新。具体自动刷新触发点在节点交互契约中列清，不提前添加推送总线或让前端自行查询通用数据/产物接口。

## 6. E4：节点所属端口、默认绑定与打开

这一步接在E3逻辑明确之后，不能把现有公开输出渲染登记当成已经具备新通信入口。

1. 节点实现提供入口声明和默认绑定，复用包/宿主的通用承载；首版建议优先复用现有HTTP承载的窄节点入口。是否独立网络端口、路由形状及具体协议尚未决定，不先分配固定数字端口。
2. 每次打开携带准确工作流和后端节点实例，会话可空；后端核对该节点及本次允许目标。同类型多个节点各自绑定，不查全图唯一节点，不从当前选中项或类型名猜归属。
3. 按钮只打开前端。打开不创建会话、不启动运行；首次运行由E2处理。不开前端，节点仍可正常graph执行及使用已声明主动入口；关闭页面不发送停止。
4. 首次运行返回真实会话后，结果只更新原节点对应前端的绑定；切换节点或会话后的迟到结果不污染当前对象。分叉也返回准确新目标，不擅自改变工作台全局选择。

这里的前端通信入口与图内`NodePort`各有职责，不借新增能力连线表达操作许可。现有trusted-local边界继续保留；本稿不扩建远程插件认证或独立前端服务管理平台。

## 7. E5：旧入口替换与联合验收

**接续订正：** 用户已明确批准旧Tavern创建及扩展、其他旧预设和准确旧测试工作流退役，保留Lorebook，本版只留普通工作流。准确施工范围以[48号](48-阶段E旧入口与预设设施退役执行规划-2026-10-15.md)为准，实际交付见[49号](49-阶段E旧入口退役与测试工作流清理实施回执-2026-10-15.md)。下表“先列待退出/额外退役另报”为本规划原阶段事实，已由本次明确清单收口；重roll/候选、分叉按钮及聊天入点仍不随E5安装。

按实际消费者成组替换，施工回执逐项列出退出结果；不以文件名整包删除Tavern。

| 旧职责 | 计划替换内容 | 保留或独立处理 |
| --- | --- | --- |
| 打开先建会话、全图唯一展示/输入门禁 | 换成节点提供的准确入口与绑定 | 开窗、忙碌和错误反馈可复用 |
| 浏览器generic consumer直接启动、控制或读取业务对象 | 换成对应后端节点的允许意图及展示结果 | 底层现有应用/服务能力仍供后端复用 |
| consumer输入草稿、external inputs发送、按工作流恢复旧client会话 | 换成输入节点配置保存与准确节点归属 | 原请求证据、未知请求核实保留；不建新草稿恢复 |
| `frontendWiring.ts`三节点自动接线及关联UI注册 | 新整体节点接通后核对并替换其新建入口 | 当前有效显式读/追加/展示节点及用户已搭图不自动删除 |
| 旧Tavern预设builder、旧聊天业务类型 | 本批先列准确消费者与待退出入口；额外退役清单另报范围 | 不自动迁移旧图；Lorebook、全局资源、有效live证据及第三方许可保留 |
| 旧渲染器及静态资源 | 适合者接收新后端提供的展示副本 | 不因此保留旧业务状态权威或通用浏览器操作接口 |

聚焦验收按对应批次完成，不重复宣称历史全量：

- 合规入口拒绝错节点/版本、未登记规则、未许可字段及错误文字格式；同原请求返回同结果，异正文同键拒绝，过期依据不自动重试。
- 可调输入在有会话时原地保存；固定输入需要确认时零写入，明确同意才派生无会话新工作流。输入操作不能同时改策略。
- 200ms内连续编辑、保存中再编辑和立即发送均以最后正式保存值启动；准备A后保存B，本轮仍输出A、下一轮输出B。
- 同类型两个前端节点、多个数据项及两个会话不串绑定/读写；前端伪造另一个输入目标或提交上下文覆盖请求被拒绝。
- 提供项、读取权限与写入权限分别成立；错误类型、ACL、CAS、producer或输入产物证据被拒绝；再次后端读取才看见新值。
- 打开/重开无会话前端不建会话；首次运行按需创建。创建已成功但启动被拒绝时如实显示已有会话及启动失败，不伪报整次成功或自动重试。
- 运行中可以经节点主动入口请求暂停，并保留接纳与安全点状态区别；没有浏览器前端时后端仍可正常执行。
- 输出后有下游写入时仍等待实际计划完成；成功存档只由runtime触发。分叉只装载现有准入类型，不承诺聊天展示随点复制。
- 切换工作流/节点/会话后的迟到输入、运行及分叉回执归原对象；关闭前端不终止后端。

完整用户工作流的端口连线、聊天写入顺序和真实模型对话在基本功能安装后联合核对。离线测试、类型检查及隔离构建按实际代码改动选择；浏览器业务操作和真实模型调用按届时授权，测试数据不覆盖用户现有工作流。
