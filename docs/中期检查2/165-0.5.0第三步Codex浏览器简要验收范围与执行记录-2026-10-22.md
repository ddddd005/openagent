## 2. 简验顺序

1. 核对现有依赖、端口、入口与隔离路径，冻结起始工程身份。
2. 启动本轮后端及前端，打开 Codex 内置浏览器，核对首次加载和错误日志。
3. 经真实界面完成适用的工作流创建、正式保存、会话与配置复制；检查副本不携带原会话。
4. 检查会话预加载编辑入口、正式保存及适用的新会话读取；不把单纯入口可见记作数据语义已验证。
5. 检查供应商/模型预设、全局内容工作台的适用本地交互及刷新读取。
6. 检查原请求入口、通知浮层与配置编辑布局；以实际可触发结果记录，不伪造未知请求或通过页面内部状态注入制造成功。
7. 对无模型的可用运行路径作适用操作；若真实界面没有安全可用入口，登记限制，不借直接数据库写入或隐藏接口调用替代浏览器链路。
8. 保存代表截图与实际结果，关闭本轮自建进程，复核工程身份和端口释放，追加执行结论。

三位子代理仅协助启动边界、页面路径和证据口径的只读核对；共享浏览器由主代理持有。并发槽位不足时顺序接续，不扩大人数。

## 5. 中间现象与处置

1. 首次仅放置孤立文本节点便点击启动，界面短暂显示提交中后恢复，刷新后仍无运行历史。随后只读核查发现普通运行要求已连接的输出节点（`graph_contracts.py` 的 `graph_no_outputs` 条件），孤立 `tools.text` 不是完整可运行图。**本轮未抓到该次即时错误信封或通知，不把源码归因写成已独立捕获的 HTTP 结果。** 未重复提交原请求或补造结果；在独立副本中经界面补齐输出和连线后，新的完整图实际运行成功。保留先前空历史截图，不冒称完整图失败。
2. 尝试把已有会话的预加载初值由 7 改为 9 时，界面提示“此固定配置修改需要创建新的工作流；原工作流及会话保持不变”。本轮取消确认，恢复表单值为 7，没有提交分叉或修改原会话。因此本轮只验证创建时预加载值，**没有验证预加载更新后新旧会话的完整对照链**。
3. 新模型预设的“真实模型容量”默认折叠，三个必填值默认 0。首次保存没有完成；展开后可见“数值不能小于 1”，填入合成值后保存成功。登记为非阻断的操作可发现性观察，不自行改 UI、默认容量或业务校验。`screenshots/07-provider-model-form.jpg` 保留初始表单。
4. 两次控制工具问题不计产品缺陷：变量标量切换导致旧 textarea 被替换，旧元素调用失效，重新观察后对整数输入框操作成功；一次只读 DOM 检查用了运行环境未提供的 `checkValidity()`，改用原生 `:invalid` 选择器读取状态。均未改变产品或仓库测试。
5. 证据终检脚本首次把 Git 的换行告警对象直接放入 JSON，出现深度告警且长时间未完成；核对命令行后仅停止本轮检查 PID 104088，原脚本与失败说明保留在 `review/`。将告警转为普通字符串后另行执行终检，不把该辅助脚本问题算作产品失败或抹去首次记录。
