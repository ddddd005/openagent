## 1. 任务与复杂度

两域已有独立领域服务、存储规则、公开操作、回执、前端和工作流消费者。本批复用这些能力，补齐来源声明、项目汇集、统一环境与真实取得关系。

判断为**中等偏小的连续接线批次**，明显小于工作流内部修整；不是只添两条静态记录。共同前置是把目前仅支持一个工作流的接入承载有限扩充到三个固定子能力。内容的动态类型上下文、供应商的私库与跨库结果，是主要保护点。

## 4. 拟采用的最小实现

### 4.1 共同声明与按身份取得

延续已确认的“来源声明、项目校验并取得”职责。抽出可复用的接入数据类型/基础校验，保留工作流来源自己的内容与特殊约束；可用小型中性模块承载，原工作流导入点按实际调用保留兼容，不建设通用依赖容器。

首版固定装配三个当前可信来源：既有 `workflow.graph` 身份不变；两域各提供一个整体来源声明，供应商与模型预设归同一能力。新增内部身份、文件名与工厂名由工程统一命名，在回执列明；不开放用户配置、字符串导入、自动扫描或多实现选择。

每份声明包括身份/接入版本/来源、真实取得绑定、必要环境、生命周期、已有公开契约及前端引用、实际跨域依赖。供应商与内容只声明现有管理角色，不伪造工作流执行角色。工作流节点、模型运行服务、内部类型和具体资源记录不升级为项目子能力。

定义管理的必要改动：

1. 汇集固定来源，按 `capability_id + role` 准确索引；重复身份、重复角色、坏绑定、路径不符显式失败，禁止取“排序后的第一条”。
2. 共同校验与工作流专属校验分开。工作流现有依赖覆盖要求继续验证；内容无需声明凭据，供应商无需声明图执行，不为过检查补假依赖。
3. 诊断带能力身份，取得检查针对所请求能力/角色及其实际依赖；没有用户供应商配置、没有内容资源，不等于接入声明损坏或整个项目不可用。原有 required/conditional/optional 含义不顺带改写。
4. 前端与业务契约引用沿固定可信来源核对，允许引用既有共享 operation；引用不是新建 operation 所有权或权限。不可把 `resource.*` 全部归给某一个新能力。
5. 声明汇集、查询及静态校验不构造服务、开库、建目录、取租约、创建凭据或发网络请求。首次实际取得仍保留各服务原有必要初始化。

原 workflow-only 调用入口可明确默认 `workflow.graph` 以保持兼容，但必须是明确身份的默认值，不能依赖目录顺序。

### 4.2 环境与真实工厂接线

两域来源提供可信本地工厂；工厂检查显式路径与项目环境一致，使用既有服务构造参数接入 `environment.open_store`。Graph 视图优先保留显式传入的 `store_factory=self._store`，它已携带环境与故障注入，不能被裸 `environment.open_store` 覆盖。不必为了新增 `environment` 字段重写领域服务；现有 `store_factory` 已可承载主库环境。

正常 Host 路径须同时覆盖：

```text
Host 管理两域
→ 项目定义管理按能力身份取得绑定
→ 两域来源工厂
→ 原领域服务（store_factory = 本项目环境）

Host 取得工作流管理/执行
→ 工作流来源工厂取得项目已校验的两域绑定
→ 以窄依赖工厂参数交给原 Graph 构造
→ Graph 按原时机建立本域服务视图
→ 原服务消费 Graph._store / 本次所需类型上下文
```

窄依赖参数只携带两域可信工厂/取得口，不传整个 Host 或项目仓储，不让工作流重新扫描来源。具体函数签名可等价调整，但不得只在声明里登记，正常 Graph 路径仍绕过已选绑定。

保留直接可信构造 Graph/两域服务的既有用法：未经过 Host 时使用明确的本地默认工厂。这是独立构造的既有支持，不是在项目声明错误后降级绕过校验。Host 路径绑定缺失必须显式失败。

### 4.3 实例、锁与生命周期

Host 缓存自己取得的管理视图；Graph 保留自己的工作流视图及现有 RLock、取得时机。**统一来源与环境不要求统一成同一个服务对象。** 不改变管理/执行按需取得，不因管理供应商、模型预设或内容而激活工作流执行租约。

两域当前不持有长期数据库连接，也没有领域 `close()`；声明应如实说明每次操作关闭连接、持有者及借用关系，不强造空关闭协议。工作流执行资源仍由原 Host/Graph 关闭；HTTP 继续借用外部对象，兼容分支所有者按原规则关闭。

## 5. 两域核心保护

### 5.1 供应商与模型预设

管理范围仍为 provider 与 model-profile。模型预设引用供应商；不复制凭据，不将 `workflow.models` 运行服务或模型节点搬入项目执行管理。

- 主库仍为同一 SQLite；凭据继续位于 `<主库>.credentials.sqlite`，原保护方式不变。
- Graph 工厂继续传 `store_factory=self._store`、原 `credential_protector`、发现 client factory；模型服务仍接原 `credential_broker_factory`，原 `public_model_factory/transport_factory` 不丢失。
- 凭据保存的主库请求预留、私库写入、主库绑定分别提交，`saved/partial/unresolved` 及原回执核实保持；不包装成跨库原子成功，不重放未知请求，不记录 secret。
- [ModelRequestResourceReader](../../backend/src/phase1_agent/model_request_resources.py#L207) 的授权、profile/provider 同一只读事务及版本核验继续使用原受限端口；不为接驳替换成两次普通 CRUD，声明中如实引用这条领域读取关系。
- 模型发现测试使用现有离线 client 替身；本批不发真实网络或模型请求。

### 5.2 全局内容

Host 默认内容视图仍支持当前内置提示词/Lorebook；Graph 视图继续支持其当前可信 registry 中的全部非 provider 全局类型。工厂保留 `type_registry_factory=lambda: self.registry.data_types`，不得在构造时取一次快照后永久固定。

| 读取/写入段 | 保留方式 | 本批接驳边界 |
| --- | --- | --- |
| 准备期依赖核验 | `records.read_global_resources` 在原数据/事务上下文内检查依赖与本次类型依据 | [graph_resource_host.py](../../backend/src/phase1_agent/graph_resource_host.py#L44)；不强拆成跨服务多次读取 |
| 节点使用当前内容 | 冻结可读身份，使用时按本次 `RunBasis` 类型读取当前值 | [graph_resource_host.py](../../backend/src/phase1_agent/graph_resource_host.py#L105)；原同库领域读取可保留，登记真实端口，不借接驳修改时序 |
| 宿主服务读取内容 | 经内容服务并显式传本次 registry types | [graph_runtime_host.py](../../backend/src/phase1_agent/graph_runtime_host.py#L217)；须命中新接入的服务工厂 |
| 内容资源 CRUD | 原类型校验、CAS、幂等、回执与删除墓碑 | 不增表，不收窄可信类型，不改为项目跨域改表 |
| 展示名 | 独立 metadata sequence、短事务及原生回执 | 不与内容资源保存合成一次新的事务/成功结果 |

非内容资源原冻结政策不变。内容使用时读取不意味着放开节点授权，也不允许因当前包目录变化而改用另一份运行类型依据。

## 9. 冲突取舍与停止线

| 情况 | 处理 |
| --- | --- |
| 文件/类/工厂名、共通类型是否小模块、兼容导出、窄参数组织 | 可自主收口；保证来源维护、准确身份、真实取得及已有入口可用，回执列明 |
| 旧测试只断言“项目永远只有工作流”或强制所有能力两角色 | 精确改为三个固定来源及各自真实角色，保留无副作用和坏绑定拒绝意图；不弱化成“非空就过” |
| Host 默认类型与 Graph 动态类型不一致 | 保留原两种视图与各自工厂参数，不以共享单例解决，不静默增加或缩小类型范围 |
| 引用与前端来源模块不符、声明锚点移动 | 回查真实固定来源后订正引用；保留权限与校验，不能删除检查让其通过 |
| 必须改 operation/结果 schema、凭据保护/位置、事务、unknown、读取时机、类型/授权政策 | 停止受影响路径，报告原因、范围、当前事实及所需决定 |
| 需要新职责平台、多实现共存、统一所有领域数据端口或强行合并服务实例 | 停报，不以“接驳”填充架构设计 |
| 实际需动原准备事务、模型授权 reader、业务结算、T6 控制/错误收尾 | 停报，不借本批薄接线安装新行为 |
| 出现相邻已知遗留或非本批失败 | 原样留证、独立归因；局部测试自身错误可修，产品跨范围问题不得顺手施工 |
| 需要真实库/凭据/模型、操作既有服务、构建/安装、提交/推送 | 不执行，另获明确授权 |

原则：优先保留既有业务事实与本次已定边界；源码中的偶然耦合不是新架构要求。发现实质冲突时停止受影响部分，不用 fallback、重试、补偿或绕过声明掩盖问题。
