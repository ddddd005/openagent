代表路径先追完整，再补相邻分支。发现某项已有明确实现时记录其真实用途，不为了“统一”要求所有旧调用无差别迁移。

## 6. 决策如何收口

执行方可自行完成检索、事实归类、表格合并、行号订正与文档组织。既定的准确版本、同源依据、原事务、权限和错误政策无需重新请求批准。

| 需要形成的判断 | 回执必须给出的材料 | 何时需要用户决定 |
| --- | --- | --- |
| “项目”“全局”作用域 | 当前数据库路径、资源 scope、服务实例及工作流引用之间的实际关系；首期可采用的范围建议 | P2 细化前；不能自行新增项目实体、多租户或物理拆库 |
| 首批装配与持有关系 | 正常/兼容消费者清单；哪些职责拟从 Graph 调整、为何调整、对构造和关闭有何影响 | 涉及新责任交接或调用行为时，先报告具体方案；不默认采用全局单例或统一容器 |
| 数据领域接入范围 | 128 号既定资源范围下的具体路径、类型来源差异和保留适配 | 只有扩大领域、改变类型供给或事务/取用语义时需决定；普通转发和内部命名留待实施选择 |
| 包来源与查询发布 | 尚未接线的启动参数、当前选择入口消费者、管理/执行结果关系及发布顺序 | 涉及来源配置承载、新 UI 或查询刷新机制时，在对应 P4 施工前确认，不要求无关 P2 工作等待 |

建议沿 128 号先明确装配，再推进内容资源、供应商/模型与包注册接续。P1 回执应给出可讨论的窄范围建议，不能只列一组抽象问题，也不能代替用户决定新架构。

P1 核查完成与所有产品决定已确认分别表述。未决项如只影响后续 P4，不阻止已核清部分形成 P2 局部规划；P2 本身依赖未决职责时不得直接施工。

## 7. 保留语义与停止线

- 复用现有领域业务、loader 和只读定义目录。共享功能不取得共享运行状态或越过 Agent/节点自身权限。
- 提示词/Lorebook 在使用时取值；模型新逻辑请求准备时取得资源，已准备请求保留原依据。项目整理不得改为整轮冻结或每次发送重新取用。
- 主库、凭据库及元数据各自的事务与结果继续分别表达；不补做未知请求、不自动重放、不因本步另设恢复或重试。
- 1.0-4.0 及联合修整的关闭结论、Q14/G16 等限制和历史审计损失继续沿 127 号；原件不能因新核查被称为恢复。

出现以下情形时，暂停受影响路径并报告原因、范围和所需决定；其余独立调查可继续：

1. 用户最新决定与现行文档/候选方案实质冲突，或必须改变未确认的责任、契约或产品行为。
2. 需要访问真实库、凭据、业务正文，构造会初始化存储的服务，或启停既有服务、调用模型/供应商，才能获得关键证据。本步先登记静态不能证明之处，不越界执行。
3. 需要修改产品/测试、迁移/删除数据、改变包或类型定义、安装依赖、提交或推送，才能继续某项“核查”。
4. 读取期间相关产品文件发生实质漂移。先列出变化并重新绑定受影响结论，不覆盖或撤回他人改动。
