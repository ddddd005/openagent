# 工作流数据管理与定义域、会话域契约

日期：2026-10-17，Asia/Shanghai。

性质：本阶段职责契约。本文规定工作流数据管理的范围、数据归属和交互原则，不要求本阶段立即完成所有代码迁移。

## 1. 数据管理的定位

工作流数据管理是数据定义、数据展示、数据读写、数据修改、版本管理、数据库存储和数据库适配等功能模块的架构统称。它不是必须由一个类或一个进程实现的真实层级。

数据管理模块是工作流与其他模块之间的统一数据交互口。配置管理、Runtime、能力模块和基础支持都应通过对应的数据接口读写工作流数据。

数据管理不负责：

- 节点执行；
- 执行顺序；
- 前端交互策略；
- 检查点、重roll或分叉的业务选择；
- 代替定义目录收集和建立定义；
- 将所有业务规则压缩成一个通用 CRUD 服务。

## 2. 数据域划分

### 2.1 工作流定义域

工作流定义域保存静态工作流及其修订依据，包括：

- 工作流身份、名称、状态和修订；
- 节点实例、精确节点类型和版本；
- 数据边、控制边和节点组；
- 节点配置和静态节点内容；
- 节点绑定、对象声明和资源引用；
- 工作流 package lock；
- 前端画布位置、折叠状态等属于工作流编辑结果的布局数据；
- 工作流级变量声明，包括名称、类型、默认值、作用域和允许操作；
- 工作流级提示词配置或对全局提示词资源的精确引用。

定义域的数据由配置管理模块按照规则修改，再通过数据管理接口持久化。

### 2.2 工作流会话域

工作流会话域保存某次工作流运行及其会话内容，包括：

- 会话身份和固定的工作流定义修订；
- 会话状态、运行状态和暂停信息；
- 会话变量当前值；
- 会话上下文、逻辑聊天和候选；
- 节点运行、链运行、运行事实和输出；
- 会话错误和结束信息；
- 检查点、候选和分叉引用；
- 允许进入检查点的会话配置快照。

会话域不能直接修改工作流定义域。需要修改静态工作流时，应重新进入配置管理路径。

### 2.3 项目级资源引用

全局提示词、Lorebook、供应商、模型配置等项目级资源不因被工作流引用而转移所有权。工作流定义只保存精确引用或必要的冻结依据，会话保存当次解析结果或允许保存的快照。

### 2.4 变量归属

变量声明和变量当前值必须分开：

- 变量声明属于工作流定义域或相应的定义目录。
- 变量默认值属于定义域。
- 变量当前值属于工作流会话域。
- 创建或修改变量声明不要求先创建会话。
- 运行期间的变量写入必须绑定具体会话，并通过会话数据接口完成。

## 3. 数据管理接口原则

数据管理应提供按领域区分的接口，而不是暴露任意表操作。概念上至少包括：

- 工作流目录和定义修订接口；
- 节点实例、连线和配置保存接口；
- 会话创建、读取和状态更新接口；
- 会话对象、变量、上下文和聊天接口；
- 运行事实、输出和错误接口；
- 检查点准入、保存和装载接口；
- 版本、修订、并发检查和事务接口。

所有接口都应明确：

- 作用域；
- 数据所有者；
- 读写方向；
- 版本或 CAS 条件；
- 是否允许进入检查点；
- 错误和诊断表达。

底层数据库适配器只能由数据管理模块使用。配置管理、Runtime、能力模块和前端不能直接改写数据库表。

这是当前开发和维护的合规指标，用于防止职责交叉和数据分散维护；本阶段不把它表述成对未来所有扩展代码的不可绕过安全边界。

## 4. 定义和数据的关系

数据管理可以保存数据类型声明、配置 schema 和定义证据，但定义目录负责向消费者提供统一的只读视图。

定义目录不拥有定义的最终修改权。定义的来源可以是：

- 基础能力包或插件；
- 工作流数据管理中的持久声明；
- 配置管理生成的节点实例声明；
- Runtime 或能力模块提供的功能声明。

来源模块负责产生和维护声明，定义目录负责读取、合并、解析和展示。

## 5. 存储实施原则

本阶段允许继续使用共享 SQLite。应先通过表、仓储、事务和接口区分逻辑数据域，不以物理拆库作为前置条件。

数据库迁移、表重命名和历史数据处理必须在确认影响范围后单独规划。不能为了形成架构名称而随意复制数据、建立第二套权威或删除旧证据。
