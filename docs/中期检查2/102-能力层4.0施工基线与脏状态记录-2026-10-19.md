## 4. 施工中的决定

| 项目 | 实际决定与理由 |
| --- | --- |
| 包位置 | 新增 `workflow.tool-bindings@1.0.0`，不改 `workflow.tools@1.0.0` / `workflow.agents@1.0.0` 的既有 manifest 和节点版本。理由：给已发布包追加导出属于契约变化；升版本会让既有文档 `package_lock` 在编译时报 `graph_missing_package`。代价：既有项目的已保存包选择不含新包时须经包选择管理启用，记入留存。 |
| 锚点 | `tool-bindings.variable-tools@1`，`non_working`、无端口、无 executor、无对象访问、无服务/资源声明，不进入图执行顺序。 |
| 工具提示词 | 新增 `tool-bindings.tool-prompt@1`，只从准备帧读取同名工具描述与参数 schema；不授予权限、不决定加载。`prompts.tool@2` 静态目录保持不变。 |
| 调用身份 | 新增 `ToolInvocation`，内核在唯一下发点把 `tool_call_id` 与 `tool_execution_id` 传入；不增加 Agent 节点 capabilities 或新节点版本，使用注入到 `NodeExecutionContext` 的有限调用桥。 |
| 授权 | 工具目标上下文使用目标节点定义的能力，ACL 主体始终是真实 Agent `node_binding_id`；锚点不取得变量权限。 |
| 接纳 | 每次变量写使用独立 `_change("graph.tool.object-write", "tool:<execution_id>")`，经 `ExecutionState.apply_objects` 保存；操作键含工具执行身份与目标对象；事务后独立重读并比对；idempotency result payload 保留 binding/tool call/tool execution/object 关联。 |
| 视图同步 | 接纳后调用 `NodeExecutionContext.apply_accepted_object` 更新 Agent 运行对象视图；Agent 成功事件再从数据库刷新下游视图。Agent 的对象写集保持为空，避免结算时重复提交。 |
| 目标范围 | 首版只接受原生 executor、无服务/资源/私有态/settlement/额外图连线的目标；越界在启动准备显式拒绝并记入留存。 |

## 5. 已知风险与停止线

- 不新增表、存储版本、历史迁移或公共 snapshot/包协议版本。
- 不向功能层交出 `GraphRecordStore`、连接、仓储或任意 `get/put`。
- 不取消 CAS、对象 ACL、同源依据、原子接纳；不以重试或补写掩盖失败。
- 不为通过测试删除同对象一次写限制；逐工具接纳使用独立有限上下文。
- 宿主执行器目标、服务/资源依赖目标、私有态或特殊 settlement 目标不进首批；遇到时明确拒绝并报告。
- 工具提示词不得授予权限；展示顺序不决定能力加载。
