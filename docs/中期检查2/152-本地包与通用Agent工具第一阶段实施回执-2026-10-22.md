## 4. 发布失败与真实消费保护

| 位置 | 实际行为与证据 |
| --- | --- |
| 发现、依赖、导入、导出失败 | 具体来源/包/阶段诊断；无法识别项不执行，所选集合不部分发布；保留安全公开信息及原异常因果 |
| 数据库失败 | 选择、类型证据按原事务回滚；旧 registry/平台及 loader 七组历史不变，后续合法加载不受污染 |
| 已提交、内存发布失败 | `package_publication_failed` / 503，记录 `selection_committed=true` 与 `publication_completed=false`；不伪称回滚或自动重放 |
| 失败实例的工作流入口 | application 和直接业务入口拒绝；节点接受/状态读取拒绝；原 patch/start/reroll 回执只读核实仍可用 |
| 独立供应商与内容 | 业务 CRUD 及其 `request-evidence.write/resolve/read`、`receipt.read` 保留；按 evidence 内嵌 operation 判断领域，不开放工作流新证据写入 |
| 消费时的发布窗口 | 内容类型经最后确认 registry 取得；屏障探针验证发布中与失败后不会看到未确认类型，成功后切换且同一 registry 的动态变化仍可见 |
| 已保存选择缺包 | 保留原诊断/管理路径及纠正选择入口，不清空持久选择或谎称加载成功 |

曾实际发现并修正三个接线问题：错误缺来源/阶段；独立两域请求证据写/解被总门禁误挡；内容 metadata 在发布窗口可能看到未确认 registry。对应独立测试和敏感性对照保留于主证据根 `integration/`。不能把这些修正写成“从未出现产品问题”。

## 5. 工具契约与独立扩展

纯计算适配器提供 `normalize`、`call`、`result` 与可选提示输出；共同层核对准确目标及配置。参数沿用严格必填标量对象；执行仅原生同步普通 working 节点，拒绝业务状态、资源/服务、外部效果、`executor_ref`、特殊结算、异步及生成器，包括 callable 对象。结果须是有限严格 JSON 对象。

准备不执行业务，提示说明不授予权限，说明与调用来自同次 RunBasis。示例使用已有 `PROMPT_MATERIALS@1`，不扩大旧工具提示枚举。可信包可执行 Python 的事实不因宿主限制而成为沙箱保证。

A4 冻结后，另一代理独立增加 `example.numeric-clamp@1.0.0`。它只依赖 `workflow.content@1.0.0` 与 `workflow.agents@1.0.0`，只选该包即可解析闭包，不靠全默认包掩盖缺项。两个目录包与变量工具在同一 Agent 中实际调用，正式配置、工具事实和会话可关闭重开独立重读。

六个核心文件与 `.local/execute150-a4-tools-20261022/a4-freeze.json` 逐一相等：`tool_binding_contract.py`、`tool_bindings.py`、`graph_tool_host.py`、`graph_contracts.py`、`runtime.py`、`agent_executor.py`。因此 A5 证明的是批准协议内新增同类工具无需修改核心；不外推为任意领域权限均已支持。
