## 2. 当前机制与模块职责

`retry_failed_node` 是显式创建失败节点的新一次调用，不是继续原句柄，也不是重新保存原成功结果。此前已接纳的节点不重做；旧失败调用和事实不得改写为成功。

```text
A 成功接纳 → B 调用失败 → 图中止，C 不执行
                         ↓ 用户显式请求 retry_failed_node
A 的结果保留 → B 新调用 → 成功接纳 → C 执行 → 原共同结算
```

| 模块 | 当前职责与本项落点 |
| --- | --- |
| [graph_service.py](../../backend/src/phase1_agent/graph_service.py) | 公开 `control` 受理、回执重放、运行依据选择、控制事务和后台调度；清理 `_control_change_current` 的本动作不可达代码 |
| [graph_failed_retry.py](../../backend/src/phase1_agent/graph_failed_retry.py) | 捕获原调用证据、执行包许可检查、比较状态依据、创建新 node_run 并更新 chain 调用索引；只在测试发现原语义缺陷时局部修正 |
| [capability_packages.py](../../backend/src/phase1_agent/capability_packages.py) | 现有 `register_executor` 和 `register_node(..., **implementation_hooks)` 已能登记测试执行器与 `failed_retry_validator`；不增加注册协议 |
| [runtime_hosting.py](../../backend/src/phase1_agent/runtime_hosting.py) | 真实 `RuntimeHost` 创建、推进和释放句柄，提供原失败调用快照；不能以手工伪造 host 替代正向验收 |
| [execution_data.py](../../backend/src/phase1_agent/execution_data.py) / [configuration_data.py](../../backend/src/phase1_agent/configuration_data.py) | 经 `RunData` 和数据管理绑定原事务；重试准备与接纳不得恢复通用 repo 直连 |
| [graph_records.py](../../backend/src/phase1_agent/graph_records.py) / [graph_store.py](../../backend/src/phase1_agent/graph_store.py) | 保留调用身份、`node_run_attempts`、状态转换和 bundle 历史校验；不为样本放宽校验 |
| 测试包与测试文件 | 仅在临时测试服务中安装；提供受控失败与计数，不加入产品默认包或公开产品目录 |

当前 `_capture_failed_retry` 要求受支持的 round、失败且未接纳的节点、包许可、原宿主调用已安全释放及保留执行环境；`_prepare_failed_retry` 使用旧 `node_run.config` 创建新的调用身份。现有 [test_execution_data.py](../../backend/tests/test_execution_data.py) 中的捕获测试使用手工宿主替身，只能保留为局部证据，不能据此称正向链路已验收。

另外两处须在施工核对，但本篇不提前认定为已复现缺陷：

- 公开 `control` 的重试预检目前用当前 registry 装配读取；须确认许可、对象类型核验和实际重试均消费原 `RunBasis`，不能用当前来源授权本次业务。
- `_capture_failed_retry` 向包策略传入固定文档的 `declaration["config"]`，新调用则复制原 `node_run.config`；须核对两者在可调覆盖下是否一致。已有“本次配置固定”语义不变，若不一致，应以实际原调用配置校验并用定向证据证明，不重新设计配置分类。

## 3. 必须保持的局部契约

| 边界 | 要求 |
| --- | --- |
| 主动性 | 失败仍立即中止并显式报错；只有用户明确控制命令才可新建失败节点调用，不自动重试或跳过 |
| 许可 | 只由已注册包策略按原证据授权；没有策略、没有候选或宿主未安全释放时拒绝，不猜测“抛错意味着无副作用” |
| 运行依据 | 同进程保留的原 `RunBasis`、原 chain 输入、已接纳上游输出及原节点调用配置；缺失时拒绝，不重新加载或回退服务当前表 |
| 身份与历史 | 保持 session / chain / node binding；仅为失败节点创建新 node_run，保留旧失败记录及原事实，更新既有 attempts 关联 |
| 控制事务 | 新 node_run、chain 的新调用索引及 prepared 状态、session 修订按原控制事务共同成立；不拆事务或第二连接补写 |
| 接纳与结算 | 节点接纳、最终结算仍是两个事务；事实仍独立事务；成功检查点、commit 和结束 manifest 的原共同结算不拆分 |
| 数据通路 | 真实重试准备与执行通过数据管理和有限端口；原 bundle 历史校验、类型证据适配、CAS 与故障点保留 |
| 请求重放 | 原幂等键和原请求只重读原控制回执；不能再次创建 node_run、再次执行或重新准备环境 |
| 错误 | 保留现有适用的 `failed_retry_unsupported`、`failed_retry_unavailable`、`failed_retry_basis_changed`、`stale_revision`、`idempotency_conflict` 等诊断和先后关系，不统一改码 |

无依据分支只做本动作的拒绝与不可达代码清理，不能顺带重写无依据 pause/close，或清扫其他控制动作的兼容分支。

## 4. 最小测试包

参考 [test_runtime_hosting_integration.py](../../backend/tests/test_runtime_hosting_integration.py) 的真实包、执行器和句柄模式，新增一个仅测试使用的包。优先在新测试文件内放小型 fixture；确有重复再提取测试辅助，不建设新的测试框架。

建议文件名为 `backend/tests/test_failed_node_retry_integration.py`，不是恢复旧退役文件。通过 `CapabilityPackage` 和现有加载器注册，不直接修改最终 registry 来绕过包加载。

- A 为可计数的上游节点，输出确定值；C 为可计数的下游输出节点；图边确保 B 成功前 C 不参与调用。
- B 绑定真实注册的受控宿主执行器；第一次 `advance` 在已知、无外部副作用的位置失败，第二次新句柄返回确定结果。
- `dispose` 真实运行并计数；包策略只认可本样本的准确失败边界，不使用“任何异常都允许”的宽泛许可。
- 样本不需要额外服务时，沿既有格式返回 `service_ref=None`、`service_evidence={}`；不为验收安装模型服务、凭据或外部 transport。
- 计数器只用于控制样本和观察调用次数，不向产品添加“失败次数决定重试”的策略。
- 正向测试不替换 `_capture_failed_retry`、`_prepare_failed_retry`、许可判断、数据端口或宿主快照；故障注入只用于明确标记的拒绝场景。

该样本只能证明既有机制在一个准确、已知的失败边界上成立，不证明任意自定义节点均可安全重做，也不证明服务专用授权、跨进程恢复或真实模型失败可重试。

### 6.1 必须提供的证据

以下按验证意图组织，可合并在少量测试内，不要求一项一文件或重建旧矩阵。

| 意图 | 验收要求 |
| --- | --- |

| 调用与事实身份 | B 的两次 node_run_id 不同，旧记录仍为 failed，新记录为 succeeded；原上游 output_id 和 payload 不变，旧事实不改写 |
| 原配置与输入 | 策略判断和新执行使用原调用配置，B 的上游引用和 chain 输入保持原依据；存在可调覆盖时不得改用固定定义中的旧值或后保存的新值 |
| 无许可与无依据 | 未注册许可的节点不显示该动作，直接请求也拒绝；受控移除原依据后拒绝；两者均无新 B 句柄、node_run 或下游调用 |

| 持久结果与释放 | 事务结束后独立读取 chain、attempts、两次 B 记录、输出、commit、检查点及结束 manifest；失败旧句柄只释放一次，成功后无活跃句柄或悬挂候选 |
