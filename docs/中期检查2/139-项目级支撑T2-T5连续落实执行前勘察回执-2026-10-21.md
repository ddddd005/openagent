### 4.4 过滤、数量、排序与必须保留的详细读取

- 过滤/数量：工作流目录默认排除归档，`include_archived=true` 时保留并带标志；前端固定传 true 再客户端过滤。会话目录返回该工作流全部会话（含归档），前端客户端过滤。无分页、无服务端计数。
- 排序：工作流按首次出现的修订行顺序（`records` rowid），会话按行写入顺序；目录响应无稳定排序声明，前端不排序。
- 版本条件：工作流固定修订（归档/删除 CAS）、`edit_sequence`（配置更新 CAS）、会话 `revision`（会话命令 CAS，命令前重新 `session.read`）、`metadata_sequence`（改名 CAS）。
- 必须保留的完整读取：`definition.read`（最新=current 组合，供编辑器 entry/接纳基线/改名/发布核对/复制来源）、`definition.read?revision`（运行历史/回执核实的历史定义）、`definition.list` 完整正文（过渡期 `loadDefinitions` 同时初始化 entry）、`definition.sessions` 完整会话视图（轮询/运行控件/历史/事件/名称锁）、`session.read`/`session.metadata.read`/`session.actions`、`catalog.node-types`（含 `package_lock/frontend_extensions`）、`run.read`/`checkpoint.*`/`events.*`/`output.*`/`draft.read|list`/`receipt.read`/`request-evidence.read`、前端节点页读取。

### 4.5 摘要候选与最小接线（候选，不冻结字段/名称）

- 工作流摘要候选：`workflow_definition_id, display_name, fixed_definition_revision, edit_sequence, archived, node_count`；`node_count` 可由最新固定修订的 `bindings` 长度投影，不必组合完整正文。
- 会话摘要候选：`workflow_session_id, workflow_definition_id, definition_revision, revision, name, metadata_sequence, archived, active_chain_run_id`；`status` 若入摘要必须由工作流派生（不能由项目反查节点输出/会话正文）。
- 位置：在 `configuration_service.py`/`configuration_data.py` 增加工作流域只读投影方法，在 `graph_service.py` 一侧增加会话摘要薄方法；公开查询建议作为**独立 query 名称**（如 `definition.summaries`/`session.summaries`，名称不冻结），复用 `POST /api/graph/queries`，**不新增 HTTP 路由**；不改 `definition.list` 的严格返回形状（前端要求每行恰为 `{document, archived}` 两键，`workflowGraphApi.ts:37-43`）。
- 前端消费者分离：侧栏行/会话行用摘要；编辑器 entry、正式配置接纳、管理回执核对、运行控件、运行历史继续用完整读取。`loadDefinitions` 需拆“目录摘要刷新”与“按需正文读取”，不能把编辑器改成摘要。
- 分页/额外统计/更丰富摘要当前无真实消费者，不建议本批新增。

### 4.6 T3 缺口与规划收口

- 现有 `derived` 路径已经证明“新工作流身份 + 保留原节点/边 id”可工作（`proposed["workflow_definition_id"]=uuid4()`、`revision=1` 后直接保存同一文档，`workflow_configuration.py:440-445`）。复制保持内部键与既有行为一致；重建全部键需新增映射并保证对象绑定/事件目标/控制边/配置节点引用一致，本批不默认。

### 6.3 外部引用与包

- 节点配置中的全局资源/模型/供应商引用是**身份引用**；文档校验只校验结构与配置 schema，不校验被引用记录是否存在（`graph_contracts.py:96-228`；`workflow_configuration.py:172-201,411-413`）；存在性/授权在运行期由全局资源/模型服务解析。复制保留引用，不复制资源。
- `package_lock` 保存期只结构校验；运行编译期才要求与当前已加载包版本完全一致，否则 `graph_missing_package`（`graph_contracts.py:241-249,824-830`）。
- 组合正式 current 时要求当前 registry 存在文档引用的节点确切版本，否则读取/复制读取阶段即 `graph_missing_node_type` 409（`workflow_configuration.py:267-282`）。
- 候选：复制不新增包可用性检查、不安装包、不改发布政策；保留来源 `package_lock` 与全局引用；不可用时按现有读取或运行编译边界显式报错，不静默换源。

### 6.4 受理、事务、回执、并发、幂等与 unknown

- 可复用：`GraphRecordStore.atomic`（`BEGIN IMMEDIATE` 内先查幂等回执，同 key 同摘要返回原结果、不同摘要 409，再执行/校验/写回执与 command identity/提交，异常回滚，`graph_store.py:131-161`）；`_configuration_change` 把配置数据端口绑定到同一事务（`graph_service.py:303-312`）；`_save_configuration_update` 完成校验/分类/固定修订+current 写入并事务内回读（`workflow_configuration.py:387-465`）；请求证据（证据操作必须是 `COMMANDS` 中带 `idempotency_key` 的既有命令，`request_evidence.py:52-98`）；应用回执与独立读取（`graph_application_identity.py:192-201`；`graph_receipts.py:540-577`）。
- **独立可核实不是自动获得**：新 operation 至少必须同时补齐①`COMMANDS` spec（否则回执读取 `unsupported_operation`，`graph_receipts.py:540-547`）；②`native_command_request` 映射到原生 receipt（未映射则 application identity 为 None，回执读取 `unresolved: application_identity_missing`，`graph_application_identity.py:35-152`）；③`_validate_result` 的该 operation 结果校验分支（否则落入其他校验而 `receipt_invalid`，`graph_receipts.py:255-385`）。这三处是最低接线要求，**不是新结果契约的完整清单**：若用独立 `workflow.configuration-copy-result`，还须在 `application_accepted_result` 增加来源/目标/版本投影（`graph_application_identity.py:155-200`），并在前端 `workflowApplicationApi.ts:97-121` 的 accepted 严格比对与专用复制适配器对应验证。否则服务端可能写入成功，前端/独立回执仍无法确认同一复制结果。
- 分派：新 operation 加入 `COMMANDS` 即经 `POST /api/graph/commands` 通用路由，无需新增 `graph_http.py` 路由；`management_request` 默认把非执行 authority 判给轻管理路径；但 `_invoke` 要求目标服务有同名方法（`graph_application.py:58-94`）。
- 复制候选受理顺序（最小建议，不冻结）：BEGIN IMMEDIATE → 回执键查询/摘要比对（命中即返回原结果，不再检查来源版本，保证重放稳定，顺序复用 `graph_store.py:139-145`）→ 事务内读来源 `configuration_view` 并校验存在/未删除、`edit_sequence`（及固定修订）匹配，不符显式冲突 → 校验目标身份不存在 → 组合正式文档 → 改写工作流身份/计数为 1/名称 → 复用 `save_fixed_revision`+`_write_configuration` 写固定修订 1 与 current → 写原生回执+应用 identity → 提交。
- 并发：SQLite `BEGIN IMMEDIATE` 串行化写者（`storage.py:47`）；来源读取与目标写入同一写事务可避免读后来源被改的 TOCTOU；不同幂等键/不同目标代表不同副本，不新增重复副本限制（§8.3 D-6），pending 不能显示为成功；同目标身份冲突应显式拒绝（现有创建路径对已有 current 目标以 `stale_edit_sequence`/`graph_configuration_missing` 拒绝，非专门冲突错误）。
- 幂等/重复提交：同 key 同摘要返回原结果、不同摘要 409；前端配置/管理通道单 pending 锁避免同通道重复发送，但复制按钮每次点击生成新目标（非幂等操作）。
- unknown：保留原请求证据与 pending，只读回执，不重放；新增 operation 的最低三处接线与新结果的后端/前端 accepted 核对必须一起闭合，不能以业务提交成功替代独立核实。
