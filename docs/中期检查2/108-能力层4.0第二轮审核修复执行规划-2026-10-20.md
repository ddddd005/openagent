## 4. 核心修复参考

### 4.1 F1：先确认准备存在，再判断是否为空

沿现有 `_bound_tool_specs` 顺序作局部调整：

1. 保留请求字段与准确 Agent 身份的检查。
2. 取得本链 frame 后，先要求其存在；缺失统一沿用 `tool_binding_not_prepared`，不得返回空集、临时重建或换用当前注册表。
3. frame 存在且 Agent 查询自身、该 Agent 确实无业务绑定时，仍允许 `[]`。
4. 有绑定时继续执行原有绑定、descriptor、RunBasis 和运行 owner 核验，再返回同帧声明；不能把缺帧修复变成权限放宽。

`PublicAgentExecutor` 的非图/独立调用上下文没有安装业务工具桥，与“已经进入图执行桥却缺 frame”不是同一情况。[agent_executor.py](../../backend/src/phase1_agent/agent_executor.py#L48) 的有限桥可选入口不因本项被强制接入图模块。

验证至少区分：缺帧报错、帧存在且无绑定允许空集、有绑定正常返回、未授权描述不得读取其他 Agent。保留原无绑定 Agent 图可运行的正向证据。

集成缺帧注入要精确落在 Agent 取声明前；若先删除 frame 导致 loader 的 `prompt` 桥报错，并不能证明 `_bound_tool_specs` 已修正。可在测试侧 Agent `specs` 桥调用前移除本链 frame，断言经过该分支后失败且受控 transport 调用为 0，不引入 sleep 竞争或新的调度机制。

### 4.2 F2：提示参数与真实工具使用同一校验规则

优先在 `validate_tool_prompt` 复用真实工具已使用的 `_model_tool_schema(name, parameters)`，保留外层成对身份和 presentation 检查。不为了验证而注册 callable 或执行业务。

现有真实工具接受的是严格对象 schema：准确包含 `type/properties/required/additionalProperties`，`type=object`、`additionalProperties=false`、属性与 required 完整对应，参数项遵守当前标量与说明规则。合法无参数 read schema 仍应通过；本批不另行开放嵌套对象、可选参数等真实注册路径尚不支持的形式。

将参数校验范围内的 `SchemaError`、`TypeError`、`ValueError` 等明确拒绝映射为既有 `tool_prompt_invalid`，保留异常原因。不得用覆盖整个节点的 `except Exception` 隐藏其他错误；presentation 的既有诊断也不被改写。

负例至少含合法 JSON schema 但不是严格工具对象的 `{"type":"string"}`、缺少必要结构、`additionalProperties=true` 和 required 不完整；原非法 schema 负例仍保留。正例应取自真实准备声明，覆盖 read 及写操作，并确认投影没有改写其参数。

这属于补回 106 号既定验证，不是借机发布新契约。优先保持 `tool_prompt_schema()` 及 `DataTypeDefinition.to_dict()` 的持久声明不变；[TypeContractStore](../../backend/src/phase1_agent/type_contract_store.py) 会拒绝同身份声明改变。施工方应记录修复前后声明对比，并在隔离旧库上验证合法内容重读，而不是利用声明未变化去宣称所有旧数据都已兼容。若确需改公开 schema、包导出或处理历史非法内容，先报告影响，不默改版本、迁移数据或删除证据。

### 5.1 无普通实例样本

现有 `build_graph` 总会加入下游变量读取；只设 `with_normal=False` 不足以满足该意图。应新增小型专用样本或扩展现有 helper 的明确选项，同时移除对应数据边、控制边和 ACL 中已不存在节点的引用；保留现有成功样本，不统一改造所有旧图。

变量注册仍走已有显式事件。Agent 的四个工具通过准备声明取得真实目标，即使画布没有对应读写业务实例；统计三次写对应的修订增量与工具回执，确认最终 Agent 结算未再写一次。

### 5.2 独立重读故障样本

注入仅在 `graph.tool.object-write` 已完成接纳之后、该工具的事务后读取处触发一次。不要把注册、启动准备、事务内写入或最终验收读取一并阻断，否则无法证明故障阶段。

通过正常查询或重开隔离库，分别核对已保存值、修订、写入回执与本次调用身份。不得出现该调用成功返回或成功 `tool_settled` 结果；失败事实可以正常保留。只提交一次、executor 不被自动再次调用，后续 Agent 失败不回滚这次正式写入。

该验证首先检查现有实现，不预设要改接纳代码。若暴露真实事务或错误传播问题，报告具体故障点与影响后再确定修复范围，不为通过测试自动增加补偿、重放或第二套回执。

### 5.3 消息证据的准确比较

规范 `agent_message` 使用 `blocks`，模型请求使用对应的 transport 投影，不能直接要求两种封套整体相等。比较应沿现有投影规则核对本次受控文本消息的顺序、角色及文本，继续检查 tool prompt artifact 来源，并对照 snapshot 工具名称、说明及参数。未覆盖的元数据不概括成“完整请求逐字段相等”。
