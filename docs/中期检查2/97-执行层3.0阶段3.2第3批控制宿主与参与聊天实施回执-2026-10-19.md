### 1.1 验收 P2 修正

验收发现：`_execution_read` 在没有本次依据时对所有宿主读取回退当前 registry，活跃宿主服务分支只检查持久 owner/status，随后仍执行 `frame.call`。受控故障中，移除本次依据后服务仍收到并处理请求，直到节点接纳才报 `run_basis_unavailable`，服务副作用可能先发生。

修正：

- `_execution_read` 改为严格要求本次 `RunBasis`，缺失时在读取 owner 和执行 `frame.call` 前报 `run_basis_unavailable`；
- 新增 `_execution_read_current`，只用于 `_describe_runtime_input_origin` 这一显式诊断、宿主释放/控制清理和订阅通知等不执行服务的路径；
- `_host_call` 的服务、输入、产物和 executor facts 分支均使用严格读取；活跃服务调用不再接受当前 registry 回退；
- 保留公开/历史读取和 postcommit 前端通知的当前来源只读路径，但它们不执行宿主服务。

新增 [test_host_service_integration.py](../../backend/tests/test_host_service_integration.py) 回归 `test_active_host_service_call_requires_the_retained_run_basis`：节点在调用服务前移除本次依据，服务实例 `calls == 0`，运行以 `run_basis_unavailable` 失败；修正前该服务会先被调用一次。现有输入来源诊断仍保留原 `runtime_origin_owner_mismatch`，不因严格化改成新的业务错误。

## 2. 实际改动

### 2.1 执行数据端口扩展

[execution_data.py](../../backend/src/phase1_agent/execution_data.py) 增加：

- `ExecutionFacts`：在数据管理入口打开的独立事务内检查 session/chain/node_run owner 并调用原 `RuntimeFactStore.accept`；不加入 `RunData`。
- `ExecutionState.read_object`：按原节点、修订和对象权限读取单个对象，供宿主产物闭包使用。
- `ExecutionRecords.executor_facts`：按原 executor stream 和 fact ids 读取事实，供 `facts:read` 宿主调用使用。
- `ExecutionChatData.round_inputs` / `materialize_checkpoint`：reroll 读取冻结输入和检查点状态，不直接持有检查点仓储。

[configuration_data.py](../../backend/src/phase1_agent/configuration_data.py) 增加 `WorkflowDataManagement.accept_fact(owner, stream_id, fact)`：

- 新 store、`BEGIN IMMEDIATE`、owner 检查、事实写入、`before_runtime_fact_commit`、提交/回滚和关闭都在该入口内；
- 不经过 `_change`/`GraphRecordStore.atomic`，不生成管理幂等回执；
- `after_runtime_fact_write` 仍由 `RuntimeFactStore.accept` 触发。

### 2.2 控制与失败收尾

[graph_service.py](../../backend/src/phase1_agent/graph_service.py)：

- `_control_change_data` 承接保留运行依据的 pause/resume/close/retry_archive/retry_acceptance/retry_failed_node：
  - session、chain、node_run、private、variables、objects 经 `RunData.records/state`；
  - close 使用 `_commit(data)` 和 `_save_manifest(data)`，round 的 closed_execution commit 与 `chain_end` manifest 在同一控制事务；
  - retry_acceptance 的保留结果依据比较使用 `data.state.variables`、`data.records.private_states`、`data.state.objects`。
- `_control_change_current` 只在运行依据已释放时承接跨进程控制：
  - close 保留当前来源的 closed_execution commit 和结束 manifest；
  - pause 保留原有 session/chain 状态更新，不执行节点；
  - resume/retry_archive/retry_acceptance 先保留 `recovery_unavailable` 或 `failed_retry_unavailable` 的原有诊断，再拒绝无依据执行；
  - retry_failed_node 在无依据时明确 `failed_retry_unavailable`，不调用只接受 `RunData` 的重试准备。
- 控制事务内重新核对 `active_chain_run_id` 与事务前探测值一致，避免探测和写入之间切换链后使用另一条链的运行依据。
- `_execute` 失败收尾在运行依据存在时经 `RunData` 写 chain、node_run、session 和结束 manifest；无依据时保留 3.1 的 repo 收尾和 `chain_start` 回退。
- `_execute` 装配事务改用 `execution_read`，只读装配不再绑定可写 `RunData`。
- 宿主 `_validate_runtime_references` 保留调用方传入的 registry，不再无条件重取运行依据。
- `_start_run` 在 `_change` 内构造一次 `RunData` 并交给 prepare；普通 start、事件提交、聊天 submit/reroll 都接收同一数据包，不再由 prepare 各自从 repo 重建。

[graph_failed_retry.py](../../backend/src/phase1_agent/graph_failed_retry.py)：

- `_failed_retry_basis`、`_capture_failed_retry`、`_prepare_failed_retry` 只接受 `RunData`，删除 repo 分支；
- 修正 `_capture_failed_retry` 仍引用旧 `target` 的未定义变量，失败重试捕获改为使用传入的 `data`；新增直接回归确认捕获结果和 state/private/object 依据。

## 3. 事务与权限边界

| 边界 | 本批保持 |
| --- | --- |
| 节点接纳 | 仍是一次 `_node_event` 的 `_change`/`atomic`，保存该节点输出、约定写入、变量、私有态、对象写集、node_run/chain 进度和 session 修订；不是整图事务 |
| 最终结算 | 仍是 `finish` 的一次 `_change`/`atomic`，共同保存终态、commit、成功检查点和结束 manifest；未拆分 |
| 控制关闭 | round 的 chain/session 关闭、closed_execution commit、state_snapshot manifest 和 chain_end manifest 在同一控制事务；event 关闭不 commit |
| 事实 | `accept_fact` 独立 `BEGIN IMMEDIATE`，owner 检查与 immutable fact 写入同事务；不生成管理回执，不并入执行事务 |
| 独立重读 | `read_execution` 新 store + 读事务，事务结束后读取；不是保存响应或内存缓存 |
| 类型证据 | 仍由 `ExecutionTypeEvidence.check_registry` 承接；只读定义口没有新增 `check/register` |
| bundle | `_change` 仍以当前 `definition_registry` 构造 `GraphRecordStore` 并执行 `_validate_changes`；端口写入未绕过 |
| 认领/重试 | resume、retry_archive、retry_acceptance、retry_failed_node 仍依赖同进程 `_futures`、保留候选和运行依据；未合并成一个动作 |

## 5. 留存与未认证

以下路径本批未迁移，不能算作 3.2 全表完成：

- 失败链释放绑定后的生命周期管理关闭（archive/delete 的 `_close_owned_runs`）仍使用当前来源；95 号 §2.4 允许该管理关闭，但本批未把它改成可写执行数据；
- 公开/历史/消费者读取（`get_session/list_sessions/get_run/list_checkpoints/read_checkpoint`、`GraphPublic`、`GraphInformation` 独立历史）仍保留原只读实现；
- 聊天 select/fork 的候选规则、检查点前缀复制和部分对象写业务仍留在聊天功能；本批只迁移参与执行链的提交、reroll、冻结写入和成功绑定；
- 模型授权桥仍使用调用方专用 `mode=ro`/`query_only` 连接，不改成 `RunData`；
- provider/global resource 管理、项目包管理和删除/归档管理未迁移；
- 运行事实历史页、信息绑定写入和独立历史 reader 保留原来源；
- `_execute` 在运行依据缺失时的收尾仍保留 repo 回退和同链 `chain_start` manifest 复用；
- 控制无依据 pause/close 仍走当前来源，以保留跨进程诊断和既有管理行为；这不是执行主链的数据端口迁移；
- `retry_failed_node` 的完整正向路径没有产品包注册 `failed_retry_validator`，本批只验证了捕获数据依据和错误边界，未把该动作宣称已端到端验收。
