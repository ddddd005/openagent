# 能力层 4.0-2 变量工具绑定局部契约

日期：2026-10-19，Asia/Shanghai。

性质：按 [99 号执行规划](99-能力层4.0节点与Agent工具统一调用执行规划-2026-10-19.md) 第 4.2、5、6 节记录的施工局部契约。用户已确认“Agent 自身真实节点身份授权”和“变量写工具逐次接纳、已接纳结果不因后续失败回滚”两项业务边界；本文落实其余具体接口、配置表示与包契约，作为 4.0-3/4/5 的实现依据。本文不是验收回执。

2026-10-20 第二轮接续订正：第 2.2/2.3 节的两节点、两输出和展示默认值保留为首轮已实施契约；最新要求改为一个工具加载节点、一个成对结构化工具提示输出，进入上下文装配，列表与参数分别支持上下文前/中/后，默认前/后。首轮准确能力、Agent ACL、统一依据及逐次接纳语义继续有效。实际总量和来源校验尚有核验缺口；第二轮实施、版本安排及验收按 [105 号执行规划](105-能力层4.0第二轮收口执行规划-2026-10-20.md)，不能继续将本篇旧节点形式当作最新目标或悄悄改写旧版本。

## 1. 范围

首版只接 `workflow.variable@1`：

| 模型操作 | 真实能力 | 目标配置 |
| --- | --- | --- |
| `alias_read()` | `tools.variable-to-content@1` | `{object_key, mode: "json"}` |
| `alias_set(value)` | `tools.variable-assign@1` | `{object_key, operation: "set", value: ""}`，值经输入端口 |
| `alias_add(value)` | 同一 `tools.variable-assign@1` | `operation: "add"` |
| `alias_subtract(value)` | 同一 `tools.variable-assign@1` | `operation: "subtract"` |

字符串、布尔变量只生成 read/set；`add`/`subtract` 仅在变量已注册为 integer/number 时生成。不新增变量注册、删除、跨会话、动态类型、通用数据类创建。

## 2. 包与加载锚点

### 2.1 新能力包

新增内置包 `workflow.tool-bindings@1.0.0`，manifest schema 1，依赖：

- `workflow.content@1.0.0`（内容类型与提示词材料类型）；
- `workflow.tools@1.0.0`（两个真实变量 executor）；
- `workflow.agents@1.0.0`（锚点引用的真实 Agent 类型）。

不改 `workflow.tools@1.0.0`、`workflow.agents@1.0.0` 的既有 manifest 或节点版本。原因：配置线勘察确认给已发布包追加节点导出属于契约变化，而升版本会使既有文档 `package_lock` 在 `GraphCompiler._compile` 处报 `graph_missing_package`。新包只在新建默认选择中出现；既有项目默认选择不含新包时仍可运行原图，只是不能保存/启动锚点节点，须经包选择管理启用。该留存记入回执。

### 2.2 锚点节点

`tool-bindings.variable-tools@1`，显示名“变量工具绑定”，分类“变量”，`execution_class="non_working"`，无输入/输出端口，无 `object_accesses`、无 capability、无 service/resource 声明、无 executor。它不是隐藏业务实例，不排入图执行顺序。

配置：

```json
{
  "agent_node_id": "<真实 Agent 节点实例 UUID>",
  "variables": [
    {"alias": "score", "object_key": "variable/score",
     "operations": ["read", "set", "add", "subtract"]}
  ]
}
```

约束：

- `agent_node_id` 使用 `config_node_references` 指向 `agents.execute@10`，`multiple=false`、不允许空串；校验复用 `GraphCompiler` 的同一规则。
- `variables` 最多 64 项；`alias` 匹配 `^[A-Za-z_][A-Za-z0-9_]{0,54}$`（保证 `_subtract` 后缀后不超过 64），同一 Agent 内唯一；不得生成 `final_answer`。同一 Agent 的实际模型工具总数（含静态工具余量）不超过 120 项。
- `object_key` 必须是文档 `object_bindings` 中已有的 `workflow.variable@1` 对象；不得由锚点创建对象。
- `operations` 为 `read|set|add|subtract` 的非空不重复子集；真实类型不支持的操作在启动准备显式拒绝。
- 锚点不取得变量 ACL；ACL 主体是 `agent_node_id`。

### 2.3 提示词节点

`tool-bindings.tool-prompt@1`，显示名“工具提示词 · 已绑定”，分类“提示词”，`working` 节点，输出 `tool-descriptions`、`tool-schemas` 两个 `PROMPT_MATERIALS@1` 材料端口。配置：

```json
{
  "agent_node_id": "<同一真实 Agent 节点>",
  "tool_name": "score_read",
  "description": {"role": "system", "placement": "before", "depth": null, "order": 0, "enabled": true},
  "schema": {"role": "system", "placement": "before", "depth": null, "order": 1, "enabled": true},
  "description_member_id": "<UUID>",
  "schema_member_id": "<UUID>"
}
```

它只从本次已准备帧读取同名工具的描述与参数 schema，生成与真实工具声明一一对应的材料；不授予权限、不决定能力加载、不改变目标。展示顺序由它的 presentation 决定，不影响 Agent 工具集合。

## 3. 绑定声明与准备结果

### 3.1 包侧适配器

`tool_binding_contract.ToolBindingAdapter` 是 `RegisteredNode` 的新可选声明，仅由可信包注册：

```python
ToolBindingAdapter(
    normalize(config) -> [{"alias", "object_key", "operations"}],
    bind(entry, item) -> [{"name", "operation", "access", "description",
                           "parameters", "target": {"component_id", "component_version"},
                           "config"}],
    call(spec, arguments) -> (config, inputs),
    result(spec, outputs, item) -> dict,
)
```

包负责变量语义、工具名/schema、目标节点身份与调用参数/结果转换；执行层负责注册表解析、ACL、上下文、调用与接纳。执行层不导入变量包业务代码。

### 3.2 启动准备

`_prepare_run` 在 `GraphCompiler.compile` 成功后、`_check_implementations` 前收集：

1. 遍历文档节点，仅处理注册结果中带 `ToolBindingAdapter` 的节点；
2. 手动跑 `registry.validate_config` 与 `config_node_references`（锚点不在 `plan.ordered_node_ids`，编译器不会访问它）；
3. `agent_node_id` 不在本次 `ordered_node_ids` 时跳过该锚点，不激活无关能力；在本次计划内则继续；
4. 对每个声明：读取会话对象当前记录（只读），校验 `workflow.variable@1`、Agent 在 `readers`（写操作还须在 `writers`）、已注册/类型/操作；add/subtract 在启动只核对数值类型，是否已赋值仍由调用时的真实 executor 检查（允许上游普通节点先赋值）；
5. 解析每个目标的精确 `component_id + component_version`：必须存在、`execution_class="working"`、有原生 `executor`、无 `executor_ref`、无 service/resource 声明、无私有态/settlement builder/额外 session item 提供者；否则启动显式失败；
6. 冻结为 `PreparedToolFrame`，存于服务每链映射（与 `_execution_registries` 同址），不写入图、不新增 node_run、不创建边、不调用 executor；
7. 释放点与 `RunBasis` 相同的五个收尾位置；暂停、archive_failed、可失败重试链保留。

准备结果至少包含：`binding_id`（本次运行生成的 UUID）、锚点节点、Agent 节点、alias、object_key、操作集合、每个工具入口的 name/operation/access/description/parameters/target/config、descriptor 节点到 Agent 的只读映射。

### 3.3 错误码

沿用既有码优先；新增：`tool_binding_invalid`、`tool_binding_agent_missing`、`tool_binding_variable_missing`、`tool_binding_type_mismatch`、`tool_binding_access_denied`、`tool_binding_alias_conflict`、`tool_binding_operation_unavailable`、`tool_binding_target_unavailable`、`tool_binding_target_unsupported`、`tool_binding_not_prepared`、`tool_binding_not_found`、`tool_invocation_scope_invalid`、`tool_acceptance_mismatch`。

## 4. 共同调用桥

内核当前只调用 `RegisteredTool.execute(arguments)`。本次新增：

- `tools.ToolInvocation(tool_call_id, tool_execution_id, tool_name)`；
- `RegisteredTool.execute(arguments, *, invocation=None)`；新增 `register_bound_tool(name, description, schema, invoker)`，invoker 接收 `(arguments, invocation)`；
- `SnapshotKernel` 在唯一下发点把内核已生成的 `call_id` 与 `execution_id` 传入；`final_answer` 路径不变；
- 不用全局/线程局部“当前工具”，不把调用身份塞进模型参数。

`PublicAgentExecutor` 在构造时通过 `NodeExecutionContext.bound_tool_specs(agent_node_id)` 取得本次帧内的只读工具声明，与包静态注入工具合并；工具名冲突、`final_answer` 保留、快照 `tool_definitions` 的 `name/version/description/parameters_schema` 由同一份声明生成。快照与内核工具对象仍互相校验。

`NodeExecutionContext` 新增：

- `bound_tool_specs(agent_node_id)`：只返回 name/operation/description/parameters/binding_id，不返回对象值或 ACL；
- `invoke_bound_tool(binding_id, operation, arguments, tool_call_id, tool_execution_id)`：仅允许调用帧中该绑定所属 Agent 节点自身调用；
- `apply_accepted_object(object_key, record)`：把已接纳并重读的对象记录写回本次运行的共享对象视图。

调用桥方法由 `execute_graph(tool_bridge=...)` 注入；`tool_bridge` 仅接受本次链的准备帧和活动 owner，缺帧、缺绑定、owner 不再运行、越权或未准备均显式报错。

## 5. 逐次写入接纳

每次 `set/add/subtract`：

1. 桥校验调用身份与活动 owner；
2. 从数据库独立读取目标对象当前记录，构造仅含该对象的有限 `NodeExecutionContext`，`node_binding_id` 使用真实 Agent id（ACL 主体），`node_run_id` 使用 Agent 本次调用，`operation_scope="tool:<tool_execution_id>"`；
3. 调用目标真实 `executor`（与普通节点同一函数对象），只形成写意图；不把意图并入 Agent 的 `object_writes`；
4. 要求恰好一个写意图，目标、期望修订与读取一致；
5. `GraphRecordStore.atomic` 事务内重查 session/chain/Agent node_run 仍活动，经 `ExecutionState.apply_objects` 接纳；`node_id` 为 Agent id，`operation_key` 包含 `tool_execution_id` 与目标对象；`write_evidence` 含 tool_call/tool_execution/binding 身份；
6. 事务提交后独立重读目标对象，修订、revision_id 与值必须与接纳结果一致，否则报 `tool_acceptance_mismatch`，不返回成功；
7. 更新 Agent 上下文共享对象视图后，才把实际值、修订和对象键作为工具结果返回模型。

读取工具使用真实目标 executor 和每次调用时的最新正式对象值，不创建写事务，不接纳对象变更。

已接纳写入不会在 Agent 节点成功结算时再次提交；Agent 的 `_save_effects` 只看到空对象写集。事实仍是独立事务：`tool_dispatch` / `tool_settled` / `message_accepted` 只记录过程；对象接纳回执在 `session_object_receipts` 的 operation key 中关联本次工具执行。不新增表、列或事实种类。

## 6. 运行视图与失败保留

- 工具写入接纳后立即可被同一 Agent 后续工具读取（每次从数据库读当前值），并写回共享对象视图；
- Agent 节点成功时 `_node_event` 返回的 `object_states` 再次从数据库读出，后续普通节点看到新值；
- 后续工具失败、Agent 失败、暂停或关闭不撤销此前已接纳对象；不回滚、不自动重放已计算的 `add/subtract`；
- 暂停/关闭竞争在接纳事务内以 session/chain/Agent run 状态拒绝；拒绝时不自动重试；
- 不伪造 node_run、不调用 `_node_event`、不把工具调用说成完整画布节点执行。

## 7. 明确不做

- 不改 `agents.execute@10` 的公开 capabilities/service 声明，不为工具调用新增 Agent 节点版本；
- 不支持宿主 `executor_ref` 目标、服务/资源目标、私有态、settlement builder、外部输入或需图连线的目标；遇到时启动显式拒绝并记入留存；
- 不把变量对象完整权限并入 Agent 总权限；`object_accesses` 仅用于目标上下文，不写回 Agent 定义；
- 不修改 `workflow.variable@1` 类型契约、图文档 schema、manifest 协议、`input_snapshot`、执行事实字段集或存储版本；
- 不实现通用工具导出种类、工具商店、自动发现或运行期热加载；
- `prompts.tool@2` 的内置静态目录保持不变；变量工具提示词由新的 `tool-bindings.tool-prompt@1` 表达，不把两者混成同一权威。

## 8. 验证计划

| 面 | 计划证据 |
| --- | --- |
| 配置通路 | schema 2 文档经 `_save_definition`/公开配置接口保存，独立重读锚点配置与变量绑定一致；不依赖进程内列表 |
| 启动准备 | 无目标业务节点实例仍生成准备帧；未执行任何变量 executor；缺类型/实现/ACL/操作/Agent 引用时在 `start` 前失败，后台提交与 Agent 执行为 0 |
| 共同实现 | 正常 `tools.variable-assign@1` 节点与 Agent 工具调用命中同一注册 executor；计数器验证 |
| 权限 | ACL 缺 Agent id 时启动拒绝；写操作缺 writers 时拒绝；不借用锚点或其他实例身份 |
| 首版样本 | 注册变量初值 → 普通节点 set 5 → Agent read 5 → set 10 → add 2 → read 12 → 下游读 12 |
| 逐次接纳 | 两次写各自新增 revision 与 operation receipt；Agent 成功不重复提交；重开库仍为 12 |
| 失败保留 | 第一次写已接纳后第二次工具失败，Agent/验证失败但第一次值保留 |
| 提示词 | `tool-bindings.tool-prompt@1` 输出与 Agent 快照中的同名工具描述/参数一致；改 presentation 顺序不改变可调用集合 |
| 前序保护 | 运行依据、图执行、Agent 工具、变量节点、配置保存代表组回归 |
