## 4. 3.4 跨层验收

### 4.1 实际路径与层次

```text
公开入口（GraphWorkflowService / WorkflowOperations / 事件 / 前端节点）
→ 流执行协调（prepare、execute、control、finish）
→ 图编译与图执行（GraphCompiler、GraphPlan、execute_graph）
→ 节点实现（原生 callable 或宿主执行器）
→ 执行数据管理（WorkflowDataManagement）
→ RunData 六个有限会话
→ 现有 GraphRecordStore / ProgramVariableStore / SessionObjectStore /
   RuntimeFactStore / TypeContractStore / CheckpointRepository
→ 消费者只读已持久结果
```

外层管理业务（项目创建、归档、删除、包管理、provider/global resource 管理）不在本路径中，也没有被本批宣称已迁移。

### 4.2 领域与事务清单

| 领域 | 有限端口 | 内部复用 |
| --- | --- | --- |
| 运行记录与输出 | `ExecutionRecords` | `GraphRecordStore`；不向业务开放任意 kind 或 `get/put/rows` |
| 变量、对象、私有态 | `ExecutionState` | `ProgramVariableStore`、`SessionObjectStore`；保留 CAS 和类型核验 |
| 共同结算 | `ExecutionSettlement` | `GraphRecordStore`、`StateManifestStore`、`CheckpointRepository` |
| 类型合同 | `ExecutionTypeEvidence` | `TypeContractStore`；准备核验仍可能登记缺失证据 |
| 配置依据 | `ConfigurationReadSession` | `ConfigurationDataSession`、固定修订 |
| 参与聊天 | `ExecutionChatData` | 聊天 runtime、检查点物化；候选规则仍在聊天功能 |
| 运行事实 | `WorkflowDataManagement.accept_fact` / `ExecutionFacts` | `RuntimeFactStore`；独立 `BEGIN IMMEDIATE`，不生成管理回执 |

事务边界保持：

| 边界 | 本批保持 |
| --- | --- |
| 准备 | prepared 记录、节点调用配置、会话活动指向同一命令事务；失败不发布半套环境 |
| 节点接纳 | 该节点写集、输出、变量/私有态/对象、node_run/chain 进度和会话修订同一 `_change`；不是整图事务 |
| 最终结算 | 终态、commit、成功检查点、聊天候选绑定和结束 manifest 同一 finish 事务 |
| 控制 | pause/resume/close/retry 的原控制事务；close 的 commit 与结束 manifest 同事务 |
| 事实 | owner 校验和不可变事实同独立事务，可在节点结束前成立 |
| 只读 | `execution_read` 在当前事务内读；`read_execution` 新开 store + `BEGIN` 读事务 |

### 4.3 关键诊断

本批复核始终以显式诊断阻断，不用当前来源掩盖缺失或不符：

- `run_basis_unavailable`：活跃宿主服务/输入/产物/事实在缺少本次依据时阻断，服务调用次数为 0（第 3 批回归）；
- `graph_acceptance_basis_changed`：保留结果的状态/私有态/对象依据变化时拒绝重接纳；
- `recovery_unavailable`、`failed_retry_unavailable`：无同进程继续或失败重试条件时不重放；
- `execution_owner_changed`：事实 owner 已不再运行；
- `runtime_artifact_reference_denied`：产物引用不在授权闭包；
- `checkpoint_source_definition_mismatch`：检查点收集的固定修订与持久文档不一致；
- `package_missing_dependency`、`idempotency_conflict`、`stale_revision`：原有包、回执和版本门禁保留。

### 4.5 运行控制、求值与节点自由度

- 暂停/继续：新增测试用真实 `service.control` 和阻塞门节点验证暂停前缀保留、继续不重复执行门节点、控制写经 `ExecutionRecords`；
- 暂停期间保存 B：新增测试验证继续仍使用节点记录中的 A，下一轮才使用 B；门节点只执行一次；
- 准备边界：新增测试拦截 executor submit，`start` 返回 prepared 时节点执行次数为 0，准备事务不提前执行业务；
- 关闭/重接纳：既有测试验证 closed_execution、原结果复用和状态围栏；不合并 `resume`、`retry_acceptance`、`retry_archive`、`retry_failed_node`；
- 求值：配置固定在 prepare，执行时读取持久 `node_run.config`；节点在调用时求值，准备阶段不提前执行业务；
- 自由度：节点不自行激活、不指定下游、不要求内部步骤登记；图执行按真实边推进，外层顺序注册仍属另项。

### 4.6 运行事实与宿主边界
