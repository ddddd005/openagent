### 5.2 五步顺序与边界事实

事件链 `d8f4916e-d794-48fa-9eda-95444be38eaa`；实测进入顺序：

```
['_run_prepare_stage', '_run_execute_stage', '_run_settle_stage', '_run_notify_stage', '_run_release_stage']
```

即 `0100→1000→2000→2100→2200` 各 1 次。只读包装的 before/after 关键事实：prepare 前无本次事件链、session 非 running，prepare 后 session prepared、active=事件链、chain prepared、start manifest prepared；execute 后 session/chain running；settle 后 chain/session succeeded、end manifest succeeded、未通知、commit=1/checkpoint=1（沿用已结算 round 基线）；notify 后 `round_notifications` 记录 business_committed=true、business_status=succeeded；release 后 `_resource_frames/_execution_registries/_acceptance_candidates/_failed_retry_candidates/_execution_errors` 均无该链。

事件作为运行来源：chain 记录 `execution_kind="event"` 且 event 字段与提交一致；`ordered_nodes=[text,output]`（事件 target=output 含其上游）；公开 `event.read` 返回 `workflow.event-run`，`status="succeeded"`、source/event/chain_run_id 与记录一致；可选同进程 close→reopen 后 session/事件运行/event.read/round run 逐项相等（`mismatched=[]`）。

结算口径须分两句写清：事件前同一 session 先跑普通 round，得到 commit=1/checkpoint=1 基线；事件运行后观察值仍为 1/1，但**事件自身 delta=0/0**——当前产品仅对 `execution_kind=="round"` 执行 completion commit 与 checkpoint（`graph_service.py:1533`；`test_graph_events.py` 文件头也写明 event 运行 without completion commits）。这是既有已批准语义，不记为失败；本探针如实记录，未改产品。

## 6. 新观察：成功事件的 `event.read` 带“失败风格” diagnostic（待裁定，未修）

- 现象：权威探针中成功事件链的公开 `event.read` 返回 `status="succeeded"`，同时带 `diagnostic={"reason_code":"event_failed","message":"Event execution requires attention"}`。
- 静态原因（只读核对）：`backend/src/phase1_agent/graph_service.py:1606-1611` 在 notify 阶段把 `round_notifications` 并入 `chain["diagnostic"]`（成功链的 diagnostic 因此非空）；`backend/src/phase1_agent/graph_events.py:87-96` 的 `_read_event` 以“diagnostic 非空”即投影为通用 `event_failed`，未区分“成功 + 通知诊断”。
- 覆盖缺口：`backend/tests/test_graph_events.py` 对 `read_event` 只断言 status/targets 等（如 :205、:310、:324、:341），`backend/tests/test_variable_http_registration.py:93-96` 也未断言 diagnostic；未搜到其他 `event.read` diagnostic 用例。
- 影响判断：不影响本次五步顺序/边界/来源/释放结论；但调用方（含前端 `workflowEvents.ts` 的 `readWorkflowEvent` 消费方）可能把成功事件误读为需要关注。事件五步观察本身通过；该诊断投影是**另一个待裁定的产品观察**，可能影响浏览器阶段对事件体验的判定。
- 本轮未修：产品未改，按“失败/新观察先交回”的口径，建议由审阅方决定它是已知限制、单独修复批次，还是纳入浏览器准入前的必须项。若修复，受影响行为、测试与复验范围需另行授权。第三轮审阅已确认这是产品缺陷并要求浏览器准入前窄修，处置见 [164 号事件诊断投影窄修回执](164-0.5.0事件诊断投影窄修与163统计订正及定向复验回执-2026-10-22.md)。
