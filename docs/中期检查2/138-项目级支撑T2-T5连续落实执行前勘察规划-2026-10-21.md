## 1. 目标与交付顺序

围绕一条真实工作流使用链，回答怎样在现有 T0-T1 基础上连续完成：

```text
T2 来源声明与项目取得
→ T3 工作流/会话目录及摘要
→ T4 公开管理委托与工作流前端归拢
→ T5 正式配置复制及结果接纳
```

执行方交付应足以支持一份覆盖 T2-T5 的实施执行规划。连续实施可以分步验证、最后汇总回执；不代表必须一次改完共享文件，也不代表未决业务契约已确认。

本次流程固定为：按本文勘察 → 交回勘察回执 → Lead 复验事实、依赖和建议 → 必要事项交用户确认 → 落实施执行规划 → 另按授权实施。**本轮止于派发规划；执行方勘察止于回执。**

## 4. 分项勘察要求

### 4.1 T2：工作流子能力声明与真实取得

1. 追踪当前项目定义占位、Host、薄取得组织、工作流管理/执行服务的真实连接，指出从“可取得对象”变成“按公开声明接入”还缺哪些接线。内部管理/执行对象的数量不成为项目声明内容。
2. 列出最小接入信息的现有来源、维护方及真实消费者；优先引用现有业务契约，区分子能力声明、工作流内部定义目录、节点能力包、包来源/启用选择/加载注册，不复制另一份参数或组件目录。
3. 建立跨域依赖清单：调用方、提供方、用途、公开契约、实际取得/调用位置、调用时点、适用条件。由真实调用补全，不只按“供应商/内容”两个名称搜索，也不把所有内部函数拆成声明。
4. 明确哪些依赖有正式公开契约、哪些只是现有直接调用；提出最小接续建议。依赖是必需、按需还是可选，若无已定依据应列待决；说明缺失/不符在何处报告的候选及影响，不能自行决定一项可选能力缺失就阻断整个项目启动。
5. 核对前端声明与可信本地实现的关联。后端有声明不等于页面已经可用；不引入任意导入、动态发现、逐次调用代理或新的权限系统。

回执应说明声明、实际取得、生命周期和跨域调用如何相互核对；不冻结新 schema、工厂签名或依赖检查时点。

### 4.2 T3：环境接续、目录摘要与真实消费者

1. 复用已接通的环境和工作流领域接口，核对目录读取是否仍需额外接线；不再建一套路径、连接或数据管理框架。
2. 从正式记录追踪工作流/会话身份、归属、名称、归档情况、简单运行状态及管理版本条件，说明实际权威、查询接口、读取一致性、过滤和数量范围。状态由工作流解释，不由项目反查节点输出或会话正文自行计算。
3. 从项目前端目录和后续管理消费者反查所需字段，区分摘要读取与编辑器完整配置读取；指出最小投影位置与公开查询候选，不能把仍需正文的消费者一并改成摘要。
4. 追踪草稿、待提交、待核实和正式资产的本地存放与接纳规则，覆盖目录刷新、重开及已归档/删除项的处理。草稿可以保留，但不得被计作正式创建成功或正式数量。
5. 分页、额外统计、专用 HTTP 查询和更丰富摘要只按实际消费者提建议；已有完整读取与内部查询不因本批一律外开或退役。

回执交付字段—权威—领域入口—消费者对照，以及需保留的详细读取，避免只给一份候选字段列表。

### 4.3 T4：公开管理委托与前端归拢

| 操作/界面 | 必须追清的当前通路 |
| --- | --- |
| 创建工作流、增加会话 | 谁维护初始配置、何时形成草稿、谁发请求、业务初始化及正式接纳、回执与独立读取、目录更新；区分现有能力与尚缺接线 |
| 工作流/会话归档与删除 | 发起入口、版本条件、管理互斥、运行停止等待、共同结算、引用/未知结果保护、领域清理、释放及结果消费 |
| 工作流区域及左侧栏 | 按钮、菜单、弹窗、事件/回调、composable、store、adapter 和状态归属；项目容器必须留下什么，工作流应承接什么，哪些已归域可原样保留 |
| 提交与核实交互 | 配置确认/派生、请求证据、正式回执、unknown 保留、迟到响应、失败提示与管理锁定；追到当前实际接线，不只查看组件名称 |

给出逐项前端移动清单：当前位置、真实业务所有者、建议目标、随迁状态/调用、保留依赖及保护测试。只移动按钮、仍让业务协调散留项目外壳，不算完整建议；也不为归拢重新设计整套页面或前端插件平台。

公开管理能力不因按钮归拢而退役。项目管理应委托原路径，不复制工作流初始化、关闭或清理算法；后端调用者仍可按原公开契约使用。

### 4.4 T5：正式配置复制

以已定范围为前提核查下列内容，不能继续把“是否复制未保存编辑、是否带会话历史”列为开放选择：

| 调查点 | 回执要求 |
| --- | --- |
| 正式来源 | current、固定修订及覆盖如何形成正式可复制文档；读取位置、实际版本条件与来源绑定，不从编辑器内存冒充正式来源 |
| 身份和引用 | 工作流、节点、边、对象键、事件绑定、控制关系及其他真实引用的作用域；哪些可保持、哪些必须重建，以及重建后引用如何一致；无依据不默认全部换键 |
| 外部引用与包 | 共享资源引用、包锁等现有校验和可用性边界；保留引用不等于复制资源，不自行安装包或改发布政策 |
| 受理与事务 | 现有创建/配置更新可复用到哪里；复制是否需要独立公开 operation，来源条件与回执重放的检查顺序、并发冲突、新目标身份及回执绑定的候选 |
| 结果与前端 | 保存成功、明确拒绝、结果未知分别如何经过现有核实与独立读取进入目录；草稿/副本本地行不能充当正式完成证据，未知不自动重放 |
| 边缘状态 | 来源变更、归档/删除、目标冲突、重复提交、已有会话但只复制配置等情形的现有事实、缺口和待定规则；不顺手新增限制或放宽规则 |

准确 operation、参数/回执结构及新行为先给依据、最小建议和影响，交后续复验论证与执行规划收口。旧前端克隆路径若不满足已定正式来源要求，应列明确替换范围，不能因“已经有复制按钮”判断已达标。
