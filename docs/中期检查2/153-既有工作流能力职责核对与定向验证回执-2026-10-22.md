## 2. 能力与责任清单

| 能力 | 真实入口及规则所有者 | 存取、事务及结束职责 |
| --- | --- | --- |
| 成功检查点保存 | [Graph 2000 结算](../../backend/src/phase1_agent/graph_service.py)、[收集与投影](../../backend/src/phase1_agent/checkpoint_collection.py) | RunData 有限 configuration/state/settlement 端口；成功候选绑定、commit、checkpoint、chain_end 同一个 `graph.run.finish` 事务；2100 通知、2200 释放在后 |
| list/read 元数据 | application → [WorkflowOperations](../../backend/src/phase1_agent/workflow_operations.py) / 节点适配 → Graph | 准确工作流/会话/固定修订归属；[CheckpointRepository](../../backend/src/phase1_agent/checkpoint_repository.py)只查该 owner，公开接口不返回完整逻辑态 |
| checkpoint load | fork 内部 → [checkpoint_loading](../../backend/src/phase1_agent/checkpoint_loading.py) | 只接受准确新初始化目标、固定配置相容、准入键集及初始 CAS；调用者持有事务，load 自己不提交，不是覆盖任意旧会话的公开 restore |
| checkpoint fork | application / WorkflowOperations → Graph → [共同 fork 核心](../../backend/src/phase1_agent/workflow_chat_service.py) | 原稳定/版本门禁；复制准确 prefix、重映射 ID/引用、新目标初始化、load、冻结输入复制、seed commit 同事务 |
| reroll | [纯规则和门面](../../backend/src/phase1_agent/workflow_chat_operations.py) → chat service → `_start_run` | 重取同轮冻结输入、恢复原基点；进入原 RunBasis 和 round 结算链，不新造执行路径 |
| select | chat 纯规则 → `chat_select` | 四版本门禁；恢复所选计算态、写选择、更新会话/commit 同一个原 `_change(repo)`；仅新接纳后通知，回执重放不重算 |
| floor fork | `plan_chat_floor_fork` → `chat_fork_floor` → 共同 fork 核心 | 区分复制到的最后成功点与所选计算点；原截断及复制范围保留 |
| run control close | `run.control` → Graph | 有依据走 RunData，无依据仅走有限 RunBoundary；回执重放先返回；关闭结算后释放与通知，不把无依据当普通执行依据 |
| archive/delete | [WorkflowLifecycle](../../backend/src/phase1_agent/workflow_lifecycle.py) | marker/版本 → pause+wait → 原事务内未决保护、关闭和管理 → 成功后释放；定义删除委托配置领域删除端口 |
| service close | Host / Graph 生命周期 | 等待执行器、清进程内映射和租约；不等于 run close，不关闭持久 prepared 链 |

前后调用边界相同，本轮没有架构迁移图。职责表明确后续修改应落何处，不把源码位置本身当成永久不可变设计。

```text
round/reroll -> RunBasis + 已有执行
            -> 2000: 候选 + commit + checkpoint + chain_end [原事务]
            -> 2100: 通知及独立诊断 -> 2200: 释放/按原规则保留

select/fork -> 各自纯规则 + 原协调事务 -> 原提交后处理
archive/delete -> 停止并等待 -> 原管理事务 -> 成功后释放
```
