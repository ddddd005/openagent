## 2. 审核发现与实际修正

### 2.1 F1 缺准备帧不得降级为空绑定

`graph_tool_host.py` 的 `_bound_tool_specs` 原先把“整份 frame 缺失”和“frame 存在但该 Agent 没有业务绑定”合并为 `[]`。修复后先要求本链 frame 存在，再判断合法空绑定：

```text
frame 缺失 → tool_binding_not_prepared（继续拒绝，409）
frame 存在 + Agent 查询自身 + 无业务绑定 → []（保留原无工具 Agent 行为）
frame 存在 + 有绑定 → 原 descriptor / RunBasis / owner 核验后返回声明
```

没有重建 frame、没有改用当前注册表、没有放宽 descriptor 或 owner 权限。

### 2.2 F2 工具提示参数必须符合真实工具规则

`tool_prompt_contract.validate_tool_prompt` 原先只要求 `parameters` 是合法 JSON schema，`{"type":"string"}` 可以通过。修复后复用真实工具注册已使用的 `_model_tool_schema(name, parameters)`：

- 必须是严格对象 schema：准确包含 `type=object`、`properties`、`required`、`additionalProperties=false`；
- 属性与 required 完整对应，参数项遵守当前标量与说明规则；
- 合法无参数 read schema 和单参数写 schema 继续通过；
- `SchemaError`、`TypeError`、`ValueError` 在参数校验范围内映射为既有 `tool_prompt_invalid`，保留异常原因；
- 不改变 `tool_prompt_schema()`、`TOOL_PROMPT@1` 声明或包导出。

修复前后公开声明 SHA-256 均为 `31134a52a8ec5d49b658ceccdde88acf2fdf317458918f11d51700120bda1b4c`，`test_type_contract_store` 通过。重开隔离库测试只验证公共类型校验入口仍可用，没有保存或读取旧 `TOOL_PROMPT` 产物，不能作为旧产物兼容或历史数据验收。
