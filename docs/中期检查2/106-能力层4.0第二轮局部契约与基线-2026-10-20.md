## 2. 为何新增包而不是改 `workflow.tool-bindings@1.0.0`

首轮包 `workflow.tool-bindings@1.0.0` 已被部分项目选择并写入 `package_lock`。项目选择不会被默认值悄悄升级（`test_graph_package_selection` 明确覆盖），而同一包版本不能在加载时悄悄改变已固定的声明。若把该包改成 `2.0.0`，已保存 `1.0.0` 选择的项目会因缺少精确版本而整体不可用；若原地增加导出，则违反“不得在 `workflow.tool-bindings@1.0.0` 下悄悄改变已固定声明”。

因此本轮采用并列新包：

| 项目 | 值 |
| --- | --- |
| 新包 | `workflow.tool-prompts` / `1.0.0` |
| 依赖 | `workflow.content@1.0.0`、`workflow.tools@1.0.0`、`workflow.context@1.0.0`、`workflow.agents@1.0.0` |
| 数据类导出 | `TOOL_PROMPT`，scope `content`，schema version `1` |
| 节点导出 | `tool-bindings.variable-tools@2`、`context.assembly@6` |
| 默认选择 | 加入 `DEFAULT_PACKAGES`；只影响新项目或显式选择该包的项目 |
| 旧包 | `workflow.tool-bindings@1.0.0` 保持原样，继续导出 `tool-bindings.variable-tools@1`、`tool-bindings.tool-prompt@1` |

这不是把能力拆成两套执行实现：变量工具参数适配、准备帧、真实 executor、ACL 和逐次接纳仍只有一套代码；新包只是新增合并节点和上下文输入的新版本。

## 3. 合并节点契约

### 3.1 身份与职责

| 项目 | 值 |
| --- | --- |
| 组件 | `tool-bindings.variable-tools` / component version `2` |
| 显示名 / 分类 | “变量工具加载” / “变量” |
| 执行类 | `working`，原生 executor（不是宿主 `executor_ref`） |
| 输入 | 无 |
| 输出 | 唯一端口 `tool_prompt`，类型 `TOOL_PROMPT@1` |
| 配置节点引用 | 唯一字段 `agent_node_id` → `agents.execute@10`，`multiple=false` |
| 对象 / 服务 / 资源 / 会话项声明 | 无 |
| 能力 | 无（工具写通过执行侧有限桥，不声明 `objects:*`） |
| 可信声明 | `tool_binding` 适配器，带唯一提示输出身份和 Agent 配置字段 |

启动准备阶段从正式配置提取 Agent、变量和操作，只读校验包来源、目标 executor、类型、ACL、目标边界并生成准备帧；不运行该节点 executor，不调用变量 executor、模型或写入变量。

图调用阶段该节点作为普通 working 节点参与计划，executor 只从本次准备帧取本节点自身的绑定，生成一个 `TOOL_PROMPT@1` 输出；不重新装载能力、不查询服务当前表、不产生变量写入。

### 3.2 配置

```json
{
  "agent_node_id": "",
  "variables": [
    {"alias": "score", "object_key": "variable/score",
     "operations": ["read", "set", "add", "subtract"]}
  ],
  "list_presentation": {"role": "system", "placement": "before", "depth": null, "order": 0, "enabled": true},
  "parameters_presentation": {"role": "system", "placement": "after", "depth": null, "order": 0, "enabled": true}
}
```

- `variables` 语义与首轮一致：0 < 数量 ≤ 64，别名唯一、非空、不是 `final_answer`，操作是 `read/set/add/subtract` 的非空唯一子集。
- 两个 presentation 走既有 `presentation_schema` 与 `middle` depth 规则；只影响布局，不影响可调用集合或权限。
- 配置校验同时核对 Agent 引用、变量声明和两个 presentation；保存后独立重读仍必须通过同一校验。

### 3.3 注册约束

`NodeRegistry.register` 不再把 `tool_binding` 一律限定为“non_working 且无 executor”，而是分两种可信形式：

1. **非执行声明**：`execution_class=non_working`、无 executor、无输入/输出端口。首轮 `tool-bindings.variable-tools@1` 继续使用。
2. **执行加载节点**：`execution_class=working`、原生 executor、无 `executor_ref`、恰好一个输出端口且与适配器声明的 `prompt_output` 完全一致；无输入、无 `port_modes`、无服务要求、无对象访问、无外部输入/资源输入声明、无 settlement、无能力声明。

两种形式都必须声明精确的 Agent 配置引用（由适配器的 `agent_config_field` 指定，`multiple=false`）。删除全部校验、允许任意节点自称工具加载器、增加隐藏调度节点均不允许。

## 4. `TOOL_PROMPT@1` 内容契约

```json
{
  "schema_version": 1,
  "kind": "workflow.tool-prompt",
  "agent_node_id": "<uuid4>",
  "source": {
    "anchor_node_id": "<uuid4>",
    "component_id": "tool-bindings.variable-tools",
    "component_version": "2"
  },
  "list_presentation": {"role": "system", "placement": "before", "depth": null, "order": 0, "enabled": true},
  "parameters_presentation": {"role": "system", "placement": "after", "depth": null, "order": 0, "enabled": true},
  "entries": [
    {
      "binding_id": "<uuid4>",
      "name": "score_read",
      "operation": "read",
      "description": "Read the variable 'score' and return its current value.",
      "parameters": {"type": "object", "properties": {}, "required": [], "additionalProperties": false}
    }
  ]
}
```

- `entries` 数量 1–120，与一个 Agent 的模型工具预算一致；每个条目必须唯一 `(binding_id, name)` 且 `name` 全局唯一。
- `parameters` 必须是严格对象 JSON schema，并通过 `Draft202012Validator.check_schema`；不能退化为不可校验的 JSON 字符串。
- 列表项与参数项按 `name` + `binding_id` 成对，不依赖两个数组的位置对应。
- 输出只含可展示声明、来源和 presentation；不含 callable、存储句柄、对象当前值、对象键、ACL 或额外权限。
- 新类型不替换 `PROMPT_MATERIALS@1`，也不改变 `prompts.tool@2` 静态目录。

## 5. 上下文输入契约

| 项目 | 值 |
| --- | --- |
| 节点 | `context.assembly` / component version `6` |
| 新输入 | `tool_prompt`，类型 `TOOL_PROMPT@1`，`required=false`，单值 |
| 既有输入 | `view`（`CONTEXT_VIEW@5`）、`materials`（`PROMPT_MATERIALS@1`，多值，可选）、`current_input`（`TEXT@2`） |
| 输出 | `PROMPT@6`，与 `@5` 相同 |
| 服务要求 | 与 `@5` 相同（`context:validate`） |
| `@5` | 原样保留，端口和语义不变 |

装配步骤：

1. 校验 `CONTEXT_VIEW@5` 与当前输入，和 `@5` 相同。
2. 若 `tool_prompt` 存在，校验成对结构和 presentation；缺项、重复、名称冲突、非法参数 schema 时显式失败，不静默截断或只保留一侧。
3. 将每个条目的列表项按 `list_presentation` 投影为一个 `PROMPT_MATERIALS@1` 条目，参数项按 `parameters_presentation` 投影为另一个条目；`purpose` 分别为 `tool-description` / `tool-schema`，`lifecycle=per_request`，`compaction=never`。
4. 列表项文本为工具说明，参数项文本为参数 schema 的规范 JSON 文本；结构化参数仍保留在 `TOOL_PROMPT` 及条目字段中，文本渲染只用于模型展示。
5. 条目身份由装配节点 id、`binding_id`、工具名和部分派生，保持稳定；来源证据保留 `agent_node_id`、`tool_name`、`binding_id` 和 `part`。
6. 合并普通材料后调用既有 `assemble_native_context_prompt`；`source_output_refs` 同时保留 `materials` 与 `tool_prompt` 的真实 artifact 引用。
7. 消费侧 `agent_computation_input` 校验接受后的 `PROMPT@6`：工具材料必须来自当前消费的 Agent；不一致时以 `tool_prompt_agent_mismatch` 拒绝，不放宽 artifact 校验。

布局沿用既有 prompt lifecycle、compaction 与 `prompt_depth` 逻辑：默认列表在 `before`、参数在 `after`；改变 presentation 只改变消息位置/顺序，不改变 Agent 可调用工具或对象权限。

## 6. 来源与总量准入

### 6.1 来源

- 每个工具加载声明节点（`tool-bindings.*`，含旧锚点）和每个真实工具目标都从同次 `RunBasis.definitions` 取得非空 `source`。
- `source` 中每个 `{package_id, package_version}` 必须出现在本次冻结的 `registry.package_lock` 中；缺来源或与本次依据不一致时拒绝准备，错误码 `tool_binding_source_missing`。
- 不回退当前 registry、不按名称或 latest 猜测包、不人工填充来源字段。
- 本轮只收紧工具准备路径；普通自定义 registry 的合法无来源查询保持原行为，不因本项删除。

### 6.2 总量

- 最终模型工具集合按 `_agent_tools` 的真实合并结果计算：静态工具 + 已准备业务工具 + 合并后唯一的 `final_answer`。
- 总数不得超过 120；超量在首次模型请求前显式失败，模拟 transport 调用为 0。
- 保留名称冲突检查；不静默去重、不截断、不把绑定上限写死为 118。准备路径原有的绑定上限继续保留，但不作为最终总账。

## 7. 旧图边界与迁移

- `workflow.tool-bindings@1.0.0` 的旧锚点和旧提示词节点不删除、不改版本、不改声明；已选择该包的项目继续按原样加载和运行旧图。
- 新包不导出旧节点，也不把旧图自动转换、重写包选择或删除旧节点。
- 旧项目若要使用合并节点，必须显式把 `workflow.tool-prompts@1.0.0` 加入项目包选择；未加入时新节点显示为不可用，而不是静默替换。
- 新项目默认同时包含旧包和新包；旧图仍可用，新图使用合并节点。
- 首轮 104 号回执、旧双节点测试证据保留为历史，不冒充本轮新契约的证据。

## 8. 诊断

| 场景 | 错误码 |
| --- | --- |
| 加载声明或目标没有来源 / 来源与冻结包不符 | `tool_binding_source_missing` |
| 提示输出配对、字段、参数 schema 非法 | `tool_prompt_invalid`（presentation 的 depth/placement 冲突沿用 `content_invalid_placement`） |
| 工具材料属于另一个 Agent | `tool_prompt_agent_mismatch` |
| 合并后模型工具总数超过 120 | `agent_tool_budget_exceeded` |
| 目标实现缺失、目标类型不支持 | 沿用 `tool_binding_target_unavailable` / `tool_binding_target_unsupported` |
| 缺准备帧、绑定身份不符 | 沿用 `tool_binding_not_prepared` / `tool_binding_not_found` / `tool_binding_access_denied` |
| 参数不符 schema | 沿用 `tool_arguments_invalid` |

不新建统一错误分类框架；未处理错误仍中止当前业务调用链并显式报错，不吞错、不删工具、不重放未知写入。
