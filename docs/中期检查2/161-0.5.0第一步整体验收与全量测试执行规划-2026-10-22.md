## 6. 隔离、工具与命令结构

### 6.1 路径与 I/O

证据根建议为仓库根 `.local/accept050-step1-<实际日期时间>/`，创建前确认未存在，记录实际绝对路径。`baseline/`、`inventory/`、`runs/`、`probes/`、`review/` 分开；每次 pytest basetemp 在根 `.local/` 下另取未存在的独立兄弟目录，不是证据根或其父目录。

最低防护要求：

- SQLite/凭据仅本次测试临时根或内存；真实路径在连接前拒绝。保留原保护器，Windows DPAPI 仅处理本批合成值，不用假保护器取代既有验证。
- 网络只允许本批测试自行绑定的临时回环 listener 和明确审阅的关联子进程客户端；禁止既有端口及外部/DNS 上游。默认不继承可触发真实调用的环境选择；记录存在性/隔离措施，不记秘密值。
- 复核 Node/Python/PowerShell 子进程的实际命令、cwd、环境与文件路径。Python monkeypatch guard 不是操作系统沙箱，不宣称自动覆盖子进程；子进程需要独立核对。未有安全把握则停相应身份。
- guard 在测试模块导入/收集前生效；先以合成正/负例证明允许临时库/自建 HTTP、阻止越界。越界负例用哨兵或受控 spy，不打开真实库、真实 vault 或连接既有服务来“验证拦截”。
- guard 只约束 I/O，不改变业务 executor、事务、ACL、凭据保护器、返回值和断言；发生非预期阻断先归因，不能卸掉防护或改成 skip。

### 6.2 命令模板

使用现有仓库 `.venv`、Node 和 `frontend/node_modules`，不得 npx 下载或安装。先确认实际导入 `backend/src/phase1_agent`，不是历史 checkout、旧 wheel 或错误 editable 路径。

以下是执行方 runner 应落实的参数结构，**不是当前即可直接粘贴的成品脚本**：`$repo/$python/$node/$evidenceRoot` 等均须 F0 固定；`acceptance_guard` 须先按 6.1 创建、自测，并由本批 `PYTHONPATH` 可取得；`$excludeArgs` 是 5.2 逐条生成的 `--deselect <完整 nodeid>` 数组。runner 必须分别保存原始 stdout/stderr、开始结束、耗时和真实退出码，不能被管道/后续命令覆盖。

```powershell
# cwd: <repo>\backend; common arguments shared by collect and execution.
$pytestBase = @('tests', '-q', '-ra', '-p', 'no:cacheprovider', '-p', 'acceptance_guard')

# Full inventory, then the exact selected inventory. Each uses a fresh basetemp.
& $python -B -m pytest @pytestBase --collect-only --basetemp $inventoryTemp
& $python -B -m pytest @pytestBase @excludeArgs --collect-only --basetemp $selectedTemp

# After inventory and safety checks pass; no -x, --maxfail or name filter.
& $python -B -m pytest @pytestBase @excludeArgs --basetemp $backendTemp --junitxml $backendJunit

# cwd: <repo>\frontend; output destinations belong to this run only.
& $node node_modules/vitest/vitest.mjs list --json
& $node node_modules/vitest/vitest.mjs run --reporter=default --reporter=junit "--outputFile=$frontendJunit"
& $node node_modules/vue-tsc/bin/vue-tsc.js --noEmit
```

固定 `PYTHONDONTWRITEBYTECODE=1`、`PYTHONUTF8=1`，必要缓存导向本批目录；环境不带历史源码目录，不能隐式取用旧测试助手。工具版本以 F0 实测记录，本文不预设历史版本。若本地 CLI 不支持模板参数，读现存工具帮助后只修 runner 调用，保留失败原件；不升级工具或修改仓库配置。

### 6.3 等待与失败

后端整套、前端整套与类型检查可在资源和输出互不干扰时分别运行，但同一后端集合默认单进程顺序执行，不额外引入 xdist/shard。验收探针在全量后执行，避免共享端口/进程干扰。

**耐心等测试自然结束，不设置代理总时限、不因慢或第一项失败杀进程。** 测试自带的明确超时保留；若长时间无输出，先看进程状态和增量日志。只有用户要求、安全越界、确认死锁/资源耗尽等实质原因才停止，保留 PID/时间/最后进度并记为未完成，不能把超时包装为通过。

普通失败不 fail-fast，继续完成其余安全集合；后端失败不妨碍已确认独立的前端/类型检查。安全越界、基线漂移等优先停止受影响部分。
