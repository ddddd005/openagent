## 1. 验收目标、范围与已定事项

验收要回答：项目基础框架是否真实承载当前工作流子能力；环境、目录、管理、前端及配置复制是否沿公开边界接通；同一最终树上的运行是否真实消费 T6 五步声明，并保留原事务、控制、通知与释放。

核心对象为 T2-T5 + T6；同时复核 T0-T1 在最终组合树中的承载关系。T0 作为身份/交接判据，T1 作为基础保护，不重做 P1 调查或重建历史占位。本篇承接 T7 的统一验收部分；全量测试、交付环境验证、最终阶段文书和下一 Git 基线分别接续。

| 已定事项 | 验收采用的口径 |
| --- | --- |
| 项目与工作流 | 项目接入整套工作流子能力，提供环境与容器；工作流维护内部构造、领域数据和业务规则 |
| 管理与执行 | 按需取得，普通管理不额外取得执行权威；不要求常驻双实例，也不要求全能单实例 |
| 数据环境 | 沿用现有主库；工作流保留领域存取、事务、CAS、回执。既有凭据私库边界不变 |
| 生命周期 | 谁持有生命周期谁关闭；HTTP 借用外部对象，自建兼容对象由自建方正常关闭 |
| 接入声明 | 来源维护公开声明和可信绑定，跨域依赖必须说明；供应商/内容当前仅引用既有契约，不假称已项目化 |
| 前端 | 项目提供外壳和容器，工作流提供本域业务区域、侧栏交互及协调；共同祖先允许薄装配调用 |
| 配置复制 | 正式保存的 current + 准确来源版本，新身份、零会话、零运行历史；不含未保存编辑；允许归档来源复制，选中会话不改变范围 |
| T6 | `0100 prepare → 1000 execute_graph → 2000 settle → 2100 notify → 2200 release`；原同步/后台两段真实消费，同号报错，连续事务不强拆 |
| 首版边界 | 不建设插件插入协议、用户改序、多引擎、调度器、前端全面重设计或自动重试/补偿 |

137 的“定义占位”是当时状态，当前应核查 T2 已接入的定义管理；140 的 G-A 未决已由用户允许归档源复制取代。141 的本地提交记载不构成用户对本次组合树的联合验收。遇历史“完成/验收”措辞，按其时点、对象和证据类别解释。
