## 1. 事务边界订正

95 号第 2.4 节和第 6 节原先把节点接纳与最终结算写成同一个共同事务，表述有歧义。按 93 号既定规则订正为两个事务：

| 边界 | 实际事务 | 保存内容 | 故障影响 |
| --- | --- | --- | --- |
| 节点接纳 | `_node_event` 的一次 `_change` / `atomic` | 该节点的 `workflow_output`、约定写入、变量、私有态、对象写集、`node_run`/`chain` 进度和会话修订 | 只回滚该节点本次接纳；此前已接纳节点保留 |
| 最终结算 | `finish` 的一次 `_change` / `atomic` | 运行成功终态、`_commit`（snapshot/commit/ref/变量绑定）、成功检查点、结束 manifest | 只回滚本次最终结算；已接纳节点输出和数据保留 |

`after_checkpoint_write` 故障只发生并回滚最终结算事务。现有 `test_checkpoint_write_fault_rolls_back_and_replays_exact_success_receipts` 保持通过；本批新增断言确认故障后已接纳节点的 `workflow_output` 和 `node_run` 仍为成功状态，而 Head、commit 和检查点没有半套结果。

### 1.1 关口 2 的 P2 修正

- **私有态等值**：`_save_private` 新分支恢复规范 JSON 字节比较，替换 Python 字典相等；整数 `1` 与布尔 `true` 不再被判为相同。新增真实 `start` 回归，节点把私有态从 `1` 写成 `true` 后持久值为 `true`。
- **调度与 begin 读取**：`_start_run` 决定是否调度、`_execute` 构造 begin 请求时的 chain 读取，改为 `execution_read(...).records.chain`。新增栈级回归，直接 `GraphRecordStore.get("chain_run")` 从 `_start_run`/`_execute` 发起时失败。
- **测试夹具**：`test_candidate_mutation_retirement` 的 `_selected_chain` 调用改用 `execution_read(...).records`，不恢复旧 repo 生产接口。
- **独立重读补齐**：新增检查覆盖 commit、`chain_start`/`chain_end` manifest、非空私有态和非空对象；对象链另由 `test_graph_session_objects` 的真实运行验证。

## 2. 实际改动

### 2.1 执行数据入口

新增 [execution_data.py](../../backend/src/phase1_agent/execution_data.py)：

- `RunData` 只含 `records`、`state`、`settlement`、`type_evidence`、`configuration`、`chat` 六个有限会话，不提供 `store`、`connection`、`repo`、`atomic`、通用 `get/put/rows`。
- `ExecutionRecords` 提供具名的 session/chain/node_run/output/Head/commit/snapshot/私有态读写、会话元数据、归档状态、资源预读和历史映射。
- `ExecutionState` 提供变量、对象、对象写集、检查点对象值；对象 `_check_type` 与准备路径共用 `ExecutionTypeEvidence`。
- `ExecutionSettlement` 保存 manifest、原 commit、成功检查点和检查点读取；不自行开事务。
- `ExecutionChatData` 提供聊天绑定、冻结输入/调用、检查点读取和成功候选值写入；本批选中链只走空调用读取。
- `ConfigurationReadSession` 只暴露固定文档、当前覆盖、定义修订和归档读取，不暴露保存方法。

[configuration_data.py](../../backend/src/phase1_agent/configuration_data.py) 的 `WorkflowDataManagement` 增加：

- `execution_transaction(records, *, basis)`：要求调用方已有事务，绑定 `RunData`，不新开、不提交；
- `execution_read(records, *, registry)`：绑定只读端口，写方法失败关闭；
- `read_execution(*, registry)`：新 store + 读事务，供事务后独立重读。

### 2.2 代表主链接线

普通 round 的以下调用已改用端口：

| 位置 | 入口 | 关键点 |
| --- | --- | --- |
| `start` / `_prepare_run` | `RunData` | 配置文档、类型证据、资源预读、node_run/chain/session、`chain_start` manifest |
| `_execute` begin | `RunData.records` | 只写 chain 运行状态 |
| `_execute` 装配 | `RunData` | 固定文档、node_run config、变量、私有态、对象、全量输出、聊天上下文 |
| 事务后重读/保留结果校验 | `execution_read` / `RunData` | 不读保存响应或内存缓存 |
| `_node_event` | `RunData` | 节点接纳事务 |
| `_settle_node_result` | `RunData.records` | 输出、node_run |
| `_save_effects` | `RunData.state` | 变量、私有态、对象写集 |
| `finish` 成功分支 | `RunData` | 终态、聊天成功绑定、commit、成功检查点、结束 manifest |
| `_commit` | `RunData.settlement` | snapshot/commit/ref/变量绑定 |
| `_append_success_checkpoint` | `checkpoint_collection` + `RunData.settlement` | 收集规则仍在检查点模块，端口只持久化 |
| `_save_manifest` | `RunData.settlement` | 不接收 registry 作为 manifest 写参；P2 缺绑定路径仍走原 repo 回退 |
| `_bind_chat_success` | `RunData.chat` | 本批空调用读取 |
| `_view` | `RunData.records/state/configuration` | 事务内响应投影 |

检查点收集新增 `collect_checkpoint_configuration_document`、`collect_agent_contexts_data`、`collect_checkpoint_state_data`，接收精确固定文档、`ExecutionState` 和本次 types/registry；旧的 repo 参数函数保留给历史读取、管理调用和未迁移检查点测试，不用于本批选中执行链。

### 2.3 类型证据与 bundle

- `_prepare_run` 的完整类型核验走 `RunData.type_evidence.check_registry`，底层仍是 `TypeContractStore.check_registry` 的嵌套 savepoint。
- 对象 `_check_type` 通过 `SessionObjectStore(..., type_evidence=...)` 使用同一适配；只读执行读会话在证据缺失时失败关闭，不登记新证据。
- 端口写入仍调用原 `GraphRecordStore.put`，`_change` 仍以当前 `definition_registry` 构造 repo 并执行 `_validate_changes`；本批没有取消或缩小 bundle 历史校验。
- 管理、历史、公开输出、控制关闭等未迁移路径继续使用原来源。

1. `RunData` 仅六个会话，禁止通用 repo/连接/`get/put/rows`；`execution_transaction` 要求原事务；
