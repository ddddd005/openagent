## 2. 阶段结论

### 2.1 前置一：统一格式、注册规则和存取边界

已完成首批局部契约：

- 内部只读查询统一使用 `kind`、`registration_ref`、`declaration`、`source`、`availability`。
- 节点和数据类型保留各自正文、校验和实现绑定。
- 包来源维护真实定义；查询只投影已加载来源。
- `executor`、validator、factory 等可调用实现不进入定义正文；受控的可序列化 `executor_ref` 可作为现有节点声明的一部分保留。
- 外部 HTTP 和前端协议不新增字段，继续由适配器投影既有形状。

### 2.2 前置二：极简真实包加载

已完成工作流侧真实适配：

- `WorkflowDefinitionPackages` 接受准确包版本需求。
- `TrustedLocalPackageSource` 委托现有 `CapabilityPackageLoader`。
- 依赖解析、注册回调、manifest exports 校验和失败隔离均经过真实样本。
- 测试包不进入生产默认集合，不引入目录扫描、安装、下载、热更新或项目包管理 UI。

后续项目级包来源可以替换本地来源适配，而不改变定义查询、数据端口和消费者接口。

### 2.3 2.1：框架接通

已完成：

- `workflow_definitions.py` 提供节点和数据类型的统一只读查询。
- `definition_data.py` 提供已有类型证据的只读读取。
- `definition_packages.py` 提供准确包需求和本地来源适配。
- 工作流固定修订可解析节点实例、端口数据类型引用和 `package_lock`。

### 2.4 2.2：内部职责与存取

已按首批范围完成：

- 定义数据模块只读取 `registered_type_contracts`，不暴露 `check/register/check_registry`。
- 配置数据模块继续负责固定工作流修订和当前配置。
- 数据管理入口分别分发定义和配置请求，仓储之间不互调。
- 保存后关闭读取上下文，再通过独立连接重读证据和固定修订。
- 未新增通用定义表、存储版本、迁移或通用摘要规则。

尚未完成的是全项目注册面整理：`HostRegistration` 仍按类别提供注册方法，`registration_catalog` 七类汇总及会话、全局资源等旁路仍保留原路径。

### 2.5 2.3：消费者接入

已完成首批三个真实消费者：

1. 配置描述通过定义查询取得准确节点声明。
2. 编辑器和消费者输入声明通过受限 `NodeDefinitionAccess` 使用配置校验及外部输入声明 hook。
3. `catalog.node-types` 通过定义查询生成，再投影为既有协议 1/2。

前端继续消费原 HTTP 协议，没有新增独立定义协议或前端定义副本。

### 2.6 2.4：跨层使用验证

已验证以下代表链：

```text
准确包需求
→ 依赖解析与真实注册
→ 定义查询
→ 类型证据读取
→ 固定修订引用解析
→ 配置/输入声明/节点目录消费
→ 无模型节点执行
```

缺版本、缺依赖、注册中断、视图修改隔离和固定修订不回读 current 均有对应测试。该结果证明首批代表路径已贯通，不证明 Runtime、检查点、重roll、分叉或 Agent 工具共同调用已经迁移。

## 4. 审核后仍需保留的边界

三路只读审核未发现已验证的 High 级问题，但确认以下事项不能写成已收口：

| 事项 | 当前状态 | 后续处理 |
| --- | --- | --- |
| `executor_ref` 表述 | 节点声明会保留可序列化执行引用；可调用 executor 本身未暴露 | 统一“实现对象不序列化、受控引用可保留”的契约文字 |
| registry 旁路 | `WorkflowDefinitionCatalog.registry` 仍可取得完整可信 registry | 后续收窄或内部化，避免绕过定义查询 |
| 包来源接口 | 构造时校验 `load`，`resolve` 依赖未提前校验 | 补来源接口契约或收窄公开方法 |
| 固定修订与 package lock | 当前按运行时 registry 判断 `registered`，未校验锁定包完全一致 | 若要证明冻结包来源，另立一致性规则 |
| loader 与数据库时序 | loader 内部历史契约先更新，数据库随后提交；持久失败不会回滚该历史字典 | 后续单列原子发布/失败后再次加载的架构项 |
| registry 与 definitions 双输入 | 编辑器输入声明同时接收 registry 和 definitions，调用方传入不同对象时可能来源分裂 | 后续增加身份绑定或收窄调用参数 |
| 严格只读重读 | 当前是普通 SQLite 关闭重开，不是 `mode=ro/query_only` | 需要严格只读回执时另立存储边界 |

这些事项不阻塞首批代表路径验收，但会阻塞“全项目统一定义来源”或“固定包来源证明”等更强目标。
