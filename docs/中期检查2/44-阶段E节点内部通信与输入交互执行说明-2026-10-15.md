## 1. 200ms的准确范围

用户再次明确：200ms只是当时拟定的一个输入更新时间，**只属于当前整体前端节点`frontend.node@1`**，不扩到其他节点或配置表单，也不是工作流核心保存机制。

本批只在该节点自己的客户端中使用这个时间合并输入更新。E1统一配置修改模块、`tools.editable-input@1`、runtime、检查点、定义及数据层不登记或消费200ms，不建立通用autosave服务、保存队列平台或定时器声明。普通工作台配置字段保持原交互。

## 2. 本批具体职责

| 范围 | 本次接入 | 不扩大到 |
| --- | --- | --- |
| 节点内部后端通信 | 固定准确工作流/修订/节点/可空会话，处理初始化、输入、启动、暂停及原请求回执 | 任意管理命令、对象键、上下文覆盖或目标选择 |
| 节点自己的客户端 | 临时输入、私有200ms合并、发送前等待保存、结果归属、只读展示副本 | 旧consumer草稿、浏览器持久业务状态或通用工作流SDK |
| 独立功能调用 | 复用E2的绑定门面及E1保存、runtime、数据读写 | 再实现配置保存、运行调度或聊天追加 |
| 原请求保护 | 复用既有`pending_commands`及证据结案，精确三操作证据白名单 | 通用dispatch目录、新pending表或未知请求重试 |
| 入口和承载 | 注入准确节点通信port以独立测试内部逻辑 | E4网络端口、HTTP路由、开窗和推送传输 |

初始化必须由对应后端节点读取当前正式输入文字及编辑序号。E2固定定义中的正文可能仍为旧值，不能拿它代替`_configuration_document`提供的当前输入。会话运行版本和状态也由节点读取投影，不让浏览器查询通用consumer或管理数据。

## 3. 窄通信合同

请求只包含`owner`、`operation`和`parameters`。owner固定为：

```json
{
  "workflow_definition_id": "准确工作流UUID",
  "definition_revision": 1,
  "node_binding_id": "准确节点UUID",
  "session_id": null
}
```

由后端已核对的节点绑定检查每次请求；请求不能换到别的节点或任意输入项。

- `state`：只读初始化/刷新。返回自己的输入原文、编辑序号及固定/可调策略，可空会话的revision/实际状态，以及后端读取的展示快照；无会话不创建会话，也不读取会话数据。
- `patch_input`：仅原文字、原编辑序号、原key及可选明确布尔确认，调用E2输入修改。
- `start`：仅原会话revision（无会话为null）及原key，调用E2真实create/start分阶段流程。
- `pause`：仅准确会话revision及原key，调用E2正式运行中控制。
- `receipt`：按完整原请求仅读实际回执，没有原生回执就是尚未核实，不重新调用业务操作。
- `accept_receipt`：先校验实际原生回执，再明确结案原证据。只更新证据元数据，不修改配置、数据项或runtime；不能借它放行仍未知的请求。

返回携带原owner、实际操作和原key。配置结果只投影当前节点需要的值与准确`next_owner`，不返回整张图；创建、启动及控制的实际阶段结果分别投影，保留准确工作流、修订、会话、revision、状态及chain身份。

## 4. 原请求与未知保护

证据私有操作名为`frontend-node.patch-input/start/pause`，不加入`GraphApplication.COMMANDS`或generic浏览器派发。证据保存完整原owner和原方法参数；owner编码由后端按准确绑定及input/start/pause操作槽派生，浏览器不能选择证据owner。

正式保存证据后才调用E2。成功或正式配置提问/派生已有原回执时可结案；已知明确拒绝仍保留原请求并按现有archived处理，不新增失败事实表。未知结果保留pending，显式读取仍未知时不换key或补发。未知输入保存不得阻止运行中pause，其操作槽分别核验。

E2没有新增“明确失败的持久回执”。create已成功、start明确被拒后，首次可如实返回失败；重开或重读若只有create回执而没有start原生回执，仍返回unknown及实际已创建的会话，不把临时失败诊断当持久化事实。

响应丢失后的核实拆成两件事：先`receipt`只读核对，再`accept_receipt`明确结案证据；结案响应再丢失也只再次核对/结案，不再次派发业务请求。

## 5. 本节点输入交互

客户端只临时维护当前页面输入、编辑generation、正式保存依据及在途原请求。

1. 本节点输入变化按私有200ms时间合并。保存过程中继续编辑只更新最新页面文字，迟到回执不覆盖新文字。
2. 发送先等待最后一份文字正式`saved/unchanged`，再调用对应节点启动。发送中的新编辑不插入已经捕获的保存→启动链。
3. 错误、版本冲突、`confirmation_required`或unknown阻止发送；不自动重基、换key重试或先发后补保存。
4. 固定修改确认使用捕获的原正文及编辑依据，明确同意时使用新key。确认提问不等于保存；派生不自动运行。
5. 派生或无会话固定保存推进修订时，返回准确新绑定；首次创建会话同样返回实际新绑定。交由后续宿主明确接续对应通信port，不改变工作台全局选择。
6. 展示只接收对应后端提供的快照深拷贝，不上传上下文修改。关闭只取消客户端计时和连接，不停止后端、不新增草稿存储。

同一客户端只保证自己的本地保存及发送顺序。可调输入仍属于工作流共享当前配置；另一页面或工作台在保存与启动准备之间修改输入时，runtime按**准备时的正式当前值**冻结。本批不承诺跨页面排他“必定运行刚才这份文字”，不增加启动配置CAS或跨派发锁；需要更强的输入依据合同应另行审阅。
