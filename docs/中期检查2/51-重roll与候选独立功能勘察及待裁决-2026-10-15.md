# 重roll与候选独立功能勘察及语义订正

日期：2026-10-15，Asia/Shanghai。

性质：基于现行文档及源码的调查，已按用户最新说明订正业务语义。重roll是同一回合重来，一条用户输入可以对应多次生成；该楼的全部回复都是候选，均须同步数据层并由检查点保存，用户可以任选一条继续向下聊。基础功能属于工作流独立小模块，由外部消费者调用，不能绑定前端节点。

本次仅更新文档，未安装重roll、候选集或新的状态切换机制。文件名中的“待裁决”保留为初次调查名称；第4节原来的三项业务问题已被本次明确说明取代，不再要求用户重复裁定。尚需说明的是怎样在现行分层下完整实现这些已定行为。

**最新接续：** 用户随后同意新逻辑聊天类型方向，并明确重roll使用本楼开始前的检查点数据；已有下文的楼层固定，不能在原分支换选；从该楼分叉要携带全部候选，并允许目标重新选择。合订见[54号执行规划](54-重roll楼层候选与检查点接续执行规划-2026-10-15.md)。本页原候选语义仍有效；首轮基线及候选接续数据的有限写入职责按54号明确报告，不把用户已定规则继续当待问问题。

## 1. 已经明确的边界

| 决定 | 依据及影响 |
| --- | --- |
| 重roll属于同一回合 | 一条用户输入对应多次生成，不把每次重roll当作新的用户回合，也不在既有回答后继续追加一次普通对话来代替重来 |
| 同楼全部回复都是候选 | 例如生成5条，5条均为正式候选；不能只保留当前显示或当前选中的一条 |
| 全部候选同步数据层并随检查点保存 | 不是浏览器临时数组或旧运行历史查询的别名；检查点须能保存完整候选集合及继续消费所需状态 |
| 用户任选一条向下聊 | 选择要影响下一轮实际消费的计算上下文，不能只切换展示文字；其他候选仍须保留 |
| 业务功能属于工作流，节点负责调用 | 用户本轮明确要求功能与节点解耦；延续[40号简述](40-阶段E输入修改能力与前端后端节点职责简述-2026-10-15.md)的工作流能力、节点对外交互、节点内部通信三层职责 |
| 前端只向准确对应的后端节点提交意图 | 节点核对归属及允许目标后调用独立能力；不向前端开放通用工作流操作权，不新增能力连线 |
| 失败重试不等于重roll | [35号规划](35-变量统一登记与检查点准入及Lorebook读取接续执行规划-2026-10-15.md)及40号已明确区分；保留真实失败接纳重试的原职责 |
| 历史状态只初始化新目标，不覆盖原会话 | [当前产品决定](../中期检查/41-当前产品决定与实施边界-2026-10-13.md)；选择候选不能重新开放同会话历史覆盖 |
| 正式历史装载沿检查点分叉 | 不以旧运行commit/snapshot替代检查点，不把candidate_id冒充checkpoint_id，不建立后备旧分叉路线 |
| 检查点不承担候选重跑 | [统一工作规划](../中期检查/40-统一工作规划与实施顺序-2026-10-12.md)明确不添加检查点Head、commit/run检查点起点或来源追踪；不能因实现重roll自动改动此决定 |

此前E1至E5只确定调用边界，没有决定新重roll/候选的具体业务结果。[49号回执](49-阶段E旧入口退役与测试工作流清理实施回执-2026-10-15.md)将其列为独立后续事项，是该批历史状态。本次用户进一步明确了上面四项业务事实；不能继续以49号或本页原稿为由重复询问“同一轮还是新一轮”“全部保留还是只显示”“选择后是否用于续聊”。

## 2. 现行实现可直接复用什么

| 代码 | 当前能力 | 接续时的限制 |
| --- | --- | --- |
| [graph_candidates.py](../../backend/src/phase1_agent/graph_candidates.py)的`list_graph_candidates` | 只读列出冻结会话历史中`completed_execution`对应的成功普通回合，给出准确执行、源会话、定义和选中标记 | 这是所有可见成功执行的投影，不是“同一输入的一组备选答案”；`can_select`固定为false，不能直接改为true |
| [graph_service.py](../../backend/src/phase1_agent/graph_service.py)的`start`、`_prepare_run` | 建立新执行、重新编译当前运行配置，分配新chain/node-run身份，使用现行runtime及成功收尾 | 新跑会读取当前可调配置及当前授权资源；不是旧执行的精确输入重放 |
| [workflow_operations.py](../../backend/src/phase1_agent/workflow_operations.py) | 将启动、暂停、继续、关闭及正式检查点读/分叉抽为不依赖前端节点的独立功能，启动可接收外部输入 | 已有可复用调用边界，不等于已经拥有同回合重来、候选集及选中上下文管理 |
| [graph_service.py](../../backend/src/phase1_agent/graph_service.py)的`control`及[graph_failed_retry.py](../../backend/src/phase1_agent/graph_failed_retry.py) | 已有暂停、同进程继续、显式关闭及准确失败调用重试 | 不把这些操作改名为重roll；未知副作用或不确定接纳结果不能自动再执行 |
| 同一服务的`fork_checkpoint` | 按三个现行CAS条件核对稳定源会话，原子复制选定检查点前缀，在新会话装载逻辑数据 | 不自动运行；目标以自己的commit/ref初始化，执行历史为空，不继承旧候选列表 |
| 同一服务的`_append_success_checkpoint`及[checkpoint_repository.py](../../backend/src/phase1_agent/checkpoint_repository.py) | 整轮成功后保存全量首点或后续差分点 | 当前没有首轮运行前的检查点；失败、暂停或局部执行不能伪装成功点 |
| [graph_application_contracts.py](../../backend/src/phase1_agent/graph_application_contracts.py) | 已登记独立的`run.start`、`run.control`、`checkpoint.list/read/fork`及只读`candidate.list` | 退役候选命令只存在于`RETIRED_RECEIPT_COMMANDS`，用于原请求核实，不是活动能力 |
| [frontend_node_operations.py](../../backend/src/phase1_agent/frontend_node_operations.py)及[frontend_node_channel.py](../../backend/src/phase1_agent/frontend_node_channel.py) | 提供准确节点绑定、窄调用、原请求/回执核实和通信适配的现有接线 | 可作为消费者适配参考；候选分组、重跑规则及状态维护应在独立模块，不复制进节点实现 |

`chain_run.inputs`包含本轮外部输入和保留的冻结资源字段。直接拷贝整份记录会触及保留字段；即使剔除保留字段，也不能保证输入节点配置、加载的数据项、模型资源及实时值与上轮完全一致。用户已经明确同一用户输入、同一回合重来；实施说明仍须准确区分该回合基准、实际计算输入和按现行规则实时取得的值，不能把“同一文本”冒充完整计算输入等价，也不能默默改成新一轮继续。

## 3. 为什么旧候选逻辑不能接回

[05号退役回执](05-完整快照与退役施工首批授权回执-2026-10-13.md)已经退出三个旧写职责：

- `candidate.select`将历史运行snapshot中的状态覆盖回原会话。
- `candidate.fork`使用旧运行commit/snapshot创建新会话。
- `consumer.candidate.fork`从旧通用聊天消费者直接触发上述分叉。

这些旧入口及其服务、HTTP、SDK和按钮一起退出，只有准确旧请求的只读回执核实继续保留。[48号规划](48-阶段E旧入口与预设设施退役执行规划-2026-10-15.md)及49号又退出纯旧consumer投影和旧聊天入口。新功能应使用新职责的独立实现，不能通过改名、重新注册旧命令或开放原service恢复旧逻辑。

## 4. 本次已定语义及原问题订正

| 原调查项目 | 本次已定事实 | 实施上需要落实什么 |
| --- | --- | --- |
| 基准状态与输入 | 重roll是同一回合重来，一条用户输入对应多次生成 | 明确该回合重来所用基准，以及首轮前状态怎样取得；不能从上一候选已经写回的上下文继续生成并称为重来 |
| 重跑范围 | 对同一回合再次生成回复，成功后仍归属该楼的候选集合 | 由独立工作流功能接入实际运行；不把失败重试或新增用户回合当作替代，也不因本次说明自动增加任意节点局部重算能力 |
| 候选与选择结果 | 该楼全部生成回复都是候选，全部同步数据层、全部由检查点保存；用户任选一条继续聊天 | 持久保存候选集合及选中状态；下一轮实际使用所选候选对应的计算上下文，不能仅改变页面展示或丢弃其他候选 |

上表确定业务结果，不直接指定数据库表、候选commit、运行snapshot恢复、节点内私有存储或会话覆盖方案。旧入口的退役原因仍有效；新候选选择不能通过重新注册旧服务来实现。

## 5. 必要实现前置

| 前置项 | 需要写清的最小内容 | 不完整时的实际问题 |
| --- | --- | --- |
| 回合基准及首轮前状态 | 准确区分本次用户输入、所属回合、该回合开始前已接纳数据和重来时的实际输入；首轮还没有成功检查点，不能假定一定有上一点 | 重roll可能把上一候选内容再次读入，变成沿该候选继续；首轮可能根本无可用重来基准 |
| 候选集合及选中状态持久化 | 同一楼的准确归属、所有候选、当前选择由数据层维护，多个会话、多个提供项不能混用；检查点保存实际已接纳的完整值 | 浏览器关闭、重读或分叉后丢失未选候选，或同类型多项互相覆盖 |
| 所选候选对应计算上下文 | 续聊前需取得所选候选对应的准确上下文，并明确其与其他受本回合影响的数据如何保持一致；Agent仍只消费节点加载的值 | 页面选中第1条，实际Agent仍读取第5条的上下文，得到不同的对话分支 |
| 最新候选集合与较早候选状态共存 | 说明“保存全部候选”和“采用较早某候选继续”如何同时成立，不从候选较早的保存时刻直接丢掉后来候选 | 简单回到第1个候选时的旧点会丢后4条；简单沿最新点继续又可能消费第5条计算上下文 |
| 聊天类型版本及检查点联动 | 聊天数据类型的完整值、候选/选中信息、正常读写、展示快照、完整/差量、装载和再次分叉成组对齐；准确格式版本须另列 | 只增加准入字段会形成能保存但不能装载、能显示但不能按所选候选计算的半条链 |

具体例子：一条用户输入依次产生`C1`至`C5`，各自对应计算上下文`S1`至`S5`。生成`C5`后，数据层需要保留五个候选。用户选`C1`续聊时，待消费的是`S1`，而候选集合仍应是`C1..C5`，不能退回“当时只有C1”的集合，也不能因最新候选为C5而继续消费`S5`。检查点最终要保存能同时表达这两个事实的合规数据。

现行检查点按某一保存时刻的完整逻辑状态物化；没有“自动带上这之后才出现的全部候选”的含义。本次用户说明也没有授权悄悄合并不同时刻的状态、覆盖源会话，或恢复旧commit/snapshot路线。实施规划必须显式解决上例中的组合关系。

## 6. 最小接续建议与本轮界线

建议先用上面的`C1..C5/S1..S5`例子列清三份必要业务事实：该回合的重来基准、完整候选集合及选中值、所选候选继续所需的计算数据。先明确各自由数据层中的什么合规数据表示、何时显式写入及如何纳入检查点，再列最小类型/接口改动；这是实施说明的前置，不是重新询问已经确定的业务结果。

这里要求职责可识别，不预先要求三张表、三套存储或固定的候选状态机。候选数据的类型定义、普通读写和保存状态应复用当前定义/数据/检查点分层；独立工作流功能负责受理重来和选择，具体节点仅核对绑定、转交允许意图并返回实际结果。模块不依赖`frontend.node@1`或浏览器，也不让Agent重新承担持久项定位。

操作入口补齐与本页候选语义相互独立。聊天类型的当前引用与源删除边界见[52号勘察](52-聊天数据检查点准入与分叉引用边界勘察-2026-10-15.md)；该页原两条路径仍是实际调查记录，具体数据格式与准入需结合本次完整候选要求形成接续规划，不能把原`entries`列表加进白名单便宣称本次要求已满足。
