## 3. Host/Graph 真实接线

Host（`backend/src/phase1_agent/workflow_host.py`）：

```text
Host 管理两域
→ definitions.require_role_binding(management, capability_id=<域身份>, database, environment)
→ 域来源工厂（默认 store_factory = environment.open_store）
→ 原 ProviderConfigurationService / ContentConfigurationService

Host 取得工作流管理/执行
→ requirements：workflow 角色绑定 + 两域 management 绑定（均已校验，未实例化域服务）
→ 仅把两域 binding.factory 作为 provider_configuration_factory / content_configuration_factory
  窄依赖参数交给工作流来源工厂
→ 原 GraphManagementService / GraphWorkflowService
→ Graph 按原时机建立本域服务视图（store_factory=self._store）
```

Graph（`backend/src/phase1_agent/graph_service.py`）：`GraphWorkflowService`/`GraphManagementService` 接受同名窄依赖工厂；执行实例 provider 视图保持 `store_factory=self._store`、原 `credential_protector`、原 `discovery_client_factory`，内容视图保持 `store_factory=self._store` 且 `type_registry_factory=lambda: self.registry.data_types`（不构造时快照）；`MODEL_SERVICE_REF` 的 `credential_broker_factory` 仍绑定执行实例 provider 视图；`GraphManagementService` 懒属性同经声明工厂。直接可信构造（不经 Host）保留显式本地默认工厂，不是声明错误后的降级绕过；Host 路径绑定缺失显式失败。

生命周期：两域服务无领域 `close()`，声明 `close_entry="none"`、`borrowed_by=("http-server","workflow.graph")`，如实说明每次操作关闭连接；工作流执行资源仍由原 Host/Graph 关闭，HTTP 继续借用外部对象。统一来源/环境**不要求**统一成同一服务对象：管理先取得时两域各持有管理视图，执行出现后再建立各自执行视图；执行出现后 Host 管理入口按原规则返回执行实例。
