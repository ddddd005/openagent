## 4. 各部分的最小落实范围

### 4.1 基础运行与框架

- 梳理谁构造、谁持有、谁关闭，以及正常入口、直接构造和外部注入的支持范围；明确管理与执行如何协作，避免取得先后决定未说明的责任。
- 建立统一存储环境和取得方式，保持每个领域的连接、事务、CAS、幂等和回执语义；不另建物理项目库、项目实体或租户体系。
- 定义管理先满足子能力声明汇集和内部查询；执行管理先满足本期公开调用的组织需要，不要求所有普通读写绕行。
- 启动预检、前端托管及请求证据取得位置按真实接线整理。改变启动阻断政策、支持范围或关闭行为时，须在局部规划说明并确认。

### 4.2 子能力声明与跨域依赖

来源维护公开接入信息，项目汇集校验。第一版只接当前可信工作流实现，不建设任意导入、动态发现或多实现选择平台。

跨域依赖至少要能说明“谁调用谁、使用哪份公开契约、用于什么”，并对应真实的取得和调用路径。登记的是公开能力关系，不是每个内部函数。提供方维护接口定义，工作流声明其引用，避免重复维护参数和实现细节。

局部执行规划须明确依赖如何标识、如何取得，以及缺失或不符在何处显式报告；本大纲不默认引入逐次调用检查、动态代理或新的权限系统。工作流对供应商和全局内容的既有依赖须覆盖，其两域自身项目装配重构仍后置。

### 4.3 目录、管理与复制

| 接驳 | 本期需要的能力 | 边界 |
| --- | --- | --- |
| 环境 | 项目提供统一存储条件，工作流取得自己的领域接口 | 不把工作流仓储变成项目可任意操作的通用表接口 |
| 查询 | 工作流及会话身份、归属、名称、归档情况、简单运行状态及管理所需版本条件；数量明确统计范围 | 工作流解释摘要；不读取节点输出、变量等详细数据来拼项目目录，不维护第二份权威 |
| 管理 | 项目侧调用工作流公开能力，由工作流完成创建、归档、删除和会话管理 | 保留先停止/等待、结算、引用与未知结果保护、事务及释放 |
| 复制 | 复制正式 current 对应的配置，使用选定来源的版本条件；来源变化显式冲突 | 不静默换源，不纳入未保存编辑；内部键是否重建按实际身份作用域核对 |

正式资产与本地草稿、待提交或待核实投影明确区分，草稿可以保留，但不计作正式工作流或会话。只有正式结果接纳后才报告创建或复制完成；提交状态未知继续核实，不自动重放。分页和更丰富摘要按真实消费者决定，不为接口齐全增加一套查询平台。

配置复制的业务归属与范围已定；准确公开 operation、回执绑定和来源版本检查仍需在 T5 局部契约中定案。外部引用继续指向原共享资源，不复制供应商、全局内容或其数据。

### 4.4 前端归拢

本期先盘点工作流创建、会话管理、归档、删除、配置复制等入口及其交互、状态与调用归属，将分散部分归拢到工作流前端和左侧栏。已经位于工作流组件内的能力明确其归属即可，不重复搬写。

项目负责外层导航、容器及挂载支持，工作流负责区域内内容和业务操作。项目或其他可信调用者仍可经工作流公开业务接口调用，不因按钮移动而退役公开能力。

保持配置提交、管理互斥、确认/派生、回执核实、unknown 保留、迟到响应保护和错误展示。仅移动按钮不足以完成本项，不能把业务协调继续散留在项目外壳；也不借本期改成全新页面、设计系统或前端插件平台。

### 4.5 工作流大功能顺序

沿用 `0-9000` 方向：`0000-0999` 构建准备，`1000-1999` 工作流执行，`2000-2999` 结束处理，其余预留。注册只承载工作流层级大功能，项目加载子能力不在单次调用序列内。

T6 先明确注册单元、准确位置、冲突规则、适用条件、内置/扩展权限，以及图外控制和结束路径如何接续，再施工。定义和注册管理声明，工作流执行层组织调用；首版插件不能覆盖或修改内置位置。

必须保持同次 `RunBasis`、round/event 差异、准备与共同结算事务、节点逐次接纳、暂停/继续的已完成前缀、业务/通知分离及必要释放。不能无条件从零遍历，不能用数字替代业务条件或错误政策，不把节点、内部子函数和 Agent 内部步骤逐项登记。

## 6. 完成要求与停止线

本期最终要证明以下通路真实成立，各批实施回执须把入口、实际消费者、状态/数据权威及验证证据对应起来：

1. 项目正常取得及关闭能力，管理读取不额外激活执行权威，责任不再依赖未说明的取得顺序。
2. 工作流接入声明、可信实现及生命周期相符；跨域依赖与真实取用对应，依赖缺失显式报告。
3. 环境、目录及整体管理接驳成立，项目不跨域写工作流仓储，不新增第二份资产权威。
4. 工作流前端承载本域操作，既有提交、确认、核实和错误流程保持；正式资产与草稿清楚区分。
5. 配置复制只产生新配置身份，可核实正式结果，来源冲突和未知结果不被当作成功。
6. 大功能注册由真实执行消费，既有运行依据、事务、控制、通知和释放通过针对性保护验证。

各批先定向验证，最后联合验收；全量集合、前端构建/浏览器及安装后交付验证在相应执行规划中列明，历史通过数不计作本期新增证据。

出现未确认的职责、契约、数据归属、运行政策或范围冲突时，停止受影响路径并报告，不自行补造设计。供应商/全局内容的新项目接驳、多引擎共存、热替换、插件市场、前端全面重设计、新调度器、自动重试/恢复/补偿和未知请求重放不在本期范围。
