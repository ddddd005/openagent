## 4. 联合判据

### 4.1 正式组件、数据域与真实调用

| 核查面 | 达标所需证据 |
| --- | --- |
| 配置规则与正式接纳 | 工作台/SDK 完整保存、节点页精确修改进入共用业务规则和数据端口；前端受理与 Store 投影不绕回已退役入口 |
| 定义及运行依据 | 定义仍由来源维护；同次 RunBasis 的冻结 registry/目录贯穿准备、执行及接纳；缺依据显式拒绝续跑 |
| 选定数据通路 | Q6 只承接配置所属删除；Q10/Q11 只承接管理性边界持久化；领域内部不互用对方仓储，调用方不取得通用 SQL/连接/repo |
| 原事务与结果 | 节点接纳、工具逐次接纳、独立事实/信息绑定、整轮结算保持各自原边界；拒绝无部分写，已接纳前缀不因后续失败撤销 |
| 功能与工具调用 | 普通节点与变量工具共用真实 executor；同次准备帧、Agent 自身 ACL、结构化提示真实消费、逐次独立重读保持 |
| 消费与管理交接 | 查询/回执不产生执行许可；无效核实按钮退出，现行配置/资源/管理/草稿核实继续工作；历史读取与管理保留项不冒充未完成迁移 |

只新增模块、查到函数名、全仓 repo 命中数下降或测试数量增加都不单独构成达标。验证维护权、允许通信、实际命中及写后独立读取，不以新建类或万能入口作为统一标准。

### 4.2 图内主干与交互验证

```text
配置受理 → 共用规则与定义级锁 → 原事务保存 → 独立读取
→ 选定包/定义 → 同次 RunBasis → 准备期编译与只读准备帧
→ prepared + chain_start 提交 → 后台执行与执行期图计划
→ 普通/宿主节点调用，Agent 内按同帧调用变量能力
→ 各自原接纳事务与下游推进
→ 成功/失败/暂停/关闭对应结算 → 提交后通知与诊断
→ 按状态释放或保留 → 独立查询与当前消费者
```

用 119 号第 5 节的 O1-O10 对照记录每项触发入口、先后条件、使用依据、事务、产出、失败和消费者。两次编译作用不同；准备不调用业务 executor/模型；图内排序不扩成外层 `0-9000` 注册机制，Agent 活动于 Runtime 不等于耦合图执行器。

至少覆盖以下交互；可以由现有测试分段支持，必须注明分段，不声称存在未运行的浏览器到模型完整链：

1. **配置锁与运行准备**：同一定义的 prepared/running/paused/failed 未关闭等占用拒绝各来源新提交；所有运行退出后解锁，不相关定义正常。保留原快照隔离；同事务/交错验证不足时单列缺证，不用快照隔离替代写禁令。
2. **正常调用与首批变量工具**：准备只读；普通节点与 Agent 调用共用实现；Agent 逐次写回/重读，后续错误保留已接纳结果；提示布局不改变 callable 集合或 ACL。
3. **无依据管理性收尾**：pause/close 与 Q10 异常收尾走有限端口；pause 保留原状态更新条件，不新增 manifest 要求。close 与 Q10 涉及来源的结算分别验证合法 `chain_start`、缺失、错误身份/结构和损坏 JSON；Q11 close 500 无回执并回滚，Q10 回滚且 wait 保留原错误，禁止补造来源。
4. **结束、通知与下一次调用**：提交前错误、节点级提交后通知错误、整轮提交后通知错误分别观察；部分通知失败与未执行项准确；暂停通知失败后 resume 成功不再抛旧异常，新失败取代旧上报，close 不冒充新调用清除错误。
5. **业务结果与查询**：通知诊断独立窄事务只能注解 diagnostic/revision，不能改进度/状态/输出；诊断写失败显式表达；等待异常与持久诊断不含私有异常文本，已提交 commit/检查点/manifest 保持。
6. **退役与保留能力**：旧包装/submit/四资源路由/旧回执读取拒绝，现行配置与聊天、资源、管理及通用回执可用；旧 evidence 混存可读且不显示必然失败的核实入口。

### 4.3 三项 P2 的保护要求

不重新要求实施方重复交付同一修复；以最终身份核对及现有用例复跑保护：

- P2-1：等待上报只反映同链最新一次 `_execute` 调用；恢复成功/再次通知失败及 close 不清理三种语义分别核对。
- P2-2：来源校验不能只测错误路径；同时有合法 close 正对照、身份/结构不符、缺失、损坏 JSON；Q10/Q11 回滚读原始隔离记录，不能用会再次解码损坏 payload 的公开查询替代回滚证据。
- P2-2b：服务异常类型/固定公开文案及进程内 HTTP 500 均有证据；不能只证明 Python helper 抛错。仅覆盖 prepared-boundary 结算读取，公开 `get_run` 的相邻解码分类保留为已知未扩范围。
- P2-3：失败项仅安全公开字段，无异常 `message`；通知失败及诊断记录失败两条出口均脱敏。原始解码 cause 的内部保留与公开诊断脱敏分别判断。
