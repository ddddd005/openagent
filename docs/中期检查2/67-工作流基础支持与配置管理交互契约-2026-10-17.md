# 工作流基础支持与配置管理交互契约

日期：2026-10-17，Asia/Shanghai。

性质：本阶段职责契约。本文规定工作流基础支持、配置管理、前端入口和数据管理之间的交互边界。

2026-10-18 边界订正：工作流基础支持收窄为运行相关的启动、恢复、抛错、当前状态和会话指向；上下文由节点经 Runtime 读写。创建、删除、归档、复制等项目管理能力归项目能力层，本阶段只建设工作流底层运行。第 1、5、7 节相应的较宽管理职责保留为原始讨论，不再作为当前工作流基础支持的施工要求；以[69 号职责订正](69-工作流架构局部骨架与分批执行规划-2026-10-17.md#1-阅读关系与本轮订正)为准。节点实例增删仍属于配置管理，本订正不取消运行准备所需的数据初始化或已定分叉语义。

## 1. 工作流基础支持

工作流基础支持是工作流工作台和其他工作流能力运行的地基，负责：

- 工作流工作台的装配和承载；
- 工作流初始化；
- 工作流创建、删除、归档和复制；
- 工作流列表和工作流生命周期状态；
- 工作流会话创建、关闭、恢复和基础管理；
- 基础错误表达、诊断和操作结果；
- 为配置管理、Runtime 和能力模块提供工作流及会话上下文。

基础支持负责协调一次工作流操作，但不替代配置管理维护节点，不替代 Runtime 执行节点，也不替代数据管理持久化数据。

## 2. 配置管理

配置管理负责静态工作流的维护和配置变更规则，包括：

- 读取定义目录中的精确节点定义；
- 创建、删除和修改节点实例；
- 节点类型和版本绑定；
- 节点端口、数据边和控制边维护；
- 节点配置和静态节点内容保存；
- 节点组结构维护；
- 节点派生内容生成和校验；
- 工作流 package lock 维护；
- 前端画布映射和编辑结果转换；
- 对可调配置修改进行作用域判断。

配置管理不直接操作数据库表，也不把前端输入当作数据库字段更新。所有正式变更都转换成配置命令，再由数据管理接口保存。

## 3. 前端修改路径

当前前端节点对输入节点的修改必须统一经过配置管理接口：

```text
前端节点操作
→ 基础支持 / 应用入口
→ 配置管理命令
→ 定义目录读取定义
→ 数据管理校验和保存
→ 返回新的工作流或会话视图
```

前端不能直接调用数据库仓储，也不能绕过配置管理直接调用通用数据写入接口。

如果修改目标是静态工作流配置，写入工作流定义域；如果修改目标是当前会话的临时覆盖，必须明确标记为会话数据，不得隐式覆盖静态定义。

## 4. 节点和派生内容

节点类型、节点实例和节点运行必须分开：

- 节点类型由能力包或基础注册来源提供。
- 节点实例由配置管理创建并保存到工作流定义域。
- 节点运行由 Runtime 创建并保存到工作流会话域。

节点配置是规范化保存的原始依据。节点标签、端口展示、前端表单和其他派生内容应由配置管理根据定义目录生成或校验。除非为了修订、查询或兼容需要，派生结果不应成为另一份独立权威。

## 5. 基础支持与会话边界

基础支持可以创建会话、固定工作流定义修订并提供会话上下文，但不能因为创建会话而复制或修改静态工作流。

工作流列表的创建、归档、复制属于基础支持协调的工作流管理操作；复制时由数据管理创建新的工作流定义身份和修订依据，不能通过共享可变对象形成隐式联动。

## 6. 错误和结果

配置管理应返回结构化的校验结果、冲突结果和数据管理错误。基础支持负责把结果转换为工作台可以展示的状态。

前端显示的错误不能替代数据层的错误，也不能通过静默回退掩盖版本冲突、节点版本缺失或定义不完整。

## 7. 交互接口的最低要求

本阶段至少需要形成以下概念接口：

- 工作流定义读取和修订接口；
- 节点实例创建、绑定和删除接口；
- 节点配置修改接口；
- 数据边、控制边和节点组接口；
- 工作流级变量声明接口；
- 会话级可调值修改接口；
- 前端节点视图和配置表单读取接口；
- 工作流列表和会话管理接口。

具体 API 名称可以根据现有代码调整，但不能改变上述责任归属。
