### 4.3 工具装配与能力边界

```text
本地包导出声明/实现
  -> 工作流配置选择工具及目标 Agent
  -> 同次 RunBasis 下解析来源、依赖、参数和权限
  -> 形成已准备绑定及同源工具说明
  -> Agent 适配为统一 RegisteredTool 并装入模型请求
  -> 按调用身份进入包适配/领域功能
  -> 校验结果、按领域规则接纳副作用、返回并保留事实
```

共同层维护准确身份、名称冲突、schema、调用归属、准备依据和受限能力接口；变量名称、对象键、操作映射及单对象写规则由变量适配维护。准备阶段不执行业务，显示说明不授予权限，调用不回读当前 registry 替代冻结依据；既有变量工具每次写入的接纳与独立重读继续保留，新领域副作用协议另按 G-C 确认。`final_answer` 的内核结束职责不交插件重定义。

“新增工具不改核心”的验收范围是已批准协议内的能力。A0 必须列出可支持、明确拒绝、尚待决定三类，覆盖纯计算、既有对象读写、资源读取、宿主服务、私有态、`executor_ref`、特殊结算及外部副作用；不将后六类一次性放开。当前参数校验是严格必填标量对象，放宽为可选/嵌套/其他类型须单列契约与消费者影响，不作为普通适配悄悄修改。

建议以既有变量读写和至少一个无变量依赖的真实工具族验证状态型/非状态型差异；框架冻结后再追加一个独立工具，核对 `runtime.py`、`agent_executor.py`、通用准备/调用层不需新增工具名或业务类型分支。代表工具选取属于批准支持范围内的工程选择；新增权限、效果或调度机制须走 G-C。若仍靠修改中心目录中的硬编码清单逐个接入，不能判通用加载完成。

### 4.4 加载失败与结果发布建议

建议以“本次选择集合及其完整依赖”为发布单位，先构造完整候选，再提交必要持久变更，最后发布同一候选。正常构造与已持有服务上的选择变更分别验证，不把两条路径强行改成同一种持久副作用；轻管理构造仍保留其不取得执行权威和原只读校验边界。

| 失败位置 | 建议结果与保留状态 |
| --- | --- |
| 目录项/声明无法识别 | 返回具体来源及阶段诊断；该项不成为可用包。不执行无法识别的入口，不把选择所需包默默删掉后算成功 |
| 所选包缺失、依赖冲突、宿主协议不符 | 拒绝本次选择集合；不猜版本、不自动禁用依赖、不改写工作流 package lock |
| Python 导入或注册失败 | 不发布候选节点、工具、前端导出；保留安全错误表达和内部异常因果，不自动重试。已执行的任意 import 副作用不承诺事务回滚 |
| 导出/类型/实现/前端配对校验失败 | 丢弃候选；已发布集合与持久选择保持原状，不按“已成功的前几个包”部分发布 |
| 必要数据库事务失败 | 回滚该事务；旧发布状态不动；loader 的内部契约记录同样不能提前推进，防止影响下一次合法加载 |
| 数据库已提交、进程内发布异常 | 明确区分已提交事实与当前服务未完成发布；拒绝受影响服务继续以不一致状态消费，不伪称回滚、不自动补偿/重放。具体拒绝点在 A0 定案 |
| 单次工具准备失败 | 明确失败工具与原因，按既有准备事务退出；不悄悄减少工具集后调用模型，不重跑 Agent |

实现尽量把可失败的构造、校验、冻结操作放在提交前；提交后只发布预先形成的同一结果，不调用插件代码。此举不宣称 SQLite 与进程内存具有跨进程原子提交；进程中断后的再次正常构造以已提交准确选择为依据，历史业务事实不重放。本期不据此增加通用恢复框架。

现有特殊路径必须单列：[graph_service.py](../../backend/src/phase1_agent/graph_service.py#L174)仅读取既有持久选择且命中 `package_missing_dependency` 时记录 `package_diagnostics` 并加载空 registry；显式 `enabled_packages` 选择缺包、或无已保存选择时默认集缺包，直接失败。显式包来源供给本身不排除前一诊断路径。建议保留其可诊断/可管理用途并如实标示不可执行，不能计作加载成功。G-B 须确认允许提供的管理能力及失败可见性，不以统一失败为由默删该路径或恢复旧包。

错误对外至少能辨认来源/包身份、失败阶段、原因和是否已提交/发布；准确字段复用现有诊断，局部规划再冻结。不泄露凭据、原始业务正文，不为错误状态先建新持久表。目录内代码按可信本地扩展处理；入口应交付声明和注册，资源取得及关闭放在明确生命周期，不能把白名单称作沙箱。
