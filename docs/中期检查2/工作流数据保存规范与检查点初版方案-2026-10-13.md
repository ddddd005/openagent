## 1. 初版范围

初版目标是建立一套清晰、可用、可逐类型扩展的工作流数据保存规范，不一次迁移所有现有数据架构，也不把旧公共会话对象机制当作检查点的通用收集规则。

初版纳入两类状态：

1. **节点声明的配置字段**：保存在注册 `NodeDefinition` 描述中的明确范围；由节点表单映射，未声明字段忽略。
2. **Agent 上下文**：按其精确类型注册和自身逻辑处理能力纳入检查点。

初版明确不纳入：

- `private-state`：本版不增加其检查点声明、收集、恢复或分叉写回。现有运行时 schema、读写和会话持久化机制暂不修改；是否保留或移除以后再判断。
- **会话展示上下文**：从第一版白名单取消。
- 通用 `messages`、摘要、程序变量、其他对象、运行请求证据及所有已注册类型：不因存在或已注册而自动纳入。没有 `messages` 或展示上下文不影响会话及检查点，不造空集合。

源码中可见的 Agent 上下文候选根类型是 `workflow.effective-context@4`，其当前实现通过 `view_ref` 指向 `CONTEXT_VIEW@4` 内容。白名单只接逻辑状态，不扩为全部artifact。类型/能力是静态源码事实；03实测当前指定开发库没有已保存package、类型或数据行，不因此声称新处理器已安装。

## 2. NodeDefinition 配置声明

### 声明形状

第一版只声明配置路径，不出现 `private_state_paths`：

```python
checkpoint_save = {
    "config_paths": [
        ["mode"],
        ["options", "strategy"],
    ],
}
```

`config_paths` 是配置对象属性段数组。只允许沿 JSON Schema `properties` 显式遍历；不允许通配符、表达式或数组下标。路径可以指向完整对象或数组字段，不另定义元素级保存规则。重复路径、父路径与子路径同时声明、schema 中不存在的路径均在注册时拒绝。

声明由 `NodeDefinition` 权威描述承载。节点表单字段与路径一一映射，表单只编辑正常 `node.config`，不让用户编辑检查点声明，也不引入第二份配置权威。检查点收集器从已保存工作流定义及其固定 revision 读取配置，不读取未提交的页面状态。

收集遵循已定配置策略：未声明字段忽略；正式可调字段和取最新的全局内容不冻结进点。固定配置仍由工作流定义持有，分叉不得用历史投影覆盖当前定义或可调配置。检查点仅记录固定定义身份及声明范围所需的逻辑投影，不建立另一份可写配置状态。

### 新 descriptor 与版本处理

当前开发库已核实无旧workflow或全局node_definition行，旧描述搬移/替换不再作为前置，也不为不存在的冲突强制升组件版本。**旧descriptor按用户最新要求列入实施中退役**：与新声明注册、序列化及收集消费者成组替代，不保留旧格式兼容或自动升包，出现实际版本冲突、未分类依赖或退役范围问题再报告用户。空库不等于源码旧表示已退出，main库不在本次退役数据操作范围。

新descriptor一经保存，同component_version的完整描述必须一致；以后变义仍须新组件版本并明确更新工作流，不静默升package/节点版本。空声明采用定稿的唯一表示，不保留旧descriptor兼容分支。源码身份键及精确比较约束保留，不用退役授权绕过新数据的同版本不可变规则。

## 3. Agent 上下文检查点白名单

数据类型注册与检查点准入是两件事。第一版新增显式检查点数据登记；只有登记到白名单、且实际处理能力齐全的精确类型版本才能进入检查点。`TypeRegistry` 中存在 schema、validator 或 reference hook，不自动授予检查点准入。

每个登记项至少绑定：

- 精确的 `scope / type_id / schema_version`；
- 从当前权威 Agent 上下文读取逻辑值的处理器；
- 对检查点逻辑值的 schema 和业务规则校验；
- 必需引用的识别、读取和本地化规则；
- 将逻辑值写入新分叉目标并验证目标独立可读的处理器。

首批登记只覆盖 Agent 上下文根 `workflow.effective-context@4` 所表达的**已接纳逻辑状态**。当前运行时对象中的 `view_ref` 是源 artifact 引用，不能直接复制成目标引用。收集处理器须读取该上下文所需的实际内容，形成不依赖源 session、源 artifact ID、源对象 revision、运行 receipts 或旧历史 membership 的逻辑检查点状态。Agent 内核暂停现场、未完成请求及单轮 `AGENT_CONTEXT_UPDATE`、`CONTEXT_COMMIT` 等回执不作为额外持久状态根。

校验至少保证：上下文内容结构合法；消费/once 状态与上下文内容一致；Agent 与工作流节点绑定正确；内容没有未解析的外部会话或 artifact 引用。分叉时在同一事务内把该逻辑状态装入新目标，使用目标自身身份和正常当前写入版本；不得引用回源 session 或依赖旧 session-object 历史链。不能本地化必要内容或校验失败时，检查点保存/分叉失败且不留部分写入。

检查点存储只处理上述明确的 Agent 上下文登记项。未出现 Agent 上下文时允许无该项；不得为满足白名单而创建空 Agent 状态、空 messages 或会话展示上下文。检查点与分叉仍支持有效空数据集。

## 4. 成功点、分叉与旧路径

- 检查点仍只在可信的回合成功收尾后创建；保存节点已声明的配置投影与白名单中的 Agent 上下文逻辑状态。失败回合不建点，已建点不可变。
- full/diff 存储与检查点父链按同一逻辑状态计算；差异层不改写类型自己的校验、身份或引用规则。
- 历史操作只允许创建新的分叉会话。一个事务内复制所选检查点及完整父级前缀、按白名单复制 Agent 上下文、初始化目标并设置目标当前状态。源只读；禁止把所选状态写回源会话。
- 新分叉的规定内容必须不依赖源会话或回收站中的数据；复制源 ID、旧 revision 或历史引用不能冒充独立。失败回滚整个目标及其检查点副本。
- 旧 `candidate.select` 覆盖服务、正式命令/API/SDK及按钮需要一并退出；旧运行 snapshot `candidate.fork` 不作为新检查点分叉的后备路线。仅隐藏按钮或重命名不算完成。
- `SessionObjectStore` 可继续供本版未接管的 live 类型使用，但不能作为检查点“自动收集所有对象”或分叉“自动复制所有绑定”的规则。其他类型后续按本版登记规范逐步迁移。

## 6. 定向验收

1. 有可运行节点但无 Agent 上下文时，检查点仍可保存；只有声明配置字段进入节点投影，未声明字段不入点。
2. `private-state` 不被新检查点收集或恢复；其当前运行时行为未因本版改变。
3. 有 Agent 上下文且精确类型登记完整时，检查点逻辑状态可验证；缺失、类型错误或必要引用无法本地化时准确失败。
4. 无 `messages`、无会话展示上下文或无 Agent 上下文都不因缺失而被补造，空白名单仍可产生有效空数据点。
5. 从任一历史点只创建新目标；源会话不变，目标可独立读取 Agent 上下文，不能依赖源数据或回收站。
6. 任一分叉中途失败均不留下半成品；旧 `candidate.select` 写入口不可达，查看历史保持零写入。
7. 当前开发库无旧业务/descriptor/type/package数据；实施中旧descriptor及消费者按新契约退役，新工作流从新规范和明确package选择开始，不自动升包、导入旧数据或恢复旧格式。
