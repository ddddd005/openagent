## 2. 施工前确认的三项契约

用户已确认以下三项，不再作为本批待决项；本文只记录其实际落地方式。

### 2.1 内部统一查询封套

内部只读查询结果统一为：

```text
kind               node | data_type
registration_ref   准确身份；节点为 component_id + component_version，
                   数据类型为 scope + type_id + schema_version
declaration        类别定义正文，由类别自己解释
source             来源包列表；每项为 package_id + package_version，可为空
availability       当前运行时状态，不属于定义身份
```

- `kind` 和 `registration_ref` 是所有类别共同的身份字段；未知类别明确报 `definition_unknown_kind`，非法引用报 `definition_invalid_reference`。
- `declaration` 保留类别差异。节点继续使用既有 `NodeDefinition.to_dict()` 形状；数据类型继续使用既有 `DataTypeDefinition.to_dict()`。没有把两类正文压成同一个结构。
- `source` 是列表，因为共享数据类型可能由多个包提供字节一致的声明；不把来源解释为唯一所有者。本轮没有新增包级来源持久记录，来源只从已加载 manifest 的导出声明投影。
- `availability` 本轮只对已注册项返回 `registered`；固定修订引用找不到注册时返回 `unavailable`。它是读取时状态，不进入任何持久身份。
- `executor`、`validator`、`factory`、声明 hook 等实现绑定不进入 JSON 正文。`NodeDefinitionAccess` 只向可信宿主消费者提供配置校验和外部输入声明调用，不提供执行器替换入口。
- 对外 `catalog.node-types`、前端协议 1/2 仍保持原形状；内部查询由现有协议适配器投影出去，不新增 HTTP 字段。

### 2.2 持久化范围

本轮不新增通用定义表、存储版本或迁移：

- 数据类型继续使用 `registered_type_contracts`；查询只调用 `TypeContractStore.get`，不调用 `check`、`register` 或 `check_registry`。首次登记仍由包选择/项目保存的既有事务完成，既有 declaration 和 digest 不重写。
- 工作流实例引用从 `workflow_definition_revision.document` 的准确固定修订读取；`definition_references(identity, revision)` 通过配置数据端口读取固定文档，再解析节点、端口数据类型引用和 `package_lock`。它不读取当前覆盖，也不反向合成当前配置。
- 节点定义、执行器、校验器和输入声明 hook 仍由包注册和运行时 registry 维护；首批不把包定义正文落库。数据库没有成为第二份节点定义权威。
- 定义数据模块只承接类型证据读取；配置数据模块继续承接固定修订和当前覆盖。两者由数据管理入口分别分发，仓储之间不互调。

### 2.3 内容摘要

本轮不新增通用摘要规则：

- 数据类型继续使用 `TypeContractStore` 原有 digest；不把包来源、展示字段或封套一起重新摘要。
- 节点继续使用准确 `component_id + component_version` 和加载器契约比较；不对 `NodeDefinition.to_dict()` 或目录行整体取 hash。
- 查询视图不返回统一 `summary` 字段；也没有新增内部内容 hash 作为持久身份。
- 后续若项目级包来源需要 provenance 或包级证据，另立契约；不影响本批。

## 5. 残余与范围外

- `runtime_information.registration_catalog` 仍汇总七类注册并维护共同展示字段；本批只把节点目录主路径接到定义查询，没有把它改造成统一注册入口。
- `session_objects.py`、`global_resources.py` 仍直接使用类型证据仓储；这是会话域/全局资源域的范围外调用，未迁移。
- `checkpoint_collection.py`、`checkpoint_loading.py`、`frontend_node_operations.py`、`frontend_node_snapshots.py`、`graph_store.py`、`graph_execution.py` 等可信运行路径仍直接使用 registry；本批不把它们改造成通用目录。
- `platform_capabilities.data_types` 等平台能力投影保留原注册表路径；外部协议不变。
- `CapabilityPackageLoader.load` 在返回前更新加载器内部历史契约字典，数据库持久提交在 `configure_capability_packages` 之后发生。该静态时序风险本轮未复现、未改动、未验证为缺陷；新增定义路径没有改变加载器准备/提交契约。
- 仍是普通 `SqliteStore` 关闭重开读取，不是 `mode=ro`/`query_only` 严格只读回执；活跃写命令中的依据应使用既有 `transaction` 端口，不能另开普通存储。
- 未接项目级包来源、下载、安装入口、插件路径扫描、热更新、项目包管理 UI 或 Runtime 整体迁移。
- 未验证 HTTP/浏览器端到端、真实模型、服务启动/停止、凭据或业务数据；未安装依赖。
- 2.2-A 的“公共注册面收拢”只完成查询/类别适配侧；包注册仍按类别保留 `HostRegistration` 方法，避免在首批改变包协议。新增类别仍需补该类别 schema、校验和注册适配，不承诺零代码扩展。
