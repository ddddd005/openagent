# 使用手册

依据 2026-10-16 当前代码整理。本文说明现有功能，不把规划中的 MCP、项目智能管理系统或沙箱当作可用入口。安装、开发与正式环境的选择、启动和停止方式见[快速启动](QUICKSTART.md)。

## 1. 先分清几个对象

| 对象 | 用途 |
| --- | --- |
| 工作流 | 节点、连线、配置及会话数据项的登记和权限声明 |
| 会话 | 某个工作流固定修订下的一份独立运行数据，包括上下文、变量和聊天记录 |
| 本轮运行 | 在会话内执行一次；一个会话可以连续执行多轮 |
| 会话绑定 | 声明数据项的准确对象键、类型和允许访问它的节点，不是“选择当前会话” |
| 检查点 | 成功点保存的、已准入的状态；可据此创建独立新会话，不覆盖原会话 |

新建工作流不创建会话，也不会调用模型。普通新建会话使用独立数据，不会自动继承另一个会话的变量值或聊天上下文；需要接续已保存状态时使用检查点分叉。

左侧“工作流”中单击选中，双击、按 Enter 或点击“切换”打开。左侧“供应商”管理供应商和全局模型配置，“内容”管理全局提示词组与 Lorebook。

推荐顺序：保存供应商和模型配置，搭好全部节点与连线，完成会话项权限及前端输入绑定，最后新建会话、主动注册变量、打开前端页面测试。这样可避免已有会话后修改固定结构而反复派生。

## 2. 配好供应商和模型

### 2.1 保存供应商与 Key

1. 点击左侧“供应商”，在“模型供应商”标题旁点击加号。
2. 填名称、协议、服务地址，勾选“启用”。协议可选 `Chat Completions` 或 `Gemini generateContent`。
3. 在 API Key 密码框填写自己的 Key，点击“保存供应商”。
4. 核对保存结果。若显示待核实，先使用对应的“核实原请求”按钮，不要反复提交。

新 Key 与当前供应商配置通过同一个保存按钮提交。编辑已有供应商时，Key 留空表示保持已有 Key，不表示删除。已保存供应商不能直接切换协议，需要另一协议时新建供应商。

服务地址允许 HTTPS 或本机 HTTP，不要把密码、查询参数或片段放进地址。Key 不应写到提示词、节点 JSON、截图或文档中。本机密钥库与业务库分开，受 Windows 当前用户及原路径保护，不要通过移动数据库尝试迁移 Key。

保存成功只证明配置已保存，不证明账号、网络和模型实际可用。

### 2.2 保存模型配置：务必展开“真实模型容量”

用户所说的“模型预设”，在当前界面中叫“模型配置”，位于同一供应商面板下方。

1. 点击“模型配置”标题旁的加号。
2. 填“配置名称”，选择已保存的供应商，填准确的“模型名称”。
3. 可选：点击“获取上游模型列表”刷新图标，再选择已适配的型号。此操作会联系上游；也可以手填型号。
4. **点开折叠项“真实模型容量”，填写下面三项。它不是上方“上下文长度方式”的下拉框。**

| “真实模型容量”字段 | 填什么 |
| --- | --- |
| 实际上下文窗口 tokens | 该供应商、该型号实际支持的总窗口 |
| 实际输入上限 tokens | 该型号实际支持的输入上限 |
| 实际输出上限 tokens | 该型号实际支持的输出上限 |

三项都必须是正整数。新配置中它们默认为 `0`，必须按所用型号的实际规格填写；选择上游型号不会自动填入容量。不要把模型名称、页面默认运行值或别的型号规格当成容量依据。

5. 配置本次运行使用的参数：

| 运行字段 | 含义与限制 |
| --- | --- |
| 上下文长度方式：真实模型窗口 | 使用上面填写的实际上下文窗口 |
| 上下文长度方式：自定义长度 | 另填正整数，不得超过实际上下文窗口 |
| 压缩阈值 % | `0.01` 到 `100`，最多两位小数；默认 `85` |
| 输出上限 tokens | 本次请求允许的最大输出；不得超过实际输出上限，且必须小于实际上下文窗口 |
| 思考模式 | Gemini 路线按已适配型号选择；Chat 路线不提供此思考配置 |

默认自定义上下文 `300000`、输出上限 `32000` 只是运行设置，**不是所选模型的实际能力**。实际型号较小时必须调整。当前表单没有温度配置。

6. 勾选“启用”，点击“保存模型配置”，确认没有字段错误或待核实请求。
7. 回到工作流，选中“模型来源”节点，在“全局模型配置”下拉框选择刚保存的条目，再点击“保存模型引用”。

同一型号可以保存多套命名配置。模型来源节点只保存引用，不在节点里重复保存 Key、容量或覆盖参数。每个新模型请求准备时读取当时已保存的全局配置；已经准备或发出的请求不会被追改。

**容量完整是保存有效模型配置、计算请求预算和正常发起请求的前提，不等于“所有输出一定能保存”。** 模型返回、Agent 最终答案校验、上下文写回和成功检查点保存仍是不同阶段，见第 7 节。

Gemini 只接受代码已经登记能力的型号及对应预算/强度；“上游能列出型号”不等于已经适配。可用时显示供应商返回的思考摘要，不是完整内部思维链；两条路线目前均非流式。

## 3. 搭一个能连续对话的 Agent 工作流

使用画布工具栏的“添加节点”或空白处右键菜单。当前最小示例可包含以下八个节点：

- 可编辑输入
- 提示词条目
- 模型来源
- 读取 Agent 上下文
- 上下文装配
- Agent 执行
- 写回 Agent 上下文
- 前端节点

按下表连接数据端口：

| 来源 | 连接到 |
| --- | --- |
| 可编辑输入 `output` | 上下文装配 `current_input` |
| 提示词条目 `output` | 上下文装配 `materials` |
| 读取 Agent 上下文 `output` | 上下文装配 `view` |
| 上下文装配 `output` | Agent 执行 `prompt` |
| 模型来源 `output` | Agent 执行 `model` |
| 读取 Agent 上下文 `output` | 写回 Agent 上下文 `view` |
| Agent 执行 `receipts` | 写回 Agent 上下文 `receipts` |
| Agent 执行 `result` | 前端节点 `content` |

还需要完成下一节的上下文权限和数据项选择，以及第 6 节的前端输入绑定。只连线并不足以授予数据权限。

选中“提示词条目”，填写任务正文，按该表单的保存按钮提交。例如：

> 将用户提供的中英混杂文段改写为自然的简体中文，保持原意，只输出改写后的正文。

提示词材料可配置角色、启用状态、进入上下文方式、精简许可、位置及顺序。“每次装配”会在每次装配时使用；“仅一次”按材料是否已进入上下文判重，不是独立的永久已用标记。

连线不兼容、单输入重复连接或循环会被拒绝；配置变化后失配的旧线会保留并标红，需要人工核对。节点“运行设置”中的前序节点只表达执行先后，不传数据，不能代替上表的端口连线。

## 4. 会话绑定与上下文读写

### 4.1 三步机制：登记、授权、选择

1. **登记数据项**：声明准确对象键、类型版本及登记节点。Agent 执行节点会自动登记自己的 `workflow.effective-context@4` 项。
2. **授权节点**：在该项的 `readers`、`writers` 中填允许访问它的节点 UUID。
3. **选择数据项**：进入消费者节点配置，在“会话数据项”下拉框中选择这个准确的对象键。

同类型可以有多个数据项，系统不会按类型自动取第一项。登记项存在不等于其他节点有权访问；连线也不等于授权。

### 4.2 绑定读取与写回节点

1. 点击画布工具栏“会话绑定”，打开“会话对象绑定”。
2. 在 JSON 中找到由目标 Agent 登记的项。其 `registrar_node_id` 是该 Agent 的 UUID，`type_id` 为 `workflow.effective-context`，`schema_version` 为 `4`。保留系统生成的 `object_key`，不要新建第二份上下文代替它。
3. 在面板下方或各节点“技术详情”中复制节点 UUID。
4. 将“读取 Agent 上下文”的 UUID 加入此项 `readers`；将“写回 Agent 上下文”的 UUID 同时加入 `readers` 和 `writers`。保留原有必要权限，不要整段覆盖其他登记项。
5. 点击“校验并应用到工作流”，核对保存结果及可能出现的派生确认。
6. 选中读取节点，在“会话数据项”中选此对象键；再选中写回节点，选择**同一个**对象键。

下面只展示权限关系，不可把占位符直接粘贴到配置中：

```text
Agent 登记的上下文项
  readers: [读取节点 UUID, 写回节点 UUID]
  writers: [写回节点 UUID]
```

写回节点既要读取原状态又要写入，所以需要双向权限。只给 `writers` 时，下拉框仍可能没有该选项。

当前页面中“更改仅保留在当前内存工作流中”的旧提示不代表正式保存行为：“校验并应用到工作流”已接正式配置提交。以实际保存结果为准；不存在额外的会话绑定保存按钮。

`shared` 也不是所有节点都能读写；仍需明确权限。`private` 只允许其 `owner_node_id` 对应节点访问，不要为共享上下文随意改成私有项。

### 4.3 读取快照与写回不是一回事

读取节点输出的是本次读取的一份值。会话数据后来改变，不会自动刷新已经产生的输出；需要新值时重新读取。Agent 负责计算并给出执行凭据，“写回 Agent 上下文”负责接纳这次上下文更新。

前端节点拥有自己的聊天数据项，与 Agent 的计算上下文不是同一个对象。页面能看到回答，不足以证明 Agent 上下文写回和整轮成功保存都已完成，要继续核对整轮状态。

## 5. 变量注册、赋值与引用

### 5.1 在当前会话主动注册

1. 从“变量”分类添加“变量注册”节点。
2. 填“变量名称”和“值类型”：字符串、整数、数值或布尔值。名称为 1 到 128 个字符，只能包含字母、数字或下划线，不能以数字开头。
3. 需要初值时勾“设置初值”，填写与类型一致的值；不勾时变量注册后仍未赋值。
4. 先按第 5.2 节配好其他节点的变量权限和引用，完成其余结构、上下文与前端绑定，等待配置正式保存，再在左侧“会话”点击加号新建当前修订的会话。
5. 选中变量注册节点，点击“注册变量及初值”，刷新并核对状态为“已注册，未赋值”或“已赋值”。

变量注册节点会自动登记自己的 `workflow.variable@1` 项，并配置自身的读写权限。**添加节点、填写初值或点击普通启动，都不等于已经注册变量。** 注册是当前稳定会话内的主动交互，不自动进入普通执行计划。

已有会话时若新增注册节点触发派生，应先确认目标新工作流，再为它新建会话。按钮提示“尚无当前修订的会话”时，先核对左侧工作流和会话修订，不要对着旧会话反复点击。

### 5.2 给使用变量的节点授权

1. 打开“会话绑定”，找到该注册节点提供的变量项。
2. 变量赋值节点需要同时加入此项 `readers` 和 `writers`。
3. “变量转内容”“替换指定变量”“替换全部变量”及读取该变量的世界书节点需要加入 `readers`。
4. 点击“校验并应用到工作流”，再到使用节点的“会话数据项”选择准确项；支持多项的节点明确多选所需项。

变量名、对象键、节点 UUID 是不同东西：变量名用于正文引用，`object_key` 用于选定存储项，UUID 用于授权某个节点。不要用名称代替权限列表里的 UUID。

### 5.3 赋值和替换

- “变量赋值”支持 `set`、`add`、`subtract`；加减只接受已赋值的整数或数值变量。
- “变量转内容”把所选变量转换为文本或 JSON，供下游节点使用。
- 正文中的变量标记采用 `{{变量名}}`。要实际替换，需把内容接入“替换指定变量”或“替换全部变量”，并明确选择已授权的变量项；不是所有提示词都会自动全局替换。
- “替换全部变量”指处理所选授权项可解析的变量，不表示可以读取整个会话中的任意变量。

变量未注册、已注册未赋值、值类型不匹配或授权范围内重名时会报错，不会偷偷补默认值。

重复注册同一对象、同名同类型不会重置它的当前值。修改节点初值也不是重置已有变量的方式，应使用明确赋值；更换名称或类型可能产生冲突。

普通新会话需要重新主动注册；检查点分叉会承接该点已保存的注册和赋值状态。变量属于已准入的检查点数据，但未登记的任意数据不会因此自动进入存档。

## 6. 前端输入绑定与发送

1. 确认图中有“可编辑输入”，其输出已接到上下文装配的 `current_input`。
2. 选中“前端节点”，在“输入节点”下拉框中选择这个可编辑输入节点。该下拉只接受当前工作流内适用的可编辑输入，不接受“当前输入”节点代替。
3. 等待绑定保存成功。前端节点的数据输入 `content` 仍需连接 Agent 的 `result`；输入绑定不会代替输出连线。
4. 为方便多轮输入，核对“可编辑输入”的配置模式为“可调”。选择“固定”时，已有有效会话后的输入修改需要确认派生工作流。
5. 在左侧选择与当前修订匹配的会话，然后点击“打开前端节点”。浏览器阻止弹窗时，允许此次打开后重试。
6. 在新页面核对工作流、节点及会话身份，输入短测试文本，点击发送图标，其提示为“保存并启动本轮”。
7. 等待本轮完成，再发送第二段文本。核对页面消息、运行状态以及需要时的会话上下文。

打开页面本身不创建会话或运行；尚未选择会话时入口可携带空会话身份，首次发送才进入实际创建/启动流程。需要预先注册变量的工作流，应先在工作台创建会话并完成注册，再打开绑定该会话的页面。

“立即保存输入”只保存输入，不启动模型。页面的输入更新机制只属于该前端节点；收到后端接纳前，不要把页面内存文字当成已保存。

前端入口绑定准确的工作流、修订、节点和会话。若出现“接续此绑定”或“确认派生”，先核对新目标，不要继续使用旧标签页向旧对象提交。工作台修改固定配置或切换会话后，建议从目标节点重新打开入口。

也可以使用工作台“本次输入”给“当前输入”等声明了外部输入的节点填写具名值，再点击“启动”。这是另一种输入方式，不代替前端节点的可编辑输入绑定；复杂字段保留在“高级 JSON / 未声明输入”中。

## 7. 固定配置、保存与检查点

### 7.1 固定和可调

节点配置通过正式配置入口提交后端，不需要寻找通用“保存整个画布”按钮。带有专用保存按钮的表单，例如模型引用、提示词内容，应点击对应按钮；普通字段修改后也应等待提交结果。

这里的“有效会话”指该工作流下任一尚未归档的会话，即使其中的运行已经成功、失败或结束。结束本轮不等于归档会话，也不会解除固定配置修改的派生要求。

- 没有有效会话时，配置可以在当前工作流保存。
- 有有效会话后，固定配置修改以及增删节点等结构变化需要确认派生为新工作流。原工作流与会话保留，新工作流不继承原运行数据。
- 只有已声明可调能力的节点/字段才可切换“固定/可调”；可调字段可原地保存，对后续准备生效，不改变已经准备或发出的请求。
- 运行中或暂停中的会话不能任意编辑结构和数据。以页面锁定状态、诊断及服务提供的可用动作为准。

### 7.2 不要混淆五个保存阶段

| 阶段 | 成功代表什么 |
| --- | --- |
| 模型配置保存 | 型号、容量及运行设置通过校验并保存 |
| 输入保存 | 当前输入已被后端接纳，不代表已经运行 |
| 模型返回与 Agent 终答 | 模型请求已取得结果，Agent 通过终答校验；当前 Agent 内置 `final_answer`，使用 `answer.text` 提交正文 |
| 上下文/聊天写入 | 对应节点已实际接纳数据更新，不是前端自行覆盖 |
| 本轮成功点与检查点 | 本轮实际完成并保存已准入状态，可用于后续分叉 |

因此，“模型返回了正文”或“前端已经显示一条消息”不能替代整轮成功检查。容量配置错误先修模型配置；终答、权限或检查点错误则按对应诊断定位。

前端页面“查看检查点”可选择已保存点，并使用“从此点创建新会话”。目标会话装载该点允许保存的状态，保留源会话不变，不自动执行模型。普通新建会话不是从检查点恢复。

页面还支持重 roll 和候选选择：同楼重 roll 使用轮前基准及首次接纳输入，成功候选会保留实际成功点；有下文的楼层不能在原分支随意换选或重 roll，需要楼层分叉。分叉不删除源候选，也不自动发起模型调用。

## 8. 全局提示词与 Lorebook

左侧“内容”可以保存全局提示词组和 Lorebook。它们是独立资源，不会因保存而自动加入现有工作流或调用模型。

全局提示词组保存后，在图中添加“全局提示词引用”，选择资源并保存引用，输出接“全局提示词解析”，再接上下文装配的材料端口。图内提示词与全局资源不是同一份表单。

Lorebook 可配置条目正文、常驻/关键词规则、扫描深度、概率和注入位置，再通过“全局世界书引用”“世界书触发”接入材料。使用变量的世界书读取仍需准确选择变量项并获得权限。

全局资源更新供后续读取使用，不会改写此前已加载的值或已发送请求。组可以复制为独立身份；缺失、停用的资源不会自动替换成其他资源。

## 9. 常见问题

| 提示或现象 | 检查与处理 |
| --- | --- |
| 模型配置不能保存，提示填写真实上下文、输入和输出容量 | 展开“真实模型容量”，三项都填实际正整数；选择上游型号不自动补齐 |
| 上下文长度超过真实模型窗口 | 调小自定义长度，或选择“真实模型窗口”；先核对所填规格是否真实 |
| 输出上限超过真实模型容量 | 本次输出不得超过实际输出上限，且必须小于实际窗口 |
| `model_request_capacity_exceeded` | 实际发送输入还须满足输入上限与输入加输出预留的总窗口限制；核对材料、历史长度及容量，不要只反复调大字段 |
| 会话数据项下拉为空 | 核对项是否登记、类型版本是否匹配，以及该节点是否具有所需 `readers`/`writers` 权限 |
| “当前键没有匹配的登记项和明确权限” | 不要仅手填对象键；先修会话绑定，再重新选择准确项 |
| 变量注册按钮不可用 | 确认配置已保存、变量字段有效，且当前修订有稳定可提交的会话 |
| `variable_not_registered` / `variable_unassigned` | 在当前会话主动注册；没有初值时再通过赋值节点写值 |
| 前端输入不可用或显示未绑定 | 绑定同一工作流的“可编辑输入”，保存后重新打开准确入口 |
| `HTTP 409 / stale_edit_sequence`，保存工作流配置被拒绝 | 页面编辑依据已过期，常见于另一个页面或外部操作修改了配置；先核对原请求结果，保留未提交文字，刷新工作台、重新读取并确认目标后再编辑，不重放旧请求 |
| 会话与已保存修订不一致 | 核对当前工作流、修订和会话；为目标修订新建会话，或回到对应旧工作流查看原会话，不强行重绑 |
| `invalid_final` | Agent 未通过最终答案校验，不等同网络失败；查看节点执行信息。当前内置终答工具要求 `{"answer":{"text":"正文"}}`，不应靠提示词绕过校验 |
| 原请求结果待核实 / 结果未知 | 点击对应“核实原请求”，保留原请求身份；不要连续发送、换 Key 或重放工具 |
| `failed_retry_unsupported` | 当前失败不支持原节点重试；先查诊断、修配置，再明确决定是否发起新的测试，不能把旧请求自动重发 |

结果查看入口：点击节点“状态与结果”；工具栏“统一登记目录”及节点“信息”可读可用的信息源；“会话绑定”下方可查看当前会话对象。模型正文、上下文、聊天数据与执行事实属于不同视图。

暂停不会撤销已派发的模型请求或工具，也不保证立即中断。结果接纳重试、归档重试与重新调用模型不同，只有服务明确提供动作时才能使用。重启也不保证恢复原进程活动内核。

工作流和会话可以归档或删除。归档历史只读，不恢复执行；删除不可撤销。遇到打不开、版本冲突或结果未知时，不要通过清空数据库、浏览器记录或密钥库来“修复”。

## 10. 费用与证据

普通本地编辑、保存配置和只读核实不派发模型；获取上游型号列表会联系供应商。显式启动、发送、重 roll 和上下文精简可能发起收费请求，一轮 Agent 也可能包含多个请求。输出上限或思考预算不是总费用保证。

使用短输入验证完整链路，保存错误码、节点和运行身份即可；不要公开 Key、完整请求头、数据库、私有正文或浏览器证据导出。停止服务不删除数据，也不撤销已发生的费用。
