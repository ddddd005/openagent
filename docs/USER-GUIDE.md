# 使用手册

本文面向第一次使用工作台的人，先说明能做什么，再带你走一遍无需模型的简单运行和一条 Agent 工作流。安装、启动及本机环境选择见[快速启动](QUICKSTART.md)。

**当前推荐配合 harness 使用。** harness 是能读取项目代码、调用工具的模型协作环境，不是工作台里的 Agent 节点。你可以先描述想完成的任务，让助手用通俗语言说明是否可行，再在确认范围内帮助配置、操作或排错；不必先读懂全部代码。也可以直接按本手册手动操作。开发与扩展的协作方式见 [Vibe Coding 手册](VIBE-CODING.md)。

版本说明：`0.5.0` 是当前目标，不代表已发布；前后端版本元数据仍为 `0.2.0`。本文描述当前代码中的使用方式，不是版本验收或发布声明。

## 1. 工作台与工作流

左侧有三个入口：

| 入口 | 用途 |
| --- | --- |
| 工作流 | 创建节点图、管理会话、配置初值、启动运行和查看历史 |
| 供应商 | 保存供应商凭据及可复用的模型配置 |
| 内容 | 保存可供工作流引用的全局提示词组和 Lorebook |

项目层把这三项能力装配进同一工作台和统一环境：工作流可以引用共用的模型配置和全局内容，但运行数据仍属于各自的会话。工作流是可复用的定义与配置；会话是该工作流某个固定修订下的一份运行数据；本轮是在会话内执行一次，同一会话可以连续运行多轮。

工作流借鉴 ComfyUI 的节点化构造方式：节点承担明确职责，连线把数据交给下游节点。Agent 是核心智能节点；提示词、模型、上下文、工具和结果展示可由其他节点配合。中间节点可以整理输入、补充约束或按授权读写会话数据，从而让一轮输出更符合预期。

理解工作流时可分成四类工作，但它们不是四个独立的导航页：

| 工作 | 你在做什么 |
| --- | --- |
| 定义维护 | 内置能力及已显式加载的节点包提供可用节点类型、输入输出端口和能力目录 |
| 配置 | 在“主流程”画布添加目录中可用的节点、连接端口、填写参数并引用全局资源 |
| 数据管理 | 管理会话、上下文、变量、预加载初值以及对象读写权限 |
| 执行 | 启动一轮、查看节点“状态与结果”、回看“运行历史” |

节点配置属于工作流。业务持久数据由会话数据层管理，节点通过已授权的接口使用它们，不各自建立一份业务仓库；部分节点也有由宿主管理的运行态，这不等于用户变量或新的业务数据源。数据项通过准确对象键、类型版本和节点权限控制；连上线本身不会授予读取或写入权限。

## 2. 先跑一个不调用模型的简单链

这条路径适合先熟悉画布和检查运行结果，不需要配置供应商或 API Key。

1. 在左侧“工作流”点击加号新建工作流，打开它的“主流程”。
2. 点击“添加节点”，加入“文本”和“输出”。
3. 把“文本”的输出连到“输出”的输入，填写一段测试文本。等待编辑被正式接纳。
4. 点击顶部运行按钮“启动”。首次运行可在工作流下创建会话并执行这张图。
5. 选中节点，在右侧“状态与结果”查看输出；“运行历史”可查看已完成轮次及其结果。

`文本 -> 输出` 不接模型。空工作流、单独保存配置或只打开前端页面都不会自动运行模型。若节点图还未连到有效输出，先补齐连线再启动。

## 3. 配置供应商与模型

需要 Agent 或“模型调用”节点时，先在左侧“供应商”完成两步，再回到工作流设置模型来源。

### 3.1 保存供应商

1. 在“模型供应商”旁点击“新增供应商”，填写名称、协议、服务地址；需要调用模型时，同时在密码框填写 API Key，并按需启用。
2. 点击一次“保存供应商”提交完整配置和 Key，确认保存结果。编辑已有供应商时 Key 留空表示保留原 Key。
3. 已保存供应商不能原地改协议；需要另一协议时新建供应商。

Key 保存在本机凭据存储中，与工作流业务数据分开。不要将 Key 写入提示词、节点内容、截图或文档。保存成功只表示本机配置已保存，不证明上游可连通或鉴权成功。

### 3.2 保存模型配置

在“模型配置”中新增配置，选择供应商并填写准确的模型名称。可手动填写，也可用“获取上游模型列表”；后者会联系供应商，上游列出型号不代表该型号已适配。

展开“真实模型容量”，按实际型号规格填写三项正整数：

| 字段 | 含义 |
| --- | --- |
| 实际上下文窗口 tokens | 型号支持的总上下文窗口 |
| 实际输入上限 tokens | 型号支持的输入上限 |
| 实际输出上限 tokens | 型号支持的输出上限 |

新配置这三项默认为 `0`，必须自行填写真实规格。另选“真实模型窗口”或不超过实际窗口的“自定义长度”，设置本次输出上限、压缩阈值；输出上限不能超过实际输出上限，也必须小于实际上下文窗口。表单默认运行值不是模型能力，不能代替真实容量。

思考设置仅适用于已登记能力的 Gemini 型号；Chat 路线不提供此设置。选好参数后启用并点击“保存模型配置”。回到画布，选中“模型来源”，选择这条全局模型配置并保存引用。模型调用目前非流式；一次 Agent 运行可能包含多次模型请求。

每个新模型请求在准备时读取当时已保存的全局模型配置；已准备或已发送的请求不会被后续配置修改追改。

## 4. 搭建 Agent 工作流

下面是带会话上下文和聊天前端的常见结构。先配置好上节的模型，再在画布“添加节点”中加入：

- 可编辑输入
- 提示词条目
- 模型来源
- 读取 Agent 上下文
- 上下文装配
- Agent 执行
- 写回 Agent 上下文
- 前端节点

把数据线按下面连接。控制边只表示前序等待，不能替代传递数据的连线。

| 从 | 到 |
| --- | --- |
| 可编辑输入的输出 | 上下文装配的 `current_input` |
| 提示词条目的输出 | 上下文装配的 `materials` |
| 读取 Agent 上下文的输出 | 上下文装配的 `view` |
| 上下文装配的输出 | Agent 执行的 `prompt` |
| 模型来源的输出 | Agent 执行的 `model` |
| 读取 Agent 上下文的输出 | 写回 Agent 上下文的 `view` |
| Agent 执行的 `receipts` | 写回 Agent 上下文的 `receipts` |
| Agent 执行的 `result` | 前端节点的 `content` |

提示词条目填写任务说明，例如：“将输入改写为自然的简体中文，保持原意，只输出正文。”要复用左侧“内容”中保存的全局提示词组或 Lorebook，还需在图中添加对应的引用/解析节点并接入材料；保存全局资源不会自动把它加入工作流。引用节点在读取时取得资源，后续修改不会追改已经装配或发出的请求；缺失或停用的资源也不会自动换成其他资源。

### 上下文权限

Agent 执行节点会登记自己的 `workflow.effective-context@4` 会话数据项。要让读取/写回节点访问它：

1. 点击画布工具栏“会话绑定”，找到 Agent 登记的准确对象键。
2. 在该项的 `readers` 中加入读取节点和写回节点 UUID；在 `writers` 中加入写回节点 UUID。
3. 点击“校验并应用到工作流”，然后分别选中读取和写回节点，在“会话数据项”中选择同一个对象键。

写回节点需要读取旧状态并写入新状态；缺少任一权限时，下拉列表可能不会显示该项。节点 UUID、变量名称和对象键用途不同，不可互相替代。

### 绑定聊天输入

选中“前端节点”，在“输入节点”中选择这张图里的“可编辑输入”，等待绑定保存。然后点击“打开前端节点”，核对页面中的工作流、节点和会话身份，再发送短文本。打开页面本身不创建会话或发起模型请求；前端发送按钮“保存并启动本轮”才会保存输入并开始一轮。页面显示回答不一定代表上下文写回和整轮成功点都已保存，必要时回工作台查看运行状态与历史。

多轮聊天需要更换输入时，将“可编辑输入”的配置模式设为“可调”；选为“固定”后，在已有有效会话时修改该输入会要求确认派生工作流。

## 5. 会话初值、变量注册与引用

推荐用“会话预加载数据”为普通新会话准备初值：在工作流顶部打开“会话预加载数据”，选择类型，设置对象键、初值和节点权限，再经工作流配置保存。每个新会话创建时初始化一次；工作流之后的初值修改不会同步或重置已有会话。复制工作流会复制预加载配置，但不会复制已创建会话的值。详细类型限制见[会话预加载数据说明](SESSION_PRELOADS.md)。

同一会话也可通过“变量注册”节点主动注册变量。这是专门的会话交互流程，适合需要显式注册后再赋值的图：

1. 从“变量”分类添加“变量注册”，填写变量名称、类型和可选初值。
2. 在“会话绑定”中授权将使用它的节点：赋值节点需要读写权限，替换或读取节点需要读取权限；再在这些节点的“会话数据项”中选择准确对象。
3. 创建或选择与当前修订相符的稳定会话，选中注册节点并点击“注册变量及初值”。只有确认已注册后，其他节点才能使用它。

正文中的 `{{变量名}}` 不会自动全局替换；需连接“替换指定变量”或“替换全部变量”，并明确选择授权的数据项。没有初值的已注册变量与值为空字符串、`0` 或 `false` 是不同状态。

预加载和注册节点是两种初始化路径，不要让它们同时负责同一个对象键。新会话如需固定初值，优先考虑预加载；普通新会话不会继承旧会话的变量或聊天历史。历史分叉则从检查点恢复已保存状态。

## 6. 复制、固定配置与检查点

- **复制工作流**：工作流顶部点击“复制工作流”。副本有独立身份，只包含工作流配置和预加载定义，不带源会话、会话数据、运行历史或检查点。
- **固定配置修改**：工作流有未归档会话时，修改固定配置或节点结构会要求确认派生为新工作流。原工作流和会话保留，新工作流不继承运行数据；只有明确可调的字段才可原地调整。完成一轮不等于会话已归档。
- **检查点分叉**：在前端节点页面点击“查看检查点”，选择“从此点创建新会话”。分叉保留原会话，载入该历史点已准入并保存的状态，不会自动重跑模型，也不重新应用预加载初值。普通“新建会话”则按当前配置初始化新会话。

每轮运行会经过本轮准备、整图执行、业务结算、提交后通知、结束释放五个整体阶段。这是运行生命周期，不是节点排列顺序；节点间数据边和明确设置的前序关系才决定图内依赖。

## 7. 保存与故障

没有通用的“保存整张画布”按钮。供应商、模型配置、提示词等表单有各自的保存动作；画布编辑通过正式工作流配置流程提交。创建会话或启动前，等待顶部“配置尚未正式接纳”状态消失并核对当前修订；普通编辑可能不会逐次显示成功浮窗。

查看问题时先选中相关节点的“状态与结果”，再看工作流“运行历史”。历史会记录本轮使用的固定修订、节点结果和诊断；不要用当前画布内容替代旧运行依据。

常见处理：

- **模型容量或上下文预算错误**：核对真实上下文窗口、输入上限和输出上限；删减提示词或历史，不能只把运行长度调大。
- **会话数据项未显示或拒绝读写**：在“会话绑定”检查对象键、类型版本及该节点的 `readers` / `writers` 权限，再回节点选择准确数据项。
- **`invalid_final`**：Agent 最终答案未通过校验；查看节点诊断并修正 Agent 输入或流程，不把它当成网络故障。
- **请求结果未知或显示待核实**：在“工作流原请求”面板点击“再次只读核实”或相应的“核实原请求”。这只核对原请求结果，不会重发；确认旧请求前不要再次提交同一业务操作。
- **修订与会话不匹配**：切回该会话所属工作流/修订，或按页面提示确认派生并新建会话，不强行把旧会话绑定到新定义。

归档用于保留只读历史；删除工作流或会话会删除其关联运行与历史且不可撤销。运行中或有待核实请求时，相关归档、删除和编辑操作会受界面锁定；暂停不会撤销已派发的模型请求或工具，也不保证立即中断。遇到未知状态时不要清空数据库、浏览器记录或凭据存储。

## 8. 费用与能力边界

编辑、保存工作流配置、创建普通会话和检查本地运行结果本身不会调用模型。获取上游型号列表会联系供应商。启动包含模型节点的轮次、Agent 的工具往返以及上下文精简可能产生一次或多次收费请求；输出上限或思考预算不等于费用上限。用短输入验证流程，并查看实际供应商账单。

普通节点不会自动成为 Agent 工具。当前仅支持明确适配的纯计算工具及既有变量操作；要使用本地工作流包，需按准确版本手工放置并显式启用，且包内 Python 是可信代码，不提供沙箱。完整边界与操作见[手工工作流包说明](WORKFLOW_PACKAGES.md)。
