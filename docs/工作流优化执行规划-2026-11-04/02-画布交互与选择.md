## 1. 进入条件与目标

进入条件是第一步已交付可等待的编辑结果与准确的锁反馈。本步让连线、选择和删除表现与实际修改结果一致，不再由组件自行把“请求已发出”推断为“修改成功”。

Q04 先确认点击连线是否保留、Esc/空白/非法目标行为及节点/边混合选择规则。本规划不直接选择“仅拖拽”或“统一混合选择”架构，也不顺带增加 reconnect、自动替换输入等新功能。

### S2-00：确认可见规则

至少给出以下动作的明确结果：单击句柄、拖拽句柄、Esc、点空白、点节点/边、点击非法目标、拖拽到空白松手、切换工作流、修改进入锁定。

混合选择应另列决定：若保留节点与边同时选中，删除前应有可理解的目标集合；若采用互斥选择，所有添加、定位、事件选择路径都应遵循。不能只在垃圾桶入口修掉一条旧边，而漏掉 Delete 和撤销/重做路径。

### S2-01：连线与消息

1. 若决定保留点击连线，应纳入应用观测、提示和取消；若决定关闭，应验证单击后的 `click` 不再留下隐性 pending。
2. 拖拽取消须验证底层连接行为真正结束或被明确阻止，不能只清本地 `connecting` 就宣布取消。
3. 验证 Esc 后再松鼠标不会建边；取消后的下一次合法连线可以正常开始。
4. 完成、取消、空白松手和工作流切换时清理相应消息；非法目标按确认规则反馈，不能遗留“可连接”。
5. 提交失败使用第一步的真实结果。不能在 `onConnect` 收到事件时就永久清掉失败所需上下文。
6. 使用已安装版本的公开接口，核对其实际覆盖。`endConnection(undefined, true)` 不能单独证明拖拽闭包已取消。

不编辑 `node_modules`，不以升级 Vue Flow 作为默认前提。确需依赖变化时先说明原因、影响及最小方案。

### S2-02：选择和删除

核对添加、定位、节点点击、边点击、框选、删除、撤销/重做和正式文档重新接纳后的选择。对已不存在的身份统一修剪，但不能清掉用户在等待期间转到另一视图的新选择。

删除依然在同一份文档中完成节点及已支持引用的级联，再一次提交；原实现不是“先删节点渲染、后删边”。本步只修选择与提交反馈，配置引用和替换旧边的业务策略留给第三步。

明确失败时按第一步约定保留选择及编辑上下文；成功时才清理本次目标。无目标/无变化/锁定拒绝应有确定含义，不进入无限等待。

键盘处理要核对焦点和默认动作：编辑器输入中的 Delete 不删除节点；Esc 对弹层与连线的优先级按确认规则执行；一次按键不触发两套互相冲突的动作。

### S2-03：组件整合

`GraphWorkbench.vue` 同时包含连线、选择和键盘。其整合负责人先接收 S2-02 的 store 约定，再统一接入组件，处理 `mousedown`、`mouseup` 和随后 `click` 的事件时序。

若组件执行者为了连线修正需要变更选择入口，先与 store 执行者同步，不自行增加另一套长期选区副本。

## 5. 出口检查

| 场景 | 关键观察 |
| --- | --- |
| 单击句柄后 Esc/空白 | 按选定规则取消或没有进入待连线；下次点击不凭空连边 |
| 拖拽中 Esc，随后松手 | 不产生边；再次拖拽可成功 |
| 非法目标、空白松手 | 不保存非法连线，提示正确收尾 |
| 选边后添加或定位节点，再 Delete | 删除范围符合决定，没有残留旧选边造成的误删 |
| 删除成功/明确拒绝 | 画布、选区、历史和反馈与正式结果一致 |
| 撤销、重做、外部接纳 | 选择不保留不存在身份，迟到结果不影响其他视图 |
| 修改在途及切换工作流 | 入口禁用或拒绝一致，旧连接状态不带到新图 |
| `receipts` 起线与保存重载 | DOM 起点、边的端口身份和画线位置一致 |

取消行为必须有真实浏览器交互证据。SSR、事件桩或只检查应用变量不足以证明 Vue Flow 松手后不会建边。C01 的历史验证只能说明此前修复，不能替代本步改动后的实际检查。
