## 1. 目标与进入条件

进入条件是前三步约定目标已实现并验证，修改结果、保存边界和诊断能够解释。本步以新测量找出真实重复工作，再精简保存协议、历史读取和前端重复查询。

Q07-Q10 分别约束证据保全、坏历史处理、读取新鲜度与精简范围。测量和使用面核对可先进行；改变契约或删除内容须先取得对应决定。

不以删代码量作为验收，不把现有证据/幂等/版本/投影一律认定为冗余。

## 2. 成本基线

既有代码计数：已初始化的正常画布配置保存经过五次串行请求；管理命令正常一轮为六次证据调用加一次业务请求，其他初始化/结果核对还可能增加读取。这是原实现的代码计数，执行时应重新核对。

历史测量中的库容、103 次保存、44 个修订、单次载荷和纯解析耗时，只作线索。本步不得以这些数字代替前三步完成后的新基线。

| 场景 | 必须分开记录 | 指标 |
| --- | --- | --- |
| 展示修改 | 不产生 fixed 修订的保存 | 请求次数/字节、验证次数、事务耗时、前端锁窗口 |
| 可调/固定修改 | 有无 fixed 修订写入、有无有效会话 | 历史读取次数、实际保存结果、锁窗口 |
| 无变化/拒绝/待确认 | 不能和成功写入混算 | 请求数、是否写入、反馈时间 |
| 结果未知与结案失败 | 不按正常路径推算 | 核实读次数、保全内容、可用动作 |
| 轮询与历史面板 | 闲置/运行、同会话/切会话、链修订变化 | 查询数、响应体积、冻结定义重复读取 |
| 管理命令 | 本批实际涉及的命令 | 证据调用和业务调用分别计数 |

优先使用临时库、固定大小的图与可控 API 夹具。不同历史规模采用相同文档和机器条件，报告数据集大小、轮次和测量范围；不要为本次优化默认读取或修改用户业务库。

没有隔离 HTTP 环境时，可先做应用层计数和纯函数测量，但须明确其不包含网络、服务调度和实际前端等待，不能据此宣称端到端提速。

### S4-04：限定范围的冗余核查

可以核查退役状态字段、旧草稿/保存路径、重复校验或投影，但每个候选都需列出：

1. 全部仓内读写、测试与导出入口。
2. 已知仓外或将被外部 Agent 复用的用途；未知使用面需如实标注。
3. 与现行契约、证据和历史记录的关系。
4. 确认保留行为由哪项当前检查覆盖。
5. 拟精简的准确文件/符号，以及不属于本批的内容。

“前端零调用”“已被另一路替代”或“旧测试仍引用”都不是单独的删除依据。使用面不能确认的候选保持现状并记录，不以扩大清理范围完成阶段。

## 5. 出口与失败判定

必须交付优化前后同口径的指标，说明改善发生在哪一段。新测量不能沿用旧库快照数字，也不能以解析时间代替实际等待时间。

除变快之外，至少检查：

- 正常、明确拒绝、未知结果、业务已确认但投影/结案失败仍可解释。
- 原请求和历史事实按确认规则保全；不存在自动换 key 或自动覆盖新基线。
- 无变化/待确认不产生多余正式修改。
- 坏历史按 Q08 处理；没有把应显式报错变成静默忽略。
- 其他会话按 Q09 更新；迟到响应不覆盖当前视图。
- 冻结定义按准确身份读取；C01 和必要的第二步交互未退化。

若没有测得明确收益，或者只能通过未批准的保全/历史变化获得收益，应记录结论并停止该项优化，不堆叠兜底或隐式恢复。进入第五步前汇总前四步实际完成范围与仍保留限制。
