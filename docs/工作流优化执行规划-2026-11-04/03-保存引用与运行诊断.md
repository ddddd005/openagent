### S3-00：先分清四种情况

| 情况 | 当前理解 | 决定方式 |
| --- | --- | --- |
| 正常未接完输入的图 | 允许保存，暂不可执行 | 保留现行能力，不升格为保存错误 |
| 普通边指向不存在节点 | 保存端点存在性缺口 D01 | Q05 决定是否成为保存硬约束及错误定位 |
| 删除/替换后配置引用、对象键或端口失效 | 节点声明及对象访问语义各异 | Q05 用具体图例决定提示、阻止、保留待修复或限定清理 |
| 保存成功但编译/准备不满足 | 保存与运行是不同判断 | Q06 决定如何反馈及是否扩展预演，不默认阻断保存 |

引用处理必须依据节点声明与真实访问规则，不能按字段名猜测并自动擦除 `node_id` 或 `object_key`。

### S3-01：保存、引用和契约

1. 若 Q05 确认普通边端点为硬约束，在正式保存入口与相应前端边界对齐；错误至少能定位具体边及缺失目标。
2. 明确删除时哪些引用在同一份文档中处理。保留现有控制边、事件目标、对象绑定和预加载的同批一致性，不拆成“先删节点保存，之后再补边”。
3. 替换节点不猜端口映射。保留旧边、清理失效边或阻止替换依 Q05 执行，并说明对已有图的影响。
4. 对齐当前 schema 的校验时机。生产 schema 3 不是完全没有校验，本步解决迟到失败和定位问题，不能用另一份手写大校验器制造漂移。
5. 整理完整文档字段、限制、版本语义、配置分类、派生结果与错误说明，优先复用应用描述和节点目录的既有信息源。
6. 如确需机器可读 schema 或预演查询，先给出承载与维护责任，经 Q06 决定后实施。旧报告建议的接口名和字段集合不是既定设计。

结构检查、编译可执行性与实际运行资源检查应分别说明。预演即使成功，也不预留保存权；提交时 CAS/G21/资源检查仍执行。

### S3-02：运行占用和失败阶段

按实际路径区分保存校验、编译、准备、节点执行、结算/归档等失败。诊断字段和位置格式按 Q06 确认，不在此新增一套全系统错误模型。

重点落实：

- 准备失败可能没有 chain/node_run，调用方必须保留并显示本次错误响应，不能只跳转空历史。
- 有节点、边、端口、字段路径或期望/实际类型的已知信息，按确认契约保留；不虚构缺失上下文，不泄露凭据或整份敏感请求。
- G21 按同一定义的全部会话 active 占用判断；失败/暂停不意味着可编辑。若现有响应不足以定位占用，提出最小补充。
- `close` 是关闭链、节点和相关记录的正式控制，不等于清一个界面锁；只在允许状态及授权下提供动作。
- 关闭一条链后仍可能有其他会话占用；会话未归档时 fixed 修改仍可能要求派生。反馈不能承诺“关闭后一定原地可改”。

不自动 close，不自动恢复/重试，不把错误呈现任务扩大为运行生命周期重构。

### S3-03：前端消费

前端与后端共用确认后的含义，展示时至少区分：保存成功、待派生确认、结构不合法、可保存但不可运行、陈旧基线、修改忙、运行冻结、准备失败和执行失败。

错误定位应能关联实际节点/边/字段；目标已不存在或用户切图时保留错误文本和原目标身份，不跳到无关对象。

如使用 `definition.inputs`，同时检查 `diagnostics` 与 `required_for_run`。HTTP 200 或查询完成不代表编译成功；该查询不覆盖全部保存与运行前置条件。

## 5. 出口检查

| 检查 | 应有结果 |
| --- | --- |
| 缺必需输入的未完成图 | 仍可保存；运行受限原因可见 |
| 悬挂普通边 | 行为严格符合 Q05；若硬拒，事务无部分配置写入 |
| 删除被引用节点、替换失效端口 | 按确认策略处理；不发生猜字段清理或隐式端口迁移 |
| schema 3 非法编辑 | 反馈可定位，不宣称该 schema 无校验，也不掩盖真实后端拒绝 |
| 当前文档与固定修订 | 编辑基线和历史事实不混用 |
| 200 加编译诊断、准备失败无运行记录 | 不误判成功；原响应仍可用于定位 |
| active/failed/paused 及多会话占用 | 不绕过 G21；显示真实限制 |
| 已授权 close | 只在可用状态执行，明确正式后果，不承诺清掉全部会话占用 |

本步向第四步交付：当前保存/编译/运行边界、已确认诊断格式、原请求保全和历史准确性要求，以及实际验证记录。未被确认的新增预演或诊断扩展不得假记为已实现。
