# 交接与并发派工

日期：2026-11-04。本文件用于后续代码执行组织，本次没有发起代码实现任务。

## 1. 推荐执行方式

建议每步由一名负责人统一决定记录、契约样本、文件归属和出口，配合两至三条独立任务。并发数量以实际文件独立程度为限，不以保持执行者满载为目标。

大步骤串行。单步内部采用“先核对/定边界，随后并发实现，最后串行整合与验收”。下一步的必要材料可在本步出口整理，但不提前安装后续业务改动。

无需为本规划新建调度器、分支策略或多套契约。使用现有协作方式；若执行者共享工作树，同一文件不得同时写入。

## 3. 高冲突文件的写入归属

| 文件或区域 | 建议归属 | 其他执行者如何配合 |
| --- | --- | --- |
| 前端 `stores/workflowGraph.ts` | 每阶段指定的一名前端/store 执行者 | 提交所需入口/返回样本，由负责人或文件所有者整合 |
| 前端 `GraphWorkbench.vue` | 第 2 步连线/组件执行者；其他步骤重新交接 | store/诊断执行者提供修改要求，不同时写组件 |
| 前端 `application/workflowConfiguration.ts` | 第 1 步前端、第 4 步协议执行者 | 等阶段完成且文件释放后转交 |
| 后端 `graph_service.py` | 第 1 步后端、第 3 步运行执行者 | 保存/预演需求由唯一所有者接入 |
| 后端 `graph_store.py` | 第 1 步后端、第 4 步历史存储执行者 | 证据任务涉及公共存储函数时串行协作 |
| 后端 `graph_contracts.py`、`workflow_configuration.py` | 第 3 步保存/引用执行者 | 运行和前端基于固定契约样本消费 |
| 后端公共诊断和应用声明 | 第 3 步波次 A 指定的一人 | 其他任务先提出字段/操作差异，避免各自扩协议 |
| 测试文件 | 随对应行为指定唯一负责人 | 验证执行者可独立设计场景；共享测试文件也不得同时写 |
| 本目录阶段状态与决定记录 | 执行负责人 | 各任务提交实际结果，由负责人集中登记 |

此表是执行组织，不是永久代码所有权；接手时以最新实际文件和任务范围重新确认。具体代码入口的绝对链接见各步文档。

## 4. 什么时候不能并行

- 后端结果/错误格式还在变化，而前端已按另一份猜测实现。
- 两条任务要修改同一状态机、同一公共类型或同一文件。
- 后端尚未明确事务完成时点，前端却准备新增自己的“成功”判断。
- 删除引用策略未决定，就同时做后端硬拒与前端自动清理。
- 证据保全未决定，就一边删读写、一边改未知结果核实。
- 需要改同一条浏览器检查或启动同一测试服务，并行会争端口/状态。

遇到这些情况，把共享部分交给一名执行者，其他任务继续独立核对、准备夹具或处理不依赖部分。不能通过复制状态、重复接口或临时兼容层来强行并发。

## 5. 负责人派工模板

每次领取一条任务时至少给出：

```text
任务：Sx-xx，具体目标和问题编号
当前阶段：第 x 步；前置任务/决定的实际记录
已确定行为：本批允许改变的结果
待定边界：不能自行选择的事项
责任文件：允许写入的准确文件
共享文件：唯一写入者及整合方式
交付接口：输入/结果样本或被依赖的方法
验证：相关行为检查、临时库和命令范围
限制：保留用户改动，不启停现有服务，不调用真实模型
结果：实际修改、实际检查、未完成项和释放文件说明
```

需要用户决定时，应提交具体差异、理由、影响范围与最小选项。已确定的串行修改方向和执行顺序不重复询问。

若使用子代理，执行负责人负责控制权限和文件边界，不以子代理的总结代替检查。用户后续授权的是代码执行方及其具体任务，本次文档派工模板本身不启动执行或授予额外操作权。

## 6. 各步交接包

| 从哪步交出 | 至少包含 |
| --- | --- |
| 第 1 步 → 第 2 步 | 可等待的返回语义；锁原因与释放时点；选择/历史何时更新；失败与未知状态处理 |
| 第 2 步 → 第 3 步 | 连线/选择规则；删除目标计算；组件与 store 责任；真实取消及坐标回归证据 |
| 第 3 步 → 第 4 步 | 保存/编译/准备边界；引用策略；诊断契约；G21 与控制限制；保全与历史要求 |
| 第 4 步 → 第 5 步 | 内部实际能力清单；新测量结果；保留接口；已确认未知结果规则；仍存在的限制 |
| 第 5 步 → 使用方 | 实际接入方式与权限；完整调用示例；错误和未知结果处理；运行/控制授权边界 |

每次交接同时给出已释放的文件和尚未完成事项。以 06 中实际记录为准；未决事项不得因文档流转自动变成批准。

## 7. 给代码执行方的起始说明

先读 README、00、01 和 06，记录当前工作树并开展 S1-00。先提交 Q01-Q03 中仍需决定的具体范围，同时准备不依赖这些决定的调用链核对与行为场景。取得相关决定后并行推进后端和前端，完成 S1-04 再进入第二步。

后续每步遵循相同方式，不从最后的外部 Agent 包装开始，也不把本目录当作要求一次性重构整个项目的授权。
