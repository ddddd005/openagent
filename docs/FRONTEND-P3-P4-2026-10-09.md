## P4：凭据与模型

新增管理专属 `credential.protection/status/receipt`、`credential.save/delete` 及 `provider.models.list`，不开放消费端或模型工具权限。

私有库为 `<public database>.credentials.sqlite`。Windows 使用当前用户 DPAPI，并绑定原私有库路径；无系统保护时不降级为明文。保护失败或无法解密不报告凭据可用。公开 provider 只存不透明 `local:<UUID>` 或原环境引用；新增 data schema 3，原 schema 1/2 声明不重定义。

Key 正文仅在密码组件内存及一次秘密提交中出现。通用草稿只保管非秘密原请求身份，秘密 mutation 不进入普通资源 outbox 或公开应用身份存档。私有回执用受保护 HMAC 依据核实同一请求；前端严格校验回执、目标和接纳状态，未知结果不重发 Key。核实旧回执后重读当前代次，不把已发生轮换/删除当成原 Key 仍有效。

Key 保存与供应商绑定分开确认。输入未提交时不承诺切换后恢复；原请求未知、回执缺失、清理失败或记录不兼容时保留锁定。迟到响应不绑定到另一表单上下文。运行准备后轮换或删除 Key 拒绝后续派发，包括以相同 Key 正文重新保存；已经发出的上游调用不能据此撤销。

模型列表只使用已保存供应商身份及 update sequence，在后端携带凭据。禁止跨域重定向、隐式重试和代理环境；限制超时、10 页、总响应 1MB 与 1000 型号，错误不携带上游原文。请求前后核对供应商与冻结凭据。Gemini 按 `generateContent` 过滤，未知型号标为未适配；列表缺失容量仍须手填，输入/输出上限不相加伪造总窗口。

酒馆面板可选 Chat/Gemini，采用当前图唯一有效或明确选择的模型配置，或明确创建待配置流。两条路线保留完整 12 节点：Chat 使用 `models.source@2` / `agents.execute@4`，Gemini 使用 `@4` / `@8`；不新建执行器，不自动运行模型。
