## 3. 当前共同边界

### 3.1 成功存档、当前数据与进度

成功检查点只保存已规定的回合结果，并提供固定恢复起点。当前输入、未发送内容、节点当前状态及运行中进度由节点、数据层和 runtime 各自维护；之后的交互不修改旧存档。

39规定只保存两类内容：节点明确注册、合规且允许保存的业务内容；数据层中合规注册的上下文、变量和其他节点内容。不另建once台账、通用计数平台或核验证据包，once装配时依据当前上下文检测。未注册保存数据的默认处理和初始点时点仍需最小具体收敛，不原样安装31/35全面reset。

检查点是历史回溯唯一权威，Head不另维护第二份不同含义的成功状态指针。对象、变量、session及Head的正常CAS不作为历史业务值倒退，恢复不覆盖工作流当前可调配置。

内部 KernelCheckpoint 仍是同进程执行继续现场，不变成成功存档，也不因此次方案增加进程外自动续跑。

### 3.2 检查点与正常执行事实

同工作流历史新会话拷贝整份规定历史检查点，拥有自己的检查点和当前状态，与原会话独立变化。相同节点结构和身份不做映射、替换或跨版本迁移；不依赖源current/Head、旧产物来源链、跨会话history membership或历史模型事实重建。

原执行和请求事实只承担正常运行、结果核实及诊断等既有职责，不作为检查点复制和恢复前置材料。已发送请求不追改，未知请求不自动重发；正常保存、发送及接纳仍检查真实身份、格式、权限、CAS和结果。检查点之外不规范历史不做兼容、补救或额外恢复。

正常公开数据权限、private Key保护不因取消历史追证而放宽，不开放任意UUID事实查询。这里不建立另一套历史恢复权威；30/38及随后暂停的相关源码仍在tree，未因本次文档同步被删除。

### 3.3 输入保存、发送和聊天投影

每个后端节点绑定自己的前端实例；复制节点新身份、新实例绑定。共享提交/组件代码不共享owner或业务状态，原集中映射不是所有节点唯一owner；跨工作流、节点和会话的迟到结果仍只归原对象。

200ms 自动通信接纳后的未发送输入是后端节点正式数据，不是浏览器草稿，也还不是一条已发送用户消息。全局资源及私有 Key 的保存节奏不受此规则改写。

初期固定/可调按钮只在单条提示词节点内部由注册机制提供，不扩group。固定修改存在未归档会话时，由后端先判需派生，前端询问，同意后才写/derive；拒绝不写、不造新流。原流和会话不改，新流不继承历史，现未安装基础的自动derive必须改。

发送消费已接纳的准确输入版本，保留原正文及不重复创建同一条用户消息的行为。普通运行通过明确读取取得这一输入，生成本轮正式产物；不能把先前交互产物伪装成本轮已执行producer。聊天追加和后续重来复用已接纳输入，不因新执行再插入同一条用户消息。具体身份字段、引用和消息关联在最小契约中收敛，原提案的`input_id/entry_id`不能登记为本轮已批准字段。

手工会话/运行数据编辑的运行中禁令保持；工作流可调配置及全局资源的独立修改不能被会话 can_submit 一概锁死。具体输入调用在何种状态可写、发送读哪个版本，由 32 的权限及顺序契约明确。

### 3.4 runtime 与成功收尾

普通执行范围、非工作节点排除、孤立节点排除及同批顺序统一由 runtime 处理。依赖优先；创建序号只排序，不改变 UUID 身份，也不从 rowid、时间戳或页面数组当前位置推测。

A/B 上下文和聊天按真实输入依赖及 runtime 顺序分别接纳，不强制跨业务写回先序。真实助手闭合凭证是成功条件之一；仍需所有计划工作节点和必要写回接纳后，服务才能原子形成成功检查点、消息关联、Head 及 chain 成功状态。页面显示文字不能代替该凭证。
