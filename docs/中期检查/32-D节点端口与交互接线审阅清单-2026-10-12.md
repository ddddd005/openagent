这里推荐普通聊天回合以一个 append 2 原子处理 U/A；不是规定所有工作流只能有一个追加节点。三个来源口均可选，但实际调用须至少提供一种来源；user_input 与 content/model_result 的身份和角色分别验证，不能仅凭前端自报 role 制造助手事实。close_round 的准确唯一助手来源还须与实例固定映射及实际图输入一致。需要多个追加节点时，前一个 `view` 直接作为下一个的实际数据输入；升级后的 view 验证支持准确已接纳 read/append lineage，不用“上一个写者 -> 再造 reader”的控制边补线。没有依赖的同对象写者仍由 runtime 顺序执行、数据层按真实 basis/CAS 接纳，冲突直接报错。

非工作节点不能靠普通数据边提供本轮产物。instance/input 的映射是注册 config_node_references，不是 graph data edges；上述 work reader 才进入普通图。现 [graph_records.py:304](../../backend/src/phase1_agent/graph_records.py#L304) 要求 live input_refs 对应同 chain、已成功的实际上游 producer，必须继续保持，不能删掉 non-work 的执行后用旧 artifact 冒充本轮 producer。

旧提案曾把 `frontend.instance` 的逻辑身份设为 `(workflow_definition_id,node_binding_id,workflow_session_id)`，并以集中映射组织输入/展示。39要求这组归属约束适用于每个节点自己的实例，不能只给集中节点一个owner而吞并其他节点。通用 JS/Vue 代码和本机 HTTP 宿主可以复用，实例及业务状态不共享。`frontend_kind` 不是服务端 TCP port；页面通信生命周期也不是跨节点或跨会话业务owner。

function mapping 的受信目标、权限和非任意函数调用原则可复用，但具体字段与入口仍待收敛。固定映射变化若存在未归档会话，按39必须由后端判需派生、前端确认，同意后才写入；旧自动派生不能视为合规。实例查询由后端返回实际动作和回执，不由前端 can_submit 代替权限。

## 4. 历史注册与记录版本提案

本节runtime行为方向中与28一致的部分保持；traits1、manifest5、binding3/definition3等具体声明与版本只是旧提案，不是现已批准的安装契约。

当前 `NodeDefinition` 没有 work/non-work 或 interaction 操作声明，[graph_contracts.py:306](../../backend/src/phase1_agent/graph_contracts.py#L306)。当前 compiler 从 output/root 的祖先做 DFS，target 按 UUID 排序、控制边按 edge UUID 排序；并仅因共享对象读写而强制先序，见 [graph_contracts.py:600](../../backend/src/phase1_agent/graph_contracts.py#L600)、[671](../../backend/src/phase1_agent/graph_contracts.py#L671)、[749](../../backend/src/phase1_agent/graph_contracts.py#L749)。这不是 28/29 的最终 runtime 规则。

推荐注册增加一个最小 `runtime_traits` schema 1 声明，按精确 component_id/version 归所属包，包含 `execution_class: work|non-work`、精确 interaction_operations、需要的 checkpoint projection 声明。作为现 package/node registry 的版本化附属声明核对，而不覆盖未改变节点的原 NodeDefinition；manifest/catalog/export 校验相应增加准确声明（推荐 manifest schema 5），不新建能力平台。普通工具和 Lorebook 保留原节点契约版本也要有明确 work 声明；不能默认页面类别文字就是调度类别。修改端口/业务契约的节点用上表新版本，不能原版本覆盖。

runtime 对普通运行统一做三件事：排除 non-work，排除无任何上下游数据/控制连接的孤立节点，按实际连接/输入依赖确定范围和就绪顺序。非工作节点的显式操作独立于普通连线，但复用应用 command/receipt、节点配置/权限及数据事务，不另建执行引擎。普通运行的 roots/targets 选择必须纳入有上游、无输出的工作写者；不能继续仅沿输出逆查而漏掉 side-effect sink，也不能让 root 绕过孤立排除。需要依赖 non-work 普通输出的连接直接报契约错误。

成功、暂停及模型请求仍由现 runtime 管理。变量注册不会作为自动初始化例外；assign 执行器只处理值和写入，不计算“是否孤立/是否激活”。Lorebook 只读取实际执行时有权限的值。退出共享对象键推导先序门禁，保留真实数据/控制依赖、缺失输入、类型、循环、ownership、权限及 CAS。

创建序号推荐复用 **definition-owned 的服务器元数据**：node_binding 记录由 schema 2 升 3 保存 `creation_sequence`，workflow_definition_revision 记录由 schema 2 升 3 的服务器包络保存 `next_node_sequence`，不另建独立排序表，不放进业务 config/current adjustable/checkpoint。记录新 schema 应与图 schema 3 配置消费者一起审阅；GraphCompiler 取得对应固定 revision 的可信序号映射，页面只能查询显示。这里仅建议升级被改变的记录，未改变的 node_definition 不跟随改号，也不从旧产品记录补算序号或建设迁移读取。

对比：现 node_binding 已拥有 workflow/revision/node UUID 和不可变固定声明，随新 record schema 保存序号可直接核验历史；独立排序表会再多一组一致性关系，首版不建议。现 rowid/created_at 不是创建业务顺序，不能事后推测。

- 正式自动创建时后端分发序号；一批新节点按该次完整 document 的新节点出现顺序确定，回执返回实际序号。请求未被接纳前页面只能显示临时状态。
- 既有节点 UUID 在同流保持序号；复制一个节点使用新 UUID 和新序号；删除留出空位、不回收序号、不允许拿已退役 UUID 冒充新节点。

## 5. 200ms 输入、提交和准确发送值

推荐以现应用通道新增精确 `node.interaction.call`，请求含 workflow/fixed revision/session/node/operation、expected input/session basis、原 idempotency_key 和严格 payload。后端用实际实例映射及操作声明授权；不是任意节点执行 API。input.save 和 input.submit 使用同一个正式数据层及回执，不保存浏览器副本。

| 操作 | 推荐最小 payload / 实际结果 |
| --- | --- |
| input.read | 空 payload；返回正式 text/input_sequence、submitted 状态及所属 instance/node/session |
| input.save | `{expected_input_sequence,text}`；接纳后返回实际 text、递增 input_sequence、digest 与准确原请求回执；已接纳未发送正文就是该输入节点 current data |
| input.submit | `{expected_input_sequence,text_digest}`；事务读取对应正式 text，只创建一次 immutable input_id/entry_id、输入事实和 U -> 当前 checkpoint（或 initial baseline）关联；不调用模型、不修改该 checkpoint |
| run.start | `{input_id}`；由 instance 转交 runtime，chain_start 捕获准确 input_id/starting checkpoint/current state；不是附带一份页面 text |

推荐客户端按 **200ms 合并节奏**发送当前最新内存值：dirty 时每 200ms 至多捕获一次，单实例至多一条在途 save；在途期间继续输入只更新内存，前条成功后按下一节奏发送最新值。不在连续键入期间无限推迟通信。200ms 是节奏而非完成保证，以真实接纳为准。

点击发送时捕获当时正文 T 和所属实例，暂停该实例后续编辑/自动 tick，等待已在途 save 准确结束，再补交 T（若已是同正文的正式最新 sequence 则不重复写）。核对正式回执 text/digest/sequence 确实为 T 后，才 input.submit，再 run.start 使用该稳定 input_id。T 不能从更早 timer 捕获值、未接纳内存或另一个会话输入中取；旧 save 回执不能覆盖新内存。

save/submit/run.start 的不确定结果各保留准确原请求证据和对象级锁，只查原回执、不自动重放；不因此增加 browser input backup、失败草稿或另一套输入恢复。正常明确失败直接报错。用户切换工作流/会话后迟到回执只归捕获的原 owner，不把它写到当前实例。多页面对同输入序号冲突直接报错，不静默覆盖。

**运行中手工 session/runtime 数据编辑禁令同样覆盖 input.save、input.submit 和变量 register。** 后端必须实际检查 active unfinished run（包括 paused/budget_exhausted/archive_failed 等仍未闭合进度）和原 input.submit/run.start 未决，不仅检查当时有没有执行 CPU，也不能仅 disable UI。当前没有批准“运行中先编辑下一轮输入队列”；不借 200ms 绕过禁令。可调工作流配置/全局资源保存与运行数据编辑是两种操作，可按既定规则对后续装配/请求生效。200ms 不扩到供应商、Key、全局模型或内容表单。

旧提案曾以traits的exclude/reset-default统一处理input buffer、通信序号和控制状态；39未批准这套全面reset。未发送输入不进入早先成功存档、数据层CAS不回退仍保持；未注册保存的数据如何处理须按最小需要重新列明。主动变量注册产生的正式业务值可按合规注册保存，non-work类别本身不决定保存范围。页面连接状态不成为历史恢复权威。
