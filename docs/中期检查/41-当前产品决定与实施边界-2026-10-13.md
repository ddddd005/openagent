## 2. 管理、配置与编辑

- 左侧栏只负责布局、收起、导航和组件承载。工作流、供应商与模型、全局内容各自拥有业务数据和操作，共用存储及传输不等于共用业务归属。
- 管理操作直接处理目标对象，不以无关表单保存、图执行就绪或宿主初始化作为前置条件。实际错误由负责的操作报告。
- 工作台与节点编辑器使用同一正式配置提交入口，工作流编辑自动提交后端。保存不要求工作流可运行，只保留必要格式、身份、权限和真实写入冲突检查，不为保存探测模型上游。
- 当前不做独立草稿，包括持久编辑草稿、失败后的草稿保存和恢复。普通内存表单编辑保留；保存失败直接报错。
- 执行中禁止手动修改会话或运行数据。允许的数据修改只影响后续运行，不自动删除后续历史、重算结果或改写已确认事实。
- 归档数据只供查看，不恢复归档会话继续执行。对象归档、删除及其失败应如实报告。

## 3. 供应商、Key 与模型

- 供应商编辑先在内存表单中完成，以一次“保存供应商”提交完整配置和新输入的 Key。Key 留空保留已有 Key；输入 Key 不锁其他字段，也不因编辑其他字段丢失。提交或请求未决时才锁相应修改。
- 产品凭据只通过供应商页面输入并保存，使用私有受保护 vault 中的 `local:<UUID>`；不恢复环境变量凭据、手工凭据引用选择器或明文兜底。
- 原请求证据、真实回执和秘密保护保留。未知请求只核实原请求，不自动重发；不以新 UUID、当前 Key 或空秘密补造原请求。
- 普通 Key、模型、温度、思考或容量修改不触发工作流或历史清理。
- 工作流只引用全局模型配置。Chat/Agent 每个新请求准备时读取当前已保存设置，包括未结束运行中的后续新请求；不冻结整轮配置，不追改已经准备或发送的请求。
- 模型四参数为思考强度、上下文长度、压缩阈值和输出上限；既定三项默认值保持 `300000 / 0.85 / 32000`。不增加模型第五项参数。
- 工作流二次限额、覆盖值、调用次数配额及对应限额节点退出，含旧 `8192` 人为上限；模型实际容量及协议能力检查保留。暂停、停止属于 runtime 控制。
- 必要非限额压缩由上下文模块承担。`enabled / keep_depth / summary_prompt` 本期维持现状，不迁移、不额外开放配置；`trigger_tokens / target_tokens` 随工作流二次限额退出。

## 4. 当前状态与检查点

| 对象 | 已定职责 |
| --- | --- |
| `workflow_ref` | 指向会话当前最新状态的 commit/snapshot，负责当前状态定位和 CAS；不是检查点指针 |
| 检查点 | 不可变的成功状态存档，只承担规定内容的历史回溯，不跟踪当前输入、交互变化或未完成进度 |
| 当前数据与未完成现场 | 由节点、数据层和工作流运行机制维护，不由成功检查点持续更新 |

- 检查点是历史回溯的唯一权威。检查点之外的不规范历史数据不补救、不迁移、不另建恢复路线。
- 用户在2026-10-13进一步明确：历史检查点只能创建新的分叉会话，状态还原只发生在本次新目标中，不能覆盖原会话。没有用户可单独操作的同会话恢复，原会话的状态、消息及可见聊天不由历史分叉改写；“恢复后聊天是否截断”不再是待确认问题。
- 节点保存声明落在注册 `NodeDefinition` 描述中，由节点表单映射正常配置字段；第一版只声明 `config_paths`，未声明字段忽略，不引入第二份配置权威或外部输入声明。
- `private-state` 第一版不处理：不增加检查点声明、不收集、不恢复、不随历史分叉写回；现有 runtime schema/default、读写与会话持久化机制暂不修改。是否最终保留、改造或删除以后再判断，不重复裁定本版范围。
- 第一版数据白名单只覆盖 Agent 上下文已接纳逻辑状态，候选根为 `session / workflow.effective-context / 4`；具体字段投影、必要内容读取、校验及新目标写回处理器须在第1步定稿。类型注册不等于检查点准入，不能直接复制源 `view_ref` 或沿用全部会话对象收集。
- 会话展示上下文、通用messages/摘要、程序变量、其他对象、请求证据及全部已注册类型不纳入第一版检查点；有无这些数据均不因此阻断会话、成功点或分叉，不造空集合。其他类型接入及公共会话对象机制改造后议。
- 初始检查点在第一回合成功完成后建立。成功回合存档固定保存当时的规定状态，后续输入、编辑或运行变化不改旧点。
- 实际注册类型若提供助手消息与后续用户消息的检查点关联，真实关联使用实际身份，后补关联不改冻结状态；是否存在、保存及复制该数据仍按类型自身注册规则，不能将消息或关联设为所有成功检查点的必填前提。
- 用户最新明确：消息及已有摘要不是检查点必需内容。若 `messages` 已存在，其是否保存、复制或纳入检查点由该类型自身注册规则判断，不因它是消息、已有正文/摘要或历史展示而无条件纳入。
- 分叉内部装载所选点的规定业务状态到新目标的数据层和节点，保留工作流当前可调配置；使用新目标实际初始化后的 CAS 正常写入，不复制历史存储版本，已准备、发送和确认的源请求事实不追改。
- 不另建检查点 Head，不改造 `workflow_ref` 承载检查点选择，不给 commit 或 run 增加检查点起点、来源等额外追踪记录。
- 新分叉状态装载完整后建立目标自己的当前 commit/snapshot/ref，再交回工作流处理，不自动运行。候选查看和重跑仍属工作流职责，但不能借候选选择覆盖原会话，也不因此扩入检查点契约。
- 复制来的检查点与后续新增的检查点没有特殊类别，使用同一保存、读取及再次创建分叉机制。父点及 full/diff 引用只表达检查点自身的存储关系；从任一副本还原也须另建新目标。
- 不以历史 chain、membership、artifact 闭包、native lineage 或逐层模型事实证明作为恢复前提。正常 live 调用的身份、授权、真实接纳和原请求核实不取消。

### 数据类型独立与messages订正

- `messages` 不绑定会话，也不是每会话必有数据；不创建空 `messages` 来满足会话契约，有无 `messages` 都不影响会话。各数据类型独立判定，不能将消息设为平台保留集合或类型注册之外的特例。
- 本条明确替代此前“复用会话对象物理存储、每会话必有messages”的确认。现有会话对象存储依赖session binding，原物理落点不再视为已定；需按不绑定会话的最新边界重新核对类型注册、存储、访问和生命周期，不自行决定新表、全局归属或兼容路线。
- 若实际存在 `messages`，其字段、读写及保存/复制/入点范围按类型自身合规注册契约核对，不另建每会话必有消息接口。消息和已有摘要不自动入点，不为缺失消息建空集合、补摘要或造身份。
- 实际处理消息时仍须区分Tavern `entry_id`、Agent `message_id`及投影身份，不混用或伪造；原基于 `(session_id, identity)` 的唯一性和跨会话ID复用提议不能继续当作已定存储契约。
- 对按注册规则实际纳入保存/复制的数据，核对其规定内容及引用的独立可读性；不将未纳入的消息/摘要强制复制，也不因此整删仍有用途的通用渲染器、输出artifact及正常live请求保护。D的实际消息接纳和最终成功收尾仍后置。

### 同工作流历史分叉

1. 用户在源会话选择检查点。
2. 创建独立目标会话，与源会话隔离；源会话及其当前状态不变。
3. 将所选检查点及其父级链上的全部检查点各复制一份到目标会话，即初始点至所选点，包含所选点，不复制其后的点；所声明状态和各类型按自身注册规则纳入的内容随其契约复制，不无条件附带messages或摘要。
4. 仅在本次新目标中装载所选点声明的状态，建立目标自己的当前 commit/snapshot 和 `workflow_ref`。
5. 目标后续新增检查点接在所选点的目标副本之后，不另外维护可变的“当前检查点”指针。

新会话建立、检查点及按各类型注册规则纳入的数据复制、必要ID与父点/full-diff引用映射、新目标状态装载和目标 `workflow_ref` 初始化在一个完整事务中处理。失败不留下半成品；源会话删除后，目标仍能独立读取规定内容，并从自己的检查点再次创建分叉。不做节点映射或跨工作流、跨版本状态迁移。

**已定范围：** 所选检查点及全部父级复制一份，新会话与原会话隔离，不改冻结业务状态，不复制后续检查点。消息、摘要、关联及后续用户内容仅在实际存在且各自注册规则决定纳入时按该规则处理，不再要求一律随行。目标的规定复制内容须独立可读；未纳入messages不能被视为会话或分叉缺损。

**落地与旧路径：** 完整分叉可复用现有 SQLite 原子事务、当前状态 commit/ref 和 CAS。现有 `copy_session` 复制当前状态并创建另一工作流，旧 `fork_graph_candidate` 从运行 commit/snapshot 创建会话，二者不是检查点历史分叉的实现捷径，也不保留旧候选分叉作为绕过正式检查点的历史创建路线。现有 `candidate.select / select_graph_candidate` 会覆盖传入原会话的变量、节点状态和对象并更新其 commit/ref；该入口及“恢复候选完整状态”按钮须纳入后续阻断/退出清单，不能仅改名称或隐藏按钮。普通历史/候选查看不因此整删。不接入检查点 Head、`workflow_history_membership` 和历史 artifact 闭包证明；通用 full/diff 父链读取能力可按需复用，删除旧基础前仍需核对依赖。若最终新增数据库表，再同步开发重置白名单。上述产品入口目前未因文档订正被禁用。

**仍需具体契约：** 1.1收口NodeDefinition字段/注册/序列化/收集接口与Agent上下文独立逻辑投影，1.2消费结果收口目标写集合。当前开发库已核实无旧descriptor或业务行，不再把旧描述处置/回收站移动作为该目标的前置；新描述保存后的同版本不可变约束保留。首版不以messages替代存储、全部类型或公共对象改造为前置。不得借清理增加来源追踪、Head或候选重跑，不恢复产品实施授权。

## 5. 提示词、once 与单条按钮

- 装配或汇总时按来源是否已经在其中判重：已在就不入，不在就入；压缩前后同一规则。上下文不维护来源标识，不建立 once 台账。
- 提示词格式零新增字段、零升版，现有格式继续承担装配。`PROMPT@3/@7` 及其来源证明安装表整体不落地。
- 工作流运行的结构预检只检查有输出节点、无缺失上游依赖；运行中途的用户设计问题不成为新增复杂预检或来源证明平台的理由。正常调用的身份、授权、协议能力和原请求保护仍保留。
- 单条按钮使用提示词条目已有能力，包括位置、顺序、内容等；初期只开放单条条目，不扩到提示词组或任意节点策略平台。
- 固定/可调切换本身算固定修改。有未归档、未删除会话时，后端判定需要派生，前端作轻量防误触确认，同意后才写入新工作流；取消无写入，不静默拷贝。
- 派生后的新工作流不继承旧会话或检查点，原工作流及会话不变。可调字段修改原地保存，无有效会话时固定修改原地保存。
- 实现不写死单条按钮，与全局引用节点同族：内容不纳入工作流检查，检查点不保存该内容，取值取最新；为后续统一整理留口，不在本期扩造平台。

## 6. 节点与前端归属

- Agent executor 和内核是节点内部实现，不另设工作流层。工作流提供交互能力，页面布局和渲染归前端。
- 每个后端节点绑定自己的前端实例。复制节点绑定新节点身份；代码、组件和传输可复用，实例业务状态不能共用。
- 后端节点维护正式交互与展示数据，由工作流数据层持久化。前端只是壳，关闭不影响后端流程；重开时映射后端数据。
- 切换工作流、会话或节点后，迟到回执仍归原对象，不污染当前对象、不强行切回；共享提交代码不共享业务状态。
- 上下文和变量先通过显式读取、引用进入运行时，处理后明确写回；不是本期新增 JSON 导入导出功能。

## 7. D 与 E 的已定行为

### D：节点执行与聊天数据流

- runtime 统一普通执行范围、工作/非工作节点筛选和孤立排除，节点不重复判断激活。依赖优先，同批就绪节点按创建序号串行执行。
- 变量注册及初始赋值由用户主动触发；上游连接可以激活无输出端口的写入节点。世界书读取执行时的变量值，不隐含注册或赋值先序。
- 统一聊天输出连接下游追加节点，与数据层交互。Agent A/B 上下文独立，写回按实际依赖与 runtime 调度，不强加跨 Agent 或上下文/聊天的固定先序。
- 具体节点、端口、包、授权和调度安装在前三项完成后另行逐节点人工审阅；不因已有基础、旧精确表或此次文档整理自动开工。

### E：创建与酒馆入口

- 创建只建工作流，首次运行按需建立会话。
- 200ms 保存是输入节点内部逻辑，将前端输入映射进节点配置，与工作流、检查点和各入口无关。输入在点击运行/发送时对本回合生效。
- 后端已接纳的输入可重读；未被接纳的页面内存内容可能丢失，不另建浏览器副本、独立草稿或恢复路线。此规则不扩到供应商、Key 或全局资源表单。
- 酒馆入口通过带按钮的大节点打开；按钮派生的前端自动绑定该节点、该会话和该工作流。
- 具体节点在 D 之后按需求逐步推进，已定用户流程不重新审议；未定架构直接问用户。
