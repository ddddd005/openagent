## 2. 普通内存资源表单

新增 `useResourceFormEditor.ts`，接管四类资源面板的当前表单及正式 `expectedSequence`。编辑使用正式记录的内存副本，新增/复制使用序号 0；取消、切换或重新打开不恢复未提交输入，不维护其他资源的待恢复副本。

保存继续调用各业务模块已有正式接口，整项提交并核对 CAS、真实回执和必要原请求证据。明确失败保留当前内存输入；只有精确匹配资源身份、提交序号及正文的成功回执才关闭对应表单。显式重新读取正式配置直接替换当前输入，不先归档表单，也不将替换结果写入草稿。

- **供应商**：移除表单草稿恢复、列表、notice、flush 和表单归档。完整配置及新 Key 仍通过一个“保存供应商”动作提交；空 Key 保留已有 Key，填写 Key 后仍能修改其他字段。Key 的非秘密原请求通道仍保留，见第 5 节。
- **命名模型**：移除同类草稿链和数字保存门禁，数字原文只存在当前表单。参数与容量继续一次明确完整保存，不将字段编辑拆成多个请求。运行契约和旧容量字段本轮没有改造。
- **提示词/Lorebook**：移除正文表单草稿链及数字草稿门禁；正式提示词名称继续由独立元数据接口持有，Lorebook 名称仍属于正文。新增/复制使用明确创建操作，已有资源明确整项保存。

本轮没有接入正文失焦自动提交，也没有接入工作流统一自动后端提交。全局资源采用 R07 已允许的现有对应保存入口；不将本轮称为“全部表单自动提交完成”。

## 3. 数字输入和请求保护

`RawNumberInput` 新增 `persist`，默认 `true`；`PromptMembersEditor`、`LorebookEntries` 和 `RolePlacementFields` 透传 `persistNumericDrafts`，默认同样为 `true`。两类全局内容资源显式传 `false`，关闭数字草稿读写，未接管的节点消费者继续沿用原行为。

不合法或尚未输入完成的数字保留为当前内存原文，阻止当前表单保存。内容编辑器以完整资源身份作为组件 key，避免相同 UUID、不同 scope 的数字原文串入另一资源。

原请求 outbox、证据适配器和后端证据接口没有更换或删除。资源未知结果仍锁定原请求，只核实原回执；重建控制器不会恢复普通资源表单或重新派发请求。共享 outbox 仅将错误文案改为“当前表单尚未确认”，不再声称普通表单需要落盘。

第一次全量回归暴露了 `RolePlacementFields` 可选布尔参数被 Vue 默认转换为 `false` 的问题，导致两项未接管 Lorebook 节点回归失败。已显式声明默认 `true`，没有放宽旧测试断言；随后全量回归和构建通过。初次失败日志和 XML 保留供调查。
