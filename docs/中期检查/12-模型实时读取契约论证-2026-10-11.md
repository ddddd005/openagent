## 3. 为什么不能只热切换通信层

仅在 `_boundary` 或 adapter 构造时读取最新供应商、模型及 Key，看起来会让下一次外部调用采用新配置，但不能满足完整规则：

- 公开绑定与 Agent 快照仍声称旧模型参数，实际请求却采用新值，模型请求事实和 Agent 事实会出现两份不同依据。
- 输出上限、上下文窗口、摘要上限和冷输入预算仍来自旧容量。新模型的预算可能更小或更大，旧值会导致漏报超限、误报超限或压缩证明不成立。
- `protocol` 或模型能力改变时，工具投影、思考参数和响应协议也可能改变，不能复用旧 adapter 或旧能力声明假装等价。
- 私有 Key 换代后，原整轮租约继续授权会拒绝新 Key；直接替换租约又可能改变已经派发请求的安全依据。
- 若先读取最新配置再识别旧逻辑请求，全局保存会改变摘要；原本应只接纳旧响应的请求可能变成冲突，或被错误当作新请求派发。

因此，问题不只在通信层缓存，实际涉及公开模型绑定、Agent 请求边界、容量计算和已接纳事实证明。B 不能通过改后端私有字段绕过 D 的节点契约关口。

## 4. 最小接口建议

已定生效方向是每个新逻辑请求采用当前配置，已接纳请求保留自己的配置事实。以下据此提出接口建议：**运行保留授权身份；每个新逻辑请求读取一致的当前配置；已接纳请求保留自己的不可变配置事实。** 优先复用现有模型节点，不新增通用管理平台或另一套工作流配置。

可复用现有全局资源身份、可信类型声明、精确源输出授权、私有凭据 broker、请求事实与回执。工作流仍仅引用命名模型配置，不拥有供应商/参数副本；源节点输出仍承担绑定身份和能力授权，不再把整轮参数/容量快照作为所有后续请求必须相等的依据。

候选请求主路径：

1. 先按原运行、消费者调用及逻辑请求键识别是否已有请求。已有请求只核对其原输入与事实并接纳/返回原结果，不读新配置后重算其有效参数，更不重新派发。
2. 对真正的新请求，在预算判断之前读取当前命名模型配置及供应商，取得这一请求一致的参数、容量和能力依据。相关资源修订不一致时报告实际冲突，不猜测补全。
3. Agent 普通请求或压缩请求使用同一份依据进行投影、输出预留、窗口和冷输入校验；通信不得在预算之后另取一份不同配置。单次压缩的前后测量保留同一容量依据。
4. 在单次请求边界冻结受保护的凭据租约，接纳请求和 attempt 事实后执行一次通信；仍保持 SDK 自动重试关闭及派发前授权检查。
5. 新请求使用与该请求配置匹配的 transport。配置换代不能复用旧设置；可以先采用每个新请求创建/释放的直线实现，不预设多级缓存或恢复框架。
6. 原响应、错误、未核实结果及结果接纳继续按现有事实处理。之后再发生的新请求可采用更新值；已发送请求不改参数、不改容量、不改 Key 事实、不自动重放。

按 2026-10-12 集中管理和精简的方向，接口建议收敛为：公开模型绑定主要保留配置引用及必要授权，由新请求边界取得当次有效设置，不再让初始参数展示快照同时承担后续执行配置。引用是命名模型配置的资源身份，不是工具调用。

这仍需给出具体 API、公开字段及版本方案。不能把“再次执行源节点取得新绑定”当成默认方案，因为同一 Agent 内核可产生多次正常/压缩请求，而改写已接纳输出会破坏原输入授权。同一引用允许协议/能力切换已明确，后续方案须核对现行固定协议消费者的限制，不能继续以旧投影处理新请求。

普通请求与压缩请求分别在自己的新请求边界读取设置；预算、投影及通信在单次请求内部一致，不要求整个运行采用同一旧值。上下文长度触发基准、模型容量及开始压缩阈值需要明确计算关系，不能把触发点解释成压缩后目标，也不新增多套用户预算参数。

## 5. 影响范围与不扩展范围

前端供应商和命名模型配置仍沿用现有一次保存，不增加手动 Key 引用选择器或第二个生效按钮。若节点或历史面板展示绑定参数/容量，需标明它显示的是初始观察还是实际请求事实；运行中的全局编辑保持可用，不触发工作流派生或清理。

本论证不改变节点激活、执行排序、上下文消息更新路线、roll 生成、外部工具副作用恢复、酒馆创建/打开流程或跨流状态迁移。P03 的其他旧协议与迁移注册问题仍在对应 D 方案中单独核对，不按本页整删。

## 6. 已定方向与具体方案

已确定的方向不再重复提问：全局配置集中管理、后续新请求实时采用而不改旧事实、运行参数精简为四项、上下文长度可沿用或调低模型配置容量、压缩阈值表示开始压缩，以及同一模型配置引用允许协议/能力切换。温度退出本轮用户可调参数清单；模型选择、供应商连接及 Key 等必要身份和连接信息仍归各自管理模块。

仍需交付的具体方案是：

1. 公开绑定的引用/授权字段、单次请求取得当前设置的接口与版本，以及需要同步调整的现行消费者。
2. 普通请求与压缩请求如何使预算、投影、凭据及通信对应同一次设置；已接纳请求仅处理原事实的关联格式。
3. 模型容量、用户可调低的触发基准、压缩占用阈值及输出预留的计算关系。阈值采用比例或绝对数量尚未指定，不自行把它改成压缩后目标。
4. 协议/能力切换对现行模型节点、Agent、压缩和请求证明的适配范围；真实不支持直接报错，不降级、不改写旧事实，也不泛删其他业务的 schema 1。

这些是依照已定方向整理的接口和消费者方案，不重新引入两份生效配置；具体契约提交审阅后实施，验证主路径及必要回归，不扩建假想异常矩阵。

## 7. 定向离线验收

确认方案后的验证采用 mock、合成 Key 和独立临时数据库，不启动服务、不调用真实模型：

- 同一未完成运行中，第一请求使用旧配置；保存模型、参数或供应商地址后，真正的第二请求使用新值，第一请求及响应事实不变。
- 保存容量和输出上限后，后续普通请求与压缩请求的预算、投影及通信一致；超过当前容量时真实失败，不猜测扩容。
- 上下文长度沿用或调低模型配置容量、到达占用阈值触发压缩；触发基准不冒充模型真实容量，不混入压缩后目标参数。
- 同一引用修改协议或能力后，新请求采用匹配的投影和通信；旧请求和已装配输入不被改写，真实不支持明确报错。
- 更新 Key 后，新请求使用新保护租约；Key 不进入公开绑定、请求参数、诊断或日志。原请求待接纳时仍不再发送。
- 已完成请求重入、成功响应接纳重试及派发未知请求，在全局配置改变后仍只处理原事实，外部调用次数不增加。
- 关闭供应商、删除引用或协议/能力不支持，在对应新请求边界报告真实错误，不重写旧结果、不清理工作流。
- 更新证明能核对每个正常/压缩请求的实际设置和容量，而不是要求全部请求等于首次整轮绑定。

以上是待实施的验收要求，不是当前通过证据。真实 DeepSeek 统一验收仍由用户启动可见页面并填写、保存 Key 后进行；本页不授权代理代为操作。
