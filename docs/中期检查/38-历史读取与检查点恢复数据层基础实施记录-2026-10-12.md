## 2. 权限、事实和恢复核对

历史读取使用绝对 URI `mode=ro`、`query_only` 和一个 `BEGIN`；不实例化带 DDL 的 `SqliteStore` 或 `RuntimeFactStore`。类型证据通过只读 SQL 取得并与准确注册声明核对，缺失直接拒绝，不补写声明、不读取当前资源或配置作为旧事实。

正式 root 不是客户端自报 state、引用或 UUID 清单。原 chain 仍是唯一执行出处，源 session 存在时交叉核对，缺失时不借源 current 或 Head。目标必须有自己的 session、检查点父链和准确 membership；原 chain、run、output 和 fact 不改 owner、ID、正文或时间。

原 artifact 的输入核对只证明真实接纳坐标，不把 producer 全部输入变成任意可读集合。内部 `read_context_update_facts` 从已授权 update、原 receipts 和真实输入推导准确 executor/M2 facts，复用 `ModelRequestFactReader._facts` 和 `validate_execution_update_v2`，缺少纯 projector、事实、原坐标或完整证明均拒绝。默认官方来源列表没有自动加入 fixture 的 Agent9/Model7；测试明确注入 synthetic frozen declarations，不是产品注册。

交叉审阅补齐了几项必要边界：

- artifact 递归保留原读者约束；同一个 artifact 经不同对象读者到达时分别验证，不由首次缓存跳过 private 检查。
- root 建立失败不留下部分授信；每次使用从正式 roots 重建并核对完整闭包，深层 revision membership 撤销、根或中间证据丢失不能继续借缓存读取。
- 已成功 producer 的 required 输入、cardinality、order 和 control 前驱必须与真实冻结调用一致；保存阶段不因此增加可运行性检查。
- 历史 absent 对象也先验证原 exact type evidence，不能由恢复操作补出一份注册证据。
- 恢复前检查当前对象 SQL tombstone、正文、身份和 revision membership；不以合法旧值覆盖并掩盖当前坏记录。

`restore_logical` 不退回旧 CAS 或 revision ID。业务正文或 deleted 状态变化才新写并推进当前 revision；未变不新增值、不前移对象 CAS。固定 binding 保留，tombstone 与移除 binding 分开。当前可调提示词 row、原 facts、旧请求事实、后续 checkpoint 均不在它的写入范围。
