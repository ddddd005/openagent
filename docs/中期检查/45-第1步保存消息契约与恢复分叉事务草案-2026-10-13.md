## 4. 注册保存声明与状态收集

### 声明形状提议

```text
NodeDefinition.checkpoint_save = {
  config_paths: [[<属性名>, ...], ...]
}
```

路径采用属性段数组，只沿 `config_schema.properties` 显式遍历，不采用通配、表达式或数组下标。对象/数组字段可整体声明；重复、祖先/子路径并存、schema不存在的路径在注册时拒绝，不静默去重。空声明的唯一规范表示、字段排序及导出/持久化一致性仍待定稿。表单编辑正常node.config，不另建可编辑的保存声明权威。

配置先按当前固定/可调策略走 `fixed_configuration_projection`，排除可调值与取最新的引用内容，再按声明收集。即使一个通用声明覆盖了更大的子树，已定不入点的内容仍排除，不以“历史展示”为由另存可调旧值。描述及已持久化注册记录必须一致，不静默改变同版本节点契约或整批升包。

### 逻辑状态与写回

收集接口职责提议：使用caller-owned connection及已核实的session/workflow/fixed revision，同一事务中从已保存定义及当前权威Agent上下文读取，禁止从未提交页面状态收集；精确签名/返回结构待审。只取得：

- 声明并经过固定配置排除策略的节点配置逻辑投影，以及固定定义身份；不存private-state、节点存储版本或第二份可写配置。
- `session / workflow.effective-context / 4`白名单处理器读出的已接纳逻辑状态及其必要内容；不是把底层全部artifact或所有对象入点。
- 允许空配置投影和空白名单数据；未出现Agent上下文时不补造Agent状态，其他数据即使存在也不自动入点。

配置仍以固定definition + 正式可调投影为权威，分叉不新增overlay/配置表；同固定revision的声明配置仅作一致性读取，不覆盖定义或当前可调值。private-state及程序/其他对象只按目标正常初始化契约产生，不使用源值或点内值写回。E输入不在这里另设架构。

Agent上下文登记项须绑定逻辑读取、校验、必要引用本地化及目标写回处理器。当前view_ref是源artifact引用，不能直接复制；字段白名单、消息/工具语义身份、目标内容引用和当前写入版本须定稿。要求目标内容不依赖源session/artifact/对象revision、receipt或旧history；不能本地化就失败。现有reference_mapper或要求HistoryArtifactAuthority的restore_logical不能直接承担该职责。

新描述保存后同component版本必须完整一致。一般而言归档workflow不移除全局node_definition，仅升package版本也不消除冲突；但03已实测当前开发库records为空，不存在需要退役/替换的旧描述，不因不存在的冲突强制升组件版本。不得静默升包或重写已保存同版本。

4. 逐点复制前缀及首版逻辑内容，必要owner/point/parent/full-diff引用映射到目标；不复制所选之后的点、通用messages/摘要/展示上下文、源运行或其他点外数据。
5. 白名单Agent上下文按其处理器本地化规定内容、重建目标身份及必要内容引用，保证各点逻辑值及所选装载状态独立。不得仅授予源revision membership或直接保留source view_ref，映射不变成持久来源台账。
6. 在同回调内只对本次新目标装载所选声明状态，完整后一次建立目标snapshot/commit/ref及正常manifest。新目标 `history=[]`，普通source不承载源点/session/commit/run来源链；manifest按实际图对象契约处理，不安装平台消息排除特例或源运行恢复依赖。
7. 同回调完成 graph bundle校验、普通命令级幂等回执及适用的既有 application identity记录，再 COMMIT；任意失败整体 ROLLBACK。

这些阶段是同一事务内部次序，不是分开提交的批次。禁止从回调调用会再开 store/事务的普通 `create_session / copy_session / fork_graph_candidate` 等 API；不复制 source output/run/chain或历史 proof以通过旧校验。

### 对象、历史与删除前提

`_commit`默认继承 `_history`且写 manifest，`GraphRecordStore`也会沿 snapshot.history_refs读取 chain。新分叉明确排除此依赖，否则删除源会话可能因 history guard被拒绝。源live历史及正常事实保持不变；分叉不清理源history、不截断源聊天，也不以它们逐层证明所选状态。目标后续正常live事实继续由原机制维护。

[session_objects.py](../../backend/src/phase1_agent/session_objects.py) `:138` 的 initialize可复用旧 revision，`:349` 的 restore读取旧 manifest，`:422` 的 restore_logical依赖 `HistoryArtifactAuthority`；均不能原样当新分叉装载落点。复用其类型、正常对象权限和当前 CAS骨架，但不接旧历史 authority，不因此保留同会话历史覆盖功能。

实际注册对象可能含 artifact/session revision引用，[context_v4_nodes.py](../../backend/src/phase1_agent/context_v4_nodes.py) `:118` 等旧消费者还保留 artifact引用。只换外层对象 revision并不保证目标独立；被采纳的收集/写回消费者必须保证规定逻辑内容和必要可解引用数据均目标自足或合法全局自有。源依赖尚未退出的实际类型不能假报验收；不能本地化时明确失败并回滚，不增加 artifact历史闭包、proof reader、未知请求重放或泛用补救路线。具体替代文件在1.3收口，不按文件名整删正常 live功能。

若采用 `workflow_checkpoints`，它不是records表，[workflow_lifecycle.py](../../backend/src/phase1_agent/workflow_lifecycle.py) `:143` 的正常会话删除须显式纳入该会话点，不能仅靠records sweep。正常图对象按现有值/绑定生命周期处理；不绑定会话的messages不因此随会话清理，其实际生命周期待类型契约核对。保留未知执行/请求拦截及原回执证据，不额外删除无关内容。
