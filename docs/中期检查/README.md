- 已明确的后端所有权、供应商配置与通信、内容边界优先，现有前端只做对应的必要接口对接。

## 已确认的总体特点

1. 左侧栏属于应用壳和管理界面，不是工作流执行节点，也没有独立的“左侧栏业务服务”。
2. 后端已有统一的 `GraphApplication` 请求分发入口；统一入口不等于统一、明确的业务所有权。
3. 工作流目录、编辑草稿、已保存定义、会话和目录归档分别散落在不同状态及存储路径中。
4. 供应商配置服务已有独立类，但页面入口和正常请求生命周期仍依附图宿主。
5. 提示词、世界书等内容属于全局资源，当前管理读写却经过供应商配置服务，模块职责与名称不一致。
6. 顶部新增先生成编辑草稿；目录归档只保存隐藏标记。两者都不是直接创建或搬移一份完整后端工作流实体。
7. 目录操作和导航依赖全部表单保存、图宿主状态及部分会话状态，存在跨功能影响。
8. 节点执行顺序由后端编译器计算；当前图内节点还承担聊天展示记录维护。执行排序、展示历史、模型上下文和对象权限是不同职责。
9. 提示词表单与节点配置不是两套业务配置，而是编辑副本与当前值；表单草稿、工作台保存和定义发布有不同生效时点。提示词节点草稿不归会话所有，但校验依据包含当前会话。
10. 画布“先序”属于工作流定义的控制边，只声明先后、不传递端口数据；用户确认相关节点逻辑后续需要重整。

## 规范方向与状态

已在讨论中确认的原则是：左侧栏采用应用壳薄基底，承载职责清楚的工作流、供应商与模型配置、全局内容组件。任何业务不持有整个左侧栏；不要因为三者出现在同一左侧栏，就让一个“左侧栏后端”包办全部业务。

可以共享存储、传输、校验及应用入口；共享基础设施本身不是问题。需要明确的是各模块持有什么数据、接受什么操作、何时生效、失败影响哪些功能。

工作流与会话归属、创建时点、编辑自动提交、归档删除、运行数据编辑权限和全局配置采用规则已由 06 确立，尚未实施。具体接口和界面细节在后续实现中整理；模板管理平台不在本轮范围。各检查项区分“现状已确认”与“方向已确认、待实施”，不登记为已修复。

03 保留早期关于聊天职责的现状和候选分工。后续已选择读取、装配、内核、更新的节点流程及通用前端宿主，不采用应用壳专用聊天执行路径；失败可中止或继续，回合重来由用户明确选择。具体整改与验收纳入 MID-R09，不表示已完成整体重写。

04、05 保留草稿、应用和先序机制的调查事实。后续已确定工作流编辑自动提交后端，不再分段应用和保存；第一版依赖优先，同批就绪节点按节点序号串行执行，孤立节点不随意激活，变量注册是独立初始化例外。不倒改历史文档，也不要求再建设必须手动配置的先序层。

用户随后明确以工作流为核心，先不做调试模式。有未归档、未删除会话时修改执行定义派生新工作流，不继承旧会话数据；没有此类会话时原地修改，包括全部会话归档或删除后。归档只保存历史数据、不恢复；运行期间禁止手动编辑运行数据，全局内容和模型配置独立实时读取。完整决策及暂缓范围见 06，此方向替代会话核心双模式、隐式数据继承和跨工作流状态迁移路线，不倒改各现状调查。
