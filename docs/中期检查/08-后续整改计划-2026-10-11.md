## 1. 总体目标与范围

以工作流为核心，用一套明确的定义、会话、数据归属和节点执行规则替换交叉改绑、分段保存及过度环境校验。

工作流管理自身会话；全局供应商配置和内容独立管理，工作流只引用和实时读取。前端通过节点声明和通用宿主承接输入、输出及展示，不再让应用壳为酒馆逐项接驳业务。

左侧栏采用薄的应用壳基底，只负责布局、收起、导航和组件承载。工作流、供应商和全局提示词/世界书等分别作为独立业务组件接入，各自持有数据和操作，不由其中任何业务持有整个左侧栏或代办其他组件的保存。共享通用存储、传输不等于共用业务所有权，不另造包办业务的左侧栏后端。

### 简化实施原则

- 优先完成核心目标和清晰的正常链路，不先完善每个单项的所有情况；已确认的业务分支直接实现，不额外枚举假想情况。
- 保存采用“提交当前内容 -> 必要写入 -> 返回实际结果”的主路径，不叠加多层草稿依据、应用确认、发布状态或通用异常恢复框架。
- 管理操作直接处理目标对象，移除无关表单、宿主就绪及执行可运行性等互相嵌套的前置流程；真实错误在实际写入或运行的责任模块报告，不把跨业务流程限制作为替代。必要的真实失败与未知请求保护仍保留。
- 开发中只做核心路径及必要回归，不以完整异常矩阵、穷尽故障注入或预防性抽象作为批次推进条件；本页验收项是对应核心规则的验证，不授权围绕每项继续增加机制。
- 实测发现的非核心问题先登记复现、实际结果、影响和责任模块，再汇报并经人工论证形成定向联调规划；不在单个功能内不断补分支或自行扩展行为。
- 明确阻断核心链路的问题做范围内最小修复；跨模块职责调整、新行为和节点优化仍须汇报。必要的数据归属、真实写入结果、Key 保护及未知请求不自动重放底线保留，不借简化掩盖真实失败。
- 主动考虑删除或归档后移除过期、无效、重复内容，不刻意回避删除；不为保留旧内容而维持多套架构。新增删除建议先按第 7 节汇报内容、原因和影响，已明确授权的历史数据清理免重复汇报。

## 2. 批次 A：所有权和会话生命周期

范围是工作流管理、会话及所属历史的后端操作与前端管理接口，不建设一个包办供应商和内容业务的“左侧栏后端”。

- 将目录、定义、会话、运行数据、节点状态、历史和管理元数据纳入工作流管理责任，订正对应后端管理和前端状态接口。
- 新建工作流仅保存定义；未选择会话时运行才创建会话，已有所选会话时继续使用。
- 从历史新建会话按明确历史起点建立独立新会话，不形成原会话下的子会话，不跨工作流隐式迁移。
- 补齐会话归档和删除。归档停止相关运行、保存历史数据、不恢复执行；删除停止相关运行并移除所属数据。
- 工作流归档或删除同样停止所属运行。删除不连带全局资源和私有 Key，归档不只是前端隐藏标记。
- 清理旧的跨工作流采用修订、自动改绑及节点状态映射路径，暂停进度仍归原工作流。

验收：创建后无会话；首次运行只创建一次目标会话；切换会话不修改定义；归档数据可查看但不能恢复；删除只影响目标所有权范围；停止或归档失败不假报完成。

## 3. 批次 B：全局配置、通信和内容解耦

范围是模型供应商模块、模型调用接口、全局内容服务及其在运行中的读取路径。复用现有通用存储和应用请求入口，不因模块独立重复建库。

- 左侧栏从业务宿主中分离为薄基底，复用现有界面组件分别承载工作流、供应商和全局内容；布局、收起及导航归基底，各业务保存、错误和状态归组件及对应后端，不引入新的通用管理平台。
- 提供商、模型和多套命名配置在模型供应商模块内管理；上下文容量仅手填，思考强度及温度按模型支持处理。
- 用户填写的 Key 与完整供应商配置通过一次保存生效。空 Key 保留已保存 Key；不恢复环境变量入口、手动凭据引用或明文兜底。
- P01 已批准删除保存失败后单独补绑定 Key 的 mutation/UI 及专属包装，不追加预设补救体系；保存真实失败直接说明，实际问题出现后再讨论处理，Key 保护及未知请求证据保留。
- 供应商通信层只负责 API 协议和收发，不依赖工作流、会话或草稿业务。
- 提示词、世界书等全局内容移到其自身业务边界，不经供应商服务管理。
- 清理整轮冻结的模型或全局资源配置路径；后续调用、读取使用当时已保存的全局值，当前运行也可采用。
- 已发送请求和已确认结果保留原事实，不通过修改全局配置自动重放模型或工具请求。

验收：不启动图执行宿主也能管理配置和内容；左侧栏任一业务组件不持有其他组件，也不代办保存；保存、重读及 Key 保护成立；模型列表按保存配置获取；同一未完成运行后续调用可读取修改后的全局配置，既有请求事实不被改写；超限呈现真实错误。

## 4. 批次 C：修改、保存和管理操作

对应 07 的第 4-6 项。第 4 项将 MID-R02 与 MID-R03 作为同一修改和提交链路实施，内部先落实原地修改或派生，再接自动保存；随后订正数据编辑约束和管理隔离。

- 按工作流下是否存在未归档、未删除会话判断原地编辑或派生，不按当前是否选中会话、不增加空占位数据量规则。
- 节点、配置、连线、依赖、运行目标和对象绑定均属于执行定义；改名和移动等纯展示操作不派生。
- 有会话时派生新工作流，只带定义、配置和全局引用，无会话、历史、输出及暂停位置。新流无会话时可继续原地编辑。
- 工作流编辑自动提交后端，取消独立“应用条目”和手动正式保存的生效步骤；不另建用户可见本机草稿发布路径。
- 保存不要求工作流可运行，不做完整执行编译或模型上游探测；只保留必要格式、身份、权限和真实覆盖冲突检查。连线未完成、模型未选等可保存，执行问题到实际运行时报告。
- 失败保留输入、说明原因；提交中的排队和真实覆盖冲突不得把用户带回多段保存。工作流提交不保存其他资源表单。
- 运行期间禁止手动修改会话和节点运行数据；非运行期间的数据修改弹窗说明范围与影响，修改只影响后续运行，不自动删除后续楼层、重算结果或改写既有请求事实。全局内容和配置独立正常保存。
- 切换、新建、归档和删除只处理目标对象。运行 A 不全局阻塞 B；归档或删除目标时停止其运行，不掩盖未核实请求。
- 简化上述管理操作的调用链，不再嵌套无关组件的保存、执行校验或就绪判定；错误由实际失败的操作直接说明，不用一层流程限制掩盖另一层失败，不额外构建通用恢复状态机。

验收：有会话修改配置或连线派生，无会话原地修改；归档或删除全部会话后可原地修改；派生无旧运行数据；展示操作不派生；不完整图保存、重读成功，运行时报告实际缺项；无“应用后还未保存”的中间状态；无关表单失败不阻塞其他工作流；运行数据修改受限，允许的修改不删历史、不重算，全局编辑正常。

## 5. 批次 D：节点数据流与执行

对应 07 的第 7 项，合并 MID-R10 与 MID-R09。既定架构方向保留，但本批当前只允许进入调查与报告准备，后续需要人工参与具体方案讨论、确认和验收，不能按旧顺序直接实施。

### 汇报确认关口

先提交报告，至少列出实际缺项、是否确需新增节点、可复用能力、拟改节点与端口/数据契约、执行顺序依据、前后端影响、复杂度和定向验收方式。新增或适配更多节点、顺序优化、节点职责/契约优化均在此关口内，不能仅以“后端整改”名义提前修改调度或节点实现。

用户确认方案后才开始相应实现；若缺少节点适配会阻塞其他批次，先报告具体阻塞范围，不临时绕出另一套硬编码运行路线。

### 确认后实施范围

内部先订正节点激活、执行顺序和访问校验，再实现读取、处理、更新链路及失败操作；不将聊天归属和顺序规则重新列为待选方案。

- 执行范围由运行入口和连线激活；孤立节点不因任意运行目标选择进入执行。变量注册保留独立初始化例外，已有会话不反复重置。
- 数据依赖优先，同批无明确依赖的就绪节点按节点序号串行执行，不能改为 UUID 或画布位置排序。
- 写入节点可无输出端口，上游连接可以激活并确定其顺序；保留缺失输入和循环检测，重整旧手动前序及对象访问冲突校验。
- 采用读取上下文 -> 提示词装配 -> agent 内核 -> 上下文更新的节点链路；原始读取结果可连接装配、内核和更新，不反复读取同一记录追加用户和助手。
- 聊天消息按同样的数据处理模式接线；会话持久化归属不变。复用已有节点前端扩展和通用宿主，不另造应用壳专用聊天运行路径。
- 未完成失败提供中止和继续，保留输入与已确认进度；回合重来是独立明确动作，与重试失败节点区分。
- 按 P02 保留同一固定工作流内与 roll 相关的候选回复选择及必要状态恢复，不保留跨流/跨执行定义改绑。选择已完成候选不是再次生成回复；具体 roll 生成与用户流程到本阶段人工讨论，不能提前宣称已实现。
- 外部工具副作用回滚、重来时重复执行及恢复策略仅留占位，本轮不实现、不要求完整外部工具验收。待核实请求仍按事实处理，不自动重放未知结果请求或声称外部副作用已回滚。

验收：一次读取可扇出给处理和更新；消息与上下文保存、重读一致；上游激活无输出写入节点；无关孤立节点不执行；同批节点序号稳定且依赖优先；变量不反复初始化；失败可继续、中止或明确重来，恢复使用原工作流进度。

## 6. 批次 E：创建和酒馆节点入口

本批与 D 一样需要后续人工参与。先提供创建、首次运行、从节点打开酒馆的具体操作流程及其接线依据，人工讨论确认后才实施，并由人工验证使用流程；即使只复用现有节点，也不自动越过此关口。下列范围是待确认方案的约束，不是本轮开工授权。

- 整合新增、自动保存和首次运行，创建失败说明真实原因，不将“已产生前端条目”当作后端创建成功。
- 新建工作流不预建会话；首次运行按批次 A 的规则处理。
- 酒馆从聊天展示节点打开，携带当前工作流和所选会话，由节点声明输入、输出和展示能力。
- 若尚无会话，入口与首次提交沿用按需创建规则，不借此提前制造空会话或第二套绑定流程。
- 现有示例工作流按批次 D 的节点契约接线，不另建模板管理平台。
- 优先复用已有展示节点和前端宿主；若需新增或优化节点、端口、契约或运行顺序，先提交第 5 节要求的报告并等待用户确认。
- 错误说明原因与可执行操作，不继续要求用户先采用新修订或手工修复 UUID 关系。

验收：新建、首次发送、继续发送、会话选择、刷新重读和从节点打开形成一致用户流程；没有多余绑定步骤和会话修订假冲突；失败反馈能指向实际对象和操作。
