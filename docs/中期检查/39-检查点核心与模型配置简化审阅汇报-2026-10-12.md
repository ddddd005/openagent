## 2. 检查点机制

### 2.1 唯一权威与完整继承

- 历史回溯只使用正式检查点机制。检查点机制应独立提供完整的规定恢复内容，不以源会话当前状态、旧节点产物来源链或模型事实重建作为前提。
- 回溯会话历史时，拷贝整份历史检查点；新会话拥有自己的检查点和当前状态，之后与原会话独立变化。
- 同工作流的会话使用相同节点结构和身份，不做节点映射、替换或跨版本状态迁移。
- 不建立此前提议的跨会话历史 `membership` 授权机制，也不以原 chain 作为另一套历史恢复权威。
- 检查点机制之外的不规范历史数据，不做补救、兼容或额外恢复保障。
- 恢复保持工作流当前可调配置，不用历史配置覆盖当前配置。正常数据层 CAS 不作为历史业务值倒退。

这里的“完整”是规定保存内容完整，不是将所有运行记录、当前编辑内容和原始诊断事实都纳入检查点。

### 2.2 仅两类保存内容

| 类别 | 范围 |
| --- | --- |
| 节点注册内容 | 节点明确注册、合规且允许检查点保存的业务内容 |
| 数据层内容 | 上下文、变量，以及其他节点合规注册存储在数据层中的内容 |

不另行建设 once 台账、通用计数器保存平台、历史核验证据包或其他未提出的数据类别。已有计数、聊天结果等若本身属于上述注册内容，按其声明处理；不能因为名称出现在旧方案里就自动成为独立必存分区。

once 在装配时依据当前上下文实时检测，检查点维护好上下文即可。恢复不追溯旧请求来重新证明 once，也不新增独立消费账本。必要的上下文来源信息和压缩后检测方式尚须在具体上下文契约中收敛，不自行增加其他存储。

输入、控制数据不能被不加区分地扫描进检查点。具体节点注册中的保存范围、默认值以及未纳入保存的数据如何处理，按最小实际需要列明后审阅，不先安装旧 [35](35-runtime交互声明与记录版本精确契约-2026-10-12.md) 的全面 reset 方案。

### 2.3 不混同正常执行

取消的是非检查点历史恢复和逐层历史核验路线。正常保存、请求发送及结果接纳仍须如实处理身份、格式、权限、写入冲突和实际结果，不能伪报成功、改写已发送请求或自动重放未知请求。这不建立第二个历史回溯机制。

原执行和请求记录可以继续承担现有正常运行、结果核实及诊断职责，但不作为检查点复制和历史恢复的前置证明材料。模型压缩摘要属于上下文内容，不成为另一套会话历史恢复权威。

## 3. 节点与前端实例

- 前端实例绑定后端节点，每个节点的实例有自己的归属和状态。
- 复制节点产生新节点身份，加载的前端实例绑定复制后的节点，不继续使用原节点实例或把操作发给原节点。
- 相同类型节点可复用前端代码、组件实现和通信基础设施；这种代码复用不等于实例或业务状态共享。
- 跨工作流、节点、会话切换时，操作及迟到结果必须仍归原所属对象，不能写入当前另一个实例。
- [32](32-D节点端口与交互接线审阅清单-2026-10-12.md)/35 的实例映射方案须按逐节点归属重新核对，不能把旧提案的集中映射当作本轮已批准实现。

第 28 份规则继续有效：变量注册由用户主动触发；普通执行范围和顺序由 runtime 统一决定；世界书读取实际执行时的变量值；聊天输出连接追加节点，由数据层持久化；A/B 上下文独立，按真实依赖写回，不增加固定跨业务先序。

本稿不凭这些已定行为批准未审节点名称、版本、端口、包、service grant 或调度记录字段。

## 4. 模型配置与拉模式

### 4.1 单一配置来源

已批准：工作流内仅指定使用哪份模型配置，不再配置第二套模型限额和对应限额节点。

已批准执行边界：

| 位置 | 职责 |
| --- | --- |
| 模型配置页面 | 保存思考强度、上下文长度、压缩阈值和输出上限 |
| 工作流模型源 | 提供所选模型配置引用，不复制整轮参数 |
| Chat/Agent 的模型请求服务 | 每个新请求准备时，根据引用读取当前已保存设置并实际使用 |
| 上下文写回 | 更新所属数据层上下文，由检查点保存规定内容 |

不在工作流内另加输出上限、上下文容量、压缩阈值、调用次数配额或节点内覆盖值，也不换成另一套隐藏限额。模型真实容量及协议硬上限仍由模型模块检查；这是实际能力约束，不是工作流二次限额。

### 4.2 生效顺序

```text
页面保存模型配置
→ 模型源传递配置引用
→ Chat/Agent 准备新请求时拉取当前设置
→ 使用这次实际读到的设置发送请求
```

模型源已经执行后修改配置，下游尚未准备的请求取得新值。同一未结束 Agent 运行中的后续新请求也重新读取。已经准备或发送的请求不因后续配置修改而被追改。

这是“配置取值拉模式”；引用、提示词、结果仍沿实际工作流连接传递。不是广播配置，也不是节点反向拉动整条执行链。暂停、停止属于运行控制，不作为模型限额节点。

### 4.3 现压缩节点的混合职责

现 `agents.compaction-policy` 同时含重复阈值 `trigger_tokens`、占位 `target_tokens`，以及非限额字段 `enabled/keep_depth/summary_prompt`。

已批准职责方向：退出工作流重复限额及占位字段；撤掉策略节点时，把必要的上下文压缩行为收回上下文模块内部，不再另造限额节点，也不能顺带取消压缩功能。

非限额处理归上下文内部的方向已批准；`enabled/keep_depth/summary_prompt` 的最小实现及本阶段是否开放配置仍须具体收敛。不新增模型第五项参数，不把方向批准记成未列明节点和字段的完整退役授权。

## 5. 提示词格式修订

`PROMPT@3/@7` 是数据格式版本，不是模型或前端实例版本。

| 原推荐格式 | 用途 |
| --- | --- |
| PROMPT@3 | 普通 Chat 的实际装配结果 |
| PROMPT@7 | Agent 的上下文装配结果，包括实际消息、布局和 once 检测结果 |

原 [34](34-提示词装配读取与来源证明精确契约-2026-10-12.md) 的升版理由包括新增 `assembly_sources/read_fact_id`、独立来源读取事实和历史来源重建证明。因此不能原封不动安装原 3/7 提案。

简化后需要保留的业务路径：

```text
装配时读取当前提示词配置
→ 根据当前上下文实时检测 once
→ 形成本次实际消息
→ 交给 Chat/Agent 执行
→ 需要保留的结果写回数据层
```

应重新列出实际运行必要字段及消费者。是否仍需新格式、最终版本及端口变化，在字段确定后审阅；不能为了已否定的历史核验保留额外证据数据，也不能静默覆盖同版本注册声明。正常运行的格式、实际输入归属和数据接纳检查与历史追证分开处理。

“成组接入”仅指模型界面、配置、源节点、Chat/Agent 和上下文写回使用一致接口，避免界面已支持 `32000` 而实际调用仍受旧 `8192` 人为上限约束，不代表建设历史追证系统。

工作台负责结构、连线等编辑；节点实例只提交自己注册负责的字段。共享前端提交代码，不共享实例业务状态；前端应用层不是配置权威，不保存第二份正式配置，不调度 runtime，也不统管侧栏业务。

200ms 只按既定输入节点规则使用，不扩到供应商、Key 和全局资源表单。配置保存不要求图已经可运行；编译、缺输入、循环及模型实际可用性在运行路径处理。

### 6.1 单条提示词按钮

初期仅单条提示词条目支持固定/可调切换。按钮位于节点内部，通过节点注册与现有前端扩展机制提供，不推广到提示词组或任意节点，不另建策略管理平台。

按钮走同一正式配置提交入口，不能只切换内存状态后声称已保存。按钮切换本身是否属于需要派生的固定修改，本轮尚未单独裁定；现未安装基础把策略变化归入固定变化，需在安装前明确。

## 7. 保存、派生与结果

| 修改情形 | 处理 |
| --- | --- |
| 可调提示词业务配置 | 原工作流保存；后续装配使用新值 |
| 固定配置或结构修改，存在未归档会话 | 后端判定需要派生，前端弹窗询问；同意后才派生 |
| 没有有效会话时修改固定内容 | 原工作流保存 |
| 无实际变化 | 确认无变化，不创建新工作流 |

派生时原工作流和会话不改；新工作流不继承原会话或历史检查点。用户不同意派生则不写入这次修改、不创建新工作流，不先写入再要求确认。待确认内容只可作为普通当前内存编辑，不新增持久草稿。

具体后端确认请求、用户同意后的正式提交参数、依据变化时的真实冲突结果尚待收敛。本稿不批准临时绕过后端判断、前端猜测派生条件或静默重交。

**迟到回执：** 提交 A 后切换到 B，A 的结果仍只归 A，不能覆盖 B 或强行切回 A。较旧结果不能覆盖较新的正式配置。节点复制、工作流派生和会话切换均保持准确原归属。

**未知请求：** 超时、断线不能证明后端没接受。页面显示结果待核实，保留已提交请求的准确身份，只查询原回执，不自动重发、不假定失败或回滚。限制落在相关提交对象上，不锁住其他独立表单。这是提交结果核实，不是编辑草稿恢复，也不是历史回溯权威。

**明确失败：** 如实报告实际错误，不显示成功，不另存失败恢复草稿。普通当前内存编辑与持久草稿分开。

### 7.1 接管后退出范围

| 替代完成后退出 | 保留 |
| --- | --- |
| 工作台、节点的持久草稿和草稿恢复入口 | 普通当前内存编辑、后端正式节点数据 |
| 仅修改内存的旧 configureNode/“应用成功”通道 | 按节点注册授权的正式配置提交 |
| 旧手动发布、重新绑定/采用修订，以及运行前套用这些步骤的旧配置路径 | 直接对象管理、正式保存结果和必要运行准备 |
| 同一编辑动作的重复旧保存入口 | 实际写入冲突、准确回执和未知请求核实 |

这是待实施退出清单，不是本次删除结果。供应商/Key 等独立资源保存不能被整套替换成输入 200ms 通信；混合用途模块不得整删。
