# 酒馆入口与旧存档修补

日期：2026-10-09，Asia/Shanghai。承接用户在正式 BAT 验收中反馈的“找不到创建酒馆工作流”“不知道如何打开酒馆前端”及“浏览器原记录已保留”常驻提示。前置 P1-P6 功能提交为 `0c15587`，文档同步后本地主干为 `92b15e1`。本批不修改 BAT、节点版本或后端数据 schema，不推送、不自动启动服务或调用真实模型。

## 修补范围

- 工作流列表上方新增可见“创建酒馆工作流”，进入内容顶部的酒馆模板；创建按钮不再只写“新建”。未启用精确酒馆包或面板时禁用并提供诊断。
- 保留 Chat/Gemini 协议、有效模型配置复用及待配置选项。创建仍只产生独立草稿，不发布、创建会话或运行。
- 新建模板后选中聊天展示节点，右侧显示“打开酒馆前端”或“新建会话并打开酒馆前端”。保存、会话修订、精确包和公开输出校验不放宽，入口仍绑定当前工作流和会话。
- 原浏览器工作台 `workflow-workbench:fixed-base:v1` 与旧隔离工作台 `workflow-workbench:isolated-graph:v7` 先按原始字符串及 SHA-256 归档本机。地址包括来源与摘要，不覆盖其他快照；坏 JSON 和未知格式也保管原文，不自动导入或执行 pending。
- 存档使用既有管理端本机草稿 API 的独立 `form` 记录；必须确认写入后再核对并清理对应浏览器旧命名空间。未知写入只读原回执，归档/容量/清理失败或其他页面改动时保留原文，当前工作台继续独立保存。
- 顶部归档图标“旧版存档”读取、校验并导出原文，已归档记录不再常驻错误条。资源 outbox 和消费者原请求仍走各自原保护路径，未混入本次旧工作台归档。
- 修正表单依据按 `JSON.stringify` 字段顺序比较产生的假冲突。复用图签名的规范化 JSON 规则，对象字段顺序不影响依据；数组顺序、类型、真实配置与目标身份仍严格检查。
- 根 `AGENTS.md` 和开发手册登记后续破坏性变更的旧测试工作流归档/清理责任；不因普通界面更新清空现行可用图。

## 交付边界

真实工作台仅做入口查看，没有代用户创建工作流、会话或派发模型。浏览器验证使用生产 dist、全请求拦截和受控数据，不监听新端口，不改用户数据库。浏览器旧记录的实际归档由用户打开更新后的工作台触发；本批不直接操作用户浏览器存储或整批删除运行历史。

当前可用图、供应商、正式/开发库、会话和运行事实不因本次界面更新合并或清空。存档保存原文，可能包含私人正文，不能作为公开日志上传。归档容量仍受既有本机草稿限制，超限保留原记录并报告，未新增无限容量、自动恢复旧执行或整个工作台手机适配。
