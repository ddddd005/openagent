# Development Priorities

- The project is currently a development and debugging environment. Keep code and features simple, and consistently prioritize debugging and development over delivering a finished product for direct end-user use. Allow and support program problems becoming visible so their causes can be investigated, organized and fixed.
- Do not add excessive fallback, recovery or speculative error-handling mechanisms. Report failures directly and preserve their diagnostic information; investigate connection interruptions, database errors and other underlying faults instead of hiding them behind alternative execution paths.
- Do not implement a draft mechanism at the current stage, including persistent editor drafts or draft-based recovery after failed saves. Ordinary in-memory form editing is sufficient. A failed save must report the error directly, without an additional draft-saving or recovery flow.

Before considering a fallback mechanism or an additional error case, explicitly ask and answer both questions:

1. Could this fallback mechanism or the handling of this additional error case conceal a deeper error?
2. Would the program be unable to run normally without this mechanism?

Prefer exposing and diagnosing the underlying problem. Leave out mechanisms that are unnecessary for normal operation, and fix the root cause when a fallback would mask it.
