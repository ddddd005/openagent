# OpenAgent

OpenAgent 是一个面向本机开发的 Agent 工作流工作台。它借鉴 ComfyUI 的节点化组织方式，把 Agent 放进可组合的图中，让输入、提示词、上下文、模型、工具能力和结果在明确的节点之间流动。中间节点可用于整理材料、约束运行并检查过程，目标是让单轮处理更可控、提升输出质量；它不保证特定模型结果。

项目层提供运行与存储环境，并装配各项子能力。产品主要由以下部分组成，工作流是核心：

- **工作流**：在画布上组合节点，管理配置、会话、运行与历史。
- **供应商和模型配置**：集中保存供应商连接信息与可复用的模型预设，由工作流引用。
- **全局内容**：管理可复用的提示词资源与 Lorebook 内容。

## 核心特点

- **显式编排**：节点通过端口连接，工作流决定处理顺序和数据流；Agent 的可用能力由图中的明确配置决定。
- **显式工具**：Agent 核心节点只调用已声明、装载并绑定的工具。普通工作流节点不会自动变成 Agent 工具，也不会因此获得工具权限。
- **会话数据与检查点**：会话保存各自的数据和运行历史；预加载项在创建新会话时初始化一次。检查点只保存明确准入的状态，可据此创建独立新会话，不是整个项目的完整备份。
- **手动本地扩展**：可信工作流包可提供节点和显式 Agent 工具能力。包由用户手动放置并选择启用，不会自动安装或升级。

## 当前状态

项目仍在开发中。目标版本为 `0.5.0`，但前后端源码元数据仍为 `0.2.0`；尚未正式发布，也未完成最终整体验收。请将其视为持续演进的本机开发版本，不要据此推断全量测试全绿或适用于生产部署。

**推荐配合 harness 使用和开发。** 这里指能够读取本仓库、调用本地工具的模型协作环境，并非 OpenAgent 内置功能。你可以先用自然语言说明目标，让助手协助配置工作流、定位问题，或按现有扩展机制制作节点和工具包。工作台仍可手动使用；采用 harness 不代表自动授权真实模型调用、数据修改或发布操作。

## 运行与数据安全

- 显式运行真实模型节点可能连接外部服务并产生费用。
- API Key 通过受保护的凭据存储与普通工作流数据分离；Windows 凭据库受当前用户和存储位置保护，不要复制或迁移。无法提供保护的环境应拒绝保存凭据。
- 本地 Python 扩展是可信的进程内代码，没有沙箱。只放置可信来源的包；没有市场、网络下载或热更新，也不支持让 Agent 任意取得文件、网络或宿主权限。
- 未知结果的请求应核实原请求及其回执，不要自动重发或更换凭据重试。
